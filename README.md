# GeoFlora — flore française

Référentiel léger destiné à une application de recherche dans la flore vasculaire de France métropolitaine.

Les mots de l'interface (bloc, rubrique, panneau, case, disposition, mode…) et leur nom dans le code : [`docs/LEXIQUE.md`](docs/LEXIQUE.md).

## Dataset local

Le build TAXREF v18 produit actuellement :

- **7 745 espèces**
- **180 familles**
- **1 245 genres**
- **15 487 noms vernaculaires français uniques**
- **33 121 synonymes scientifiques**
- **7 177 espèces** avec au moins un nom français
- **568 espèces** sans nom français disponible dans les données TAXREF utilisées
- **3 504 espèces** avec une vignette de recherche Wikimedia Commons (**45,24 %**)

Le principe est simple :

- **IndexedDB locale** = recherche, tri, filtres et données taxonomiques de base ;
- **sources ouvertes distantes** = vignette, photos, répartition, descriptions, traits et liens détaillés ;
- les images ne sont **pas téléchargées dans le dataset**.

## Source et sélection

Le générateur utilise l'archive officielle **TAXREF v18** diffusée par PatriNat/MNHN :

- `TAXREFv18.txt` pour taxonomie, auteurs, synonymes et statut en France métropolitaine ;
- `TAXVERNv18.txt` pour les noms vernaculaires.

Filtres actuels :

- règne `Plantae` ;
- rang espèce `ES` ;
- nom accepté uniquement (`CD_NOM = CD_REF`) ;
- groupe TAXREF `Trachéophytes` ;
- présence en France métropolitaine ;
- statuts `P N E S C I J`.

Les synonymes TAXREF de rang espèce sont rattachés au taxon accepté. Les noms français portés par ces synonymes sont également rattachés à l'espèce acceptée.

**Statuts de protection** : `scripts/enrich-statuses.mjs` ajoute `statuses` depuis la **Base de connaissance Statuts** de l'INPN (PatriNat — OFB, MNHN, CNRS ; données ouvertes, archive `BDC.zip`), rapprochée par identifiant TAXREF (`CD_REF`). Sont retenus : protections **nationale** (`PN`), **régionale** (`PR`) et **départementale** (`PD`), **réglementation de la cueillette** (`REGL`), et **listes rouges** nationale (`LRN`) et régionales (`LRR`) pour les seules catégories menacées (RE, CR, EN, VU, NT). Chaque statut garde son territoire (`area`, `level`, `iso`) et l'intitulé du texte (`label`) ; les territoires d'outre-mer sont écartés. Si le téléchargement échoue, les statuts du jeu de données déjà versionné (`git show HEAD:data/plants.json`, `scripts/previous-data.mjs`) sont repris plante par plante, avec un avertissement dans le journal de l'action et `kept: true` dans `meta.json` ; sans jeu précédent, le build échoue. Un jeu de données n'est donc jamais publié sans ses statuts de protection.

**Territoires** : `data/territories.json` (généré par `scripts/build-territories.mjs`) contient les contours simplifiés des départements métropolitains (d'après IGN ADMIN EXPRESS via france-geojson, Licence Ouverte), avec leur région actuelle et leur **ancienne région** : beaucoup d'arrêtés régionaux de protection nomment encore les régions d'avant 2016. Il porte aussi les contours propres des régions et de la France métropolitaine (simplifiés un peu plus : ils ne servent qu'à tracer un périmètre vu de loin) : des départements simplifiés un à un ne partagent plus exactement leurs frontières, leur assemblage en garderait des bouts à l'intérieur.

**Catalogue des couches de l'IGN** : `data/ign-catalog.json` liste, en compact (identifiant, titre, description de 600 caractères au plus — raccourcie si le fichier dépasse 600 ko —, format, style, zooms, mots-clés `<ows:Keywords>`, emprise `<ows:WGS84BoundingBox>`, légende du style par défaut, fiche de métadonnées, puis son classement), les couches WMTS de la Géoplateforme que les cartes savent afficher (grille Web Mercator, tuiles PNG ou JPEG), lues dans sa description `GetCapabilities` — plusieurs Mo de XML, trop lourds à télécharger et à analyser sur un téléphone — par `scripts/build-ign-catalog.mjs`, avec le même lecteur que l'app (`lib/ign-catalog.mjs`, sans dépendance). Le service nomme ses grilles `PM_6_16`, `PM_0_19`… (zooms mini et maxi) et non `PM` : c'est ce qu'ignorait l'ancien lecteur, qui ne trouvait aucune couche (« Catalogue de l'IGN indisponible »). **Le fichier publié est régénéré à chaque déploiement** (`deploy-pages.yml`, job « catalog », lancé aussi **le 2 de chaque mois** pour qu'il reste frais sans commit) et contrôlé (au moins 50 couches, chacune avec un identifiant sûr, un format PNG/JPEG, un titre et des zooms ; les couches de l'app présentes ; pas de chute de plus de 30 %) ; si le service ne répond pas, la copie versionnée est publiée, avec un avertissement, et le déploiement continue. **Classement** (`lib/ign-classify.mjs`, pur, testé sur le catalogue livré par `tests/unit/ign-classify.test.mjs`) : des règles ordonnées sur l'identifiant (thèmes INSPIRE `ORTHOIMAGERY.*`, `ELEVATION.*`, `LANDCOVER.*`… ou préfixe du producteur `Patrinat_*`, `ADEME_*`, `INSEE.*`, `OCSGE.*`…) et le titre, puis sur les mots-clés et la description, rangent chaque couche dans une taxonomie française de 15 catégories et leurs sous-catégories — Photos aériennes et satellite (actuelles, par année, infrarouge, historiques, par département, satellite, prises de vue locales), Cartes (plans, topographiques, anciennes, Grande Guerre), Relief et altitude, Forêts et végétation, Nature et espaces protégés, Sols et géologie, Occupation du sol, Eau et littoral, Agriculture, Limites administratives et cadastre, Population, bâti et services, Transports, Énergie, Risques, Autres ; une couche qu'aucune règle ne reconnaît va dans « Autres », jamais perdue (le build vérifie que chaque couche a sa place). Les **séries** — une même couche par année, période, édition, département ou ville (photographies aériennes 2000 à 2024, RPG, ADMIN EXPRESS, CORINE Land Cover, OCS GE, Édugéo…) — sont regroupées en une entrée avec un sélecteur (660 couches → ~330 entrées) ; les copies d'une même couche sous deux identifiants aussi. Les titres codés reçoivent un titre lisible (« Patrinat_ZNIEFF1 » → « ZNIEFF de type I »), le producteur est nommé quand il est sûr (PatriNat, ONF, ADEME, INSEE, Copernicus…), et un rang « pertinent pour la botanique » (forêts, espaces protégés, ZNIEFF, Natura 2000, sols, habitats, végétation, zones humides, relief, infrarouge) fait les « Recommandées ». Format du fichier **2** (`version`, `taxonomy`, `groups` : titre de chaque série) ; l'app relit aussi l'ancien format 1, et reclasse à la lecture toute copie classée avec d'autres règles (une copie lue au service sur l'appareil est classée dans le worker). Après un changement des règles : `node scripts/build-ign-catalog.mjs --reclassify` réécrit la copie versionnée sans redemander le service. Il est précaché par le service worker et compté dans sa `VERSION` : un nouveau catalogue fait une nouvelle version, un catalogue inchangé n'en fait pas. La copie versionnée n'est qu'un repli (et le fichier des tests) : la première est une **graine** (`"seed": true`), tirée de l'autoconfiguration publiée par l'IGN (dépôt IGNF/geoportal-configuration, elle-même générée depuis ce `GetCapabilities`), que l'app tient pour vieille ; la remplacer par une copie lue au service : `node scripts/build-ign-catalog.mjs` (`--check <fichier>` vérifie un fichier). Dans l'app (`app/core/ign-catalog.js`), la copie la plus récente — livrée, ou lue sur l'appareil — s'affiche tout de suite ; plus d'un mois (ou une graine), module allumé et en ligne, le service est redemandé en fond : téléchargement lu au fil de l'eau, abandonné seulement après 20 s sans aucun octet (3 min au plus en tout), analyse dans un worker (`app/workers/ign-catalog.worker.js`), liste remplacée puis gardée sur l'appareil. Un échec ne remplace jamais la liste, n'est pas redemandé avant 5 minutes, sauf par « Réessayer ». `api-health.yml` lit chaque jour ce `GetCapabilities` avec ce même lecteur (au moins 50 couches) et échoue si le catalogue publié est une graine ou date de plus de 45 jours ; `post-deploy.yml` le signale après chaque déploiement.

**Floraison** : `scripts/enrich-baseflor.mjs` ajoute `flowering: [premier mois, dernier mois]` (1–12 ; un dernier mois plus petit que le premier signifie une floraison à cheval sur l'année) depuis **Baseflor**, l'index botanique, écologique et chorologique de la flore de France de Philippe Julve (programme CATMINAT), diffusé par [Tela Botanica](https://www.tela-botanica.org/ressources/donnees/telechargements/) : données sous licence **CC BY-SA 2.0**, base sous **ODbL 1.0**. Le tableau (`baseflor.xlsx`, colonne `floraison` au format « 6-9 ») est récupéré dans le porte-documents Tela Botanica (Cumulus). Le rapprochement se fait par identifiant TAXREF (`CD_REF`), sinon par binôme latin (nom accepté, puis synonymes TAXREF) ; la ligne de l'espèce l'emporte sur celles de ses sous-espèces. Une autre adresse peut être imposée par la variable de dépôt `BASEFLOR_URL`. Environ la moitié des espèces ont une floraison renseignée dans Baseflor (case vide pour certaines plantes courantes, comme l'ail des ours ou l'ortie) ; pour les autres, le calendrier s'appuie sur les observations iNaturalist. Si le téléchargement échoue, les floraisons du jeu déjà versionné sont reprises de même (avertissement, `kept: true` dans `meta.json`).

## Enrichissement distant

`lib/plant-sources.mjs` fournit une couche ES6 sans dépendance pour enrichir une plante au moment où elle devient visible ou lorsque l'utilisateur ouvre sa fiche.

Sources actuellement prises en charge :

- **GBIF** : correspondance avec le Backbone GBIF (`species/match`, plantes seulement), descriptions, noms vernaculaires, répartition, profils d'espèce (habitat, port, envahissante), synonymes, catégorie UICN, publications ; occurrences en France (présences seulement, coordonnées sans problème connu) : nombre, par mois, par année, régions et départements (GADM), types de relevés, principales sources, carte de densité (tuiles GBIF), les plus proches de vous ; images d'occurrences sous licence libre (CC0, CC BY, CC BY-SA), photos d'observation et planches d'herbier à part. Chaque donnée n'est demandée que si son bloc ou sous-bloc est affiché ;
- **iNaturalist** : taxon, nombre d'observations et photo par défaut lorsque sa licence est libre ; **phénologie** : observations en France par mois, annotées « en fleurs » / « en fruits » (`phenology()`, histogramme `month_of_year`, `place_id=6753`) ;
- **Wikidata** : résolution sûre par propriété taxonomique `P225` ;
- **Wikimedia Commons** : photos libres avec URL, miniature, auteur et licence ;
- **Trefle** : taxon, image principale et fiche détaillée (token gratuit requis).

Exemple :

```js
import { PlantSources } from './lib/plant-sources.mjs';

const sources = new PlantSources({
  trefleToken: null
});

// Pour une ligne visible dans la liste :
const thumbnail = await sources.thumbnail(plant);

// Quand la fiche est ouverte :
const details = await sources.details(plant);
```

Avec un token Trefle :

```js
const sources = new PlantSources({
  trefleToken: 'YOUR_TREFLE_TOKEN'
});
```

Trefle impose actuellement un token et une limite standard de 60 requêtes par minute. Pour une application publique, il est préférable de placer le token derrière un petit proxy si le quota doit être protégé.

**Source indisponible — Réessayer.** Une source qui ne répond pas n'est plus prise pour une absence de donnée. Chaque bloc de la fiche (Descriptions, Noms, Occurrences, Interactions, Climat, Usages, Taxonomie, Identifiants…), le Calendrier et les infos d'un lieu (zones naturelles, plantes vues ici, pollens, climat) affichent « Source indisponible : GBIF (hors ligne | pas de réponse à temps | erreur 503 | réponse inattendue) — Réessayer » ; « Réessayer » redemande ce qui a échoué. Les messages « Aucune… » sont réservés aux réponses valides et vides, et un module coupé dans les Réglages reste « module désactivé » (rien n'est demandé). Un appel qui ne répond pas abandonne après 15 secondes : plus de « chargement… » sans fin sur un portail captif ou en zone blanche.

Côté code (audit STO-7, STO-8, STO-9, OPS-2, QUA-6, ARC-14, PERF-15, STO-17) :

- `app/core/net.js` : `fetchJson(url, { signal, headers, timeout, expect, allowEmpty })`, seul chemin des appels JSON distants : délai (15 s, corps compris, `AbortSignal.any` avec le signal de l'appelant), contrôle de forme minimal (`expect`, sinon `SchemaError`), erreurs typées (`SourceError.kind` : `offline`, `timeout`, `http`, `schema`, `network` ; `errorKind()` y ajoute `aborted` et `module-off`). `lib/plant-sources.mjs` le reçoit en option (`new PlantSources({ fetchJson })`) et nomme les services en échec (`unavailable`) au lieu de les lire comme « absent » ;
- `app/core/cache.js` : le seul cache des réponses (store `plantDetails`), utilisé par `sources.js`, `geoservices.js`, `open-data.js`, `nearby.js`, `uses.js`, `protected.js`, `ign.js` : requêtes en vol partagées, une panne jamais enregistrée (cache négatif de 5 min, en mémoire seulement, oublié par « Réessayer »), un résultat dégradé jamais gardé plus de quelques minutes ni à la place d'une copie complète, une copie expirée en repli hors ligne (pas après une annulation). Chaque entrée garde sa durée de vie (`ttl`) ; une purge, une fois par jour après le démarrage et au repos, retire les entrées expirées depuis plus de 30 jours, puis les moins récemment utilisées au-delà de 4 000 entrées ou d'environ 40 Mo. Clés versionnées à dessein pour oublier les réponses de panne déjà gardées : `details3`, `thumb2`, `wikibooks2` ;
- `app/core/source-state.js` : le message « Source indisponible — Réessayer » des blocs et des panneaux.

### Politique média

Par défaut, GeoFlora préfère uniquement les médias dont la licence est clairement compatible avec une réutilisation libre :

- CC0 / domaine public
- CC BY
- CC BY-SA

Les images iNaturalist sous CC BY-NC ou sans licence exploitable ne sont pas choisies automatiquement. Les résultats Wikimedia Commons sont filtrés de la même manière (jamais NC ni ND : « CC BY-NC 4.0 » ou « cc-by-nd » ne passent plus pour libres ; `tests/licenses.mjs`, lancé par `tools/check.sh`, vérifie la table des licences).

**Partout dans l'application**, une photo iNaturalist n'est montrée que sous CC0, CC BY ou CC BY-SA (son `license_code`) : cartes Rencontres et fenêtre du match, Toutes et Matchs, Carte › Autour, « Plantes vues ici », points photo des cartes ; sinon, la vignette de la flore (ou une feuille sur la carte). **Chaque photo porte son crédit** — « © auteur · licence · source », sans « © » pour CC0 et le domaine public — sur les cartes Rencontres, la fenêtre du match, les vignettes de Toutes et Matchs (au bas de la photo), la petite fiche d'un point de la carte, l'espèce choisie dans Carte › Autour ; les auteurs des « Plantes vues ici » sont cités sous la rangée, et la carte nomme ses sources de photos dans son attribution. Une vignette CC BY dont l'auteur manque renvoie à sa page Commons (« auteur sur sa page »). « On dit de moi » cite Wikipédia (CC BY-SA). Au build, l'auteur d'une vignette Commons vient d'`Artist`, sinon de son attribution ou de son crédit ; une vignette CC BY sans auteur est vérifiée de nouveau au build suivant, et une image sous GFDL, GPL ou FAL n'est plus choisie.

**Wikimedia** : les appels aux API de Wikidata, Wikipédia, Commons et Wikibooks portent l'en-tête `Api-User-Agent: GeoFlora (https://github.com/yannouche-dev/flora)`, comme le demande la politique User-Agent de Wikimedia (un navigateur ne peut pas changer son User-Agent). Le service de requêtes (`query.wikidata.org`) n'en reçoit pas.

Trefle reste disponible pour ses données structurées et ses images par organes, mais une image dont la licence précise n'est pas vérifiée n'est pas utilisée automatiquement comme miniature, sauf avec l'option :

```js
new PlantSources({
  trefleToken: '...',
  allowUnverifiedMedia: true
});
```

## Architecture GeoFlora

```text
Recherche / filtres
        │
        ▼
IndexedDB
7 745 espèces
        │
        ├── famille
        ├── genre
        ├── espèce
        ├── noms vernaculaires
        ├── synonymes
        └── statut TAXREF
        │
        ▼
Liste de résultats
        │
        ├── données locales immédiates
        └── thumbnail.url déjà présent dans plants.json
        │
        ▼
Fiche plante
        │
        ├── photos / organes
        ├── répartition
        ├── descriptions
        ├── traits
        ├── observations
        └── ressources externes
```

Les réponses distantes peuvent être mises en cache quelques heures ou quelques jours dans IndexedDB. Les images restent servies par leur source ; le service worker garde les 400 dernières vignettes et photos vues (pas les originaux), d'une version de l'app à l'autre, pour les afficher hors ligne. Il les demande en CORS : une réponse lisible est gardée à sa taille réelle ; un hôte sans CORS voit ses images affichées mais jamais gardées (une réponse opaque compte environ 7 Mo de quota chacune).

### Disposition et panneaux

**Tous les panneaux sont redimensionnables horizontalement, toutes les dispositions sont responsives.** Un *panneau* est une région posée à côté d'une autre (une colonne) ; entre deux, un *séparateur* ; la *disposition* est leur arrangement selon la largeur : téléphone (moins de 700 px, `BP.phone` : les panneaux empilés, sans séparateur), tablette, grand écran (des colonnes qui ne tiennent plus se replient ou passent en onglets).

- **Un seul séparateur pour toute l'application** : `PaneSizer` (`app/core/panes.js`) — glisser (une ligne guide suit le pointeur, la largeur est prise au relâcher), ← → au clavier (Maj : par 64 px), Début / Fin, double-clic ou Entrée : largeur par défaut ; lu « Redimensionner le panneau … » (`role="separator"`, `aria-controls`, `aria-valuenow` / `min` / `max`) ; au doigt, 44 px à tenir et une languette.
- **Entre deux parts d'un partage par proportions** (l'arbre des panneaux de la fiche, une disposition libre), la poignée commune de `app/core/split-grip.js` : glisser (les deux voisines suivent, chacune garde son minimum), ← → dans une rangée, ↑ ↓ dans une colonne (5 %, Maj : 20 %), Début / Fin, Entrée ou double-clic : parts égales ; lue « Redimensionner … et … », sa valeur en %.
- **Chaque panneau a son minimum et son maximum**, et la somme ne dépasse jamais l'écran : une largeur choisie sur un grand écran se resserre sur un plus petit, sans être oubliée (la fenêtre agrandie ou l'appareil tourné, elle revient). **Jamais de défilement de côté**, dès 320 px de large.
- **Les largeurs sont gardées par écran**, chacune sous sa clé de `config.storageKeys` listée dans `config.paneLayouts` (Flore, Mes plantes, Carte, éditeur d'un lieu, « À propos de l'image » à côté d'une photo…) : les premiers pas ne la prennent pas pour un « habitué ». Une mini-application garde les siennes dans son espace (`geoflora.app.<id>.*` : ses colonnes, le panneau des photos, la fiche d'une plante à côté des cartes), listées dans son `owns` : « Recommencer » les oublie.
- **Ne sont pas des panneaux** : les barres d'outils et d'en-tête, une barre repliée (rail), le Sommaire et les menus (par-dessus la page), une carte flottante (le point de la Carte), les grilles de cartes (Découvrir, Mosaïque) et les colonnes d'un texte (étiquette / valeur des Réglages).
- `tests/e2e/panes-all.spec.mjs` le vérifie sur chaque écran, de 320 à 1920 px.

### Mini-applications

Rencontres, le Parcours botanique, Cueillette prudente, Mosaïque et Faux amis sont des **mini-applications** : chacune s'ouvre **seule à l'écran**, à son adresse `#/app/<id>/<étape>` (`#/app/rencontres/cards`, `#/app/parcours/walk`, `#/app/cueillette/map`, `#/app/mosaique/cards`, `#/app/faux-amis/play`), sans en-tête ni barre d'onglets, sous une barre de 48 px : **« × Quitter … »** (la seule sortie : elle ramène là d'où on l'a ouverte — la liste de Découvrir, si on l'a ouverte de là), son titre, **ses étapes** (Départ › Carte › Rencontres, Cueillette ou Mosaïque ; Départ › En marche › Bilan ; Départ › Partie) et **⋯** : masquer ou afficher les étapes, remettre la mise en page, **Rejouer**. Les étapes se touchent : une étape déjà faite y ramène, « Suite › » passe à la suivante ; chaque étape est une entrée de l'historique (Retour revient à la précédente). Les anciennes adresses (`#/discover?s=meet`, `?s=trail`, `?s=harvest`, `?s=mosaic`, `#/discover?p=<id>`) y mènent.
- **L'adresse dit tout l'écran** : `#/app/<id>/<étape>?p=<plante>&v=<vue>&m=<image>&fiche=1` — `p` la plante de l'écran (Rencontres : la plante choisie ; Cueillette prudente et Mosaïque : la plante ouverte dans sa fiche), `v` la vue de la liste (`matchs`, `toutes` ; rien : la sienne), `m` l'image montrée (sa place parmi les médias de la plante ; rien : la première), `fiche=1` sa fiche ouverte (Rencontres). Toujours dans cet ordre, les valeurs par défaut omises : un écran, une adresse. **Recharger, Retour, Suivant ou un lien partagé** rouvrent exactement cet écran. **Une autre plante est une nouvelle entrée de l'historique** (Retour revient à la plante d'avant), une fiche ouverte aussi (Retour la ferme) ; la vue, l'image ou une fiche fermée remplacent l'adresse. L'adresse suit l'écran et l'écran suit l'adresse (`gf-miniapp.js` : l'adresse appliquée n'est jamais réécrite, pas de boucle) ; `router.js` la lit (`parse`) et l'écrit (`href.app`), testé sous Node (`tests/unit/query.test.mjs`).
- **Chacune sa partie** : Rencontres, Cueillette prudente et Mosaïque gardent **chacune leur lieu, leur distance, leurs cartes passées et leurs matchs** (`geoflora.app.<id>.state` ; Cueillette prudente, aussi ses sosies toxiques reconnus, `avoided`) : « Reprendre » (le lieu gardé, sur l'écran de départ) et « Continuer » (la liste) sont propres à chacune, et rejouer l'une ne touche pas les autres ; Faux amis garde la sienne (les six cartes tirées et les réponses). Avant, les trois partageaient une même partie (`geoflora.discover`) : elle est **donnée une fois à la dernière jouée** si l'adresse ouverte le dit (`#/discover?s=harvest` ou `?s=mosaic`), sinon à Rencontres — rien n'est perdu, et une seule propose « Continuer » ; puis chacune va son chemin.
- **Rejouer** (⋯) et **Recommencer** (la liste de Découvrir) font la même chose : ils demandent d'abord, dans un dialogue qui dit **ce qui sera supprimé, avec les nombres** (« Recommencer : tout effacer ? Seront supprimés : 12 favoris ajoutés par Rencontres, la partie en cours. Cette action est définitive. » ; pour le Parcours « le parcours en cours « Chemin du lavoir » (4 plantes) », puis, s'il y en a, « Vos 3 parcours enregistrés dans Mes plantes sont conservés. »), le focus sur « Annuler » ; puis ils effacent **tout ce que la mini-application possède et tout ce qu'elle a fait**, et seulement cela, comme si elle n'avait jamais été ouverte, et rouvrent **son premier écran** (`#/app/<id>/start`, rien ne le saute, même après un rechargement), aussi dans les autres onglets ouverts : sa partie et sa mise en page (`geoflora.app.<id>.*`), en mémoire ses cartes, son paquet, ses retours en arrière, la vue choisie, le filtre « En fleur », l'animation qui montre qu'on peut glisser (elle revient) ; pour Rencontres aussi ses étapes guidées, l'embranchement, le premier match fêté et les largeurs de sa mise en page guidée (`geoflora.discoverLayout`) ; pour le Parcours le parcours en cours, la liste des parcours à reprendre, le bilan affiché et la largeur de sa colonne (`geoflora.trailLayout`). **Ce qu'elle a fait dans Mes plantes s'en va aussi** : chaque favori ajouté par un match et chaque parcours enregistré portent **l'application qui les a faits** (`origin: { app }`, gardé dans la sauvegarde et les exports GeoJSON, relu à l'import) ; Recommencer supprime ces favoris et le parcours en cours (ou un parcours resté vide), en une seule transaction. **Sauf ce que vous avez fait vôtre** : un parcours **terminé avec au moins une plante** (son bilan), ou renommé, modifié, complété depuis Mes plantes, partagé ou exporté seul ; un favori de match ensuite **rangé dans une liste** ou **annoté** (une note sur la fiche) — à ce moment-là il perd son origine (il garde seulement `from: { app }`, pour dire d'où il vient) et devient une donnée comme une autre : Recommencer le garde, et le dialogue le dit. Ce qui existait avant cette version est attribué une fois, au mieux, sans rien détruire : **les favoris d'avant sont à vous** (jamais attribués à une partie) ; le parcours en cours et les parcours vides sont au Parcours ; un parcours terminé avec ses plantes est déjà à vous. **Ce qui ne vient pas d'elle reste** : un favori mis depuis la Flore, ou qui l'était déjà avant le match, les autres lieux et leurs plantes, les premiers pas de l'application (les onglets venus, les plantes vues), les réglages et les réponses des services en ligne gardées en cache.
- **Afficher les étapes** (*Réglages › Premiers pas*) : « Pendant la découverte » (par défaut : jusqu'à la fin d'une première partie), « Toujours » ou « Jamais ».
- **Pour un développeur** : une mini-application est un **manifeste** (`app/miniapps/<id>.js`, inscrit dans `app/miniapps/index.js`) vérifié au chargement par `defineMiniApp` (`app/miniapp/define.js`) : son contexte et ce qui en dérive, ses colonnes (largeur de base, min, max, rang, colonne où se replier), ses étapes (la première est le départ ; chacune ajoute ou retire des composants du kit, `app/miniapp/kit.js`), ce qu'elle **possède** (`owns` : ses clés, `reset()` pour le reste — mémoire, ce qu'elle a fait dans Mes plantes —, vidés par Rejouer ; chaque manifeste en dresse la liste, avec la frontière de ce qu'elle **partage**, `shared`, jamais effacé). La grille (`ma-grid`) met toutes les cellules dans une seule grille CSS : changer d'étape ou de largeur ne recrée jamais une carte ; sous 700 px, une seule colonne ; quand la place manque, la colonne de plus petit rang devient un onglet de sa voisine, sans défilement horizontal. **Le kit des plantes autour** (`app/miniapp/kit/`) : la session de la partie (`session.js` : cartes, observations, Wikipédia, retours en arrière), la distance sur la carte (`ma-distance`), la liste (`ma-around-list` : le paquet `ma-deck`, les matchs, la grille ou la mosaïque, la fiche `ma-plant-sheet`, le premier match, et pour Rencontres les photos du premier match, `ma-meet-media`), la découverte guidée de Rencontres (`ma-guided`, sa carte `ma-around-map`), et ce qui est pur (`cards.js` : l'ordre de la Cueillette et ses sosies toxiques jamais aimés, la bio et ses lignes de sécurité, testés sous Node : `tests/unit/around.test.mjs` ; la partie de la Cueillette contre une flore en mémoire, `tests/unit/harvest-session.test.mjs`). Cueillette prudente et Mosaïque assemblent `distance` puis `aroundList` ; Rencontres, `meet` (la découverte guidée pendant les premiers pas, sinon les mêmes). **Le kit du Parcours** : sa partie (`trail-session.js` : le parcours en cours, ceux à reprendre, le bilan, la position suivie ; `trail-store.js` : ce qu'il garde sur l'appareil, et ce qui est pur — les plantes regroupées ; `trail-recap.js` : les chiffres du bilan ; testés sous Node), son écran de départ (`trail-start.js`, dessiné par la boîte), la marche (`ma-walk` : sa carte `ma-walk-card`, ses plantes `ma-walk-list`, sa recherche sous le pouce `ma-walk-search`, sa carte `ma-walk-map`) et le bilan (`ma-trail-recap`) ; ses étapes Départ › En marche › Bilan sont celles du manifeste (une adresse chacune, Retour étape par étape ; ouvert sans étape, le parcours en cours ou son bilan reviennent aussitôt : `resumeAt`). **Le kit de Faux amis** : sa partie, pure (`faux-amis.js` : les critères attribués à une plante, les cartes tirées, les réponses et le score, la partie relue dans le fichier — testés sous Node), son écran de départ (dans son manifeste) et ses cartes (`ma-faux-amis` : la carte, sa réponse, le bilan). Aucune mini-application n'enveloppe plus un écran d'avant : `gf-discover` et `gf-trail` n'existent plus.

### Créer une app : une grille ou un modèle, puis des blocs

`#/builder` (carte **« Créer une app »** en tête de Réglages, bouton **« Modifier »** d'une Disposition libre ; `app/layout/gf-builder.js`) : **le seul endroit où l'on fabrique une app**, et ce qu'on y voit est **l'app elle-même, en direct** — la vraie Disposition libre (ci-dessous : la vraie carte, la recherche, la fiche…, reliées par le même état), avec les outils de chaque case.

1. **Le départ** : trois **grilles** — **Une colonne**, **Trois colonnes**, **Tableau de bord** (`gf-builder-grids.js`) — et les **modèles** de la Disposition libre, chacun dessiné en petit.
2. **Découper** : l'icône **« construire »** (🛠) d'une case ouvre sa **croix** — un bras vers chaque côté la **coupe en deux** dans ce sens (à côté d'elle si sa liste va déjà dans ce sens, sinon elle devient une liste de deux), le centre la **déplace** avant ou après ses voisines ou la **retire** (sa place revient à sa voisine, une liste réduite à une case s'efface). 12 cases au plus, 3 niveaux d'imbrication ; Échap ferme la croix. Entre deux cases, **les poignées** règlent largeurs et hauteurs.
3. **Remplir** : chaque **« Emplacement »** (`slot`, un composant du registre) est un endroit où construire : il montre **ses tuiles** (le premier niveau du choix du contenu, à sa taille — icône et nom quand il est petit, avec leur phrase quand il est grand ; **aucun refusé** : un bloc un peu grand pour la case est proposé comme les autres, avec un conseil (« Un peu bas pour « Carte » : 180 px de haut conseillés (la case en a 120) » — la case s'agrandit ensuite) ; ce qui manque suggéré d'abord). **Un toucher** et l'emplacement devient ce bloc (la Fiche : la liste de ses blocs ; la Carte : ses **intentions** d'abord, en cartes). Une case coupée en deux donne un nouvel emplacement, sa première tuile sous le focus.
4. **Régler** : **✎ « Choisir le contenu »** dans l'en-tête de chaque case ouvre **le choix du contenu** (`app/layout/gf-block-picker.js`), ancré à droite (en feuille du bas sur un téléphone, 85 % de la hauteur au plus) : *Contenu* (une tuile par composant), *Que montre-t-il ?* (les intentions), *Affiner* — une ligne par groupe de réglages du registre (Où, Fond, Couches, Points, Liens, Interface, Cadre… ; « Réglages » pour ceux qui n'en ont pas) avec **le résumé de ses valeurs** (« Photos aériennes · 2D ») et **un point ●** quand un réglage y est écrit à côté de l'intention ; ses commandes faites selon la sorte de chaque réglage : quatre choix au plus en boutons (« Par défaut » compris), au-delà une liste ; oui / non un interrupteur (trois boutons quand le défaut est « selon Réglages » : la 3D) ; une distance un curseur sur les crans du rayon ; une liste (couches, commandes `ctl=`) des pastilles ; des mots un champ (nettoyé pour la grammaire) ; une plante fixée un numéro, ou « Fixer la plante courante ». **« Revenir à l'intention »** efface ce qui est écrit à côté d'elle ; **« Changer de bloc »** refait de la case un emplacement. Fil d'Ariane (`Case 1 › Carte › Couches`), Retour, Échap (le focus revient au bouton), le clavier partout. Le panneau ne nomme jamais un composant dans son code : tout vient du schéma du registre.
5. **Ouvrir l'app** : **« Ouvrir l'app »** ouvre `#/layout/<la même disposition>?<le même état>` (nouvelle entrée de l'historique ; un emplacement laissé reste un endroit où construire) ; **le lien à partager** du constructeur est celui du constructeur (pour continuer à construire), celui de l'app celui de l'app.

Autour de l'aperçu : le **titre** de l'écran (l'adresse suit la frappe, sans nouvelle entrée), un aperçu **« Ordinateur »** (toute la place) ou **« Téléphone »** (390 px de large : les onglets de la disposition, sans jamais réduire un dessin — une carte vivante ne le supporterait pas), ce qui ne va pas, et replié **« Avancé : le texte de la disposition »** (l'écran suit la frappe ; « Tailles par défaut » ; comment l'écrire).

**Chaque changement s'applique aussitôt et l'adresse garde tout** (sans nouvelle entrée) — **y compris ce qu'on fait dans les cases elles-mêmes**, comme dans l'app (voir *Ce qu'on fait dans une case est gardé*) : la 3D ou le fond d'une carte, ses couches et leur opacité, ses jumelles, sa légende, « Seule », la période, **le cadrage** (la carte déplacée ici part de là : `vue=`), les filtres ouverts, les résultats en liste ou en grille, une case repliée ; on construit, puis on envoie le lien. Retour suit l'adresse (une plante choisie puis Retour : plus de plante). `#/builder?g=<disposition>&<état>` — la disposition dans la grammaire de la Disposition libre, puis son état (`p`, `at`, `r`, `place`, `title`, `q`…). Par exemple `#/builder?g=[map(floraison,r=2km)@30,[results,slot]@35,plant.wikipedia@35]&at=48.85,2.35`. Les anciens liens marchent : `#/builder/trois` (une grille par son nom), `#/builder/trois?g=…` (la disposition l'emporte). Les opérations sur la disposition (`app/layout/builder-grid.js` : lire, écrire, couper, retirer — chaque case gardée telle que l'adresse l'écrit) et le choix du contenu (`app/layout/summary.js` : une case dite en pastilles, la ligne d'un groupe ; `app/layout/picker-model.js` : les groupes, la commande de chaque sorte, un réglage, une intention ou un composant choisi, la place qu'il faut, les suggestions) sont purs et testés sous Node (`tests/unit/builder-grid.test.mjs`, `tests/unit/block-picker.test.mjs`) ; de bout en bout : `tests/e2e/builder.spec.mjs`, `tests/e2e/block-picker.spec.mjs`.

### Disposition libre : composer son écran

Un écran à composer avec les outils de GeoFlora côte à côte — la carte, la recherche de Flore, ses résultats, la fiche ou **un seul de ses blocs**, les photos, les cartes de Rencontres, le choix d'une zone —, **tous reliés entre eux**, et **écrit dans l'adresse** : `#/layout/<disposition>?<état>`. Un lien reproduit l'écran tel quel (disposition, tailles, plante, zone, recherche) ; Retour et Suivant le parcourent ; un rechargement le retrouve. On y entre par **Réglages › Disposition libre** (cinq modèles), par le menu « Modèles » de l'écran lui-même, ou par « Ouvrir l'app » de **« Créer une app »** (ci-dessus), où elle se fabrique : le bouton **« Modifier »** de l'écran l'y rouvre, avec son état (`#/builder?g=<la même disposition>&<le même état>`, nouvelle entrée). Un **« Emplacement »** (`slot`) y reste un endroit où construire : ses tuiles proposent un bloc.

**La grammaire** (`app/layout/grammar.js`, pure, testée sous Node) :

```text
disposition := '[' nœuds ']'        les crochets extérieurs sont facultatifs : map,search = [map,search]
nœud        := ( '[' nœuds ']' | cellule ) ( '@' part )?
cellule     := composant ( '.' bloc )? ( '(' paramètre ( ',' paramètre )* ')' )?
paramètre   := clé '=' valeur | valeur          une valeur seule va au paramètre qui la lit : map(20km) = map(r=20km), map(plan) = map(base=plan)
```

- **Le premier niveau, ce sont les colonnes** (de gauche à droite) ; une liste dans une colonne la coupe **en lignes** (de haut en bas) ; une liste dans une ligne la recoupe en colonnes, et ainsi de suite (trois niveaux de crochets au plus, douze cellules au plus).
- **`@30`** : la part de la cellule (ou de la liste) dans son parent, en % ; les autres se partagent le reste.
- **Noms et valeurs** en anglais ou en français, casse et accents indifférents (`carte` = `map`, `fiche` = `plant`, `plant.calendrier` = `plant.calendar`, `results(grille)` = `results(view=grid)`) ; `:` vaut `.` (`plant:wiki`), `;` vaut `,` entre paramètres, une virgule entre deux chiffres est décimale (`r=2,5km`). L'adresse est réécrite sous sa forme canonique (anglais, `clé=valeur`, sans espaces ; `;` là où une virgule tomberait entre deux chiffres : `annee=2020;3d=1`).
- **Jamais d'erreur bloquante** : un crochet oublié est refermé, un caractère de trop sauté, un composant inconnu devient une case qui le dit et propose le nom le plus proche (« Composant inconnu « mpa » : vouliez-vous dire « map » ? ») ; chaque remarque est dite en français, avec sa position. Une adresse illisible n'est pas réécrite tant qu'on ne l'a pas corrigée.

Exemples :

```text
#/layout/[map(r=2km),search,plant]                                   carte | recherche | fiche entière
#/layout/[map(r=2km),search,[plant.wikipedia,plant.calendar]]        la 3e colonne : Wikipédia au-dessus du calendrier
#/layout/[map:radius(20),search,fiche]                               écrit à la main, lu [map(r=20km),search,plant]
#/layout/[[place@22,map],deck,[media,plant.status]]                  zone sur carte | cartes à swiper | photos sur statuts
#/layout/[map@40,[search(list=0)@25,results(view=grid)],plant(scientific)]?p=128268&at=48.85,2.35&r=1km&q=ortie
```

**Les composants** (`app/layout/registry.js` : id, titre, icône, paramètres validés avec leurs valeurs par défaut, ce que chacun lit et écrit de l'état ; `app/layout/cells.js` : chacun branché sur un élément existant de l'application) :

Dans l'éditeur, « Interface » a une case à cocher par commande (cochées : celles qu'a la carte, écrites seulement si elles diffèrent du défaut).

**Des cases qui se reflètent** (`state.js`, `cells.js`) — toutes lisent et changent le même état, jamais l'une l'autre :

- **la liste est celle de la carte** : la carte de la zone montre **ses observations** (les plus récentes de la période, de ses sources, avec ses filtres : iNaturalist — les 1 000 dernières, de niveau recherche par défaut — et GBIF, fusionnées : `core/observations.js`, `state.js#loadScope` ; voir **Observations : sources et filtres**) et la liste (recherche, filtres, résultats) en est **les plantes**, une ligne par plante de la flore présente parmi elles, quelle que soit la source qui l'a vue, avec son nombre d'observations (`core/nearby.js#speciesOf`) ; ce qui est sur la carte est dans la liste, et inversement ; un filtre, une recherche : ses seules plantes, sur la liste et sur la carte (une observation d'une plante que la flore ne connaît pas n'est sur la carte que si elle ne suit pas la recherche, `suit=0`) ;
- **chaque ligne dit les observations de sa plante dans la zone** (« 12 obs. », avec les deux sources « 12 obs. (9 iNat., 3 GBIF) » : `core/nearby.js#plantCounts`, `core/observations.js#obsNotes`), la grille a leur colonne « Observations », et le tri **« Plus observées »** (les plus observées d'abord, puis le nom français ; `sort=obs` dans l'adresse) s'ajoute au menu — seulement pour une liste de zone : Flore, sans zone, n'a ni l'un ni l'autre. Le défaut reste « Nom français A–Z » ;
- **la liste suit ce que montre la carte** (`liste=vue`, le défaut) : la carte déplacée **à la main** (glissée, zoomée, au clavier), la liste ne garde que les plantes de ses points visibles — son nombre, ses filtres, son tri avec elle (`state.js#setView`, `workers/search-core.js` `within`) —, dit au-dessus : « Dans la vue de la carte : 4 plantes sur 12 · **Toute la zone** » (la zone entière de nouveau, la carte recadrée sur elle), et « · dans la vue » dans l'en-tête de la case. Une carte qui montre tout le cercle rend toute la zone ; ce que la carte fait d'elle-même (voler vers un point touché, se recadrer, suivre la position) n'y change rien ; un autre cercle (un autre lieu, un autre rayon) lâche la vue, une autre période ou d'autres filtres la gardent. Les points des cartes, le paquet et une case vide (`vide=masque`) restent ceux de toute la zone (`inZone`). Plusieurs cartes : la dernière déplacée à la main mène ; une carte de la France ou du monde, jamais. Rien dans l'adresse ; sur téléphone, la carte glissée dans son onglet, la liste dans le sien ;
- **le survol croisé** : une ligne survolée (ou atteinte au clavier) allume sur la carte les points de sa plante, comme son propre survol les allume (`gf-map` `litKeys`) ; un point survolé allume la ligne de sa plante (`gf-plant-card` `lit`), sans faire défiler la liste. C'est l'état du survol (`state.js#hoverOn`), jamais écrit dans l'adresse ; au doigt, rien (un toucher choisit) ;
- **les observations ont leurs filtres en tête de ceux de la liste** : « Observations de la zone » (sources, jeux de données GBIF, taxon, qualité, photo, sauvages), communs au groupe et écrits dans l'adresse (`&sources=inat,gbif&taxon=espece…`) — la carte et la liste suivent ;
- **la période est celle de toutes les cases** (`&periode=toujours|annee|mois` dans l'adresse ; sinon celle d'une carte, `when=`) : les observations de la zone **de cette année, ou de ce mois-ci** (iNaturalist `year=`, `month=`) — les points des cartes, et donc la liste, ses filtres, Rencontres ; les puces « Toujours · Cette année · Ce mois-ci » d'une carte l'écrivent ;
- **une plante choisie hors de la liste de la zone** (une plante fixée, une recherche sur toute la France) : son taxon trouvé par son nom, ses observations dans la zone montrées ;
- **une zone déplacée** : ce qui avait été chargé pour l'ancienne s'en va aussitôt (jamais ses points sous le nouveau cercle) ;
- **trois cartes, une même recherche** : `[map(r=2km),map(france),map(monde),[search,results]]` — ici, la France, le monde, les mêmes plantes (portee=).

**Des groupes** (le réglage du cadre `groupe=a|b|c`, dans « Liens » du choix du contenu) : les cases d'un groupe partagent une zone, une plante, une période et une recherche ; celles d'un autre groupe en ont d'autres — deux listes, deux cartes qui ne se suivent pas sur un même écran. Le premier groupe (`a`, le défaut) garde les clés de l'adresse comme avant ; un autre les écrit après sa lettre : `&b.q=chêne&b.at=48.85,2.35&b.r=1km&b.p=…&b.periode=mois`. Chaque groupe a sa propre recherche (`core/search-channel.js` : son texte, ses filtres, son tri, ses résultats, gardés à ses plantes) ; celle du premier est celle de l'app (Flore). Quand la disposition en a plusieurs, l'en-tête de chaque case porte la lettre de son groupe dans sa couleur.

```text
#/layout/[[search,results]@50,[search(groupe=b),results(groupe=b)]@50]?q=ortie&b.at=48.85,2.35&b.r=1km&b.q=allium
```

**Les liens dans le constructeur** (`registry.js#linksOf`) : dans l'en-tête de chaque case, une pastille par lien — **Zone**, **Recherche**, **Période**, **Plante**, et pour une carte **Liste** —, allumée quand la case suit (et change) cet état ; touchée, elle **détache** la case ou la **relie** de nouveau, en écrivant le réglage qui le fait : une carte qui montre la France (`portee=france`) ou toutes les plantes de la zone (`suit=0`) ou pas la plante courante (`plante=non`), qui laisse la liste à toute la zone (`liste=zone`) ; des résultats sur toute la France (`zone=0`), qui ne changent pas la plante courante (`ecrit=0`) ; une fiche fixée sur la plante courante (`plante=<son numéro>`), puis qui la suit de nouveau. Une pastille sans réglage (la période d'une carte) dit seulement ce que fait la case.

**Ce qu'on fait dans une case est gardé** — dans l'app comme dans « Créer une app » : l'adresse est l'app, envoyée telle quelle. Chaque commande d'une case écrit son réglage dans la disposition (`cell-param`, `gf-layout.js` ; `registry.js#withParam` : comme l'éditeur l'écrit, laissé de côté quand la case l'a déjà sans lui — son défaut, son intention), l'adresse remplacée sans nouvelle entrée : la carte — la 3D (`3d`), son propre fond (`base`, `annee`) et ses noms (`noms`), ses propres couches cochées dans son panneau ▦ dans leur ordre (`layers`), leur opacité (`opac`), les jumelles (`jumelles`, `jrayon`), « Seule » (`plante=seule`), la légende ouverte (`legende`), et dans le constructeur son cadrage (`vue`) — la période, elle, est celle de toutes les cases (`periode=` dans l'adresse) ; la recherche — ses filtres ouverts (`filters=1`) ; les résultats — **en liste ou en grille**, deux boutons dans leur en-tête (`view`) ; une case repliée (`etat=replie`, ci-dessous). Une carte de disposition qui dit son fond ou ses couches les garde (ce qu'on y fait est à elle : jamais écrit dans les réglages communs) ; celle qui ne dit rien suit les réglages communs à toutes les cartes, et son panneau ▦ les change pour toutes. Ses jumelles sont toujours à elle. Ces réglages-là ne sont pas dans « Affiner » du choix du contenu : on les fait sur la case. **L'opacité des couches à portée de main** : sur toutes les cartes, dès qu'une couche est affichée, un bouton « Opacité des couches » parmi ceux de la carte ouvre un curseur par couche (la plus haute d'abord ; Échap referme) — gardée par la disposition pour une carte de disposition qui a ses propres couches, dans les réglages communs sinon.

```text
#/layout/[map(r=2km,base=plan,3d=1,legende=1),results]                plan IGN, en 3D, la légende ouverte
#/layout/[map(base=spot,annee=2020),results]                          les images satellite SPOT de 2020
#/layout/[map(annee=2016-2020),results]                               les photos aériennes de 2016 à 2020 (les plus récentes en gris pâle ailleurs)
#/layout/[map(base=spot,annee=2020,noms=0;3d=1),results]              les images SPOT de 2020 sans les noms par-dessus, en 3D
#/layout/[map(layers=reserves+ign:LANDCOVER.FORESTINVENTORY.V2,opac=reserves.40),results]   deux couches, les réserves à 40 %
#/layout/[map(3d=1,jumelles=inat+gbif),results]                       en 3D, les jumelles allumées
#/builder?g=[map(r=1km,vue=45.77123:3.08456:13.5),results]&at=45.77,3.08   le cadrage de départ choisi dans le constructeur
```

**Une valeur seule** va au réglage qui la lit : une distance au rayon (`map(20km)`), un mot d'intention à l'intention (`map(terrain)`), `photo`, `plan` ou `satellite` au fond (l'année, jamais : `annee=2020`), `noms` aux noms par-dessus, `3d` / `2d` à la 3D, des noms de couches aux couches (`map(znieff+n2000)`), `mois`, `pastille`, `seule`, `fiche`, `nue`… à leur réglage. **L'adresse réécrite reste courte** : l'intention d'abord, seule, puis les seuls réglages qu'elle ne donne pas, dans l'ordre des groupes, le lieu en dernier — `map(Terrain ; base=photo ; r=2km)` devient `map(terrain,r=2km)`. Dans l'éditeur, les réglages de la carte sont repliés sous « Réglages », par groupe (une liste : une case à cocher par valeur ; ce qu'une intention donne est dit « selon l'intention »).

```text
#/layout/[map(terrain,r=2km),plant]                                  sur le terrain : autour de moi, photos, commandes compactes
#/layout/[map(protege,lieu=Fontainebleau 77),search,plant]           les espaces protégés autour de Fontainebleau
#/layout/[map(floraison,pts=pastille),results]                       ce qui fleurit ce mois-ci, en pastilles
#/layout/[map(repartition,r=20km),plant]?p=128268                    toutes les observations de la plante, iNaturalist et GBIF
#/layout/[map(r=1km,ui=nue,toucher=fiche)@30,search]                 une carte nue dont les points ouvrent la fiche
```

#### Cadre commun à tous les blocs

Chaque case, quel que soit son composant, a le même **cadre** (`app/layout/registry.js#FRAME`, rendu par `gf-layout.js`) : son en-tête, les actions de cet en-tête, ce qu'elle montre quand elle n'a rien à montrer, et ses liens à l'état partagé. Ses réglages s'écrivent dans les parenthèses de la case, **après ceux du composant**, **seulement s'ils ne valent pas leur défaut** (`tete=oui`, `actions=aucune`, `vide=message`, `zone=1`, `toucher=plante`, `ecrit=1` ne sont jamais écrits), dans cet ordre : `tete`, `actions`, `vide`, `plante`, `zone`, `toucher`, `ecrit`, puis `titre` en dernier (des mots libres, comme `lieu` : une virgule entre deux chiffres serait décimale). Sans eux, rien ne change : les dispositions existantes restent telles quelles.

| Groupe | Réglage | Valeurs (défaut en premier) | Effet | Composants |
| --- | --- | --- | --- | --- |
| Cadre | `tete` (alias `entête`, `en-tête`, `bandeau`, `head`) | `oui` (`complet`), `simple` (`seul`), `non` (`aucun`) | l'en-tête complet (icône, titre, marque, ce que montre la case), **le titre seul**, ou **pas d'en-tête** : le contenu prend toute la place (sur téléphone, l'onglet nomme toujours la case ; en modification, l'en-tête revient pour ses outils) | tous |
| Cadre | `titre` (alias `title`, `nom`) | des mots, 40 caractères au plus | **un titre à soi** à la place du nom du composant : dans l'en-tête, l'onglet sur téléphone, les poignées, la case elle-même pour les lecteurs d'écran. Texte simple, une ligne ; pas de `,` `;` `(` `)` `[` `]` `=` `@` (l'éditeur les remplace par des espaces) | tous |
| Cadre | `actions` (alias `boutons`) | aucune, puis `agrandir`, `replier`, `partager` joints par `+` (alias `plein`, `plier`, `reduire`, `lien`, `share`…) | des boutons dans l'en-tête : **agrandir** — la case par-dessus toute la disposition, Échap ou le même bouton la remet en place (le focus y revient) ; **replier** — la case réduite à son en-tête (couché, dans une colonne), sa part donnée aux autres, jusqu'à « Déplier » — **gardé dans la disposition** (`etat=replie`, écrit par le bouton lui-même ; jamais dans l'éditeur) ; **partager** — le lien d'une disposition **de cette seule case avec le même état** (`#/layout/[<la case>]?<la même plante, zone, recherche>`), partagé ou copié comme le bouton Partager de l'écran (« Lien copié »). Sans en-tête (`tete=non`), pas d'actions | tous |
| Cadre | `vide` | `message`, `masque` (`masquée`, `cachée`) | sans rien à montrer, la case **dit pourquoi** (« Aucune plante choisie… »), ou **se cache** : sa part va aux autres, elle revient dès qu'il y a quelque chose. Jamais cachée pendant la modification, ni quand tout l'écran (ou, sur téléphone, tout un onglet) le serait | `plant`, `plant.<bloc>`, `media` (pas de plante), `results` (aucune plante trouvée), `deck` (pas de cartes : pas de zone, ses plantes injoignables ou aucune ; les cartes déjà passées ne comptent pas) — la carte, la recherche, les filtres et la zone ont toujours quelque chose |
| Liens | `plante` (alias `épingle`, `fixe`) | la plante courante, ou un numéro de plante (celui de `p=`) | **une plante fixée** : la case montre toujours celle-ci, quelle que soit la plante courante (une épingle dans son en-tête, avant ses noms) ; une plante choisie ailleurs n'amène pas son onglet. L'éditeur a « Fixer la plante courante » | `plant`, `plant.<bloc>`, `media` |
| Liens | `zone` (alias `scope`) | `1`, `0` (seul : `france`) | **toute la France** au lieu de la zone : la recherche de l'écran (texte, filtres, tri) sur toute la flore (`core/search.js#searchWhole`, `state.js#wholeOf`), son compte dans l'en-tête (« 300 espèces · toute la France ») ; les autres cases restent dans la zone | `results` |
| Liens | `toucher` (alias `tap`, `clic`) | `plante`, `fiche`, `rien` | une plante touchée (un résultat, une carte du paquet, un lien de la fiche — un sosie) : elle **devient la plante courante**, **sa fiche s'ouvre** (la disposition quittée, comme un lien), ou **rien** | `results`, `search` (sa liste), `plant`, `plant.<bloc>`, `deck` |
| Liens | `ecrit` (alias `écrire`, `write`) | `1`, `0` | `0` : la case **ne change plus la plante courante** — toucher une plante ouvre sa fiche au lieu de la choisir (`toucher=rien` reste rien) ; le paquet ne met plus ses cartes en plante courante quand on les passe (un cœur fait toujours un favori). La recherche, elle, reste celle de l'écran : son texte et ses filtres s'écrivent toujours | `results`, `search`, `plant`, `plant.<bloc>`, `deck` |

La carte garde **ses propres liens** (`suit`, `plante`, `toucher` : ci-dessus) ; elle n'a que `tete`, `titre` et `actions` du cadre. Un réglage du cadre écrit sur un composant qui ne l'a pas est dit (« Filtres : « vide » ne s'applique pas à ce composant. ») et laissé. Les réglages du cadre ne font pas de marque dans le menu des colonnes (seule la plante fixée a son épingle, dans l'en-tête). Dans l'éditeur, chaque case a, sous **« Réglages »**, un groupe **« Cadre »** (en-tête, titre, actions, état vide) et un groupe **« Liens »** (ceux que son composant suit) ; ce qu'on y change s'écrit dans le texte de la disposition, puis l'adresse à « Appliquer ».

```text
#/layout/[map(r=2km,tete=non),search,plant(actions=agrandir+replier+partager)]          une carte sans en-tête ; une fiche qui s'agrandit, se replie, se partage
#/layout/[results(list),plant.wikipedia(vide=masque),plant.calendar(titre=En fleur)]     Wikipédia n'apparaît qu'une fois une plante choisie ; le calendrier renommé
#/layout/[results(list),plant(plante=128268),plant]?p=152766                             à gauche des résultats, une fiche toujours la même, à côté de la plante courante
#/layout/[place(r=1km),search(list=0),results(list,zone=0)]?at=48.85,2.35                la recherche dans la zone, et la même sur toute la France
#/layout/[results(list,toucher=fiche),deck(ecrit=0),media(tete=simple)]                  des résultats qui ouvrent la fiche ; un paquet qui ne change pas la plante courante
```

**Le câblage** (`app/layout/state.js`) : un seul état partagé, que chaque case lit et écrit — jamais une case vers une autre :
- **la zone** (`at`, `r`, `place`) : les plantes de ses observations (iNaturalist et GBIF selon ses sources et ses filtres, les plus récentes de la période, rapprochées de la flore : `core/observations.js`, `core/nearby.js`) **gardent la recherche à elles** (`core/search.js#setSearchScope` : les résultats, leurs compteurs et les facettes des filtres sont ceux de la zone ; quitter la disposition rend toute la flore) ; sans zone, toute la flore de France ;
- **la recherche** (texte, filtres, tri) : celle de Flore (le magasin de l'application), donc la barre, les filtres et la liste de Flore telles quelles ; ses résultats donnent **les points de la carte** (les observations des seules plantes trouvées) et les cartes du paquet ;
- **la plante courante** (`p`) : un résultat, un point de la carte, une carte du paquet, ou n'importe quel lien vers une fiche dans une case (un sosie, par exemple) la choisit ; toutes les cases `plant`, `plant.<bloc>` et `media` la montrent, les résultats la surlignent, le paquet la met dessus, la carte allume ses observations dans la zone ;
- **l'observation allumée** (`o`) : le point touché, montré sur la carte.

**À la première visite**, l'écran s'affiche pendant que la flore se télécharge : les cases de la plante (`plant`, `plant.<bloc>`, `media`) et leurs en-têtes attendent qu'elle soit enregistrée, puis montrent la plante de l'adresse — jamais « Plante introuvable » pour une plante qui existe.

L'adresse porte cet état à côté de la disposition — `?title=<titre>&p=<plante>&at=<lat>,<lon>&r=<rayon>&place=<nom>&o=<observation>&periode=…&sources=…&qualite=…&taxon=…&photos=…&sauvages=…&jeux=…&q=…&family=…&sort=…` (les observations de la zone et leurs filtres, laissés de côté quand ils valent ceux de la disposition ; la recherche avec les mots de Flore).

- **Un titre** (`title=`, écrit en premier) : du texte simple (jamais du HTML), sur une ligne, 80 caractères au plus. Présent, il s'affiche en bandeau discret en haut de l'écran (le titre de niveau 1 de la page ; sur téléphone, au-dessus du menu des colonnes), donne le titre de l'onglet (« <titre> · GeoFlora », même quand une case montre une fiche) et celui du partage ; absent, pas de bandeau. Il se tape dans « Créer une app » (champ **« Titre »**) : l'adresse suit la frappe sans nouvelle entrée de l'historique.
- **Un lieu en mots** (`place=` sans `at=`) : le lieu est cherché au géocodeur de l'IGN (`core/geoservices.js#findPlace`, module « IGN – adresses et altitudes », réponse gardée en cache), la zone posée là, puis **l'adresse remplacée** par `at=<lat>,<lon>` et `place=<le nom trouvé>` (le rayon `r=` gardé, sinon celui de la disposition). Les mots se lisent « nom, commune, département » (`core/place-find.js`) : un département à la fin (2 chiffres, 2A/2B, 3 chiffres outre-mer, ou un code postal ; après une virgule ou une espace : `Fontainebleau 77`) écarte tout homonyme lointain ; une commune après la virgule est cherchée d'abord (index des adresses, communes), puis les lieux du nom donné autour d'elle (index des toponymes : lieux-dits, sommets, collines…) — le meilleur du même nom dans la commune ou à moins de 10 km, sinon la commune elle-même ; sans commune, une commune de ce nom exactement, sinon un lieu, sinon une commune qui en porte tous les mots. Le nom trouvé s'affiche dans la case Zone et sur la carte (« 2 km autour de Puy de Mirabel (Ménétrol) ») : un mauvais choix se voit et se corrige. **Introuvable, hors ligne ou module coupé** : pas de zone (toute la flore), la raison dite dans la case Zone et sur la carte (« Lieu introuvable : … »), et `place=` reste dans l'adresse — un rechargement cherche à nouveau. Par exemple :

  `#/layout/[map(r=1km),place,results]?title=Orchidées de la colline de Mirabel&place=mirabel, menetrol, 63&family=Orchidaceae` — les orchidées observées autour de la colline (le puy) de Mirabel, à Ménétrol (Puy-de-Dôme, vers 45,87 N, 3,11 E), l'adresse devenant `?title=…&at=45.87…,3.11…&r=1km&place=Puy de Mirabel (Ménétrol)&family=Orchidaceae`.

**Une plante ou une zone choisie est une nouvelle entrée** de l'historique (Retour revient à la précédente) ; le texte tapé, un filtre, le rayon ne font que remplacer l'adresse, comme dans Flore. Les paramètres d'une case (`map(r=2km)`) sont des valeurs par défaut : l'adresse (`?r=`) l'emporte.

**Les tailles** : entre deux colonnes ou deux lignes, une poignée (`core/split-grip.js`). Les parts données sont **écrites dans l'adresse** (`@n` : un lien les a) et **gardées sur l'appareil pour la forme de la disposition** (`geoflora.freeLayout` : ses composants et blocs, pas ses paramètres ni ses parts) — rouverte sans parts (un modèle), elle les retrouve. **Sur téléphone** (ou quand les colonnes n'ont pas leur largeur minimale), **les colonnes deviennent des onglets**, leurs lignes l'une sous l'autre, choisis dans **un menu d'icônes en haut** : chaque colonne y montre les icônes de ses cases (celles du registre ; chaque bloc de la fiche le sien, jamais celui d'un autre ni d'un composant — une fleur pour le calendrier, un bouclier pour les statuts, un triangle d'alerte pour les plantes à confondre, une épingle sur le sol pour la carte de la fiche, autre que la carte ; un point d'interrogation pour un composant inconnu ; une icône pareille une seule fois, trois au plus, puis « +n » : les cases de plus), et une présentation choisie y porte sa marque — `plant(epure)`, `plant(standard)`, `plant(scientific)` : **É**, **St**, **Sc** ; `results(list)` **L**, `results(grid)` **G** ; un oui ou un non, `search(filters=1)` **F**, `search(list=0)` **−L** —, si bien que deux colonnes se distinguent d'un coup d'œil (deux qui se ressembleraient encore, ce qui les distingue caché après trois icônes, sont numérotées). Sur téléphone, rien que des icônes à l'écran, mais chacune a **son nom entier**, lu une fois par les lecteurs d'écran et montré au survol (« Recherche · Filtres · Résultats », « Fiche (Épuré) », « Fiche › Carte », « mpa (inconnu) ») ; dans une fenêtre ou sur une tablette, **le nom à côté des icônes** dès que chaque onglet en a la place, comme les onglets de texte d'avant (coupé par « … » au besoin) ; l'onglet montré est sur fond teinté, souligné ; ← → (en boucle), Début et Fin au clavier. Les icônes se partagent la largeur à parts égales tant qu'elles tiennent (au moins 52 × 48 px chacune, un doigt) ; au-delà, **le menu défile de côté**, sans barre, son bord estompé du côté où il en reste, et **l'onglet montré est toujours ramené en vue** (au clavier, par une plante choisie). Une plante choisie dans un onglet amène celui de la fiche, **son icône éclairée un instant**. **Un doigt glissé de côté** sur un panneau montre la colonne voisine (vers la gauche : la suivante) — sauf sur ce qui se glisse déjà lui-même : une carte, les photos, les cartes de Rencontres, un curseur, un champ, une poignée, ce qui défile de côté, ou depuis le bord de l'écran (le « retour » du système). Jamais de défilement de côté de la page.

**Pour un développeur** : un composant de plus, c'est une entrée de `COMPONENTS` (`registry.js` : id, titre, icône, alias, paramètres, ce qu'il lit et écrit, sa taille minimale) et son rendu dans `renderCell` (`cells.js`), qui lit l'état (`LayoutState` : `live`, `species`, `points`, `plantObs`, `plantInfo`) et l'écrit par `set`, `pick` et `setScope` — jamais par l'adresse. ### Observations : sources et filtres

Les observations de la zone d'une disposition (les points de sa carte, les plantes de sa liste) viennent de **plusieurs sources**, interrogées ensemble et fusionnées par une couche commune (`app/core/observations.js`) : **iNaturalist** et **GBIF** — et, par GBIF, les jeux de données qu'il rassemble (Pl@ntNet, Observation.org, l'inventaire national, les conservatoires botaniques, les herbiers…). Par-dessus, **des filtres globaux**, les mêmes pour toutes les sources : chacune les applique dans ses propres mots quand elle le sait, l'app les applique sinon, ou ils sont dits sans objet pour elle. Par exemple « toutes les observations identifiées à l'espèce, avec une photo libre, de plantes sauvages » : `&sources=inat,gbif&taxon=espece&photos=libre&sauvages=1`.

**Ce que chaque API sait filtrer** (en gras, ce dont la couche commune se sert ; vérifié dans les descriptions de pyinaturalist 0.21 et pygbif 0.7, qui reprennent la doc des deux API) :

| iNaturalist (API v1, `/v1/observations`) | Paramètres |
|---|---|
| Lieu | **`lat`, `lng`, `radius` (km)** ; une boîte (`swlat`, `swlng`, `nelat`, `nelng`) ; un lieu (`place_id`) |
| Groupe, taxon | **`iconic_taxa=Plantae`** ; `taxon_id`, `without_taxon_id`, `taxon_name` |
| Rang | **`hrank=species`** (à l'espèce ou en dessous) ; `rank`, `lrank` |
| Qualité | **`quality_grade`** : `research` (identification confirmée), `needs_id` (à identifier), `casual` (cultivées, incomplètes) ; `verifiable` |
| Photos, sons | **`photos=true`**, **`photo_license=cc0,cc-by,cc-by-sa`** (au moins une photo sous l'une d'elles) ; `photo_licensed` (une photo sous licence), `sounds`, `license` (celle de l'observation) |
| Captives, cultivées | **`captive=false`** (le niveau recherche les exclut déjà) |
| Origine | `native`, `introduced`, `endemic`, `threatened` — selon un lieu (`place_id`) : la couche commune s'en remet au « Statut en France » de la flore |
| Dates | **`year`, `month`** (la période) ; `d1`, `d2`, `day`, `created_d1`… |
| Identification, annotations | `identified`, `identifications`, `user_id`, `project_id`, `term_id` / `term_value_id` (phénologie : en fleur, en fruit…) |
| Précision | `acc_below`, `acc_above` (en mètres), `geoprivacy`, `taxon_geoprivacy` |
| Tri, pages | **`order_by=observed_on`**, `per_page` (200 au plus), `page` (10 000 résultats au plus) — la couche en prend 1 000 |

| GBIF (`/v1/occurrence/search`) | Paramètres |
|---|---|
| Lieu | **`geoDistance=lat,lon,rayon`**, **`hasCoordinate`**, **`hasGeospatialIssue=false`** ; `geometry` (WKT), `country`, `gadmGid`, `coordinateUncertaintyInMeters` |
| Taxon | **`taxonKey=6`** (les plantes) ; `speciesKey`, `scientificName`, `taxonomicStatus` — le rang de chaque occurrence (`taxonRank`) lu par l'app |
| Présence | **`occurrenceStatus=PRESENT`** |
| Nature | `basisOfRecord` : `HUMAN_OBSERVATION`, `MACHINE_OBSERVATION`, `PRESERVED_SPECIMEN` (herbiers), `MATERIAL_SAMPLE`… |
| Médias | **`mediaType=StillImage`** ; `Sound`, `MovingImage` — la licence de chaque photo (`media[].license`) lue par l'app (`license` est celle de l'occurrence) |
| Origine | `establishmentMeans` (`NATIVE`, `INTRODUCED`, `NATURALISED`, `INVASIVE`, `MANAGED`, `UNCERTAIN`), `degreeOfEstablishment` — des valeurs à garder, rarement remplies : l'app écarte celles qui ne sont pas sauvages |
| Sources | **`datasetKey`** (répété : l'un ou l'autre) ; `publishingOrg`, `institutionCode`, `collectionCode`, `recordedBy`, `networkKey` |
| Qualité | pas de note de qualité ; `issue` (les défauts relevés par GBIF), `coordinateUncertaintyInMeters` |
| Dates | **`year`, `month`** ; `eventDate`, des intervalles (`year=2020,2024`) |
| Facettes | **`facet=datasetKey`, `facetMultiselect=true`, `datasetKey.facetLimit=50`** (les jeux de la zone comptés, comme si aucun n'était choisi ; la taille d'une facette se donne par champ, `<champ>.facetLimit`, 10 sinon) |
| Pages | **`limit`** (300 au plus ; **`limit=0`** : le nombre et les facettes seuls), `offset` |

**Les filtres globaux** (`core/observations.js` : `inatQuery`, `gbifQuery`, `gbifKeep`, `APPLIES`) :

| Filtre | Adresse | iNaturalist | GBIF |
|---|---|---|---|
| Sources | `sources=inat,gbif` (au moins une) ; défaut : celles que disent les cartes (`src=`), sinon iNaturalist | — | — |
| Jeux de données | `jeux=<clés GBIF>` ; aucun : tous | sans objet | API : `datasetKey` |
| Taxon | `taxon=tous` (défaut) \| `espece` | API : `hrank=species` | app : rang espèce, sous-espèce, variété ou forme |
| Qualité | `qualite=recherche` (défaut) \| `verifiables` \| `toutes` | API : `quality_grade=research`, `research,needs_id`, rien | sans objet : GBIF n'a pas de note de qualité (ses données telles que leurs producteurs les publient) |
| Photo | `photos=toutes` (défaut) \| `avec` \| `libre` | API : `photos=true`, `photo_license=cc0,cc-by,cc-by-sa` | API : `mediaType=StillImage` ; app : une photo sous licence libre (CC0, CC BY, CC BY-SA) |
| Sauvages | `sauvages=1` | API : `captive=false` | app : ni gérées, ni cultivées, ni captives, ni relâchées (`MANAGED`, `CULTIVATED`, `CAPTIVE`, `RELEASED`) |
| Origine | — | — | — : la facette « Statut en France » de la flore (TAXREF : indigène, naturalisée, introduite…), pour toutes les sources |
| Période | `periode=` (sinon celle d'une carte, `when=`) | API : `year`, `month` | API : `year`, `month` |

Chaque clé est écrite dans l'adresse **seulement quand elle diffère de la disposition** (un autre groupe : après sa lettre, `b.sources=…`) ; les clés de Flore (`photo=`, `status=`…) restent celles de la recherche.

**La fusion** (`zoneObservations`) : iNaturalist (les 1 000 plus récentes) et GBIF interrogés en même temps, chacun avec son module (Réglages › Modules). GBIF en deux requêtes : d'abord le nombre et les jeux de la zone (`limit=0` et la facette : les 50 plus fournis), puis les occurrences (300 au plus) des jeux choisis, sinon de tous ceux de la zone **sauf sa copie des observations d'iNaturalist** (son jeu `50c9509d…`) — sa page n'est plus prise par des observations qu'iNaturalist donne lui-même ; une réponse sans facette (un ancien GBIF) : une page comme avant, la copie écartée après ; un jeu au-delà des 50 n'est pas demandé. La copie est aussi retirée de son nombre ; une occurrence GBIF qui est déjà une observation d'iNaturalist (la même plante, le même jour, à 25 m au plus) comptée une fois ; les points GBIF prennent la photo et le nom de leur plante sur iNaturalist ici, sinon ceux de la flore ; tous dans le cercle, les plus récents d'abord. Leurs plantes (`core/nearby.js#speciesOf`) : par le taxon d'iNaturalist, sinon par le nom, une plante de la flore une fois, ses observations comptées ensemble — une plante vue par GBIF seul est dans la liste et sur la carte. **Une source en panne** est dite (dans l'« État » de la carte : « GBIF ne répond pas : ses observations manquent sur la carte et dans la liste. », et à côté de son nom dans la section), les autres montrées ; toutes en panne, la zone ne filtre pas les plantes, la raison dite (« Le module iNaturalist est désactivé et GBIF ne répond pas… »).

**La section « Observations de la zone »** (`app/layout/obs-filters.js`), en tête des filtres de la liste (la case `search` aux filtres ouverts, la case `filters`) dès que le groupe a une zone : les sources cochées avec leur nombre d'observations dans la zone (ou leur panne) ; les jeux de données GBIF de la zone, leur titre et leur nombre (« Voir plus » au-delà de six ; aucun coché : tous) ; Taxon, Qualité (iNaturalist seul : grisée sans lui), Photo, « Sauvages seulement » ; ce qu'une source ne sait pas filtrer, dit dessous ; l'origine renvoyée au filtre « Statut en France » (un lien l'ouvre). Son badge compte les réglages changés, « effacer » rend ceux de la disposition. Son en-tête se colle et s'empile avec ceux des filtres de Flore (`gf-filter-panel` `lead`, `gf-facet` `facetStyles`). Une carte montre les sources de son groupe qu'elle dit (`src`) : `[map(src=inat),map(src=gbif),search]` — deux cartes, une liste.

### Découvrir : la liste des mini-applications

**L'onglet Découvrir** (`#/discover`) ouvre **la liste** des façons de jouer, en page entière : les cinq mini-applications — Rencontres, Parcours botanique, Cueillette prudente, Mosaïque, Faux amis —, dans le même ordre que le lanceur. Scientifique n'y est pas : c'est un **mode** (Épuré, Standard, Scientifique ; voir « Modes d'affichage »), qui se choisit dans l'en-tête ou dans Réglages, pas une façon de jouer. Chacune a sa carte : son illustration (voir « Illustrations des scénarios »), son titre, ce qu'elle fait et **« Jouer »** — ou, pour une mini-application dont une partie est en cours sur l'appareil (un lieu choisi ; un parcours en marche ; une partie de Faux amis pas finie), deux actions : **« Continuer »** (là où on l'avait laissée : son étape) et **« Recommencer »** (voir « Mini-applications » : tout effacer, après confirmation, et revenir au premier écran). Sur grand écran, des cartes, l'illustration en haut — au plus quatre par rangée, les rangées aussi égales que possible (cinq : trois et deux, la plus courte centrée ; jamais une carte seule sur sa rangée), deux par rangée sur un écran moyen ; sur téléphone, une liste, l'illustration en petit à côté des mots. Un titre de niveau 1 (« Découvrir »), un titre par carte, des boutons nommés d'après elle (« Jouer : Rencontres », « Continuer : Mosaïque », « Recommencer : Mosaïque »).
- **Jouer** ouvre la mini-application seule à l'écran, à son départ (`#/app/<id>/start`) ; **« × Quitter … »** ramène à la liste. Jouer la Cueillette prudente allume le mode cueillette.
- **Rien ne s'ouvre tout seul** : ni l'onglet ni le premier lancement n'ouvrent Rencontres directement.
- Les anciennes adresses mènent aux mini-applications : `#/discover?s=meet`, `?s=trail`, `?s=harvest` et `?s=mosaic` ; une plante ouverte sur leurs cartes (`#/discover?p=<id>`, `?s=mosaic&p=<id>`) aux cartes de la mini-application, cette plante ouverte (par-dessus son écran de départ s'il n'y a pas de lieu gardé) ; une adresse `#/discover?s=…` inconnue — dont `?s=science`, l'ancienne carte Scientifique —, à la liste (sans changer de mode).
- **Pour un développeur** : une seule liste, `gf-launcher` (`app/components/gf-launcher.js`), nourrie par `app/miniapps/index.js` (chaque mini-application dit si une partie est en cours : `underWay` ; l'étape où on l'a laissée est gardée dans sa partie) ; en page (`<gf-launcher page>`, l'onglet) ou compacte, dans le dialogue du lanceur (`gf-scenarios`).

### Scénarios (l'icône film)

L'icône film de l'en-tête (ordinateur et téléphone, et la barre d'une mini-application) est le **lanceur** : la même liste que l'onglet Découvrir, dans un dialogue — les cinq mini-applications, chacune avec les outils qu'il lui faut (le mode Scientifique, lui, se choisit dans l'en-tête ou dans Réglages) :
- **Rencontres** (mini-application) : les plantes observées autour de vous, à la Tinder (ci-dessous) ; ses étapes guidées sont les premiers pas de l'application.
- **Parcours botanique** (mini-application) : marchez et nommez les plantes que vous croisez (ci-dessous).
- **Cueillette prudente** (mini-application, `#/app/cueillette`) : autour de vous, seulement les plantes qui comptent pour la cueillette — les comestibles de la liste de l'Anses et des Centres antipoison et leurs sosies toxiques —, les confusions mortelles d'abord. **Toutes les plantes observées (jusqu'aux 500 plus observées que donne iNaturalist) sont lues et triées avant d'en garder 120** : une plante mortelle vue une seule fois (une colchique, une œnanthe safranée, un aconit, un vérâtre à 20 km) n'est jamais écartée derrière les plus observées (Rencontres et Mosaïque gardent, elles, les 120 plus observées). La bio de chaque carte commence par la confusion (« Ne me confondez pas avec Colchique (mortel). Partie : feuilles. ») ; un bandeau rappelle de ne jamais cueillir sans identification certaine, avec la conduite à tenir après ingestion (Centre antipoison : centres-antipoison.net, la liste officielle ; le 15 ou le 112 en cas de détresse vitale) ; le mode cueillette s'allume. **Un sosie toxique n'est jamais un match ni un favori** : sa carte porte « À ne pas cueillir », et à droite (le bouton « Je la reconnais : à ne pas cueillir », à la place du cœur ; le geste, tampon « À ÉVITER » ; la touche →) il est **reconnu, à éviter** — il ne revient pas, comme une carte passée (« Revoir les plantes passées » le ramène, ↺ l'annule), et la fin du paquet le compte à part (« 2 plantes reconnues à ne pas cueillir. »), jamais avec les matchs ; un match d'une partie d'avant devient « à éviter », et le favori qu'il avait fait est retiré (pas un favori ajouté par vous). Les comestibles restent des matchs. Aucune plante à sosie dangereux observée : un seul message, « Aucune observation confirmée ici pour ces plantes : cela ne veut pas dire qu'elles sont absentes. », et « Chercher jusqu'à … ». Si la liste des confusions ne se lit pas, l'écran le dit (« Liste des confusions indisponible pour le moment : ne consommez aucune plante sans vérification », **Réessayer**) et garde toutes les plantes du coin (les 120 plus observées), chaque bio rappelant que les données de sécurité sont indisponibles — jamais une plante écartée faute de liste ; et faute de savoir de quel côté d'une confusion est chaque plante, **aucune n'est un match** : la droite les reconnaît toutes « à ne pas cueillir ».
- **Mosaïque** (mini-application, `#/app/mosaique`) : toutes les photos des plantes du coin en grande mosaïque (la vue « Toutes », dès que les cartes arrivent ; « Rencontres » et « Matchs » aussi), filtre « En fleur maintenant » ; une photo touchée ouvre la fiche à ses images. Sur grand écran (900 px et plus), la fiche d'une plante s'ouvre à côté des cartes (Mosaïque, Cueillette prudente, Rencontres) : sa largeur se règle par son séparateur (les cartes gardent 320 px), gardée dans l'espace de la mini-application (`geoflora.app.<id>.sheet`), oubliée par « Recommencer ».
- **Faux amis** (mini-application, `#/app/faux-amis`) : un jeu sur les confusions de l'Anses et des Centres antipoison (voir « Faux amis : un jeu sur les confusions »).

### Écrans de départ des scénarios

Les **cinq mini-applications** — Parcours botanique, Rencontres, Cueillette prudente, Mosaïque, Faux amis — commencent par **le même écran**, sur le modèle du Parcours (`app/components/start-screen.js`, un gabarit partagé ; la recherche de commune est l'élément `gf-place-search`) :
- **En grand** : l'illustration, **le titre** (32 px sur téléphone, jusqu'à 40 px sur grand écran), **la description** (18 à 20 px), **la seule action** (un gros bouton de 56 à 60 px de haut, 19 à 21 px) — l'œil va droit à l'action, et elle est **sous le pouce**, dans la moitié basse de l'écran, sans défiler, jusqu'aux petits téléphones (360×640). Sous l'action : une erreur (en rouge, avec « Réessayer » si la position a mis trop de temps ou n'est pas disponible pour le moment) ou « Annuler » pendant la localisation, et toujours la ligne qui dit ce que devient la position. Le gros bouton occupé garde le focus du clavier ; « Annuler » le lui rend. **Téléphone couché** (écran bas et large) : l'illustration à gauche, les mots et l'action à droite, en vue sans défiler.
- **En petit** (14 px, 44 px de haut au doigt) : **les autres façons d'entrer** — « ou partir d'une commune » (la recherche dit « Recherche… », « Aucun lieu de ce nom », hors ligne, IGN coupé dans les Réglages ; ↑ ↓ et Entrée au clavier — Entrée choisit toujours un lieu trouvé pour tout ce qui est tapé, jamais pour moins de lettres ; la liste s'ouvre au-dessus du champ quand le clavier ne laisse pas de place dessous, sans jamais dépasser la place qui reste) ; ce qui se reprend (« Reprendre un parcours » : les 3 derniers, puis « Voir les N autres » — tous ceux qui sont gardés ; deux du même nom le même jour se distinguent par l'heure ; « Autour de Fontainebleau · 1 km » après « Changer de lieu ») ; un lien.
- **En plus petit encore** : **la seule sortie** (« Quitter … : autres scénarios » ; « Passer : montrer toute l'application » pendant les premiers pas de Rencontres — et sous la liste de Découvrir).
- **Les textes** : Parcours « Votre parcours botanique » ; Rencontres « Rencontrez les plantes d'ici » (un coup de cœur à droite, au suivant à gauche, les coups de cœur rejoignent les favoris) ; Cueillette « Cueillette prudente », avec sa mise en garde en grand, sur fond orangé (« Ne cueillez jamais une plante sans être sûr de vous. ») ; Mosaïque « La mosaïque du coin » ; Faux amis « Faux amis », avec sa mise en garde (« Un jeu pour apprendre, pas pour reconnaître : ne cueillez jamais une plante sur la foi d'un indice ou d'une photo. »). Pour les scénarios qui cherchent autour de vous : « Votre position est envoyée à iNaturalist et à l'IGN pour chercher autour de vous ; elle n'est gardée que sur cet appareil. » Pour le Parcours : « Votre position est envoyée à l'IGN pour nommer le lieu ; le parcours reste sur cet appareil, dans Mes plantes. » La mise en garde de la Cueillette porte un triangle d'avertissement (pas un bouclier coché).
- **La localisation** ne part qu'une fois (deux ou trois touchers rapides, ou une commune choisie pendant la création, ne font qu'un parcours), n'accepte pas une position de plus d'une minute, et s'arrête si l'on choisit une commune, reprend un parcours, change de scénario ou quitte l'écran ; chaque écran dit l'erreur à sa façon (refusée, trop longue, indisponible, navigateur sans GPS), et elle s'efface dès qu'on fait autre chose. « Réessayer » relance vraiment la recherche de position. Au premier chargement, la ligne « Chargement… » se pose par-dessus le haut de l'écran (sauf téléphone couché, où le titre est en haut) : l'action ne bouge pas sous le pouce.
- **Le bilan du Parcours** (« Parcours terminé ») suit le même gabarit : la carte du parcours et les plantes rencontrées en image, « Partager le parcours » en grand, puis en petit le voir dans Mes plantes, le reprendre, un nouveau parcours, et la sortie.

### Illustrations des scénarios

Chaque scénario a son image d'accueil, **composée des icônes de l'application** (Bootstrap Icons, le même sprite) : des pastilles rondes colorées façon autocollant (l'icône sur un disque cerclé, une ombre décalée), quelques icônes libres, un sol vert pâle. **Parcours botanique** : un chemin en pointillés d'un repère à un drapeau, fleurs, feuilles et arbre le long, une feuille portée par le vent, soleil et nuage — rien que des plantes ; **Rencontres** : un éventail de cartes de plantes, un cœur, des jumelles ; **Cueillette prudente** : un panier entouré de ce qui se cueille, le bouclier de la prudence et un avertissement ; **Mosaïque** : des tuiles de photos, fleurs et feuilles, légèrement de travers ; **Faux amis** : deux cartes de plantes jumelles, une ampoule pour l'indice, un avertissement et le bouclier de la prudence. Les pastilles apparaissent une à une puis flottent doucement, le chemin se trace (immobile si les animations sont réduites) ; couleurs en variables, le mode sombre suit. Le titre et le texte d'accueil sont propres à chaque scénario. (`app/core/scenes.js`.)

**Le logo GeoFlora** est au centre de l'en-tête, plus grand (38 px, le nom en vert à côté), discret : les sections à gauche, les outils à droite ; sur téléphone, le logo et son nom au centre ; entre 700 et 1 100 px, le logo seul (et « Noter ici » en icône sous 900 px), sans débordement.

### Parcours botanique

Le plus simple des modes : un parcours, c'est un lieu de « Mes plantes » où chaque plante notée garde l'endroit où vous l'avez vue.
- **Une mini-application** (`#/app/parcours`, voir « Mini-applications ») : seule à l'écran, le reste de GeoFlora n'est pas là ; on en sort par « × Quitter le parcours » ; « Quitter le parcours : autres scénarios », sur son écran d'accueil et son bilan, ouvre le lanceur. Ses étapes ont chacune leur adresse (`#/app/parcours/start`, `/walk`, `/done`) : Retour depuis la marche revient au départ (le parcours en cours y est proposé en premier dans « Reprendre un parcours »), Suivant y retourne ; ouverte sans étape, elle retrouve le parcours en cours ou son bilan.
- **Démarrer** : l'écran de départ commun (voir « Écrans de départ des scénarios ») montre **un chemin parmi les fleurs**, fait des icônes de l'app (voir « Illustrations des scénarios ») ; « Commencer ici » en grand (votre position ; « Annuler » pendant la localisation), puis, plus petits, une commune et les parcours déjà commencés, qui se reprennent d'un toucher (leur nom sans « Mon parcours botanique », leur nombre de plantes et leur dernier jour : « En forêt de Fontainebleau · 12 plantes · 3 oct. »).
- **Son nom, tout seul** : « Commencer ici » nomme le parcours d'après **le lieu le plus précis que connaît l'IGN là où vous êtes** — « Mon parcours botanique en forêt de Chatel-Guyon », « au bois de Vincennes », « au jardin des Plantes », « au parc de la Tête d'Or », « au puy de Dôme (Orcines) », « au Roc Errant (Châtel-Guyon) », sinon « à Chazemais » (la commune). Dans l'ordre : un parc, un jardin, un square, un arboretum où vous êtes ; une forêt publique où vous êtes (« Forêt communale de … » devient « forêt de … ») ; un bois nommé assez proche pour sa taille (jusqu'à 1,2 km pour un grand bois) ; un sommet, un col, une vallée ; le lieu-dit ou le hameau le plus proche (250 m), avec sa commune entre parenthèses ; le quartier ; la commune. Les noms historiques, génériques ou égaux à la commune sont écartés ; la préposition suit le mot (« en forêt », « au bois », « aux gorges », « à l'arboretum », « au château »…). GPS imprécis (plus de 250 m) : la commune seule. Le temps que l'IGN réponde (8 s au plus, une requête refusée pour surcharge est reposée une fois), le parcours s'appelle « Mon parcours botanique » ; un nom changé entre-temps n'est jamais remplacé. Parti d'une commune : « Mon parcours botanique à Châtel-Guyon », « au Mont-Dore ». Source : IGN Géoplateforme (WFS BD TOPO® — `zone_d_activite_ou_d_interet`, `foret_publique`, `lieu_dit_non_habite`, `detail_orographique`, `zone_d_habitation` — et ADMIN EXPRESS pour la commune ; sept petites requêtes en parallèle, gardées un an sur l'appareil ; module « IGN – adresses et altitudes »).
- **Sur téléphone, tout tient sur un écran** (la barre d'onglets, grisée, ne sert pas) : en haut l'en-tête du parcours, puis **la carte**, puis la liste des plantes notées, et **la recherche collée en bas, sous le pouce**, au-dessus de la barre d'onglets — **même clavier ouvert** (la page se cale au-dessus des touches, sur Safari aussi — seulement pendant le parcours : ailleurs, le clavier se comporte comme d'habitude). **Le parcours ne défile pas** : glisser sur l'en-tête, la carte ou la recherche ne fait rien bouger. En paysage ou clavier ouvert, la carte se tient dans sa place, jamais par-dessus la liste. **Pendant une recherche**, dès que le champ est touché, **les propositions montent de la recherche** et couvrent l'en-tête, la carte et la liste, qui s'effacent en fondu : on ne voit plus que les propositions, la recherche et la barre d'onglets. **Les propositions tiennent à la recherche, sous le pouce** : la meilleure juste au-dessus du champ, les suivantes en montant, « Voir plus » tout en haut ; la liste défile depuis le bas. Chaque nouvelle lettre ramène la meilleure juste au-dessus du champ ; ouvrir ou fermer le clavier ne fait pas glisser les propositions. Au clavier (Tab) et pour les lecteurs d'écran, elles viennent dans l'ordre où on les voit, et l'en-tête, la liste et la carte cachés dessous sont hors d'atteinte. ✕ efface comme Échap : le champ et le clavier restent (touché clavier rangé, la recherche se ferme). **Clavier rangé sans rien taper** (le retour d'Android, la touche ⌄), même après avoir renommé le parcours ou tourné le téléphone : les propositions redescendent et le parcours revient. Le message « … ajoutée au parcours · Annuler » s'efface pendant la recherche (il ne couvre aucune proposition) et revient, « Annuler » compris, quand on la quitte. **Une plante ajoutée, elles redescendent** (le clavier se ferme) et l'en-tête et la carte réapparaissent tels quels, la plante dessus — rien n'est redessiné ni recalé, le mouvement reste fluide (simple fondu si les animations sont réduites). Sur grand écran, la même colonne à gauche (les propositions y prennent la place de l'en-tête et de la liste, le champ reste prêt pour la suivante), la carte à droite, toujours visible.
- **L'en-tête du parcours** (compact : nom, ✎ et les deux icônes sur une ligne, le compte et le GPS dessous) : **son nom en entier** (sur deux lignes au plus), toujours modifiable (✎) et **enregistré pendant la frappe** (Échap rend le nom d'avant) ; ce qui a été noté (« 12 observations · 9 plantes »), la précision du GPS ; deux icônes discrètes : **Partager** (un lien qui porte le parcours, sa carte et ses plantes : la feuille de partage du téléphone, ou copié) et **Terminer** (drapeau ; le parcours reste dans Mes plantes). Tout est enregistré au fil de l'eau, sans bouton « Enregistrer ».
- **Nommer une plante** : un grand champ, au clavier ou à la voix. **Le micro est un gros bouton rond à côté du champ, sous le pouce** : il réagit dès le toucher (vibration courte, il rougit), pulse quand la reconnaissance vocale du système (Android, iOS, via le navigateur) écoute, et le champ dit « Parlez : « ortie »… » ; les mots s'affichent pendant qu'on parle. Sans reconnaissance vocale dans le navigateur, le même bouton dit comment **dicter avec le micro du clavier** (voir ci-dessous) ; la dictée du clavier n'est jamais perturbée par l'app (le champ n'est pas réécrit pendant la saisie) ; la flore propose les plantes qui correspondent, avec photo, famille et un gros bouton rond **marqueur ＋** (l'ajouter ici) — toutes celles que trouve la recherche principale, 12 d'abord puis « Voir plus » ; Entrée ajoute la première, toujours pour le nom complet tapé. La plante est posée là où vous êtes ; « Annuler » la retire aussitôt.
- **Le micro n'ouvre jamais le clavier** : toucher le gros bouton rond laisse le champ (le clavier se ferme s'il était ouvert), les propositions montent avec « Parlez : « ortie »… » et la plante entendue s'y propose, sous le pouce. Sans dictée dans le navigateur, le bouton dit comment dicter avec le micro du clavier, sans l'ouvrir. Au départ d'un parcours, le champ n'est pas activé sur téléphone (pas de clavier qui surgit sur la carte).
- **Parcours terminé** (le drapeau) : une vue de fin montre **la carte du parcours avec toutes ses plantes**, son nom, ce qu'il contient (« 4 observations · 3 plantes, en 1 h 05, sur 1,2 km » — la durée depuis le départ jusqu'à la dernière plante, sans les pauses de plus de 2 h (un parcours repris un autre jour) ; la distance d'une plante à la suivante à vol d'oiseau, depuis le départ quand le parcours a commencé « ici », entre les plantes qui ont leur propre place (notées avec le GPS, ou replacées à la main) — ni la commune de départ, ni le point du parcours où va une plante notée sans GPS), les vignettes des plantes rencontrées ; **« Partager le parcours »** en grand, puis, plus petits : le voir dans Mes plantes, le reprendre, un nouveau parcours, quitter vers les autres scénarios. Elle reste affichée au retour de Mes plantes et après un rechargement, jusqu'à ce qu'on en sorte (reprendre, nouveau parcours, un autre scénario choisi ; la liste des scénarios refermée sans choix la laisse en place). Toutes ses commandes font au moins 44 px de haut ; « Lien copié » reste en vue en bas pendant le défilement, sans rien pousser ni bloquer de toucher.
- **L'altitude de chaque plante notée** : à chaque enregistrement d'un lieu ou d'un parcours, l'altitude du sol (RGE ALTI® de l'IGN, jamais celle du GPS du téléphone, imprécise et mesurée au-dessus de l'ellipsoïde) est demandée pour le point du lieu et pour chaque plante qui n'en a pas encore, **par lots** (une requête pour 100 points, au plus 4 par seconde), puis gardée avec la position : une plante déplacée retrouve la sienne, les autres ne sont pas redemandées. Hors ligne ou service indisponible, rien n'est perdu : elles attendent le prochain enregistrement en ligne (pas de nouvel essai avant 10 min). Module « IGN – adresses et altitudes ». L'export GeoJSON et la copie de secours les gardent (`altitude`, en mètres). Le récapitulatif du parcours ajoute **la montée** (« sur 1,0 km, 400 m de montée ») et **le profil d'altitude**, de plante en plante, avec le plus bas et le plus haut ; chaque point dit sa plante et son altitude au survol. Le départ « ici » compte désormais bien comme première étape (il n'était pas gardé).
- **Vue 3D** (bouton « Vue 3D » sur la carte du récapitulatif, et sur chaque lieu de Mes plantes qui a des plantes) : le parcours **sur le relief**, en lecture seule, plein écran par-dessus l'app — c'est **la carte de l'app** (`gf-map`) forcée en 3D (voir « Cartes en 3D ») : chaque plante avec sa photo dans l'anneau de son abondance comme sur toutes les cartes (une feuille sans photo, ou module « Photos en ligne » coupé), le trait de la marche de plante en plante (dans l'ordre où elles ont été notées, la même règle que la distance et le profil du récapitulatif : `app/core/walk.js`), le départ quand le parcours a commencé « ici » (avec son altitude) ; toucher une plante donne son nom et **son altitude** (celle de l'IGN, gardée avec elle). Inclinaison, exagération du relief, ciel… : ceux de Réglages › Cartes. C'est un dialogue : le focus y reste, Échap, ✕ ou Retour le ferment, le focus revient au bouton ; sa carte est détruite à la fermeture (libère la mémoire graphique). Il faut **WebGL2** (sinon le bouton dit « 3D indisponible sur cet appareil ») et le module « Vue 3D (relief) » ; hors ligne, ou relief injoignable, la vue s'ouvre à plat et le dit.
- **La même plante, plusieurs fois** : une ortie rencontrée plus loin s'ajoute encore (le même marqueur ＋, la proposition dit « Déjà une fois dans le parcours ») ; chaque **occurrence** a sa position.
- **La liste** des plantes du parcours, qui défile : **une ligne par plante**, sa vignette (photo), ses noms et, rencontrée plusieurs fois, « × 3 » ; la dernière rencontrée en haut. **Toucher une plante** (dans la liste ou sur la carte) l'allume : **ses occurrences en évidence sur la carte** (les autres plantes ne changent pas), cadrées avec votre position, et **dans l'en-tête** son nom, **le marqueur ＋** (« Ajouter ici ») — une occurrence de plus, là où vous êtes — et ✕, qui retire l'occurrence touchée sur la carte (sinon la dernière), avec « Annuler ». La toucher à nouveau l'éteint.
- **La carte** : **un marqueur par occurrence** (pas de repère qui les regroupe), avec votre position qui suit ; elle est **toujours cadrée sur tout le parcours** (son départ et chaque plante), et se recadre à chaque ajout.
- **Sur ordinateur, la colonne du parcours se redimensionne** : glisser le séparateur entre elle et la carte (une ligne guide suit le pointeur, la largeur est prise au relâcher), ← → au clavier (Maj : par grands pas), Début / Fin pour les extrêmes, double-clic ou Entrée pour la largeur par défaut ; la carte garde toujours 360 px et ne se recadre pas pendant le changement. La largeur est mémorisée.

### Rencontres : les plantes autour de vous (premiers pas)

- **À la première ouverture**, l'application montre **la liste de Découvrir** (l'adresse de départ devient `#/discover` : quitter une mini-application y ramène, même une fois la Flore venue) avec, en petit, « Passer : montrer toute l'application ». **Rencontres** (« Jouer ») commence par une seule action : « Autour de moi » (la position n'est demandée qu'à ce moment) ou une commune. Puis **jusqu'où chercher** : un curseur de 200 m à 50 km (« Juste devant la porte », « Le quartier », « Une balade à pied », « Un tour à vélo », « Toute la région »), **par-dessus une carte** : le cercle du rayon, bien visible, cadré quelle que soit la taille de l'écran, et les observations de plantes qu'il contient (iNaturalist : **les 100 plus récentes** sur la carte ; leur nombre total dit par la zone d'annonce de la carte, pas écrit dessus), **chacune la photo de sa plante** dans un rond qui apparaît l'un après l'autre (sa feuille d'abord, la photo une fois chargée) ; **au survol, une petite fiche** : sa photo, son nom, son nom scientifique, la date et le lieu de l'observation (un toucher ouvre l'observation) ; changer le rayon fait glisser la carte, sans flash. Les cartes des écrans Découvrir n'affichent pas d'alertes de zones protégées.
- **Rencontres, à la Tinder** : les plantes observées dans ce rayon (iNaturalist, observations confirmées, reliées à la flore embarquée), une carte à la fois, **les plus observées — donc les plus photographiées — d'abord**. Chaque carte dit **« On dit de moi : … »** (la première phrase de l'étymologie ou de l'histoire de son article Wikipédia, CC BY-SA ; demandé seulement pour les cartes en vue) et a sa « bio », tirée de ses vraies données : floraison, alertes (toxique, protégée ; sosies dangereux, avec la partie que l'Anses dit consommée — jamais « comestible », ni d'invitation « à table » pour une plante toxique, protégée ou réglementée, ni pour une plante que la source ne nomme que par son genre : une consoude, « Symphytum » pour l'Anses, n'a que sa confusion avec la digitale, « avant toute cueillette »), popularité dans le coin (en mots, sans chiffre : « Très populaire par ici », « Rare par ici »), famille. **Glisser à droite** : c'est un match (« C'est un match ! »), la plante rejoint les favoris ; **à gauche** : on passe ; **vers le haut** (ou toucher, ou ⋯) : sa fiche. Au clavier : ← →, ↑ **sur le paquet** (Tab y mène ; il dit sa carte et ses touches), ou quand rien n'a le focus — sur un onglet, un bouton, le curseur ou la carte, les flèches gardent leur rôle, jamais de match par mégarde ; les onglets Rencontres, Matchs, Toutes se parcourent aux flèches (un seul arrêt de Tab). Pour les lecteurs d'écran : seule la carte du dessus est lue (celle de dessous est hors d'atteinte), sans les tampons « MATCH » / « BOF » ; les boutons nomment la plante (« Passer : Ail des ours ») ; chaque choix est annoncé (« Match : Ail des ours, ajoutée aux favoris. Carte suivante : … »). La fenêtre du premier match est une vraie boîte de dialogue modale : le focus va sur son bouton et y reste, le reste de la page est hors d'atteinte, Retour la ferme comme le bouton, et le focus revient ensuite au paquet. Fin du paquet : « Chercher jusqu'à 5 km », « Revoir celles passées ». À l'arrivée des cartes, la première **penche un instant à droite puis à gauche** (ses tampons « MATCH » puis « BOF » apparaissent) pour montrer qu'elles se glissent — une fois par ouverture de l'application, pas si les animations sont réduites. Une carte est décidée à 30 % de sa largeur, ou d'un geste vif ; celle de dessous monte telle quelle (pas de clignotement). **↺** revient sur la dernière carte (un match annulé quitte aussi les favoris) ; dans Matchs, « Retirer ». Un match fait vibrer le téléphone.
- **Une seule plante à l'écran : la plante choisie** (Rencontres) — **la carte l'épingle** (ses observations, sa photo en grand), **ses photos et sa fiche la montrent**, et l'adresse la nomme (`?p=`) : jamais trois plantes à la fois. **Avant le premier coup de cœur, c'est la carte du dessus du paquet** (la carte la suit à chaque carte glissée, sans `?p=`). **Un coup de cœur choisit la plante aimée, jusqu'au suivant** : passer une carte n'y change rien — la carte du dessus n'est alors qu'une candidate, et une ligne au-dessus du paquet nomme la plante choisie (« Plante choisie : … — sur la carte et dans ses photos »). **Choisissent aussi** : « ‹ Préc. » et « Suivante › » de la fiche, un point touché sur la carte (une des plantes d'ici), une plante touchée dans Matchs ou Toutes, « ⋯ » (ou ↑) sur une carte. **↺** sur le cœur qui l'a choisie revient à la plante choisie avant. Elle est gardée avec la partie (« Reprendre » la retrouve ; `geoflora.app.rencontres.state`, clé `focus`). Pour un développeur : `kit/session.js#chosenId` (la plante choisie, sinon la carte du dessus) est la seule source ; la carte (`ma-distance`), les photos et la fiche (`ma-around-list`) et la découverte guidée (`ma-guided`, `ma-around-map`) la lisent, aucune ne garde la sienne.
- **Le premier match présente ses photos** (Rencontres, une fois la découverte guidée finie) : le premier coup de cœur d'une partie dont la plante a des photos ouvre **la visionneuse des « Médias » de la fiche** (la même : sa présentation, son zoom, ses crédits, ses types de médias dans son en-tête ; les photos d'abord), avec une ligne qui dit comment s'en servir (« Voici ses photos. Double-cliquez sur une photo pour zoomer ; ‹ › ou les flèches pour passer à la suivante. » ; au doigt : « Touchez deux fois… glissez… »), jusqu'à « Compris » ou la carte suivante. **Sur grand écran** (900 px et plus), un **panneau à côté du paquet**, titré « Photos · <plante> », sa largeur réglable par son séparateur (← → au clavier, double-clic : largeur par défaut) ; il montre **la plante choisie** (la plante aimée, puis celle de chaque nouveau cœur ou choisie autrement ; la fiche ouverte prend sa place, ses « Médias » sur la même plante) ; **×** ou Échap le ferment (le focus revient au paquet, et il reste fermé, même après un rechargement) ; **« Ses photos »** (le bouton aux images sous les cartes) le rouvre, son titre prend le focus. **Sur téléphone**, la visionneuse **plein écran par-dessus le paquet** (une boîte de dialogue modale, une étape de l'historique : Retour, × ou Échap la ferment et le focus revient où il était) ; ensuite « Ses photos » la rouvre sur la plante choisie. **Une fois par partie** : les matchs suivants n'ont que leur cœur. **↺ sur ce match** ferme les photos et les rend au match suivant ; **Rejouer / Recommencer** les présentent de nouveau et oublient la largeur du panneau (`geoflora.app.rencontres.state`, clé `media` : la plante dont le cœur les a ouvertes, le panneau fermé ; `geoflora.app.rencontres.media` : sa largeur). Une plante **sans photo**, ou le module **« Photos en ligne » désactivé** : rien ne s'ouvre (jamais de panneau vide), et c'est le prochain match qui a des photos qui les présente. Lecteurs d'écran : « Photos de <plante> ouvertes, à côté des cartes » est annoncé ; le panneau est une région nommée par son titre. Animations réduites : il apparaît sans glisser. Pendant la découverte guidée, le premier match fait déjà venir ses photos à côté des cartes (l'étape « Photos ») : elles comptent pour la partie, la liste ne les présente pas une seconde fois.
- **Matchs** réunit les plantes gardées, **Toutes** les montre en grille (pastilles « En fleur », « Attention · 3 ») ; la vue est dans l'adresse (`&v=matchs`, `&v=toutes`).
- **La découverte pas à pas, du simple au complexe** (Rencontres) : **une seule mise en page, transformée à chaque étape** — chaque étape y ajoute un composant à découvrir. **Une barre d'étapes**, toujours en haut (dans la mise en page, jamais par-dessus) : Carte · Rencontres · Photos · Encyclopédie · Cueillette ou science · Voisines, celles faites cochées, celle en cours en vert, une ligne qui dit ce qu'elle montre et ce qui vient ; **‹ Précédent** et le bouton de la suivante, qui dit ce qu'elle ajoute (à la fourche, les deux chemins). Sur téléphone, les numéros seuls et le nom de l'étape en cours. **Les étapes se touchent** : une étape déjà atteinte y ramène (la mise en page de cette étape), la suivante avance comme le bouton (sauf la fourche, qui se choisit par ses deux boutons) ; les autres attendent, et chacune dit au survol ce qu'elle apporte. Pendant la découverte, pas de bulle « Nouveau : … » par-dessus : l'onglet arrive simplement dans la barre.
  1. **Carte** : la carte seule, le cercle et un **panneau d'accueil** posé dessus (en bas sur téléphone, à droite sur ordinateur — le cercle se cadre à côté) : « Jusqu'où part l'expédition ? », le lieu (changer de lieu), la distance et son curseur, ce qui a été vu (« 842 observations de plantes, 37 espèces différentes », quelques visages en vignettes) et le gros bouton **« Qui pousse par ici ? »** qui fait venir les cartes. À cette étape, toucher un point de la carte ne fait rien d'autre que montrer sa petite fiche.
  2. **Rencontres** : la même carte glisse à gauche (en haut sur téléphone), **les cartes arrivent à côté** — **rien d'autre : la carte, le bloc du lieu (distance, changer de lieu) et les cartes**, sans légende chiffrée, ni groupes chiffrés sur la carte (au plus 250 points pour la plante en vue), ni choix de zone (la carte reste sur le cercle autour de vous). La plante choisie s'allume sur la carte — avant le premier coup de cœur, la carte du dessus : **sa photo, en grand, dans chacune de ses observations** (un rond rose et or qui rebondit en arrivant ; sa feuille tant que la photo charge) ; les autres pastilles ne changent pas. **Toucher une plante sur la carte la choisit** (pas encore aimée, elle vient aussi sur le dessus du paquet ; une carte passée revient) : la carte et les panneaux la suivent, et l'adresse ; une plante qui n'est pas parmi les rencontres est signalée.
  3. **Photos** : **dès le premier coup de cœur** (ou « Ses photos »), un troisième bloc, **Médias**, à côté des cartes, **zoomé** : la première photo s'agrandit doucement, une astuce dit comment zoomer et que le cadenas garde le zoom. **La plante choisie est la plante du moment** : la carte l'allume, les médias la montrent — la plante du premier coup de cœur, puis celle de chaque nouveau cœur ; passer une carte n'y change rien. **Toucher une plante sur la carte** (ou parmi les voisines) la choisit, et la carte et les médias la suivent. Les panneaux prennent toute la largeur qui leur revient, même un panneau seul sur grand écran.
  **Le périmètre, en un seul bloc** (sur la carte ; sous elle sur téléphone) — la distance n'y est dite qu'une fois : dès le premier match, les **zones** où chercher la plante en vue : le cercle (« ⌖ 1 km »), **son département**, **sa région** (d'après l'adresse IGN du lieu ; hors ligne, d'après les contours embarqués), **la France**, **le Monde** — sur ordinateur toutes visibles, sur téléphone en une rangée qui défile, la zone choisie toujours en vue ; sous le cercle choisi, son curseur ; « changer de lieu » (le département et la région suivent le nouveau lieu) ; et la plante en vue (sa feuille, puis sa photo) avec son nombre d'observations dans la zone (« 2 345 observations (1 000 sur la carte) »). Avant le premier match, seulement la distance et son curseur ; pendant le rechargement des cartes, le bloc garde la plante affichée (rien ne saute). La carte n'a pas d'échelle : le bloc dit déjà la distance. Choisir une zone fait glisser la carte jusqu'à elle ; ses observations iNaturalist y sont placées et regroupées à l'arrivée (jusqu'aux 1 000 plus récentes) : **chaque groupe montre la photo de la plante, leur nombre en pastille**, ses points isolés aussi tant qu'ils sont au plus 40 (au-delà, des points rose et or).
  4. **Encyclopédie** : un panneau Wikipédia sous les photos.
  5. **Cueillette ou science** : la cueillette ajoute un panneau *Usages · À ne pas confondre · Calendrier* ; la science, *Carte · Occurrences · Climat · Classification*.
  6. **Voisines** : la liste des plantes autour, sous la carte ; puis **La flore complète** : la fiche dans Flore, sur cette plante, tous les onglets, en mode cueillette ou Scientifique selon le chemin choisi.
  **Seuls les panneaux des étapes franchies** s'affichent pendant la découverte (une carte ou un autre panneau déjà dans la mise en page du mode n'y apparaît pas) ; ils rejoignent la mise en page du mode, que Flore montrera ensuite. « Précédent » revient d'une étape (avant la fourche, le chemin choisi est oublié ; depuis Rencontres, retour à la carte seule).
  Les panneaux suivent **la plante choisie** : la garder (→, ♥, glisser à droite) la choisit, la passer (←, ✕, glisser à gauche) n'y change rien (avant le premier cœur, les panneaux suivent la carte du dessus) ; une plante touchée parmi les voisines est choisie. La découverte a sa propre adresse (`#/app/rencontres/…`) : l'arrivée de Flore en cours de route ne la remplace pas.
- **La fiche**, hors découverte (une fois tout montré, ou une carte touchée avant le premier match), s'ouvre en Épuré, par-dessus la liste sur téléphone, à côté sur ordinateur, avec « ‹ Préc. · 3 / 15 · Suivante › » (et ← →, le balayage) — chaque plante une entrée de l'historique ; l'adresse la garde (`#/app/<id>/cards?p=<id>` ; Rencontres : `?p=<id>&fiche=1`, la plante choisie ; Retour revient à la plante d'avant, ← ou Échap la ferment).
- **Les outils arrivent quand ils servent** : la barre d'onglets ne montre d'abord que Découvrir (et Réglages) ; **Mes plantes** vient avec le premier match ou favori, la **Carte** avec le premier lieu noté, **Flore** (toute la flore, recherche et filtres) après 5 plantes rencontrées — quelle que soit la mini-application jouée depuis la liste (un match de Rencontres, un parcours noté, des plantes ouvertes dans Cueillette ou Mosaïque) ; « Passer : montrer toute l'application », sous la liste, montre tout d'un coup. Chaque fois annoncé (« Nouveau : la Carte — … », l'onglet s'éclaire) ; de retour d'une mini-application, les onglets venus pendant la partie sont dans la barre. Pas de micro-astuces : les outils se présentent par les étapes.
- Quelqu'un qui utilisait déjà l'application garde tout, tout de suite. *Réglages › Premiers pas* : « Tout montrer maintenant » ou « Recommencer la découverte ».
- **Recommencer la découverte** (*Réglages › Premiers pas*) repart de zéro : étapes, embranchement et onglets venus sont oubliés, ainsi que les parties de Rencontres, Cueillette prudente et Mosaïque (lieu, distance, cartes passées, matchs ; les favoris restent), et ramène à la liste de Découvrir. **Rejouer** (⋯) ou **Recommencer** (la liste) une seule de ces mini-applications n'efface que sa partie et ce qu'elle a fait (voir « Mini-applications »).

- **Sur ordinateur, les colonnes se redimensionnent** : au premier pas, un séparateur entre la carte et les cartes ; ensuite, deux (carte ┃ cartes ┃ panneaux de la plante). Glisser le séparateur (une ligne guide suit le pointeur), ← → au clavier (sans faire passer la carte du dessus), Début / Fin, double-clic ou Entrée pour la largeur par défaut. Les panneaux de la plante gardent toujours 320 px, les cartes 300 : une largeur choisie sur un grand écran se resserre sur un plus petit. La carte ne se recadre pas pendant le changement. Les largeurs sont mémorisées ; sur téléphone, les colonnes restent empilées.

### Faux amis : un jeu sur les confusions

Un jeu court (`#/app/faux-amis`), fait des seules données de « Plantes à confondre » (`data/lookalikes.json`, incluse dans l'app : il marche hors ligne). **Six cartes**, chacune une paire de la liste : **la plante cherchée et son sosie toxique**, côte à côte, chacune avec **sa photo et son nom** (on ne reconnaît jamais une plante à sa seule photo ; la photo est celle de la flore, avec son crédit, aucune avec « Photos en ligne » coupé ; pour un genre, son espèce la plus connue : digitale pourpre, vérâtre blanc…).
- **Quatre cartes demandent « À qui est cet indice ? »** : un critère des sources, propre à l'une des deux (« Odeur d'ail quand on froisse la feuille… »), et l'on touche sa plante. Les critères sont ceux de `tell` qui commencent par le nom d'une plante de la paire (« Ail des ours : … », un espace insécable avant les deux-points compris) : 9 dans 5 paires. L'autre plante est celle dont l'indice la distingue (l'ail des ours pour le critère du colchique), sinon n'importe laquelle de l'autre côté.
- **Deux cartes montrent une paire sans aucun critère** dans les sources (`tell` vide : ce que dit aussi sa fiche, « Nos sources ne donnent pas de critère… ») : la carte le dit, et sa seule réponse est **« Je ne cueille pas »** — toujours la bonne. Une paire dont les critères ne sont que généraux (« Confusion des feuilles… » : digitale, vérâtre, œnanthe, aconit, cytise, laurier rose) n'est pas tirée : ni indice à attribuer, ni « aucun critère ».
- **Toutes les plantes d'une paire viennent tour à tour** (petite ou grande ciguë, raisin, myrtille ou cassis…), et **chaque réponse** dit si c'était bien vu, **de quelle plante est l'indice**, **le faux ami et sa gravité** (mortel, très toxique, toxique — « très toxique » nommé comme venant de la base TPPT d'Agroscope), **les autres plantes de la même confusion**, **la partie confondue** (feuilles, racines, baies…) et **les sources** (titre, éditeur, année).
- **Le bilan**, sur une page : le score (« 5 bonnes réponses sur 6 »), les six paires avec leur indice et sa plante, d'où viennent confusions et gravités, **la fiche de chaque plante** (dans l'adresse, `?p=`, comme ailleurs ; sur grand écran à côté du bilan, qui s'écarte pour elle, sa largeur réglable et gardée — `geoflora.app.faux-amis.sheet`, oubliée par « Recommencer »), **la conduite à tenir** (Centre antipoison, 15, 112 : des liens, même dans la mini-application), « Nouvelle partie » (une fiche ouverte se ferme d'abord, comme par Retour). Une photo qui ne vient pas (hors ligne, adresse morte) n'est ni montrée ni créditée.
- **Jamais un mot qui dirait qu'une plante se mange** : un critère qui le dit est écarté (« … est comestible »), par le même filtre que la fiche et les cartes (`edibleFilter`, `app/core/lookalikes.js`) ; la plante qui n'est pas toxique est « la plante cherchée ». Pas de minuteur, pas de carte.
- **Une partie en cours** (les cartes tirées, les réponses : `geoflora.app.faux-amis.state`) revient après un rechargement, et la liste de Découvrir propose « Continuer » ; **jamais perdue sans qu'on le demande** : sur l'écran de départ, « Reprendre la partie » est la grande action (« Carte 3 sur 6. »), « Nouvelle partie : celle en cours sera effacée » une petite. Elle ne garde que ce qui nomme ses cartes : leurs mots sont relus dans le fichier à chaque visite, et **une partie que le fichier ne donne plus** (un critère corrigé, une paire sans critère qui en a un depuis) est dite à recommencer. Le fichier illisible : « Liste des confusions indisponible… » — sans partie, aucune ; une partie en cours, à la place de ses cartes, avec **Réessayer** (le fichier relu, la partie gardée). Quitté avant que le fichier arrive, « Jouer » ne distribue rien.
- **Pour un développeur** : `app/miniapps/faux-amis.js` (le manifeste, son écran de départ), `app/miniapp/kit/faux-amis.js` (pur, testé sous Node : `tests/unit/faux-amis.test.mjs`), `app/miniapp/kit/faux-amis-store.js` (où en est une partie gardée : ce que lit la liste de Découvrir à chaque lancement, sans charger le jeu), `app/miniapp/kit/ma-faux-amis.js` (les cartes, la réponse, le bilan : il défile lui-même, un h1 par vue) ; de bout en bout : `tests/e2e/faux-amis.spec.mjs` (dont axe sur la carte, la réponse et le bilan, avec les règles de `tools/axe-rules.mjs`, les mêmes que `tools/axe.mjs`).

### Onglet Flore : filtres, résultats, plante

- **Ordinateur** : trois panneaux côte à côte, **Filtres ┃ Résultats ┃ Plante**. Chacun se replie (« / ») en une fine barre verticale et se redimensionne en tirant les séparateurs (une ligne guide suit le pointeur, la largeur est prise au relâcher), ← → au clavier (Maj : par grands pas, sans passer à la plante voisine), Début / Fin pour la plus petite et la plus grande largeur, double-clic ou Entrée pour la largeur par défaut ; les Résultats gardent toujours 280 px (une largeur choisie sur un grand écran se resserre sur un plus petit : jamais de défilement de côté). Largeurs et panneaux repliés sont mémorisés (les réglages des versions précédentes sont repris) ; sur téléphone, les panneaux restent empilés, sans séparateur. Les séparateurs sont lus « Redimensionner le panneau filtres / plante », avec leur largeur, leur minimum et leur maximum ; au doigt (tablette), une languette de 44 px les rend faciles à prendre. Toucher un résultat ouvre la fiche dans le panneau Plante (l'adresse `#/plant/<id>` reste partageable) ; ⤢ la passe en pleine largeur, × la ferme.
- **Recherche** en haut des résultats (« Ex. : ortie, Urtica dioica, ger rob, Lamiaceae »). Sous elle, **« Filtrer par »** propose les familles et genres qui commencent par le texte ; en choisir un le met en filtre (le texte s'efface) **et garde les autres propositions**, celle choisie allumée — retouchée, elle s'éteint ; tout éteint, le texte revient.
- **Filtres** : chaque en-tête de filtre reste **toujours visible** — collé en haut une fois dépassé, **empilé en bas tant qu'il est à venir** ; dans une boîte trop basse pour les empiler tous et garder 200 px de liste entre eux (les filtres de la recherche d'une disposition libre), l'en-tête du filtre lu reste seul en haut (`gf-filter-panel` compact), comme les rubriques de la fiche sur téléphone. Toucher un en-tête collé dont la liste est hors de vue y défile en douceur (sans la replier) ; liste en vue, il la replie. Le champ « Filtrer famille… » reste collé sous son en-tête, sur fond plein, pendant la saisie — même quand le texte tapé réduit la liste à une seule valeur.
- **Au clavier** : Tab atteint chaque ligne de résultat (dans la grille aussi), puis son ♥ et son 📍 ; Entrée ouvre la fiche. L'élément qui a le focus est entouré d'un anneau plein, de la couleur d'accent, partout dans l'application. **Sur téléphone**, la fiche qui s'ouvre par-dessus la liste prend le focus (le nom de la plante) ; la liste et l'en-tête cachés dessous sont hors d'atteinte du clavier et des lecteurs d'écran (la barre d'onglets reste) ; « ← » la ferme et rend le focus à la ligne de la plante.
- **Titres** : chaque vue a un seul titre de niveau 1, lu par les lecteurs d'écran (« Flore : recherche », « Carte des lieux », « Mes plantes », « Parcours botanique : … », « Découvrir » pour sa liste, « Découvrir : étape 2 sur 6, Rencontres ») ; une plante ouverte, c'est son nom, et les noms des panneaux (« Filtres », « Résultats », « Plante ») ne sont plus des titres.
- **Sans saut** : ouvrir une plante depuis les résultats ne recharge rien d'autre — la liste, les filtres et leur défilement restent tels quels, rien ne bouge sous l'en-tête.
- **Grille des résultats** : Photo, Nom français, puis Famille, Genre, Espèce (l'épithète, le genre ayant sa colonne), Statut, Protection, et les actions ♥ (favori) et 📍 (noter où je la trouve ; pleine si la plante est déjà dans un de mes lieux, elle ouvre alors la carte). Trois affichages, au choix par les icônes au-dessus de la grille (lignes · photo · tableau) : **Standard** (sans statut ni protection), **Épuré** (grandes photos, nom français sur le nom scientifique complet) et **Scientifique** (toutes les colonnes, auteur compris). Cliquer un en-tête trie par cette colonne, recliquer inverse l'ordre (`sort=-family` dans l'URL) ; un en-tête dont le filtre est actif affiche son nombre de valeurs, qui ouvre ce filtre. Quand le panneau est étroit, Genre (et Statut) se masquent, puis la liste repasse en fiches.
- **Tablette** : filtres en feuille, Résultats ┃ Plante. Les filtres cochés dans la feuille restent quand elle se ferme, par « Voir N espèces », Retour ou Échap. **Téléphone** : fiches, et la plante s'ouvre en plein écran par-dessus la liste (« ← Résultats » revient au même endroit).
- **Fiche plante : des blocs** : la fiche est faite des mêmes blocs dans les trois modes, en-tête compris : Nom, Photos, Protection et statuts, Plantes à confondre, Classification, Mes collections, Calendrier, Wikipédia, Descriptions, Noms, Occurrences et répartition, Carte, Médias GBIF, Habitat et écologie (GBIF), Trefle, Publications (GBIF), Identifiants, Ressources, et les blocs Note que l'on crée. Chacun est montré à la manière du mode (compact en Épuré, complet en Scientifique ; en Épuré, Noms n'est que la liste des noms français, style réglable en mode King ; Noms (TAXREF et GBIF, en français ; les autres langues seulement si « Autres langues » est coché) ne reprend pas le nom sous lequel la plante est affichée ni les doublons, et n'apparaît pas si la plante n'a pas d'autre nom ; de même, Wikipédia n'apparaît pas sans article) ; par défaut Nom, Photos et Wikipédia se lisent sans titre (le résumé Wikipédia porte sa source : « Source : article Wikipédia »), au choix en mode King ; un bloc sans donnée pour la plante le dit. Certains ont des **sous-blocs** (les lignes de Classification, Occurrences, Noms, Protection, chaque lien de Ressources et chaque Identifiant).
- **Même affichage d'une plante à l'autre** : en parcourant les résultats, la plante suivante s'ouvre comme la précédente — **à la même rubrique**, au même bloc s'il est là (lue sur « Carte », la suivante s'ouvre sur « Carte » ; sinon au début de la rubrique), dans Wikipédia au thème lu dès que l'article arrive — avec les mêmes choix dans les Médias (type, partie de la plante, zoom verrouillé au cadenas, détails ⓘ, diaporama), les mêmes panneaux ouverts, les thèmes Wikipédia ouverts, « Mes lieux » déplié. **Jamais cachée, jamais de saut** : la fiche apparaît tout de suite à cet endroit (l'en-tête d'une rubrique est là sans attendre les données) et y reste pendant que ses blocs se chargent. Pour la durée de la visite (en mémoire, rien d'enregistré).
- **Wikipédia, lu comme un article** : une seule requête apporte l'article entier (texte brut découpé par section), en cache 7 jours. Le bloc Wikipédia porte **dans son en-tête le sommaire de l'article** par thème — Description, Biologie et floraison, Habitat et écologie, Répartition, Toxicité et confusions, Alimentation, Usages, Noms et étymologie, Histoire et symbolique, Taxonomie —, collé en haut pendant la lecture, le thème lu allumé. Toucher un thème l'ouvre et y mène (une ancre par thème) ; **Description est ouverte d'emblée**, les autres repliées. Les références, liens, galeries et le statut de protection (l'INPN fait foi) sont laissés de côté. Sans article en français : « Lire l'article en anglais ».
- **Wikipédia dans les autres blocs** : chaque thème s'affiche aussi sous les données du bloc qui en parle — Description dans Descriptions, Biologie dans Calendrier, Habitat dans Habitat et écologie, Répartition dans Occurrences, Toxicité / Alimentation / Usages dans Usages et cuisine sauvage, Étymologie dans Noms —, en début de texte (« Lire la suite »), avec « D'après Wikipédia · CC BY-SA 4.0 · Lire dans l'article » qui ramène à son ancre ; dans l'article, « aussi dans « Usages… » → » mène au bloc. Un bloc sans donnée propre s'affiche dès que Wikipédia en parle.
- **Wikidata** : les autres noms français de l'élément (alias, CC0) rejoignent Noms, dédoublonnés.
- **Noms** : les autres noms, en italique et plus petits, sans doublons — même écrits autrement (majuscules, accents, traits d'union, article, pluriel : « Orties », « l'ortie », « Ortie-dioïque ») ou donnés en liste (« grande ortie, ortie dioïque ») ; la forme la mieux écrite (accentuée) est gardée.
- **Les rubriques, comme les filtres** : les blocs de la fiche sont **rangés par rubrique** — dans l'ordre du mode : une rubrique vient là où vient son premier bloc, et l'ordre du Mode King vaut à l'intérieur de chaque rubrique — chaque rubrique sous **son en-tête** (icône, nom ; sur Alertes, le nombre d'alertes de la plante à la couleur de son verdict, ci-dessous), **collé tant qu'on la lit**. Rubriques : **L'essentiel** (classification, noms, identifiants), **Images**, **Alertes**, **Usages** (usages et cuisine sauvage, Wikibooks), **Saisons**, **Encyclopédie** (Wikipédia, descriptions, publications, Trefle, ressources), **Écologie et climat**, **Répartition**, **Carte et territoire**, **Outils et notes**. Une rubrique est là dès que le mode a un bloc pour elle, quelles que soient les données de la plante (« Rien dans les sources consultées » sinon) : la pile garde ses places d'une plante à l'autre.
  - **Quand la place le permet** (au moins 62 % de la fiche restent à lire une fois le titre du bloc collé lui aussi : grand écran, fiche haute…), **toutes les rubriques sont empilées**, comme les en-têtes des filtres : celles déjà passées en haut, celles à venir en bas (au-dessus de la barre d'actions) — toujours toutes en vue, chacune à un toucher. **Sinon** (téléphone, panneau bas) : la rubrique lue seule en haut, poussée par la suivante quand on y arrive. Sous l'en-tête, **le titre du bloc lu** reste collé, puis **le thème de l'article lu** dans Wikipédia. Où l'on en est, c'est ce qui est collé : rien n'est calculé pendant le défilement, rien ne clignote, l'en-tête de l'application ne bouge pas. La disposition ne bascule pas pour quelques pixels (la barre d'adresse d'un téléphone qui apparaît) : la pile complète reste jusqu'à 52 % ; quand elle change, la place atteinte (si la main n'a pas bougé depuis) est rejointe sous la nouvelle pile. Ce qui est collé en haut et en bas compte aussi pour le clavier : « Page suivante » et Espace montrent les lignes suivantes sans en sauter, et un élément atteint par Tab n'est jamais caché sous une pile ; un contrôle collé (en-tête, titre de bloc, barre d'actions) qui reçoit le focus ne fait pas défiler la fiche.
  - **Toucher un en-tête** mène au début de la rubrique, juste sous les en-têtes collés au-dessus (son en-tête s'éclaire), dans les deux dispositions. Le **Sommaire** (☰ au bout de chaque en-tête ; touché de nouveau, il se ferme) s'ouvre par-dessus tout, sous l'en-tête — ou au-dessus quand la place manque en dessous (pile du bas), toujours entier à l'écran : ce qu'est la fiche (« Espèce », « Sous-espèce », « Variété », « Hybride », « Genre »), chaque rubrique, ses blocs, les **thèmes de l'article Wikipédia** — un toucher y mène —, **la place lue marquée**, et **le cadenas**. Au clavier, le focus y entre (↑ ↓, Début, Fin), Échap le ferme et revient au ☰ — sans fermer la plante dans Découvrir ni en changer avec ← → ; une entrée choisie y mène et le focus la suit (Tab continue de là). Il se ferme quand la main fait défiler la fiche, pas quand le contenu arrive pendant qu'il est ouvert. Une rubrique dont les blocs sont dans un panneau le dit (« dans un panneau ») et, touchée, déplie le panneau sur le bon onglet ; un thème de l'article choisi quand Wikipédia est dans un panneau fait défiler ce panneau, pas la fiche.
  - **Les places tombent pile et y restent** : une rubrique, un bloc ou un thème vient exactement sous ce qui est collé au-dessus de lui — d'un coup, en glissant seulement si c'est à moins d'un écran (pas avec « animations réduites ») — puis **reste en place pendant que le contenu au-dessus arrive** (photos, article, données) — tant que les données de la plante arrivent, même lentement, et jusqu'à ce que la fiche ne grandisse plus — ou jusqu'au premier geste de la main (molette, toucher, clavier) : la main a toujours le dernier mot, la fiche ne s'aimante jamais. **Lire à la main pendant le chargement** ne fait pas sauter non plus : quand la main s'arrête et se lève, la ligne lue (ou le début du bloc lu, encore vide) reste où elle est jusqu'à la fin du chargement — jamais sous un doigt encore posé ni sous le pouce de la barre de défilement, et tout défilement qui ne vient pas de la fiche la rend à la main. Une source qui ne répond pas ne compte plus au bout de 15 s. Changer de vue (Épuré, Standard, Scientifique) ou passer en Mode King et en revenir garde le bloc lu en vue. La fin de la fiche laisse la place pour que la dernière rubrique vienne en haut, elle aussi.
  - **La mémoire** (la place où s'ouvrira la plante suivante) s'écrit quand on choisit une place — Sommaire, en-tête, menu de l'article, « Lire dans l'article », une carte de la fiche mise en avant — et quand la main arrête la fiche (même si l'on passe aussitôt à la plante suivante) — jamais pendant un défilement de l'app. **Le cadenas** (dans le Sommaire) la verrouille : chaque plante s'ouvre à l'endroit lu au moment du verrouillage, même si l'on a défilé ailleurs entre-temps (choisir une place déplace le verrou).
  - **Mode King** : la liste simple des blocs, chacun avec sa poignée (ranger, masquer, renommer), sans rubriques collées.
  - Dans Flore, Mes plantes et Découvrir, l'en-tête du panneau Plante dit simplement « Plante » (Découvrir : le nom de la plante) ; les rubriques sont dans la fiche.
- **Barre d'actions** : Favori, Ajouter à… (choisir une collection ou un lieu), Partager, Noter ici, dans une barre fixée en bas de la fiche (au-dessus du menu sur téléphone), toujours à portée pendant le défilement. Chaque action s'affiche ou non, et s'ordonne, pour chaque mode : en mode King, une case ☑ sur chaque bouton de la barre ; dans *Réglages › Mode King › Barre d'actions*, la liste à cocher et à glisser.
- **Mode King** (en haut des *Réglages*) : le mode d'édition de la fiche. Une couronne dorée s'affiche en bas de l'écran tant qu'il est actif ; la toucher quitte le mode (elle disparaît). Tout est enregistré automatiquement, pour chaque mode d'affichage :
  - **ordre** : glisser un bloc par son titre (souris ou doigt ; pendant le glisser, les blocs se replient sur leur titre ; ↑ ↓ au clavier sur sa poignée ⠿) ; les sous-blocs s'ordonnent depuis l'icône « Sous-blocs » de leur bloc ;
  - **présence** : la corbeille masque un bloc (il reste, estompé, avec ↺ pour le réafficher ; hors mode King il n'apparaît pas et n'est pas chargé), une case masque un sous-bloc. Masquer ou réafficher un bloc ne touche jamais à son service : les services se choisissent pour tout l'appareil, dans *Réglages › Modules*. Un bloc dont le service y est coupé (GBIF pour Descriptions, Occurrences, Médias GBIF, Habitat et Publications ; Wikipédia, ou Wikidata, pour Wikipédia…) reste masqué, rien n'ayant à s'y afficher : en mode King il dit « service GBIF coupé pour tout l'appareil (Réglages › Modules) », un lien vers les Réglages à la place de ↺, et la palette « Ajouter » ne le propose pas ;
  - **masqué si vide** : l'icône « œil barré » d'un bloc qui peut n'avoir rien pour une plante (Protection, Plantes à confondre, Mes collections, Calendrier, Photos, Wikipédia, Descriptions, Noms, Occurrences, Médias GBIF, Habitat, Trefle, Publications, blocs Note) le retire de la fiche hors mode King quand il est vide, au lieu d'afficher « Aucune… » ; pour chaque mode (par défaut : Wikipédia, Noms, Habitat et Publications) ;
  - **titres** : ✎ renomme un bloc (vide : son nom d'origine) ;
  - **titre affiché ou caché** : l'icône « H2 » montre ou cache le titre d'un bloc hors mode King, pour chaque mode (par défaut Nom, Actions, Photos et Wikipédia sont sans titre) ;
  - **style** : certains blocs ont deux styles, au choix pour chaque mode (Noms : « Liste », les noms français seuls, par défaut en Épuré ; ou « Tableau », avec les autres langues et les sources) ;
  - **blocs Note** : « + Bloc Note » crée un bloc nommé, avec un texte libre par plante, gardé sur l'appareil (dans IndexedDB, avec les collections ; les notes des versions précédentes, dans le `localStorage`, y sont déplacées une fois au lancement, sans perte), dans l'export GeoJSON, le lien de transfert avec données personnelles et la copie de secours ; « Enregistré sur cet appareil » ne s'affiche qu'une fois le texte réellement enregistré, sinon « Non enregistré » ; ✕ le supprime avec ses textes. Importer une mise en page **ajoute** ses notes aux vôtres, sans jamais les remplacer ;
  - **blocs Carte** : la fiche a un bloc « Carte », et « + Bloc Carte » en ajoute d'autres, placés, renommés et masqués comme les autres blocs (✕ supprime une carte ajoutée). L'engrenage ⚙ d'une carte règle, pour tous les modes :
  - **le sujet de la carte** (en tête de sa portée) : **Cette plante** (sa répartition, mes lieux où elle est, ce qui est autour, ses sosies, une zone touchée), **Les résultats** (les plantes de la recherche et de ses filtres : mes lieux où elles sont, la carte suit quand les filtres changent) ou **une collection** (un lieu : lui et ses plantes ; une liste ou les favoris : les lieux où sont ses plantes). Hors « Cette plante », les couches propres à la plante (GBIF, autour de moi, sosies) s'effacent ; le cadrage suit les lieux montrés. Gardé pour cette carte (et dans ses réglages du mode King).
  - **la portée de la carte, sous elle** : tout ce qu'elle peut montrer, proposé selon ce qui est connu. **Cadrer** : Auto (selon ce qui est affiché), **Ma région** dès que votre région est connue (votre dernière position, ou le lieu choisi dans Découvrir ; la région vient de l'adresse IGN), **Autour de moi** (vous localise si besoin), **Les points** quand il y en a, France, Monde. **Rayon** (500 m à 10 km), dès qu'on cadre autour de soi ou qu'on montre ce qui est autour : gardé comme dans la Carte, les observations sont recherchées à nouveau. **Données** : la répartition GBIF (France ou Monde), Mes lieux, les observations **iNaturalist** et **GBIF autour de moi** (avec leur nombre), et **les sosies** de la plante (« Sosie : Colchique » pour l'ail des ours : leur répartition GBIF en violet, à côté). Chaque choix est gardé pour cette carte, comme dans ses réglages du mode King. (Son fond et les couches de l'IGN : son panneau ▦, comme sur toutes les cartes.)
  - **une zone touchée dans la fiche** (une région, un département, dans Occurrences et répartition) : la carte **attend d'avoir la zone** — son contour et ses occurrences, demandés ensemble — puis **glisse en douceur** jusqu'à elle, sans repasser par la vue par défaut ; d'une région à une autre, elle va directement de l'une à l'autre. **Le contour** de la zone est tracé (pointillés ambrés, IGN ADMIN EXPRESS, pour les régions et départements français) et **ses occurrences** placées en points (jusqu'à 300), **chacune la photo de la plante** dans son anneau rose et or — celle de sa fiche, avec son crédit (auteur, licence, source) même quand elle a été trouvée en ligne ; sa feuille si elle n'a aucune photo —, **regroupées** quand elles sont proches : une pile de cette photo avec leur nombre, plus grande quand elles sont plus nombreuses ; **le toucher déploie ses points** en éventail autour d'elle, chacun relié à sa place (sa fiche au survol : photo et crédit, noms, date, lieu, source ; son enregistrement au clic, jamais dans une mini-application) — un très gros groupe (plus de 24) zoome d'abord sur sa zone ; un toucher ailleurs ou un zoom les regroupe ; seules, chacune reste la photo de la plante, même nombreuses (celles loin de la vue, un point rose jusqu'à ce que la vue y vienne). Les observations autour de moi sont dessinées de même, **une occurrence GBIF exactement comme une observation iNaturalist** (mêmes marqueurs, mêmes piles, ensemble ; seule sa fiche dit « Observation : GBIF · son jeu de données ») ; chaque relevé une seule fois : la copie GBIF d'une observation iNaturalist montrée est écartée (reconnue à son numéro), autour de moi comme dans la zone, et une occurrence de la zone aussi autour de moi n'est placée qu'une fois. La légende — dans le panneau ▦ Carte de ce bloc, jamais écrite sous ou sur la carte — dit combien d'occurrences, combien placées, combien déjà sur iNaturalist, et les limites tracées (chaque nouveau compte est dit une fois par la zone d'annonce de la carte) ; la pastille de la zone a la pastille de ses points, son état (« absente de GBIF », « aucune occurrence localisée ») dans son nom. ✕ sur la pastille de la zone : retour en douceur.
    - ce qu'elle montre, à cumuler : répartition GBIF (France ou monde), mes lieux de cette plante (et chaque plant à sa position), observations proches (iNaturalist, GBIF ou les deux, dans le rayon d'« Autour » ; la position n'est demandée qu'au premier toucher de « Observations autour de moi ») ;
    - **pas son fond, ni les couches IGN, ni 2D / 3D** : ils sont dans son panneau ▦, comme sur toutes les cartes (l'engrenage le dit) — les réglages communs à toutes les cartes par défaut ; un bloc réglé avec un autre fond ou des couches dans une version précédente les garde comme **son propre fond** (`look` de sa configuration, repris une fois des anciens champs ; le plan IGN sans couche, l'ancien défaut, suit les réglages communs), et son panneau ▦ propose « Revenir aux réglages communs » ;
    - son cadrage (France entière, ajusté à ce qui est affiché, autour de moi) et sa hauteur ;
    - ses actions : « Ouvrir dans la Carte » (l'onglet Carte filtré sur la plante, avec sa répartition GBIF), créer un endroit ici (appui long : le nouvel endroit contient déjà la plante), déplacer mes plants (✎), « Noter ici », « Me localiser » (les boutons ronds de la carte — couches, me localiser, ✎ — sont petits et translucides, la carte d'abord ; ils s'affirment au survol). **Les petites fiches des plantes** (au survol d'un point, au toucher sur téléphone) **passent par-dessus tout** : boutons et panneaux de la carte, bandeaux de la page autour ; elles se posent au-dessus du point (en dessous s'il n'y a pas la place) et disparaissent dès que la carte bouge.   - **Modeler la mise en page : un arbre de panneaux.** Le panneau Plante est, pour chaque mode, un arbre de panneaux comme dans un éditeur : la **fiche** (qui défile) et, à côté, au-dessus ou en dessous, des **panneaux** qui tiennent des blocs en **onglets**, découpés en lignes et en colonnes. En mode King, on **glisse** un bloc — par son titre, par son onglet, ou depuis la palette **« Ajouter »** (les blocs masqués, et « Nouvelle carte ») :
    - **près d'un bord** d'un panneau ou de la fiche : un **nouveau panneau** de ce côté (la moitié qu'il prendra s'ombre) ;
    - **au milieu d'un panneau** : un de ses **onglets** ; sur sa barre d'onglets : entre deux onglets ;
    - **dans la fiche** : il y revient, à la place marquée d'un trait entre deux blocs (c'est aussi le geste pour réordonner la fiche) ;
    - **sur le bord extérieur** du panneau : une bande ou une colonne sur toute sa largeur ou sa hauteur.
    Échap annule ; un panneau vidé disparaît. Exemple : à côté de la fiche, la répartition, puis le calendrier dessous, puis une carte en onglet. Au clavier ou au doigt, **« Déplacer vers… »** sur un bloc fait de même (dans la fiche, nouveau panneau à droite / gauche / en haut / en bas, onglet d'un panneau). Les **poignées** entre panneaux se tirent (aussi hors mode King ; ← → ou ↑ ↓ au clavier, Maj : par grands pas, Début / Fin jusqu'au bout, double-clic ou Entrée : parts égales ; lues « Redimensionner la fiche et « Classification » », avec leur part en % ; au doigt, une zone de 44 px et une languette ; le panneau des Médias garde au moins 400 px de haut et 280 px de large — sa photo, sa barre de zoom et ses vignettes ne se chevauchent jamais, et sa bande sur une fiche étroite aussi ; en panneau, le choix du type de média — photos, herbiers… —, les parties de la plante et le compteur « 1 / 4 » sont **dans l'en-tête du panneau**, une ligne de gagnée pour l'image) ; la disposition est gardée **par mode**, partout où la fiche s'affiche (Flore, Mes plantes, Découvrir) et d'une plante à l'autre. Une vue qui garde sa propre disposition (une mini-application) donne à la fiche son arbre de panneaux (propriété `tree` de `gf-plant-detail`) : poignées, onglets, panneaux repliés ou déplacés lui reviennent (événement `pane-sizes`), sans toucher à celle du mode. Sur une fiche étroite (téléphone), les panneaux deviennent des bandes au-dessus et au-dessous de la fiche, dans l'ordre de l'arbre (l'arbre lui-même ne change pas). Le panneau Plante de Flore et de Mes plantes s'élargit quand des panneaux sont à côté de la fiche. Les mises en page des versions précédentes (blocs collés aux bords, « à côté ») sont converties en arbre. **Page web** : un bloc à placer dans un panneau (puce de la palette du mode King, ou « Déplacer vers… »). Une fois dans la mise en page, **les liens de l'application vers d'autres sites s'y ouvrent** au lieu d'un nouvel onglet — un lien Wikipédia (ouvert dans sa version mobile, faite pour une colonne), une fiche INPN, une page GBIF, une ressource… — et l'onglet « Page web » passe devant s'il était derrière un autre. Le panneau a sa barre : ← → parmi les pages ouvertes, l'adresse, « ouvrir dans un nouvel onglet », fermer la page ; la page reste d'une plante à l'autre. Certains sites refusent d'être affichés dans un autre (la page reste vide) : une ligne propose de l'ouvrir dans un onglet. Ctrl, ⌘ ou Maj + clic, ou le clic du milieu, gardent le comportement du navigateur ; sans panneau Page web, rien ne change.

  - **tableau ou liste** : les données en lignes (Occurrences : régions et départements, types de relevés, sources ; Habitat et écologie ; Publications ; Identifiants) se lisent en **tableau** par défaut (valeur, nombre, part avec une petite barre), ou en **liste** compacte, au choix pour chaque mode.
  - **Réglages › Mode King** : pour chaque mode, le **panneau Plante en miniature** (la fiche et ses blocs, les panneaux et leurs onglets) où l'on glisse les blocs comme sur la fiche — la fiche suit en direct —, puis les mêmes listes (glisser : toute la ligne à la souris, la poignée au doigt ; « Position » : dans la fiche ou un nouveau panneau d'un côté), avec leurs sous-blocs, « Par défaut » (les blocs du mode tels qu'il les a par défaut ; les services restent comme ils sont), « Nouveau bloc Note », **Exporter / Importer la mise en page** (un fichier JSON, version 2 : ordre, blocs et sous-blocs masqués, titres, arbre de panneaux, blocs Note et leurs textes ; jamais les services, qui sont ceux de l'appareil — les modules coupés qu'écrivait une version précédente sont ignorés à l'import ; un fichier de version 1 est converti) et « Tout réinitialiser » — ces trois boutons sont toujours visibles dans *Réglages › Mode King*, même sans entrer dans le mode.
- **Médias : la visionneuse** : le bloc **Médias** de la fiche (par défaut en Standard et Scientifique, à la place de Photos et Médias GBIF, qui restent disponibles en mode King ; en Épuré, la grande photo l'ouvre) réunit les images de la plante, de toutes les sources : photo du jeu de données, Wikimedia Commons, photos choisies du taxon sur iNaturalist, photos d'observation et planches d'herbier GBIF (licences libres seulement, auteur et licence sur chaque image).
  - **Dans la fiche** (compact) : l'image dans un cadre de forme fixe (4:3, 3:2 quand la fiche est large : rien ne saute d'une plante à l'autre ; pendant le chargement, la visionneuse a déjà sa taille), son crédit en une ligne, la pellicule des autres ; le type de média (Photos, Observations, Herbier) se choisit dans un menu quand il y en a plusieurs ; ⤢ l'ouvre **en panneau**, sur l'image montrée. Dans le flux de la fiche, la molette fait défiler la fiche (Ctrl + molette zoome) ; collée à un bord de la fiche ou en panneau, la molette zoome sur l'image.
  - **En panneau** : l'image en grand. L'adresse `#/plant/<id>?pane=media&i=<n>` ouvre directement la n-ième image (les liens `?media=<n>` aussi).
  - **Zoom et carte de l'image** : une image plus haute que le cadre le remplit en largeur, et la **carte de l'image entière** se pose sur son bord droit, de toute la hauteur (fond sombre presque opaque, la zone vue cernée d'un trait fin) — quand elle tient (au plus 45 % de la largeur, 35 % sur téléphone ; sinon l'image entière). **Chaque image s'ouvre zoomée à 50 %** (un pixel de l'original pour deux : net, ses détails à portée), centrée — sauf une image trop petite pour cela, qui s'ouvre sur toute la largeur ; avec l'économiseur de données du navigateur, pas plus loin que ce que sa taille d'affichage permet (l'original n'est alors téléchargé qu'en zoomant). **Jamais au-delà de 100 %** (un pixel de l'original par pixel d'écran), ni à l'ouverture, ni au zoom : une petite image n'est pas agrandie, même entière (elle s'affiche à sa taille sur son fond flouté). Le bouton du milieu passe de « Largeur » (toute la largeur) à « 50 % » puis « 100 % », sur l'image montrée. Le **cadenas** de la barre de zoom garde le zoom affiché (son pourcentage) pour les images et les plantes suivantes ; déverrouillé (par défaut), chaque image repart à 50 %.
  - **Un fondu enchaîné partout** : quelle que soit la façon de changer d'image — ‹ ›, les flèches du clavier, un glissement, la pellicule, la mosaïque, le diaporama, le type ou la partie, l'adresse (Précédent, un lien), une photo touchée sur la fiche —, zoomée ou non, l'image qui part reste en dessous, telle qu'elle était (une copie peinte, sans nouveau téléchargement : jamais d'écran noir), pendant que la suivante apparaît en fondu par-dessus ; des changements rapprochés s'enchaînent sans saut. Les vignettes de la pellicule, de la mosaïque et de la carte de l'image apparaissent en fondu une fois chargées. Seulement de l'opacité (léger pour l'appareil) ; rien si le système demande moins d'animations. (Le passage à une autre plante change encore toute la fiche : son fondu viendra avec le modèle des mini-apps.)
  - **Toujours au moins toute la largeur** : au moindre zoom, l'image remplit la largeur du cadre (une image haute se fait défiler de haut en bas) ; le bouton du milieu dit alors « Largeur ». Seule exception : un original plus étroit que le cadre s'affiche à sa taille (100 %), sur son fond flouté.
  - **La carte de l'image, discrète** : le cadre de la partie vue est fin et à peine marqué ; il s'éclaire quand on pointe ou fait glisser la carte, puis redevient discret doucement.
  - **Glisser sur téléphone** : dans la fiche, glisser sur une image change d'image, plus de plante ; une image plus large que l'écran se fait d'abord défiler, puis un glissement vif contre son bord passe à la suivante.
  - **Le plus détaillé d'abord** : dans chaque type, les images les plus grandes (en pixels, quand la source le dit) passent devant, puis les plus récentes.
  - **Parties de la plante (Trefle)** : avec un jeton Trefle (*Réglages › Modules*), les photos Pl@ntNet par partie s'ajoutent — seulement celles dont le crédit porte une licence libre (« (cc-by-sa) »…), la plupart (Photoflora) n'en ayant pas. Un menu d'icônes — Toutes, Fleur, Feuille, Fruit, Écorce, Port — filtre la scène, la pellicule, la mosaïque et le diaporama.
  - **Hauteur réglable** : dans la fiche, une poignée sous l'image en règle la hauteur (glisser, ↑ ↓, double-clic : taille par défaut) ; gardée comme une proportion de la largeur (elle suit l'écran), pour toutes les plantes et d'une visite à l'autre.
  - **Détails ⓘ** : sur écran étroit sous l'image, sur écran large à côté — jamais par-dessus, entiers quel que soit le zoom. À côté (visionneuse de 760 px et plus), leur largeur se règle par leur séparateur (l'image garde 320 px ; ← → au clavier, double-clic ou Entrée : 30 % par défaut), retenue (`geoflora.mediaLayout`).
  - **Rien ne saute au chargement** : l'image montrée est choisie une fois, quand toutes les sources ont répondu ou 0,9 s après les premières (avant, le squelette de la visionneuse, à sa taille) ; la pellicule garde sa place ; quand la vraie forme de l'image arrive, l'image glisse en place ; la carte de l'image apparaît en fondu ; le bouton de vue a une largeur fixe.
  - **Fond flouté** : là où l'image ne couvre pas le cadre, la même image, agrandie et floutée, le remplit.
  - **La carte de l'image** : saisir le cadre de la zone vue le déplace depuis l'endroit saisi (sans sauter) ; toucher ailleurs sur la carte y fait glisser la vue en douceur.
  - **Un seul zoom, comme dans une appli Photos** : double-clic ou double-tap pour zoomer à l'endroit pointé (encore une fois : l'image entière), la molette pour un zoom progressif quand la visionneuse est collée à un bord ou en panneau (Ctrl + molette dans le flux de la fiche), ou pincer, les boutons − / vue / + en bas à droite (« 100 % » : un pixel de l'original par pixel d'écran), et glisser pour se déplacer. Dès que l'image dépasse le cadre, la **carte** de l'image entière montre la zone vue ; la toucher ou y glisser déplace la vue. La carte couvrant le haut droit du cadre, l'image zoomée peut être poussée au-delà de ce côté — vers la gauche jusqu'à dégager son bord droit, vers le bas (carte moins haute que le cadre) jusqu'à passer sous la carte — : aucune partie n'en reste cachée ; ailleurs, pas de bande vide. Le cadre de la zone vue reste toujours entier dans la carte. Les flèches ‹ › sont **en bas du cadre, une dans chaque coin**, à la même place d'une image à l'autre, zoomé ou non (par-dessus la carte quand elle descend jusque-là) ; la barre de zoom se tient à côté de la flèche suivante. Clavier (quand la visionneuse a le focus) : ← → (image précédente / suivante, ou se déplacer quand on est zoomé), + − 0, Échap (l'image entière, puis fermer).
  - **La bonne image au bon moment, toute seule** : la vignette s'affiche aussitôt (floutée), l'image d'affichage (iNaturalist « large », Commons 1 280 px) apparaît en fondu, **sans effet de zoom** (l'image prend sa place d'un coup), et dès que le zoom dépasse ce qu'elle contient, **l'original** se charge (un point discret dans la ligne de crédit, qui pulse pendant le chargement). Rien n'est posé sur l'image hormis les boutons et la carte ; le crédit tient en une ligne discrète dessous. Une image qui ne se charge à aucune taille **disparaît** de la scène, du bandeau, de la mosaïque et des comptes, et la suivante s'affiche ; ailleurs dans l'application, une image en échec se cache sans icône cassée, et toutes les images hors écran se chargent à la demande. Les images voisines sont préchargées.
  - **Calme** : le crédit (type, source, auteur, licence) tient en une ligne sous l'image ; ⓘ ouvre le détail (taille de l'original, collection, année, lieu, « Voir à la source », « Ouvrir l'original »). Sur ordinateur, les commandes s'effacent quand la souris reste immobile. Au doigt : balayer change d'image quand on n'est pas zoomé ; zoomé, glisser déplace la vue.
  - Les tailles se déduisent des adresses des images (iNaturalist `…/photos/<id>/square|small|medium|large|original`, Commons `…/thumb/…/<N>px-<fichier>` et le fichier), dans `app/core/media-items.js` ; une taille qui n'existe pas (Commons n'agrandit pas) bascule sur l'image donnée par la source. Les originaux, lourds, ne sont pas gardés par le service worker.
  - **Présentations** (style du bloc, en mode King) : **Scène** (la photo, ses détails et la pellicule), **Mosaïque** (toutes les images en grille ; une image touchée s'ouvre dans la scène, « ← Mosaïque » y revient) ou **Diaporama** (une image à la fois, ▶ pour défiler toutes les 5 s). Le zoom marche partout.
- **Les blocs en panneau** : tout bloc de la fiche (sauf Nom et la barre d'actions) peut s'ouvrir **en grand dans un panneau à côté de la fiche** : ⤢ sur son titre (au survol sur ordinateur). Le panneau prend la place des résultats (les filtres se replient ; les déplier ferme le panneau), avec le nom du bloc et de la plante, « plein écran » (toute la largeur) et ✕ ; dans la fiche, le bloc laisse une ligne « affiché dans le panneau ». Une carte y remplit toute la hauteur, les tableaux s'y lisent en entier, la visionneuse y a sa loupe à côté. L'adresse `#/plant/<id>?pane=<bloc>` est partageable ; Retour ferme le panneau ; plante précédente / suivante garde le panneau ouvert, sur la nouvelle plante. Téléphone : le panneau couvre la fiche (« ← Fiche ») ; hors de Flore (Mes plantes, Carte) : par-dessus la page.
- **Plante précédente / suivante** : une barre en bas du panneau de la fiche (juste au-dessus du menu sur téléphone) parcourt les résultats dans leur ordre — ou, dans *Mes plantes*, les plantes de la collection ou de l'endroit ouvert. Sur téléphone, simple : « ‹ Préc. · 3 / 17 · Résultats « ortie » · Suiv. › ». Sur ordinateur, complète : première, précédente, les positions autour (1 … 4 5 **6** 7 8 … 17), un champ pour aller directement à un numéro, d'où vient la liste, suivante, dernière ; un trait en haut de la barre montre où l'on en est. Les touches ← → font de même ; sur téléphone, la fiche se balaie comme une carte (à la Tinder, en CSS) : elle suit le doigt en s'inclinant, et la fiche de la plante vers laquelle on va attend déjà dessous, grandissant à mesure ; lâchée assez loin (ou d'un geste vif), elle poursuit sa course hors de l'écran et la fiche de dessous, déjà chargée, devient la fiche ouverte, sinon elle revient en place ; pas sur une carte ni une galerie. La ligne de la plante reste visible dans la liste, « Résultats » ramène à la liste et le retour à la plante précédente.

### Modules : les services en ligne, un par un

L'app fonctionne hors ligne avec la flore locale ; chaque service en ligne est un **module**, une permission **de l'appareil** donnée ou retirée dans **Réglages › Modules** : une case « Utilisé sur cet appareil » par service (cochée par défaut ; Trefle demande un jeton). Le choix vaut partout, quel que soit le mode d'affichage (fiche plante, grille des résultats, cartes, mini-applications), et masquer un bloc de la fiche en mode King ne coupe pas son service. Décoché, un module n'est jamais appelé et ses données ne s'affichent nulle part, copies en cache comprises. Les choix des versions précédentes, faits mode par mode, sont repris au plus strict : un module coupé dans un mode l'est désormais partout.

**Catégories.** Les services, comme les blocs de la fiche, sont rangés par ce que la donnée dit de la plante, quel qu'en soit le fournisseur (GBIF, par exemple, sert à plusieurs) :

| Catégorie | Question | Services |
|---|---|---|
| L'essentiel | Qui est-elle, en quelques mots ? | Wikidata (TAXREF en local ; aussi GBIF) |
| Images | À quoi ressemble-t-elle ? | Wikimedia Commons, Photos en ligne (aussi GBIF, iNaturalist) |
| Alertes | Quels risques lui connaît-on ? | statuts INPN et plantes à confondre en local (aussi GBIF, Wikidata, IGN espaces protégés) |
| Usages | À quoi sert-elle, se mange-t-elle ? | Wikibooks (recettes) |
| Saisons | Quand la voir ? | Baseflor en local (aussi iNaturalist, Open-Meteo pollens) |
| Encyclopédie | Que sait-on d'elle ? | Wikipédia, Trefle (aussi GBIF, Wikidata) |
| Écologie et climat | Avec qui et dans quel milieu vit-elle ? | GloBI, Open-Meteo (aussi GBIF, IGN zones naturelles) |
| Répartition | Où pousse-t-elle ? | iNaturalist, GBIF |
| Carte et territoire | Où suis-je, qu'y a-t-il ici ? | IGN : fonds de carte, adresses et altitudes, espaces protégés, zones naturelles au point ; Vue 3D (relief) |

### Mentions légales, confidentialité et position

**Réglages › Mentions légales et confidentialité** (`#/legal`) dit qui publie GeoFlora et où il est hébergé (GitHub Pages), comment le contacter (issues du dépôt, `SECURITY.md` pour une faille), qu'il n'y a ni compte, ni publicité, ni mesure d'audience, ce qui reste sur l'appareil (flore, lieux et collections, réglages, dernier lieu de Découvrir, réponses des services gardées de 7 jours à un an, images et cartes en cache) et, service par service, ce qui est envoyé, votre position surtout et quand. Deux boutons : **Oublier ma dernière position** (Découvrir) et **Effacer le cache des services en ligne**.

**La position, après un geste.** Le navigateur ne demande la position qu'après « Autour de moi », « Me localiser », « Commencer ici », « Noter ici » ou « Près d'ici » ; la Carte, Mes plantes, un lieu ou un parcours repris ne la suivent d'eux-mêmes que si l'autorisation est déjà accordée (`whenGranted`, `app/core/geo.js`). Avant un envoi, une ligne dit à quel service elle part (Découvrir, Parcours, « Près d'ici », climat ici, observations autour de moi sur la carte d'une fiche, Autour de la Carte, adresse d'un nouveau lieu).

### Modes d'affichage : Épuré, Standard, Scientifique

Un mode pour toute l'application, choisi par trois icônes dans l'en-tête (ou dans Réglages › Affichage sur téléphone) :

- **Épuré** — grandes photos et actions rapides : photo, noms, famille, alertes de protection, calendrier de floraison ; la barre d'actions de la fiche ajoute la plante d'un geste à la **collection courante** (« ＋ *collection courante* », ci-dessous).
- **Standard** — grand public : calendrier, photos, description (résumé Wikipédia, sinon GBIF), noms ; « Dans mes collections » tient en une ligne qu'on déplie.
- **Scientifique** — tout ce que l'application connaît ou peut obtenir, sources citées : classification (Wikidata, jusqu'à l'ordre), auteur, synonymes, noms dans d'autres langues, tous les statuts INPN par territoire, statut UICN mondial, phénologie, observations iNaturalist, occurrences GBIF en France, répartition et descriptions GBIF, médias GBIF, données Trefle (avec votre jeton), identifiants (TAXREF, INPN, GBIF, iNaturalist, Wikidata, Tela Botanica, IPNI, POWO).

La grille des résultats et la fiche plante ont chacune leurs icônes pour s'écarter du mode (un point ↺ ramène au mode de l'application) ; changer le mode de l'application les réaligne.

**Vos modes** (*Réglages › Affichage › Modes d'affichage*) : « Dupliquer » un mode en crée un nouveau, copie de celui-ci — blocs et sous-blocs, ordre, titres, styles, épinglés et leur position, panneaux, barre d'actions — qu'on renomme, à qui on donne une icône, puis qu'on arrange à sa guise en mode King, sans toucher à son modèle (les services en ligne, eux, sont ceux de l'appareil, les mêmes dans tous les modes : *Réglages › Modules*). Par exemple une **visionneuse** (à partir d'Épuré : Médias en panneau, presque rien d'autre) ou un **poste scientifique** (à partir de Scientifique : carte épinglée, interactions, climat, occurrences en panneau). Il s'affiche à la manière de son modèle (Épuré, Standard ou Scientifique : la grille des résultats et la façon de dessiner chaque bloc), apparaît dans tous les sélecteurs d'affichage et voyage avec la mise en page exportée. « Supprimer » l'efface avec sa mise en page ; s'il était utilisé, l'application revient au mode Standard. Les trois modes de l'application restent, modifiables et réinitialisables.

### Recherche, filtres et tri

- **Texte** : noms français, noms scientifiques, synonymes et familles, sans tenir compte des accents ni des majuscules, ligatures comprises (`benoite` → *Benoîte*, `oeillet des chartreux` → *Œillet des Chartreux*).
- **Filtres à longue liste** (Famille, Genre) : leur champ « Filtrer… » reste sous le titre du filtre pendant que sa liste défile ; il ne s'en va qu'avec la fin du filtre, ou quand on le replie.
- **Partout la même recherche** : « Ajouter une plante » (liste, lieu) et « Noter ici » trouvent les mêmes plantes, dans le même ordre, que l'onglet Flore, avec leur nombre et « Afficher plus » jusqu'à la dernière.
- **La liste ne bouge pas** sous les actions d'une ligne (♥ favori…) : elle ne revient en haut que pour une nouvelle recherche (texte, filtres, tri), et retrouve sa position au retour d'une fiche plante.
- **Abréviations** : chaque mot tapé correspond au début d'un mot du nom, dans l'ordre (`ger rob` → *Geranium robertianum*, `ben vil` → *Benoîte des villes*).
- **Fautes de frappe** : s'il y a moins de 5 résultats, une seconde passe tolère 1 faute (mots de 5 lettres et plus) ou 2 fautes (8 lettres et plus), avec la mention « résultats approchants » (`pisenlit` → *Taraxacum*).
- **Suggestions** : les familles et genres qui commencent par le texte saisi sont proposés comme filtres en un clic (`ros` → Rosaceae, *Rosa*).
- **Filtres à choix multiples** : statut, famille, genre, photo, nom français. Les valeurs d'un même filtre se combinent en OU, les filtres entre eux en ET. Chaque valeur affiche le nombre de résultats qu'on obtiendrait en l'ajoutant.
- **Tri** : pertinence, nom français, nom scientifique, famille, avec photo d'abord. Un affichage **compact** est disponible.
- **URL partageable** : `#/?q=ortie&family=Urticaceae,Lamiaceae&status=I,J&photo=avec&sort=sci`.

Sur ordinateur, les filtres sont dans un panneau latéral ; sur mobile, dans un panneau qui s'ouvre depuis le bas de l'écran.

Fonctionnement :

1. au démarrage, l'app part **aussitôt sur la copie locale** de la flore quand elle en a une ; `data/meta.json` est vérifié en arrière-plan (8 s au plus : un réseau lent ou muet ne bloque jamais la recherche). `data/plants.json` n'est téléchargé que si son contenu a changé (son empreinte sha256, publiée dans `meta.json` — une nouvelle construction de la même flore ne se retélécharge pas), vérifié (empreinte, nombre de plantes) puis stocké dans IndexedDB à la place de l'ancienne copie ; la recherche passe alors sur la nouvelle flore, sans recharger. Un téléchargement qui échoue ou ne correspond pas laisse la copie locale intacte (« Mise à jour de la flore reportée ») ; il est retenté au lancement suivant. Téléchargement, vérification, lecture et enregistrement se font dans le Web Worker de la recherche : jamais une tâche longue de la page ;
2. **première visite** : le déploiement (`tools/assemble-site.sh`) publie aussi la flore en deux fichiers compacts (`tools/pack-flora.mjs` → `data/flora/index.<empreinte>.json`, ~0,7 Mo compressé : noms, famille, genre, statut, vignette et facette protection ; `data/flora/details.<empreinte>.json`, ~0,25 Mo : le reste de chaque fiche), décrits dans `meta.json` (`files` : chemin, sha256 et taille de chacun, vérifiés au téléchargement ; l'empreinte `sha256` de la flore reste celle de `plants.json`). La recherche marche **dès que l'index est arrivé** ; les fiches complètes suivent et s'enregistrent en arrière-plan, signalées discrètement à côté du nombre d'espèces (« · mise hors ligne… ») ; une fiche ouverte entre-temps attend la sienne (lue dans le worker), et le service worker ne s'installe qu'une fois la flore enregistrée (son précache ne dispute pas le réseau à la flore ; il revalide les fichiers déjà chargés au lieu de les retélécharger). Un fichier du paquet absent ou qui ne correspond pas : `plants.json`, vérifié comme avant (le dépôt, sans paquet, part toujours de `plants.json`). Le site déployé précharge aussi les modules du démarrage (`tools/preload-modules.mjs`, `<link rel="modulepreload">`), puis ceux de la fiche quand elle est demandée ; les écrans autres que Flore et Découvrir (Carte, Mes plantes, Réglages, mini-apps, disposition libre) se chargent à leur première ouverture. Mesure : `node tools/measure-launch.mjs _site` (premier lancement à froid, réseau « Fast 4G » et processeur ×4) ;
3. un Web Worker construit l'index de recherche depuis IndexedDB (les lancements suivants) ;
4. la fiche plante appelle `PlantSources.details()` à la demande, et la réponse reste en cache dans IndexedDB ;
5. sans réseau, la recherche, les fiches déjà consultées et les images déjà vues restent disponibles. Seule la page de l'app (la racine du site ou `index.html`) est servie et gardée comme telle par le service worker : un fichier du site ouvert dans un onglet (une icône, le manifeste) ne la remplace plus.

Lancer en local (n'importe quel serveur statique fait l'affaire) :

```bash
python3 -m http.server 8000
# puis http://localhost:8000
```

L'app démarre aussi en http depuis un autre appareil (un téléphone sur le réseau local : `http://<adresse de l'ordinateur>:8000`) : sa CSP n'exige pas https (ci-dessous). Hors https et localhost, le navigateur refuse toutefois le service worker (pas de hors-ligne), la position et le presse-papiers (copier un lien, des coordonnées) ; les lieux et les listes se créent quand même. Pour tout essayer depuis un téléphone, passer par un tunnel https.

Le workflow `Deploy web app` publie l'application sur GitHub Pages à chaque modification de l'app sur `main`, après chaque build du dataset et après chaque enrichissement des médias réussis (leurs commits, poussés avec le jeton du workflow, ne déclenchent aucun workflow sur push : `workflow_run`), puis vérifie le site en ligne (ci-dessous, « Surveillance »). Il faut l'activer une fois : **Settings → Pages → Source : GitHub Actions**.

Ajouter un fichier dans `app/`, `vendor/`, `lib/` ou `assets/` impose de l'ajouter aussi à la liste `SHELL` de `sw.js` ; `tools/check.sh` le vérifie. Une seule exception, la liste `ON_DEMAND` de `sw.js` : des fichiers de `vendor/` déployés mais **pas précachés** — aujourd'hui MapLibre (`vendor/maplibre/`, ≈ 1,6 Mo, pour la seule Vue 3D, qui a de toute façon besoin du réseau pour son relief) : le précacher alourdirait chaque installation et chaque mise à jour de l'app pour une vue facultative. Le service worker garde ces fichiers dans le cache de la version **à leur première demande** (la vue 3D marche ensuite hors ligne, à plat), et `tools/stamp-sw.mjs` les compte dans l'empreinte ; `tools/check.sh` vérifie qu'ils sont dans `vendor/`, déployés, et pas aussi dans `SHELL`.

**Version du service worker : rien à incrémenter.** Dans le dépôt, `sw.js` porte `const VERSION = 'dev';` et ne doit pas être modifié à la main (`tools/check.sh` échoue sinon). Au déploiement, `tools/assemble-site.sh` y écrit l'empreinte (sha256, 12 caractères) des fichiers de `SHELL` et de `sw.js` lui-même (`tools/stamp-sw.mjs`) : tout changement d'un fichier précaché donne une nouvelle version, un déploiement sans changement garde la sienne. Le shell est servi depuis le cache de sa version (cache-first, sans requête réseau au lancement) ; le navigateur vérifie `sw.js` à chaque lancement et au retour au premier plan, installe la nouvelle version en entier en arrière-plan (un fichier manquant : elle ne s'installe pas, l'ancienne reste intacte), puis l'app affiche « Nouvelle version de GeoFlora disponible. Recharger ». En local (`VERSION` à `'dev'`), le shell vient du réseau d'abord : une modification se voit au rechargement. Les caches des images (`geoflora-images`) et des tuiles (`geoflora-tiles`) ne dépendent pas de la version. Pour mettre Lit, Leaflet ou MapLibre à jour : `LIT_VERSION=3.x.y LEAFLET_VERSION=1.x.y MAPLIBRE_VERSION=6.x.y scripts/vendor.sh` (MapLibre : l'archive npm, vérifiée contre l'empreinte `dist.integrity` du registre, puis ses fichiers `dist/` copiés tels quels ; une version publiée depuis sept jours au moins), puis mettre les mêmes versions de `lit` et `@types/leaflet` dans `package.json` (les types que lit `tsc`, ci-dessous « Analyse statique ») et relancer `npm install --ignore-scripts`.

**Contrôles avant fusion.** `bash tools/check.sh` réunit ce qu'une modification doit passer, et liste tous les problèmes d'un coup : chaque module se lit comme module ES ; chaque import trouve son fichier et les noms qu'il demande, parmi les fichiers que publie le déploiement, carte d'imports d'`index.html` comprise (`tools/check-imports.mjs` : sans build, un import cassé ne se voit qu'au navigateur, en écran blanc) ; le service worker précache tous les fichiers de `app/`, `vendor/`, `lib/` et `assets/`, `index.html` et le manifeste, et rien qui ne soit déployé ; sa `VERSION` reste `'dev'` dans le dépôt, et l'empreinte écrite par `tools/stamp-sw.mjs` suit les fichiers (contre un site assemblé : elle correspond à ses fichiers) ; les données de sécurité tiennent (`scripts/check-data.mjs` : chaque taxon des confusions est un nom accepté de la flore ; chaque confusion « publiée » de la liste de référence `data/confusions-reference.json` est dans `lookalikes.json`, à sa gravité au moins, et aucune piste « à vérifier » n'y est (`scripts/check-confusions.mjs`) ; une paire dont la plante toxique est au niveau 4 du TPPT n'est jamais « toxique » seulement ; une confusion mortelle ou grave a ses critères et ses symptômes, ou dit qu'ils manquent ; un critère ne nomme jamais une plante qui n'est pas de sa paire — par son nom, ses premiers mots ou son taxon, sans casse ni accents (recopié d'une autre confusion, il décrirait d'autres plantes) ; `safety.json` a ses trois sources, ses effectifs au-dessus de seuils et ses libellés TPPT en français, `meta.json` porte l'empreinte sha256 et le nombre de plantes de `plants.json` — `scripts/fingerprint-dataset.mjs` les écrit, les workflows de données le lancent après la dernière étape qui modifie `plants.json`) ; la CSP d'`index.html` autorise son import map par empreinte (`tools/csp-hash.mjs`). Le workflow `CI` (`.github/workflows/ci.yml`) le lance (job « check ») sur chaque pull request, chaque push sur `main` et dans une file de fusion ; `Deploy web app` le relance sur le site assemblé avant de publier, et `Build flora dataset` vérifie les données avant de les versionner.

**Test de fumée.** Le job « smoke » du même workflow ouvre dans Chromium, **sur le site tel que publié** (`tools/assemble-site.sh`, que `Deploy web app` utilise aussi), les écrans principaux (accueil, recherche, fiche, Découvrir et deux de ses scénarios, carte, collections, réglages), au format téléphone (390 px, tactile, première visite : Découvrir) puis bureau (1280 px, visiteur habitué : la recherche et la fiche s'ouvrent dans Flore). **Analyse statique.** Le job « lint » du workflow `CI` réunit trois contrôles, qui tournent chacun même si le précédent échoue :

- **types, à cliquet** (`npm run typecheck`, `tools/tsc-ratchet.mjs`) : `tsc` vérifie les annotations JSDoc de `app/` (les fichiers portent `// @ts-check`) selon `jsconfig.json` — `checkJs`, mode non strict, avec les types de lit (`types/lit.d.ts` : ce qu'exporte `vendor/lit.js`, `repeat` et `classMap` compris) et de Leaflet (`@types/leaflet`), dev-dépendances à la version de `vendor/`. Les erreurs actuelles sont gelées dans `tools/tsc-baseline.json`, comptées par fichier et par code d'erreur (sans numéro de ligne : modifier un fichier au-dessus d'une erreur ancienne ne fait rien échouer). **Le job échoue dès qu'un fichier compte plus d'erreurs d'un code que le plancher**, en affichant les lignes en cause ; une correction fait baisser un compte : le job le signale, et `node tools/tsc-ratchet.mjs --update` réécrit le plancher — jamais à la hausse. Un éditeur ouvert à la racine du dépôt lit le même `jsconfig.json` ;
- **ESLint** (`eslint.config.js`) : les règles recommandées, `no-unsanitized` (pas de `innerHTML` ni d'`insertAdjacentHTML` avec autre chose qu'un littéral), les règles de gabarits de `eslint-plugin-lit`, `import-x/named` (chaque nom importé d'un module du dépôt y existe ; `lit` et `leaflet` passent par la carte d'imports, que `tools/check-imports.mjs` vérifie) et des interdits `no-restricted-syntax` : pas de `location.hash =` ni de `location.replace()` hors de `app/core/history.js` (passer par `openView()` et `replaceView()`), pas de `localStorage` hors de `app/core/prefs.js` (et de `sync.js`, le canal entre onglets) : chaque réglage passe par `readJSON`, `writeJSON` ou `definePref`, sous une clé de `config.storageKeys` (un test unitaire refuse une clé `geoflora.…` qui n'y est pas, hors du préfixe d'une mini-app), pas de tooltip ni de popup Leaflet en chaîne (Leaflet la pose en HTML : lui donner un élément bâti en texte, `elem()`), pas de propriété réactive Lit nommée comme un membre d'`HTMLElement` (`focus`, `blur`, `click`, `title`, `hidden`…, qu'elle masquerait : `el.focus()` lèverait une erreur). Les exceptions restantes sont écrites sur place, avec leur raison (`// eslint-disable-next-line … -- pourquoi`) ; une exception devenue inutile fait échouer le job ;
- **knip** (`knip.json`) : fichiers, exports et dépendances inutilisés. Les alias historiques lieu/collection de `app/core/collections.js` (`savePlace`/`saveCollection`…) sont signalés sans faire échouer le job, en attendant que leurs appelants n'en utilisent plus qu'un.

```bash
npm ci --ignore-scripts   # une fois
npm run typecheck         # tsc contre le plancher (quelques secondes)
npm run lint              # ESLint puis knip
```

**Dépendances de développement.** L'app n'a ni dépendance ni build : `package.json` (non déployé) ne liste que Playwright (test de fumée, accessibilité) et `@playwright/test` (tests de bout en bout), à la même version, axe-core (accessibilité), et les outils d'analyse statique : TypeScript, ESLint et ses greffons, knip, ainsi que lit et `@types/leaflet` pour leurs seuls types ; SheetJS (`xlsx`, lecture des tableurs Baseflor et TPPT) est à part, dans `scripts/package.json`, pour les seuls scripts du jeu de données (le test de fumée n'en dépend pas). Chaque `package-lock.json` fixe les versions et les empreintes ; la CI installe par `npm ci --ignore-scripts` (aucun script d'installation ne s'exécute ; `--prefix scripts` pour SheetJS), puis `npm audit --audit-level=high`, lancé après le test de fumée, bloque une PR sur une vulnérabilité haute. SheetJS vient de son propre dépôt (`cdn.sheetjs.com`, version 0.20.3) : npm ne propose que la 0.18.5, vulnérable (pollution de prototype, ReDoS). Le changement de version ne modifie pas les données : mêmes mois de floraison (3 879 plantes), mêmes 635 correspondances TPPT. Dependabot (`.github/dependabot.yml`) propose chaque semaine la mise à jour des actions GitHub (épinglées par commit) et des dev-dépendances (ESLint et ses greffons en une seule PR), une fois la version publiée depuis sept jours ; il ne suit ni lit et `@types/leaflet`, mis à jour avec `vendor/` (`scripts/vendor.sh`), ni SheetJS, à mettre à jour à la main (`scripts/package.json`, puis `npm install --package-lock-only --ignore-scripts --prefix scripts`).

**Protéger `main`** (*Settings → Rules → Rulesets → New branch ruleset*, cible : la branche par défaut). Interdire la suppression et le force-push (*Restrict deletions*, *Block force pushes*) ne gêne rien. Exiger une pull request et les contrôles « check », « lint », « smoke », « tests » et « a11y » (*Require a pull request before merging*, *Require status checks to pass*) bloquerait en revanche les commits des workflows de données, poussés directement sur `main` avec le jeton du workflow (`GITHUB_TOKEN`), qu'aucune liste d'exceptions d'un ruleset n'accepte. Il faut d'abord les faire pousser avec le jeton d'une GitHub App placée dans cette liste. D'ici là, une pull request affiche « check », « lint », « smoke », « tests » et « a11y » : ne la fusionner qu'au vert.

**Surveillance : le site en ligne et les services tiers.** Deux workflows regardent ce que la CI ne voit pas :

- **après chaque déploiement** (`post-deploy.yml`, « Check live site », dernier job « verify » de `Deploy web app`) : le site est réassemblé depuis le commit déployé, puis `tools/check-live.mjs` vérifie sur `https://yannouche-dev.github.io/flora/` que `sw.js` porte la même `VERSION` (l'empreinte de `tools/stamp-sw.mjs`) et `data/meta.json` la même empreinte de flore, en redemandant toutes les 15 s pendant 10 minutes au plus (le temps que Pages publie et que son CDN oublie l'ancienne copie), puis que chaque fichier précaché et chaque fichier de données répond 200 ; enfin le test de fumée (`tests/smoke.mjs`) ouvre chaque écran sur le site en ligne. Comme en CI, ses requêtes vers l'extérieur reçoivent une réponse locale : il vérifie le site tel que Pages le sert (fichiers, modules, CSP), pas les services tiers. Si `main` a déjà avancé (un autre déploiement suit), la différence de version n'est qu'un avertissement : le déploiement suivant est vérifié par son propre job. C'est un job du workflow de déploiement plutôt qu'un `workflow_run` : GitHub n'enchaîne pas plus de trois `workflow_run`, et un déploiement après `Enrich search media` après `Build flora dataset` est déjà le troisième. Il se lance aussi à la main (*Actions → Check live site → Run workflow*) ; en local : `bash tools/assemble-site.sh _site && node tools/check-live.mjs _site https://yannouche-dev.github.io/flora/` ;
- **chaque jour** (`api-health.yml`, « Outside services health », 5 h 41 UTC, et à la main) : `tools/api-health.mjs` pose une petite question à chaque service tiers de l'app (GBIF, iNaturalist, Wikidata et son service SPARQL, Wikipédia, Commons, Wikibooks, GloBI, Open-Meteo archive et qualité de l'air, IGN Géoplateforme WMTS — chaque couche de `app/core/ign-layers.js` et chaque fond de `app/core/backgrounds.js` (les photos de chaque année, SPOT, les noms par-dessus) doit figurer dans son catalogue, que `lib/ign-catalog.mjs` doit savoir lire —, le catalogue publié `data/ign-catalog.json` (45 jours au plus), altimétrie, géocodage et WFS, API Carto) et à l'archive TAXREF du build (son premier octet), avec l'en-tête `Origin` du site : statut, en-tête CORS (sans lui, le navigateur ne lit pas la réponse) et forme minimale de la réponse lue par l'app. Une requête par service, l'une après l'autre, avec un `User-Agent` qui nomme le dépôt (et `Api-User-Agent` pour Wikimedia, comme l'app) ; une erreur réseau, un 5xx ou un 429 est redemandé une fois 20 s plus tard. Le tableau des résultats est dans le résumé du run ; le run échoue si un service est en panne, et GitHub le notifie comme tout run planifié en échec. Aucune clé ni aucun jeton : Trefle (jeton personnel) n'est pas sondé, et le workflow n'ouvre pas d'issue. En local : `node tools/api-health.mjs [gbif ign-wmts …]` (derrière un proxy, Node 22 demande `NODE_USE_ENV_PROXY=1`).

Les sondes ponctuelles d'autrefois (workflows temporaires poussés sur une branche) n'ont plus lieu d'être : une vérification se fait par ces deux workflows, lancés à la main au besoin. GitHub garde dans sa liste les workflows temporaires dont le fichier a disparu (`tmp-check`, `Temporary API check`, `Check IGN services (temporary)`) : sans fichier sur aucune branche ils ne tournent plus, et `gh workflow disable <nom>` les retire de la liste active.

**Sécurité dans le navigateur.**
- *Content-Security-Policy* (balise `<meta>` en tête d'`index.html`) : scripts du site seulement, plus l'import map par son empreinte sha256 — après l'avoir modifiée, `node tools/csp-hash.mjs --fix` (sans `--fix`, il vérifie) ; aucun gestionnaire inline (`onerror="…"`) ni `<script>` injecté ne s'exécute ; connexions limitées aux API des modules (dont `s3.amazonaws.com`, le relief de la Vue 3D) ; workers du site seulement (`worker-src 'self'` : la recherche, et le worker module de MapLibre) ; images de tout hôte web, http compris (une photo GBIF peut l'être) ; cadres en https (panneau « Page web »). Pas de `upgrade-insecure-requests` : il ferait demander en https les fichiers de l'app elle-même, servie en http lors d'un test sur le réseau local.
- *Données tierces* : les champs libres des enregistrements GBIF (institution, lieu, collecteur…) deviennent du texte brut et borné (balises et contrôles bidirectionnels retirés ; les liants des écritures persane ou indiennes et des emoji restent) ; un lien venu d'une source (licence, page, original ou source d'une photo — dans la fiche comme dans la visionneuse —, publication, recette, zone naturelle ou espace protégé, source d'une confusion) n'est gardé qu'en http(s) (`app/core/safe-url.js`), sinon son texte s'affiche seul ; les étiquettes de la carte sont posées en texte, jamais en HTML.

### Navigation et saisie rapide

- **Navigation et historique** : chaque vue est une étape de l'historique du navigateur — recherche, fiche plante (chaque plante parcourue avec ‹ › aussi), carte et lieu ouvert, collections, éditeur, réglages. Le bouton retour du navigateur ou du téléphone revient à la vue précédente et ferme une fenêtre ouverte (Ajouter à…, Noter ici, filtres, couches de carte). La recherche (texte, filtres, tri) est une seule vue mise à jour sur place. « ✕ / Résultats » revient à la liste, « Terminé » à la vue d'où l'on venait ; une collection supprimée ou un lieu fusionné ne restent pas dans l'historique.
- Sur téléphone, une barre en bas : **Flore** (feuille) · **Carte** · **Mes collections** · **Réglages** (engrenage ; sauvegarde) ; l'onglet actif a son icône pleine sur une pastille. « Noter ici » est dans Mes collections, sur la carte (+) et dans les Actions de la fiche plante. Sur ordinateur, les mêmes entrées sont dans l'en-tête.
- **Noter ici** : le GPS démarre, des suggestions s'affichent (plantes des lieux à moins de 200 m, favoris, plantes récentes) ; un toucher sur une plante l'enregistre **dans le lieu le plus proche (< 30 m)** ou dans un nouveau lieu. Un bandeau propose **Annuler** et **Détails**.
- **Recherche vocale** 🎙 (recherche Flore et « Noter ici ») : on dit le nom, la recherche se lance. Elle utilise la reconnaissance vocale du navigateur, en français (sur Chrome l'audio part chez Google, sur Safari chez Apple ou reste sur l'appareil) ; le bouton n'apparaît que si le navigateur la propose et si le module « Dictée vocale » est actif. **Le micro est demandé au navigateur** : au premier toucher, sa fenêtre d'autorisation s'ouvre (rien n'est écouté avant) ; une fois autorisé, plus de question. Refusé, ou bloqué auparavant (le navigateur ne redemande plus), le bouton dit où le réautoriser : les réglages du site (le cadenas ou ⓘ à gauche de l'adresse) ; sans micro, il le dit aussi.

### Mode cueillette (module optionnel)

*Réglages → Mode cueillette.* Activé automatiquement si l'appareil contient déjà des récoltes, désactivé sinon. Désactivé, un lieu est simplement « des plantes vues ici » (abondance, notes) ; rien n'est effacé. Activé :

- journal de récolte, qualité (★), « Récolté aujourd'hui », bouton « + Récolte » ;
- badges **En saison** (récolté à ±15 jours de la date, une année quelconque) et **Bientôt** (dans les 30 prochains jours) ;
- **jamais de récolte cochée d'office** : dans « Noter ici », « Noter aussi une récolte aujourd'hui » est décoché à chaque ouverture (cochée pour une plante, la case ne passe pas à la suivante), comme « Récolté aujourd'hui » pour une plante ajoutée à un lieu. Pour une plante que nos sources disent toxique (liste B ou parties toxiques de l'ANSM, TPPT « toxique » ou plus, plante toxique d'une confusion), dont les données de toxicité ne se lisent pas, ou **protégée là où elle est notée** (protection nationale, ou arrêté de la région ou du département du point), cocher la récolte ouvre d'abord un **avertissement à lire**, avant que rien ne soit noté : son titre dit ce qui l'arrête (« Plante toxique : récolte déconseillée » ; « Parties toxiques : récolte déconseillée » quand seules des parties le sont, comme le fruit du laurier sauce ; « Espèce protégée : cueillette interdite »), puis le verdict de la plante (la même pastille que sur sa fiche et ses cartes, ci-dessous), chaque raison avec sa source et la partie qu'elle nomme, la conduite à tenir (Centre antipoison, 15, 112). « Noter sans récolte » est le choix proposé ; « Noter la récolte quand même » ne s'active qu'une fois « J'ai lu cet avertissement » coché ; « Annuler » ne note rien. Dans l'éditeur d'un lieu, « Récolté aujourd'hui » et « Ajouter une récolte » ouvrent **le même avertissement**, dans un volet à lui — la plante y est déjà notée : pas de « Noter sans récolte », « Annuler » d'abord, avec le focus — jamais la boîte `confirm()` du navigateur, dont le « OK » notait la récolte. Une plante qui n'est que du côté comestible d'une confusion (l'ail des ours) n'ouvre pas d'avertissement : ses sosies sont rappelés dès qu'elle est notée (ci-dessous).

**Les plantes à confondre, avec ou sans le mode** : noter une plante avec « Noter ici » rappelle toujours les plantes toxiques avec lesquelles elle est confondue (« Ne pas confondre avec : Colchique (mortel) » pour l'ail des ours), et une plante ouverte dans l'éditeur d'un lieu ou d'une liste montre toujours son encadré « Peut être confondue avec… » (ci-dessous). Le mode ne règle que ce qui tient au journal de récolte.

### Données ouvertes croisées : interactions, climat, pollens, zones naturelles

GeoFlora croise la flore avec des API ouvertes appelées directement par le navigateur, sans clé (vérifié depuis le site déployé). Chacune est un **module** (*Réglages › Modules*) ; désactivé, il n'est jamais appelé. Les réponses sont gardées en cache (IndexedDB).

- **Pollinisateurs et interactions** (bloc de la fiche, module GloBI) : ce que [GloBI](https://www.globalbioticinteractions.org/) recense pour l'espèce, regroupé par rôle — pollinisateurs et visiteurs des fleurs, ce qui la mange ou la parasite (chenilles, pucerons, rouilles…), symbioses (mycorhizes), ce qu'elle-même parasite, autres — et par groupe (abeilles et bourdons, syrphes, papillons, coléoptères, champignons…). Trois styles au choix en mode King : **tableau** (par défaut : espèce, groupe, nombre de mentions), **liste** (groupes puis espèces) ou **réseau** (la plante au centre, chaque partenaire coloré par groupe et dimensionné par ses mentions). Chaque rôle est un sous-bloc. Source : nombre de mentions et d'études.
- **Climat et pollen** (bloc de la fiche, module Open-Meteo) :
  - *Niche climatique* : le climat (température moyenne annuelle, pluie annuelle ; ERA5 via Open-Meteo, deux ans) de 24 occurrences GBIF de l'espèce réparties en France, en nuage de points ; le cadre réunit 80 % d'entre elles. « Me situer » ajoute votre position (arrondie à 100 m) : dans sa niche ou non, et le diagramme climatique de chez vous (10 ans).
  - *Altitude* : sous la niche, l'altitude à laquelle l'espèce a été observée en France — « le plus souvent entre 340 m et 1 260 m » (10 % à 90 % des occurrences), les extrêmes, et combien des occurrences GBIF la donnent (le champ `elevation`, rempli ou non selon les observateurs ; rien sous 5 valeurs). Avec « Me situer », votre altitude (celle d'Open-Meteo pour votre position) : dans cette tranche, plus bas ou plus haut.
  - *Pollen aujourd'hui* : pour les plantes dont le modèle européen CAMS prévoit le pollen (aulne, bouleau, graminées, armoise, olivier, ambroisie), le niveau du jour autour de vous.
- **Autour d'un lieu ou d'un point** (panneau d'un endroit sur la Carte et dans Mes plantes ; « Ici : zones naturelles… » dans la fiche d'un point de la carte, appui long) :
  - *Zones naturelles* (module IGN – zones naturelles au point, API Carto) : ZNIEFF I et II, sites Natura 2000 (habitats, oiseaux), parcs nationaux et régionaux, réserves naturelles qui contiennent le point, avec leur fiche INPN ;
  - *Plantes vues ici* (iNaturalist, observations validées à moins de 500 m) : les plus observées, celles de la flore ouvrent leur fiche, celles du lieu sont signalées ;
  - *Pollens aujourd'hui* (CAMS via Open-Meteo) et *Climat du lieu* (diagramme : pluie par mois en barres, température en courbe, moyennes sur 10 ans, ERA5).
- **Usages et cuisine sauvage** (bloc de la fiche, rubrique Usages) — la prudence d'abord, chaque ligne avec sa source et la partie de la plante concernée ; l'app ne dit jamais qu'une plante est « comestible » (ni la fiche, ni les cartes de Découvrir, qui nomment la partie consommée selon l'Anses, et seulement pour l'espèce que la source nomme, jamais par son genre) :
  - *Prudence* : la pastille du verdict de la plante (ci-dessous), puis chaque raison à son niveau : Pharmacopée française, **liste B** de l'ANSM (plantes dont les effets indésirables potentiels l'emportent sur le bénéfice attendu) et parties toxiques citées par la **liste A** ; toxicité de la base **TPPT** d'Agroscope (plantes toxiques d'Europe centrale : niveau, parties toxiques, principales toxines), en français — « cancérogène » (au niveau « toxique »), « œstrogénique », « seulement les plantes infestées », et « toxicité pour l'humain inconnue » quand la base ne la donne pas (aucun niveau) ; les parties traduites terme à terme (« sommités fleuries », « herbe ») ; le texte anglais de la base reste à côté (`levelEn`, `partsEn`, au survol) ; risque de confusion (Anses), à la gravité de la paire, des deux côtés (la plante toxique elle-même : « Plante mortelle, confondue avec Carotte sauvage », même sans donnée ANSM ni TPPT) ; espèce protégée ou cueillette réglementée (INPN) ; puis la conduite à tenir (Centre antipoison, 15, 112). Ces données sont dans `data/safety.json`, construit en CI (`scripts/build-safety.mjs`) et disponible hors ligne. Une source se rattache à une plante par son nom accepté, ou par un synonyme qu'une seule plante porte : un synonyme partagé (« Vicia parviflora », porté par trois plantes) ne rattache à aucune, avec un avertissement dans le journal, sauf correspondance relue à la main (`NAME_LINKS` : « Ranunculus ficaria » est la Ficaire printanière, *Ficaria verna*, qui retrouve son alerte TPPT) ; l'espèce passe avant l'hybride qui commence par son nom. La liste B « Senecio sp. » couvre aussi les jacobées (*Jacobaea*, séparées de *Senecio*, dont le séneçon jacobée), « listée sous Senecio sp. » (`GENUS_SPLITS`, relu à la main). Une source injoignable garde ses entrées précédentes, relues avec ces règles. Sans aucune donnée de toxicité, la Prudence le dit (« Aucune donnée de toxicité dans nos sources (ANSM, TPPT) : cela ne veut pas dire qu'elle est comestible ni sans danger ») ; les usages sont toujours titrés « non vérifiés ».
  - *Usages rapportés* : usages déclarés sur Wikidata (alimentation, médecine traditionnelle, autres) et, pour la liste A de l'ANSM, les parties utilisées ;
  - *Parties et produits* (tableau ou liste) : ce que l'on tire de la plante et de quelle partie (Wikidata) ;
  - *En cuisine* : plats qui l'utilisent (Wikidata) et recettes de Wikibooks (module « Wikibooks (recettes) ») ;
  - *Pour aller plus loin* : PFAF (identifiant Wikidata), monographies de l'Agence européenne du médicament, Pharmacopée française.
- La **floraison observée** (iNaturalist, observations annotées « en fleurs » / « en fruits » en France) était déjà dans le bloc Calendrier, à côté de la floraison Baseflor.

### Un verdict par plante

Chaque plante a **un seul verdict** (`app/core/danger.js`), décidé au même endroit pour la fiche, les cartes de Découvrir et des mini-applications, « Noter ici » et l'éditeur d'un lieu : une plante a la même couleur et le même mot partout. Il réunit la toxicité (base TPPT d'Agroscope, listes A et B de l'ANSM), les confusions de l'Anses et des Centres antipoison (des deux côtés) et la protection (INPN : en France, ou au point quand on le connaît — là où elle est notée, autour du lieu d'une partie). Chaque raison a son niveau, et le verdict est celui de la plus grave, avec son mot :

- **mortel** (rouge plein) : une confusion que ces sources disent mortelle — « Mortelle » pour la plante toxique (le colchique), « Sosie mortel » pour la plante cherchée (l'ail des ours) ;
- **danger** (rouge) : TPPT « toxique » (niveau 2) ou plus — « Toxique », « Très toxique » aux niveaux 3 et 4 —, liste B de l'ANSM, plante toxique d'une confusion, sosie très toxique, espèce protégée en France ou au point (« Protégée »), données de toxicité illisibles (« Toxicité inconnue ») ;
- **prudence** (ambre) : TPPT faible ou d'effet inconnu (« Prudence »), parties toxiques de la liste A (« Parties toxiques »), sosie toxique, protection régionale ailleurs ou sans point connu (« Protégée selon le lieu »), cueillette réglementée (« Réglementée ») ;
- **à savoir** (neutre) : menacée en France (Liste rouge, « Menacée ») ;
- rien dans nos sources : aucune pastille — ce qui ne veut jamais dire « sans danger ».

Le badge de la rubrique **Alertes** compte toutes les raisons, confusions comprises, à la couleur de la plus grave (l'ail des ours : 3, rouge plein ; plus de second badge sur Usages) ; la Prudence s'ouvre sur la pastille du verdict ; chaque carte des jeux autour d'un lieu porte la même pastille et le nombre de raisons (« Sosie mortel · 3 »). La pastille (`severityChip`, `app/components/ui-kit.js`) est la même partout, celles des confusions de la fiche et de Faux amis comprises (l'étiquette « Faux ami · mortel » sous la photo aussi).

### Plantes à confondre (Anses, Centres antipoison)

Sur la fiche d'une plante comestible souvent confondue avec une plante toxique — ou de la plante toxique elle-même —, un encadré **« Peut être confondue avec… »** (rouge pour une confusion mortelle ou très toxique, et sur la fiche de la plante toxique elle-même ; « Plante mortelle, confondue avec… » sur la fiche de la toxique) donne la partie concernée, les **critères pour les distinguer** (jamais un critère cité qui dit qu'une plante se mange, comme « Seul le laurier sauce est comestible… » : un seul filtre pour la fiche, Faux amis et les cartes), les **symptômes** — ceux d'une confusion mortelle dans toutes les vues, les autres en vue Scientifique — et les sources. En vue Épurée (et dans l'éditeur d'un lieu ou d'une liste), une ligne par confusion, le reste sur demande ; une confusion mortelle y garde, hors du pli, une ligne « Symptômes : … » (en entier une fois dépliée). Sous l'encadré, la conduite à tenir : **Centre antipoison** ([centres-antipoison.net](https://centres-antipoison.net/), la liste officielle des centres et de leurs numéros), le **15** ou le **112** en cas de détresse vitale (liens d'appel, utilisables hors ligne) ; la même consigne accompagne les avertissements de « Noter ici » et le bandeau de la Cueillette prudente. Exemples : ail des ours ↔ colchique et muguet, consoude ↔ digitale, gentiane jaune ↔ vérâtre, carotte sauvage ↔ œnanthe safranée, sureau noir ↔ sureau yèble, châtaignier ↔ marronnier d'Inde.

Les données (`data/lookalikes.json`, 16 confusions) ne reprennent **que** les confusions et critères publiés par l'Anses et les Centres antipoison : aide-mémoire *Plantes toxiques et plantes comestibles : attention aux confusions !* (2020), *Vigil'Anses* n°8 (2019), articles de l'Anses sur le colchique et l'ail des ours (2025), « gare aux confusions » (2020) et les plantes de l'été (2022). Un genre entier (« Digitalis sp. ») y est noté par son seul nom. Le fichier est inclus dans l'application : l'avertissement fonctionne hors ligne. Le jeu **Faux amis** (mini-application) en fait ses cartes.

**Gravité.** Trois niveaux : **mortel** quand ces sources le disent ; **très toxique** (`grave`, `severityFrom: "tppt"`) quand la plante toxique est au niveau le plus haut de la base TPPT d'Agroscope (« very strong toxic », très fortement toxique) — grande et petite ciguë, muguet, arum, cytise, laurier rose, datura ; **toxique** sinon. Mortel (rouge plein) et très toxique (rouge) passent en tête des listes et de la Cueillette prudente, et se disent dans les messages (« Grande ciguë (très toxique) ») ; la fiche cite la base TPPT comme source de cette gravité. Le laurier rose (TPPT 4) et le laurier cerise (TPPT 2) sont deux paires. Quand les sources citées ne donnent pas de critère pour distinguer les plantes, l'encadré le dit (« Nos sources ne donnent pas de critère pour les distinguer : en cas de doute, ne la cueillez pas »).

**Liste de référence.** `data/confusions-reference.json` liste les confusions que l'app doit signaler, chacune avec son statut : **publiée** (dans les sources citées : elle doit figurer dans `lookalikes.json`, à sa gravité au moins — `scripts/check-confusions.mjs` le vérifie en CI), ou **à vérifier** (une piste — ciguë vireuse ↔ carotte sauvage, panais, céleri ; grande ciguë ↔ carotte, cerfeuils ; petite ciguë ↔ cerfeuil ; œnanthe safranée ↔ céleri, panais, persil ; arum ↔ ail des ours ; digitale ↔ bourrache ; bryone ↔ tamier, asperge sauvage ; vérâtre ↔ ail victorial ; berce du Caucase ↔ berce commune — qu'aucune source lue n'a encore confirmée : elle n'est montrée à personne, et la CI refuse qu'elle le soit). `gaps` y note, pour une confusion mortelle ou très toxique, les critères ou symptômes que les sources citées ne donnent pas. Le champ `review` dit ce qui a été relu et quand : le 2026-10-13, les publications de l'Anses et des Centres antipoison (anses.fr, vigilanses.anses.fr, centres-antipoison.net) n'ont pas pu être lues depuis l'environnement de travail ; les pistes attendent cette lecture, puis l'avis d'un Centre antipoison.

**Retrouver la plante sous ses noms.** Les noms se comparent sans auteur, sans casse, « × » valant « x » : un mot seul, même suivi d'un auteur abrégé (« Colchicum L. »), est le genre entier (un auteur écrit en entier, « Colchicum Hill », serait lu comme une épithète : `scripts/check-data.mjs` refuse toute écriture qui n'est pas le nom accepté de la flore) ; le mot qui suit le genre est l'épithète, même écrit avec une majuscule (« molopospermum Peloponnesiacum »). Un nom qui n'est qu'un synonyme désigne la seule plante qui le porte, jamais une autre dont c'est le nom accepté : « Molopospermum peloponnesiacum », ancienne graphie, est bien le Couscouil (*M. peleponnesiacum* dans TAXREF), et l'avertissement « Aconit napel (mortel) » le suit, sur sa fiche, dans « Noter ici » et dans un lieu. `scripts/check-data.mjs` exige malgré tout le nom accepté tel qu'écrit dans la flore. Dans Autour et Découvrir, une observation iNaturalist d'un hybride (« Heracleum mantegazzianum × Heracleum sphondylium ») n'est jamais prise pour l'espèce de son premier parent, qui garde ses alertes.

**Jamais « rien » faute de données.** Si `lookalikes.json` ou `safety.json` ne se lit pas (première visite sans réseau, fichier abîmé ou vide), aucun écran ne conclut « aucune confusion » : l'encadré, la Prudence, le compteur de la rubrique Alertes (et la pastille « Toxicité inconnue », rouge), les cartes de Découvrir, la Cueillette prudente, « Noter ici » et l'éditeur d'un lieu disent « Liste des confusions indisponible… » ou « Données de toxicité indisponibles pour le moment : ne consommez aucune plante sans vérification » ; l'encadré, la Prudence et la Cueillette prudente ont **Réessayer** (un fichier en échec est redemandé), « Noter ici » renvoie à la fiche, et un nouveau chargement de la fiche ou de Découvrir redemande le fichier. Et quand la liste ne cite pas la plante, la fiche dit « Aucune confusion de notre liste (Anses, Centres antipoison) ne concerne cette plante : cela ne garantit pas l'absence de risque. »

### Contexte et passerelles Flore ⇄ lieux

L'application retient où vous en êtes dans chaque partie, aussi après un rechargement :

- **Flore** : la recherche (texte, filtres, tri) et la plante ouverte. L'onglet Flore rouvre la plante ; touché une seconde fois, il revient à la liste. Rouvert ailleurs (Carte, lien), la recherche est restaurée : les flèches ‹ › d'une fiche parcourent les mêmes résultats.
- **Mes plantes** : la collection ou l'endroit ouvert et la plante à côté. **Carte** : le lieu choisi et le filtre de plantes.
- **Collection courante** : la dernière collection ou le dernier lieu ouvert, ou celui où une plante vient d'être rangée (« Ajouter à… ») — jamais un parcours en cours (sa marche y range déjà ses plantes).

Passerelles :

- d'une **fiche** : « Carte » (l'onglet Carte filtré sur la plante, avec sa répartition GBIF) et « + *collection courante* », qui ajoute la plante d'un geste à la collection courante (le bouton disparaît une fois la plante ajoutée) ; deux actions de la barre, à afficher ou non par mode ;
- d'une **collection ou d'un lieu** : « Voir dans Flore » (Mes plantes, éditeur de collection, fiche d'un lieu sur la Carte) ouvre la recherche filtrée sur ses plantes ;
- des **résultats Flore** : l'icône carte ouvre la Carte limitée à mes lieux qui ont une plante de ces résultats (puce « Recherche Flore » pour l'enlever) ;

**Les données de la fiche parlent à ses cartes.** Quand la fiche a une carte (épinglée ou dans la fiche), ses valeurs se touchent (soulignées en pointillés) et la carte les montre :
- une **région** ou un **département**, un **mois**, une **année**, un **type de relevé** (spécimens d'herbier…), une **source** (jeu de données) : la carte n'affiche plus que ces occurrences GBIF (tuiles GBIF filtrées, présences aux coordonnées sans problème connu) ; une région ou un pays recadre la carte sur ses occurrences ;
- un **pays** de la répartition dans le monde, quand la liste GBIF donne son code : ses occurrences, carte dézoomable jusqu'au monde ;
- une occurrence **Près d'ici**, une **photo** ou une **planche d'herbier** géolocalisée (📍 sous l'image), un de **mes lieux** : un point rouge nommé, la carte y vole ;
- **Plantes à confondre** : « Comparer sur la carte » ajoute les occurrences GBIF de la plante à confondre, en violet, à côté de celles de la plante.
Une puce sur la carte dit ce qui est affiché (« Filtre : Occitanie », « Comparaison : Colchique d'automne ») ; ✕, ou toucher à nouveau la valeur, l'efface. Sans carte dans la fiche, les valeurs restent du texte.

Le **cadrage** d'un bloc Carte suit ses réglages : « Automatique » (par défaut) cadre le cercle autour de moi quand les observations proches sont affichées, sinon mes lieux et leurs plants, sinon le monde pour une répartition GBIF mondiale, sinon la France ; « Monde entier » permet de dézoomer jusqu'au planisphère. Chaque changement de réglage recadre la carte ; la déplacer à la main reste jusqu'au réglage suivant.

### Mes plantes : favoris, listes et lieux

Une **collection** est un ensemble de plantes, avec ou sans position :

- **Favoris** ♥ : un toucher sur ♡ dans la liste de recherche ou sur la fiche d'une plante.
- **Listes** (« Mellifères », « À chercher cet été »…) : sans position. « Ajouter à… » sur une fiche plante coche/décoche les collections et en crée une à la volée.
- **Lieux** : une liste avec une position GPS, visible sur la carte (voir ci-dessous). « 📍 Ajouter une position » transforme une liste en lieu ; « Retirer la position » fait l'inverse.
- **Noms** : dans chaque champ de nom de collection (« Ajouter à… → Nouvelle collection », éditeur d'une nouvelle collection), les collections existantes qui correspondent sont proposées ; en choisir une y ajoute la plante au lieu de créer un doublon.

**Espèces protégées** : la fiche plante, le panneau d'une plante dans un endroit et le message de « Noter ici » signalent une **protection** (bandeau rouge) ou une **cueillette réglementée** (bandeau orange) là où l'on est, ainsi que la liste rouge. Le territoire est celui du point GPS de l'endroit (département, région, ancienne région), sinon « Ma région » choisie dans *Réglages* ; les statuts d'ailleurs restent consultables. Un statut n'est **national** que s'il est une protection ou une liste rouge nationales, ou s'il n'a ni région ni département (aucun code « FR-… ») et vaut pour la France ou la France métropolitaine : la protection et la liste rouge d'Île-de-France ne s'affichent plus « ici » en Provence. Les **réglementations** (`REGL`) sont classées par code (`app/core/regulation.js`), la même règle pour le badge, la Prudence, le filtre de Flore, le bloc statut et les messages : seule la **cueillette en métropole** compte comme « Cueillette réglementée » — arrêté d'un département, liste nationale (article 3), ou espèce dont un préfet peut réglementer la cueillette (PV1, expliquée dans le bloc statut) ; le **commerce** (annexes CITES) a sa ligne dans le bloc statut ; les listes d'**outre-mer** (PV97, Nouvelle-Calédonie, SPAW) et d'**espèces envahissantes** ne disent rien de la cueillette ici. Chaque bloc renvoie aux textes officiels sur l'INPN. La recherche a un filtre « Protection et menace ».

**Calendrier** sur la fiche plante, chargé automatiquement : floraison Baseflor (hors ligne, dans le jeu de données) et observations iNaturalist en fleurs / en fruits en France, mois par mois, chaque ligne avec sa source. Ce sont des indications de floraison et de fructification, **pas des dates de cueillette**.

L'onglet **Mes plantes** les regroupe : collections, puis endroits triés par distance. Une collection à laquelle on ajoute des coordonnées GPS devient un endroit ; toucher un endroit ouvre la carte cadrée sur son point et toutes ses plantes. Toucher l'en-tête d'une collection (Favoris, collection, endroit) **déplie la liste de ses plantes** (ce qui est déplié est mémorisé) ; un endroit montre aussi **sa carte**, avec chacune de ses plantes. Toucher une plante ouvre **sa fiche à côté**, avec en bas la barre plante précédente / suivante de la collection : sur ordinateur, trois panneaux (liste · carte de l'endroit · fiche), comme dans Flore : chacun a son en-tête, se **redimensionne** en glissant son séparateur (← → au clavier, Début / Fin, double-clic ou Entrée : largeur par défaut) et se **replie** (« ») en une fine colonne titrée ; la liste garde sa largeur quand une plante ou un endroit s'ouvre à côté (rien ne bouge sous le doigt) et un panneau « Aperçu » attend tant que rien n'est ouvert ; sur tablette, la carte et la fiche se partagent la colonne de droite ; sur téléphone, la carte s'affiche dans l'endroit déplié et la fiche glisse par-dessus la page. L'adresse garde ce qui est ouvert (`#/collections?c=…&plant=…`) : le retour du navigateur revient à la vue précédente. Sur chaque ligne, **Partager** envoie un lien qui contient la collection (la position exacte d'un endroit, après confirmation) et l'icône crayon (ou carte, pour un endroit) ouvre la collection pour la modifier. Le rappel « Sauvegardez vos collections » est en bas de la page. Les modifications sont **enregistrées automatiquement**. Dans la recherche, le filtre **Mes plantes** limite les résultats aux favoris, à une liste, à un lieu ou à « dans un de mes lieux ».

**Partager** sans serveur :

- une plante : lien `#/plant/<id>` ;
- une recherche (famille, statut…) : bouton *Partager* au-dessus des résultats, l'URL contient les filtres ;
- une liste ou un lieu : le lien contient la collection elle-même (`#/shared?d=…`, JSON compressé deflate + base64url, ~200 caractères pour 30 plantes). Notes et journaux de récolte ne sont **jamais** inclus ; pour un lieu, la position exacte l'est (confirmation demandée), ainsi que celle de chaque plante — **chaque occurrence** d'une plante notée plusieurs fois, jusqu'à ~100 km du point du lieu. Le destinataire voit un aperçu — **la carte cadrée sur tout le lieu ou le parcours**, chaque plante à sa place, la liste avec « × 2 » pour une plante notée deux fois — et peut l'enregistrer comme nouvelle collection, avec toutes ses occurrences.

Partout où des plantes sont listées (lieu ou collection, ajout d'une plante, « Noter ici », fiche du lieu sur la carte, lien partagé), chaque nom est précédé de la **miniature de sa photo**, comme dans les résultats de recherche ; les photos déjà vues restent disponibles hors ligne (cache du service worker, 400 images).

### Carte : recherche, réglages, infos d'un point

Sur **toutes les cartes** de l'app (Carte, Découvrir, fiche plante, lieux, parcours, lien partagé) :
- **Les périmètres** — le cercle d'« Autour », un département, une région, la France — sont tracés à chaque fois : **leur bordure seule, en vert clair**, avec une ombre portée discrète (pas de fond : la carte reste visible). Ceux de la France (et ceux d'un département ou d'une région quand l'IGN ne répond pas) viennent des contours embarqués dans l'app : départements, régions et France métropolitaine ont chacun le leur, sans aucun bout de frontière intérieure.
- **La plante choisie** (la plante en vue de Découvrir, l'espèce touchée dans « Autour », la valeur touchée dans une fiche) : **sa photo, en grand**, dans un rond rose et or qui rebondit en arrivant, une onde au moment où il se pose. Une plante sélectionnée dans un lieu grandit et rebondit de même, cerclée de vert (trois ondes, puis immobile).
- **Survoler une plante** (la toucher, sur un téléphone) l'agrandit et **allume aussi les autres points en vue de la même espèce** — observations, plante choisie, plantes des lieux, reconnues par leur nom scientifique — ; **les autres pastilles ne changent pas** (ni estompées ni déplacées). L'allumage tient quand la carte redessine ses points (une sélection, une photo qui arrive). Une plante sélectionnée allume ses autres emplacements (cerclés d'or, avec un halo).
- **Sur un téléphone**, un premier toucher sur un point montre sa petite fiche et allume ses semblables ; un second ouvre l'observation (la première fiche touchée le dit, une fois par appareil ; ensuite seulement aux lecteurs d'écran) — l'app n'est jamais quittée d'un seul toucher.
- **Des cartes calmes** (la règle de toutes les cartes : `gf-map` et ses pages) : **rien n'est écrit par-dessus la carte** hors ses commandes (zoom, boussole, couches, Me localiser, ✎, la puce du rayon, « Observations autour ») et ses crédits, petits — ni bandeau, ni pastille, ni compte, ni « Chargement… ». Ce qui mérite d'être su va **là où on le cherche** : l'**état** de la carte (fonds IGN coupés, 3D repassée en 2D et pourquoi, vue à plat faute de relief, espaces protégés en vue, une source injoignable) en lignes courtes dans le panneau **▦ Carte** (« État », dans « Affichage », avec le lien utile), et **dit une fois** par la seule zone d'annonce de la carte (invisible, polie, pour les lecteurs d'écran : chaque chose une fois, pas à chaque redessin ni pour chaque carte de la page). Un chargement : rien sous 400 ms, puis un fin trait en haut de la carte (sans texte). Seule une **action que vous venez de faire** et qui échoue (« Me localiser » refusé, une adresse sans résultat, un point dont la plante n'est pas là, « Vue 3D » impossible ici) affiche **un petit message bref** (moins de 3 s, au premier plan, jamais deux à la fois) ; une panne en fond (tuiles, iNaturalist, relief) jamais. Le même échec redemandé est redit, et ce qui change pendant que le panneau ▦ Carte est ouvert est dit par le panneau lui-même. Un message qui porte une action (« Annuler » d'un parcours, d'une capture) n'est pas un échec : il dure plus longtemps, reste tant qu'il est survolé ou qu'il a le focus, et aucun message de carte ne prend sa place. Un geste à connaître (appui long, ✎, « touchez encore ») est dit **une seule fois par appareil**, refermable, hors de la carte (au-dessus ou en dessous) ou dans le panneau qu’il concerne, jamais sur ses commandes, puis reste dans le titre et la description des commandes (`app/core/hints.js`, `app/core/toast.js`).
- **Chaque pastille de plante apparaît avec sa feuille**, et sa photo s'y pose (en fondu) une fois chargée ; une photo qui échoue laisse la feuille.
- **La petite fiche** d'un point (photo, noms, date, lieu) a une bordure fine et transparente ; tous les points d'une plante choisie l'ont, regroupés ou non.
- Les effets ne déplacent que ce que la carte graphique compose sans redessiner (échelle, rotation, opacité) : ombres immobiles, aucune animation en boucle sur de nombreux points, les points SVG changent d'un coup ; les groupes se refont une fois le zoom (ou le vol vers une zone) fini, sans rejouer leur entrée ; tout est figé si le système demande moins d'animations.

- **Barre de recherche** en haut de la Carte : adresse, commune ou lieu-dit avec suggestions (géocodage IGN) ; le résultat choisi est centré, devient le **repère** de la carte (un choix déjà fait : sans question) et sa fiche s'ouvre.
- **▦ Carte, la maison des cartes** (au bout de la barre, ou bouton rond sur les autres cartes) : un seul panneau pour tout ce qui règle l'affichage, **le même sur toutes les cartes et dans Réglages › Cartes** (`app/components/gf-map-options.js` : `scope="map"` dans le panneau d'une carte, `scope="defaults"` dans Réglages) — **Affichage** (2D ou 3D, les options de la 3D repliées), **fond** (plan IGN, photos aériennes, satellite (SPOT), ci-dessous), **couches** de terrain (parcelles cadastrales, courbes de niveau), **toutes les couches de l'IGN** et les **règles de cueillette** (forêts publiques ONF, parcs nationaux, réserves naturelles nationales et régionales, arrêtés de protection de biotope — données INPN / PatriNat servies par l'IGN) ; s'y ajoutent ce qui est à cette carte seule : son **État**, la répartition GBIF de la plante de la Carte, les espaces protégés en vue, sa **légende** et ses **sources**.
  - **Le fond** (`app/core/backgrounds.js`, pur ; dans le panneau ▦ de chaque carte comme dans Réglages › Cartes) : trois boutons — **Plan IGN**, **Photos aériennes**, **Satellite (SPOT)** — et, sous les photos, leur **« Date des photos »** : « La plus récente » (le défaut : les photos de chaque endroit les plus récentes), **une année** de 2024 à 2000, **une période** (2021-2023, 2016-2020, 2011-2015, 2006-2010, 2000-2005) ou des **photos historiques** (1950-1965, 1965-1980, 1980-1995) ; sous le satellite, **« Année des images »** (SPOT 6-7, 2025 à 2013, la plus récente d'abord). Les photos d'une année ou d'une période ne couvrent que les départements photographiés alors : ailleurs, **les photos les plus récentes, en gris pâle**, remplissent la carte — pâles, jamais prises pour les photos historiques en noir et blanc (une note sous le choix le dit, décrivant la liste et annoncée au lecteur d'écran quand elle paraît ; en 2D les filtres `grayscale`, `contrast` et `brightness`, en 3D `raster-saturation`, `raster-contrast` et `raster-brightness-min` de MapLibre, les mêmes gris). À la limite de ce qui a été photographié, une tuile en partie hors de l'année montre, pour cette part, ce que le service y met, pas les photos grises : les années et les périodes ne sont servies qu'en JPEG, sans transparence (les historiques, en PNG, laissent voir dessous). Les identifiants, formats (les historiques en PNG, avec leur style `BDORTHOHISTORIQUE`) et zooms de chaque couche sont ceux du catalogue de l'IGN (`data/ign-catalog.json`, vérifiés par `tests/unit/backgrounds.test.mjs`) ; une couche d'une année se montre en 2D dès un zoom avant son premier (6 pour la plupart : dès le 5, la France entière sur un téléphone, ses tuiles réduites), en 3D dès le sien ; plus loin, seules les photos grises, ce que dit la note (« De très loin aussi… »). SPOT jusqu'au zoom 17 (au-delà, agrandie). Les dates sont des listes natives, chacune avec son étiquette : au clavier, au lecteur d'écran, sur un téléphone de 390 px sans défilement de côté. **Les noms par-dessus** : sur les photos aériennes (de toute date) et sur les images SPOT, une case à cocher **« Afficher les noms : villes, routes, rivières, forêts »**, cochée par défaut, dessine trois couches de l'IGN par-dessus le fond **et par-dessus toutes les couches choisies** : « Routes » (`TRANSPORTNETWORKS.ROADS`), « Hydrographie » (`HYDROGRAPHY.HYDROGRAPHY`) et « Noms » (`GEOGRAPHICALNAMES.NAMES`), dans cet ordre, les noms dessus — en PNG, leurs identifiants, style et zooms ceux du catalogue (vérifiés par le même test), dès leur premier zoom natif (6), pas avant, et jusqu'au zoom 19, un après leur dernier (18) : plus près, leurs mots seraient agrandis quatre ou huit fois ; sous la répartition GBIF et les carreaux d'observations. Ce n'est pas une couche : ni parmi les couches affichées ni dans le catalogue, sans opacité à régler. Une couche choisie qui est l'une des trois (« Cours d'eau » d'une disposition, `layers=hydro` ; « Hydrographie », « Routes » ou « Noms » du catalogue) n'est dessinée qu'une fois, à sa place parmi les couches et à son opacité ; décochée, les noms la redessinent par-dessus. Sur le plan IGN, qui a ses propres noms, pas de case (comme pas de date) et rien de demandé ; le choix fait reste, retrouvé de retour sur les photos ou SPOT. En 3D, les trois mêmes sources de MapLibre, au-dessus des autres couches de l'IGN, une seule fois chacune.
  - **Des réglages communs à toutes les cartes** (« Réglages communs à toutes les cartes », en tête du panneau) : changés dans le panneau ▦ de n'importe quelle carte ou dans Réglages › Cartes, **toutes les cartes ouvertes suivent aussitôt**, en 2D comme en 3D (et les autres onglets) ; gardés sous les clés d'avant (`geoflora.mapLayer` : fond et couches — le fond, une chaîne : `plan` et `photo` comme avant, `photo:2016-2020`, `spot:2020` ; une valeur inconnue, d'une autre version, revient aux photos ; les noms par-dessus, seulement décochés : `names: false` —, `geoflora.overlayOpacity` : opacités, `geoflora.ignLayers` : couches du catalogue ajoutées ; `app/core/map-settings.js` : `mapLook()`, `setMapLook()`, l'événement `change` de `mapLookEvents`).
  - **Une carte peut avoir son propre fond** (`gf-map` : sa propriété `look`, l'événement `look-change`) : une case de disposition libre dont l'adresse dit son fond, ses noms ou ses couches (`base=`, `annee=`, `noms=`, `layers=`, `opac=`), un bloc Carte de la fiche réglé avant (sa configuration, `look` : son fond, l'année comprise, ses noms). Elle le garde quand les réglages communs changent (ce qu'elle ne dit pas les suit) ; son panneau le dit — « Cette carte a son propre fond » (ou son propre choix des noms, ses propres couches) — et ce qu'on y change est à elle seule ; **« Revenir aux réglages communs »** le lui rend (pas à une case dont l'intention le donne, `protege`, `terrain` : son panneau le dit). La 2D ou la 3D reste un choix commun ; une case qui l'écrit (`3d=`) la montre fixée, avec **« Suivre le réglage commun »** (pas avec l'intention `relief`).
  - **Toutes les couches de l'IGN** (`app/components/gf-ign-layers.js`, dans les options de toutes les cartes) : en tête, les couches **affichées** par-dessus le fond, de la plus haute à la plus basse, chacune avec son **opacité** (curseur) et des boutons pour la monter, la descendre ou la masquer — ordre et opacités gardés d'une visite à l'autre ; puis « Parcourir les couches de l'IGN… » ouvre tout le catalogue de la Géoplateforme : une **recherche** sans accents (titre, description, mots-clés, catégorie, années et lieux des séries), « **Recommandées pour la botanique** », et l'**arbre** des catégories et sous-catégories avec leurs nombres, replié (les lignes d'une sous-catégorie ne sont construites qu'à son ouverture, 40 à la fois). Chaque ligne : une case à cocher, le titre, une description courte ; une série a son sélecteur (année, département, ville…) — changer de version remplace la couche affichée ; « Détails » donne la description entière, les zooms, la source et la licence, l'identifiant, la légende et une **tuile d'aperçu** (une seule, demandée à l'ouverture, là où la couche a des données ; jamais module coupé). Les couches de l'app (forêts publiques, parcs nationaux…) s'y retrouvent cochées comme dans leurs rubriques. Le catalogue : la copie livrée avec l'app (`data/ign-catalog.json`, voir *Catalogue des couches de l'IGN*) s'affiche aussitôt, hors ligne aussi ; vieille de plus d'un mois, elle est mise à jour en fond depuis le service, sans jamais disparaître si celui-ci échoue (« Hors ligne : catalogue gardé du … », ou « Le catalogue de l'IGN ne répond pas » avec **Réessayer**) ; module « IGN – fonds de carte » coupé, la liste reste consultable et une couche ajoutée n'affiche que les zones déjà vues ; une couche ajoutée rejoint la liste, se coche et se décoche comme les autres, sur toutes les cartes, et reste là d'une visite à l'autre (hors ligne aussi, ses tuiles déjà vues).
- **Espaces protégés** : dès le zoom 11, sur toutes les cartes (Carte, éditeur d'un lieu, fiche plante, lien partagé), le panneau ▦ Carte nomme, sous « Règles de cueillette », le **parc national** (cœur), la **réserve naturelle** nationale ou régionale ou l'**arrêté de protection de biotope** que la vue touche, avec le lien vers sa fiche INPN : « la cueillette y est souvent interdite ou réglementée : vérifiez les règles du site » ; son « État » le résume, la zone d'annonce le dit une fois par nouvel ensemble d'espaces, et **un point discret sur le bouton ▦** le signale — rien n'est écrit sur la carte. Pas pendant le déplacement des positions. Données INPN / PatriNat interrogées sur le WFS de l'IGN (noms seulement), gardées un mois sur l'appareil ; module « IGN – espaces protégés ».
- **Appui long** n'importe où sur la carte (clic droit ; au clavier, la touche menu ou Maj + F10 sur la carte : son centre) : la carte **propose le point** — un repère fantôme (une mire en pointillé, nommée « Point proposé » et sa question pour les lecteurs d'écran) et la fiche du point qui demande **« Poser un repère ici ? »**, avec son adresse, son altitude et ses coordonnées, **« Confirmer »** (sous le focus ; Entrée sur la carte elle-même aussi, jamais sur un marqueur ou une poignée) et **« Annuler »** (Échap) ; la question est dite par la zone d'annonce de la carte (aucune autre), rien ne change avant la réponse, une nouvelle question remplace la précédente. Confirmé, le point devient **le repère de la carte** (`gf-map` : sa propriété `reference`, l'événement `reference-change`) : une **mire violette**, ni lieu (carré sur pied) ni plante (rond), nommée « Repère : ouvrir sa fiche » pour les lecteurs d'écran ; glissée ailleurs, la même question (Échap la remet où elle était, ou là où son point est allé entre-temps) ; touchée (ou Entrée, Espace), sa fiche revient. Sa fiche : l'**adresse la plus proche**, l'**altitude** (RGE ALTI®), les **coordonnées** (copiables), puis « Créer un endroit ici » (l'action proposée ensuite, sous le focus ; sans elle, la fiche elle-même), « Itinéraire » et **« Retirer le repère »** ; Échap ou ✕ la referme, le focus rendu à la mire ; la modification des positions qui commence (✎, « Déplacer » d'un panneau) la referme aussi. Ce que demande l'appui long dépend de la carte : une case de disposition libre, **« Chercher autour d'ici ? »** (sa zone ne s'y centre qu'une fois confirmé ; son repère est le centre de sa zone : la zone partie ailleurs autrement — « Autour de moi », Retour, une autre case —, il s'en va) ; en modification des positions, **« Déplacer le lieu ici ? »** (le lieu de l'éditeur, le lieu choisi de la Carte). En 3D, la vue se centre sur le repère (« Me localiser » ne la suit plus) et **tourne autour de lui** (voir *Cartes en 3D*), et les Observations autour s'y placent. La fiche d'un endroit affiche sa commune et son altitude, l'éditeur l'adresse, l'altitude et les coordonnées de son point.

Source : IGN – Géoplateforme (WMTS, WFS, géocodage, altimétrie ; gratuit, sans clé, Licence Ouverte). Adresses et altitudes déjà vues sont gardées sur l'appareil.

### Cartes en 3D

**2D ou 3D** (2D par défaut) : un seul choix pour **toutes les cartes** de l'app — la Carte (et venue de Flore), la carte de la fiche plante (et dans son panneau), les lieux de Mes plantes, l'éditeur d'un lieu, Parcours (marche et récapitulatif), Rencontres et Découvrir, le lien partagé. Il se fait au même endroit que le fond et les couches : le **panneau ▦ de chaque carte** (bouton « Carte : fond, couches, légende », rond ou au bout de la barre de recherche), section **« Affichage »** — 2D / 3D et, en 3D, les **options de la 3D** (repliées) ; aussi dans **Réglages › Cartes › Affichage des cartes** (les mêmes options, les mêmes réglages communs). Changé à un endroit, toutes les cartes ouvertes suivent aussitôt (les autres onglets aussi) ; pas de bouton 2D ⇄ 3D sur la carte elle-même (une case de disposition libre a sa bascule, qui l'écrit dans son adresse : `3d=`). Deux exceptions voulues, où le choix est affiché **grisé, avec la raison** : l'étape **« Jusqu'où part l'expédition ? »** des mini-applications reste **toujours en 2D, vue de dessus** ; sur une fiche plante, les **cartes ajoutées** en plus du bloc « Carte » principal (et la petite carte « Mes lieux ») restent en 2D — une seule carte WebGL par fiche. La « Vue 3D » d'un parcours ou d'un lieu est toujours en 3D (dit de même). Pendant la modification des positions, le bouton du panneau s'efface (la carte est en 2D le temps de l'édition) ; il revient avec « Terminé ».

En 3D, c'est **la même carte** (`gf-map`), avec les mêmes marqueurs, groupes, cercles, contours, fiches de point, panneau de couches et la même API pour les pages : seul le moteur de dessin change. MapLibre GL JS dessine ; la carte Leaflet reste dessous, cachée, comme « miroir » qui garde la vue et toute la logique (cadrages, groupes refaits au zoom, plantes visibles à partir du zoom 16, espaces protégés, vue mémorisée). Ses couches de tuiles deviennent des sources raster de MapLibre ; ses marqueurs (les éléments eux-mêmes) passent dans des marqueurs MapLibre posés sur le relief ; ses cercles, contours et fils deviennent une couche GeoJSON drapée sur le terrain. Détails : `app/components/gf-map-gl.js`, `app/core/gl-style.js`, inventaire des cartes et fonctions dans l'en-tête de `gf-map-gl.js`.

**Options** (en 3D : le panneau ▦ de chaque carte, Réglages › Cartes) :
- **Relief** (tuiles AWS Terrain Tiles, Terrarium : Mapzen, EU-DEM © Copernicus) et son **exagération** (× 1 à × 3) ; **ombrage** des pentes sous les couches ; les **courbes de niveau** de l'IGN se drapent sur le relief comme toutes les couches ;
- **inclinaison à l'ouverture** (0 à 85°) et **jusqu'à l'horizon** en tournant autour (85° : les montagnes en face, comme depuis une vallée ; MapLibre s'arrête à 60° sans qu'on le lui dise) ; navigation 3D habituelle, la même sur ordinateur et téléphone : glisser pour se déplacer, **molette enfoncée** ou clic droit (ou Ctrl + glisser) pour tourner autour et incliner — sur le côté on tourne, de haut en bas on incline —, deux doigts pour tourner et incliner, molette ou pincement pour zoomer, ou au clavier (**Maj + flèches** ; flèches pour se déplacer, + et − pour zoomer) ; la **boussole** de MapLibre (sous + et −) tourne avec la carte et la montre inclinée ; touchée, elle la remet au nord et à plat ; glissée, elle tourne et incline — la même sur les cartes en 2D, où le nord est toujours en haut ;
- **bâtiments en 3D** (tuiles vectorielles PLAN IGN de la Géoplateforme, surfaces bâties de la BD TOPO extrudées à leur hauteur, dès le zoom 15) ;
- **ciel et brume** (horizon, atmosphère au loin) ; **globe à petite échelle** (la Terre ronde en dézoomant) ;
- **plan IGN vectoriel** au lieu des images du « Plan IGN » (noms et traits plus nets ; le style, les polices et symboles de la Géoplateforme) ;
- **éclairage** : fixe, soleil de maintenant, ou soleil à l'heure choisie (heure de Paris) — la position du soleil oriente l'ombrage, la lumière des bâtiments, la couleur du ciel, et la nuit assombrit le fond.

Aussi en 3D : le même fond et toutes les couches IGN du panneau ▦ (et celles du catalogue ajoutées, à leur opacité) — la carte 3D reprend celles de sa carte 2D, réglages communs ou son propre fond —, la répartition GBIF, les vols animés vers un lieu ou une adresse (aucun si le système demande moins d'animations), plein écran, échelle, crédits en français ; l'altitude d'un point, à la demande : l'appui long (celle de l'IGN, RGE ALTI®), jamais une pastille qui suit le pointeur. Le dialogue « Vue 3D » d'un parcours ou d'un lieu est la même carte, forcée en 3D, avec la marche et l'altitude de chaque plante.

**Tourner autour du repère** : un repère confirmé (appui long, adresse choisie : voir *Appui long* ci-dessus), la vue 3D s'y centre, et **toute rotation tourne autour de lui** plutôt qu'autour du milieu de l'écran — molette enfoncée, clic droit ou Ctrl + glisser (et leur élan), deux doigts, Maj + ← →, la boussole, le lent tour des Observations autour : le repère garde sa place à l'écran (`app/core/orbit.js`, pur, testé : la nouvelle position du centre pour un cap changé, en Web Mercator — le plan de MapLibre —, appliquée à chaque mouvement de sa caméra ; la hauteur de la caméra gardée, et celle où elle regarde pendant le tour, puis son centre reposé sur le sol sans qu'elle bouge : sur le relief aussi). Une rotation déplace le centre comme un glisser : « Me localiser » ne suit plus. Le repère retiré pendant un tour, la vue s'arrête où elle est ; le lent tour des Observations autour d'un autre centre (une zone, un lieu) tourne autour du milieu. Pendant une rotation, le déplacement et le zoom autour des doigts du même geste attendent sa fin. Le bouton **« Tourner autour du repère »** (parmi les boutons ronds, en 3D et seulement avec un repère) tourne la vue de 45° à chaque appui, en douceur (d'un coup si le système demande moins d'animations), et le cap atteint est dit ; les appuis s'ajoutent jusqu'à moins d'un demi-tour d'avance (au-delà, attendus : jamais à rebours). En 3D, le repère ne se glisse pas : un nouvel appui long le replace.

**Observations autour (3D)** — bouton jumelles, avec les autres boutons de toute carte en 3D : les observations de plantes **iNaturalist** (de qualité recherche, jusqu'à 400) et **GBIF** (jusqu'à 300, sans la copie GBIF d'iNaturalist), **chacune la photo de sa plante**, la même quelles que soient les sources cochées — la photo de son taxon sur iNaturalist sous licence libre (les plantes qu'iNaturalist connaît dans le cercle, une seule demande), sinon celle de la flore (sa vignette, ou celle que sa fiche a trouvée en ligne : cherchée après le premier dessin, les marqueurs redessinés avec elle), avec son nom français ; un hybride n'est jamais pris pour une espèce : une occurrence GBIF se montre exactement comme une observation iNaturalist —, et les plantes de **vos lieux**, dans un **cercle** autour d'un centre — seulement celles qui sont dedans. Le centre : la zone de la page s'il y en a une (le cercle d'une mini-application), sinon **le repère** de la carte (un **appui long** confirmé, une adresse choisie : le cercle s'y place — retiré, le cercle reste où il est) ou le lieu sélectionné, sinon le centre de la vue — puis il reste là quand la vue bouge (« Centrer ici » le ramène au centre de la vue). Le **rayon** se choisit sur la puce en bas de la carte (« 2 km · 128 », qui se déplie) avec le même curseur à crans que l'étape « Jusqu'où part l'expédition ? » (200 m à 50 km) ; les sources (iNaturalist, GBIF) et la **densité** s'y cochent aussi. Chaque carte garde les siens (affiché ou non, rayon, sources, densité ; `geoflora.around3d`, par page ou bloc), et la Carte ne les applique jamais en 2D.

Le rendu retenu, après essais comparés en captures (`app/components/gf-map-obs3d.js`, `app/core/around3d.js`) :
- le **cercle drapé** sur le relief (le trait vert pâle sur son ombre, comme en 2D) et à son bord un **mur de lumière** translucide, plus clair à son sommet — un simple trait se perd dans une vue inclinée, le mur se lit comme un lieu ; en morceaux courts, chacun posé sur le sol là où il est ; le rayon sur une étiquette au sud ;
- les **mêmes marqueurs qu'en 2D** (photo sur sa feuille, feuille seule, la plante choisie dans son anneau rose et or), **debout sur le sol** au bout d'une fine tige quand la carte est inclinée (posés à plat vue de dessus), plus petits au loin, estompés derrière le relief ;
- les points proches à l'écran groupés en **piles de photos** avec leur nombre (jamais de bulle) ; seuls les groupes les plus proches de l'œil sont des éléments (40 sur téléphone, 70 sinon), les autres points de petites **graines** au sol dessinées par MapLibre (une couche, mises à jour par état d'objet ; le même vert pour iNaturalist et GBIF, l'or pour vos plantes) : des centaines de points restent fluides ; recalculé quelques fois par seconde pendant un mouvement ;
- touché ou survolé, un point montre **la même carte qu'en 2D** (photo et crédit, noms, date et lieu, d'où vient l'observation) ; un groupe, de loin, rapproche la vue (de près, la carte de son premier point et les noms des autres) ; une de vos plantes ouvre sa fiche ; la plante choisie d'une page (sa mise en avant) passe devant, dans son anneau ;
- la **densité** : le cercle en hexagones, une colonne par hexagone, haute de sa part du plus chargé, des verts de l'app à l'or ; touchée, combien et les plantes les plus vues ;
- à l'ouverture (et quand le centre change), un **vol doux** qui cadre le cercle, incliné, puis un lent pivot de 30° autour ; aucun si le système demande moins d'animations (la vue y saute) ; une adresse choisie, une fois la carte arrivée là où la recherche l'a menée.

Une seule carte WebGL (celle de la carte en 3D), aucune image produite ; hors ligne, les observations gardées en cache (un jour) s'affichent ; sans relief, la même chose à plat. Modules : « iNaturalist », « GBIF » (chacun coupé, sa source n'est pas demandée). **Confidentialité** : iNaturalist et GBIF reçoivent le centre du cercle (le centre de la vue, le point ou le lieu choisi) et son rayon, seulement une fois le bouton activé.

**Replis** (toujours une carte, jamais d'erreur ; chacun écrit dans l'« État » du panneau ▦ Carte et dit une fois par la zone d'annonce, jamais par-dessus la carte) : pendant la **modification des positions** (glisser des marqueurs), la carte repasse en 2D le temps de l'édition et le dit, puis revient en 3D ; **sans WebGL2**, les cartes restent en 2D (« 3D indisponible sur cet appareil ») ; si MapLibre ne peut pas se charger (hors ligne avant sa première ouverture), 2D ; module **« Vue 3D (relief) »** coupé : 3D à plat, aucune tuile de relief demandée ; module **« IGN – fonds de carte »** coupé : tuiles IGN lues dans le cache de l'appareil seulement, ni bâtiments ni plan vectoriel ; **hors ligne** : à plat, tuiles déjà vues, et la carte le dit ; relief injoignable : à plat, dit ; contexte graphique perdu : 2D, dit. Au-delà de trois cartes en 3D à la fois, les suivantes restent en 2D.

**Performance** : MapLibre (≈ 1,6 Mo) n'est chargé qu'à la première carte affichée en 3D (jamais en 2D), puis gardé par le service worker (`ON_DEMAND`) ; chaque carte en 3D a son contexte WebGL, rendu (`map.remove()`) dès qu'elle quitte la page ; les tuiles de la carte miroir ne se chargent pas pendant ce temps.

**Limites** : relief grossier (EU-DEM, ≈ 25 à 30 m) ; les hauteurs de bâtiments viennent des tuiles vectorielles PLAN IGN (attribut `hauteur` de la couche `bati_surf`, une hauteur par défaut sinon) — les adresses exactes du style et des tuiles vectorielles de la Géoplateforme (`data.geopf.fr/annexes/ressources/vectorTiles/styles/PLAN.IGN/standard.json`, `data.geopf.fr/tms/1.0.0/PLAN.IGN/{z}/{x}/{y}.pbf`) sont celles documentées par l'IGN, testées avec des tuiles simulées ; groupes et éventails sont calculés vue du dessus (à plat, ils restent justes ; inclinés, un peu écrasés).

**Confidentialité** : en 3D, `s3.amazonaws.com` (relief, module « Vue 3D (relief) ») et `data.geopf.fr` (tuiles, bâtiments, plan vectoriel, module « IGN – fonds de carte ») reçoivent la **zone de carte affichée**, jamais votre position ; aucune nouvelle origine dans la Content-Security-Policy (les deux y étaient déjà).

### Autour : les plantes observées dans un périmètre

Sur la **Carte**, le bouton **Autour** trace un cercle (5 km par défaut ; 500 m, 1, 2, 5 ou 10 km) autour de l'endroit sélectionné, sinon de votre position, sinon du centre de la carte, et liste **toutes les espèces de plantes observées dans ce cercle**, classées par nombre d'observations (toutes dates confondues). Toucher une espèce place ses observations sur la carte (les 200 plus récentes, **chacune avec sa photo** ; au survol, sa petite fiche ; un clic ouvre l'observation — sur téléphone, un premier toucher pour la fiche, un second pour l'observation) et mène à sa fiche quand elle fait partie de la flore de l'app (rapprochement par nom scientifique ou synonyme TAXREF). En tête de liste, un récapitulatif : nombre d'espèces, de familles et de genres (familles et genres TAXREF pour les espèces de la flore de l'app) et d'observations ; une recherche filtre la liste par nom français, nom scientifique, genre ou famille (sans tenir compte des accents), et deux filtres à choix multiples, **Famille** et **Genre** (repliés par défaut, valeurs de la plus à la moins représentée dans le cercle, ordre fixe), la restreignent ; le filtre Genre ne propose que les genres des familles choisies.

Source : API **iNaturalist** (`observations/species_counts` et `observations`), observations de **niveau recherche** uniquement (identification confirmée par la communauté) ; résultats gardés 24 h sur l'appareil.

### Lieux de récolte

L'onglet **Carte** enregistre les endroits où vous récoltez, sur les **photos aériennes IGN** (Géoplateforme, sans clé ; aussi Plan IGN et parcelles cadastrales). Un **lieu** (endroit) est une **collection de plantes qui a des coordonnées GPS** : une lisière peut réunir l'ail des ours, l'ortie et la benoîte. **Chaque plante du lieu a aussi sa propre position GPS.** **Une même plante peut y être notée plusieurs fois** (des orties tout le long d'un chemin) : chaque **occurrence** a sa position, son abondance, ses notes et son journal de récolte, numérotée dans la fiche du lieu (« n° 2 ») ; « Ajouter une plante » propose toutes les plantes, même déjà présentes, et « Retirer cette occurrence » n'enlève que celle-là. « Noter ici » d'une plante déjà notée dans le lieu, à moins de 15 m d'une de ses occurrences, enrichit celle-ci (récolte du jour) ; plus loin, c'est une nouvelle occurrence. **La carte d'un lieu est toujours cadrée sur lui et toutes ses plantes**, et se recadre quand une plante est ajoutée, retirée ou déplacée. Les anciennes données reçoivent un identifiant d'occurrence stable (aucune migration de base) ; l'export, le transfert et les liens de partage gardent chaque occurrence.

- **Sur place** : depuis une fiche plante, « 📍 Ajouter un lieu », ou **+** sur la carte. Le GPS s'affiche avec sa précision (± m) ; l'épingle peut être déplacée à la main, ou posée par un appui long sur la carte : la carte demande alors **« Déplacer le lieu ici ? »** (un fantôme au point ; « Confirmer » ou Entrée, « Annuler » ou Échap qui remet l'épingle glissée où elle était ; le GPS ne bouge ni l'une ni l'autre pendant la question). À moins de 100 m d'un lieu existant, l'application propose d'**y ajouter la plante** plutôt que de créer un doublon.
- **Position de chaque plante** : « Noter ici » enregistre la plante à votre position GPS (et la rattache au lieu le plus proche à moins de 30 m). Ajoutée depuis l'éditeur, une plante prend votre position GPS si vous êtes à moins de 100 m du lieu, sinon le point du lieu. Sur la carte d'un endroit, les marqueurs sont **fixes** : son bouton **✎** permet de faire glisser le point de l'endroit (le carré) et chaque plante (les ronds), indépendamment (appui long : placer le lieu) ; le point du lieu est **enregistré une fois « Déplacer le lieu ici ? » confirmé** (une seule écriture, et le point devient le repère de la carte), chaque plante **dès qu'on la lâche** (sans question), « Terminé » quitte le mode. En mode modification, le panneau d'une plante propose aussi « Ici (GPS) » ; sinon « Déplacer » ouvre ce mode. Un nouvel endroit s'ouvre directement en mode modification. **Sur ordinateur** (dès 700 px de large), l'éditeur d'un nouvel endroit montre **la carte ┃ le lieu** côte à côte : le séparateur entre eux se tire (← → au clavier, Début / Fin, double-clic ou Entrée : 480 px), la carte garde au moins 260 px et ne se recadre pas pendant le changement ; la largeur est mémorisée. Plus étroit, la carte reste au-dessus du formulaire.
- **Carte et lieu, une seule page** : choisir un lieu sur la Carte ouvre **toute sa fiche** à côté de la carte (à droite sur ordinateur, dans un panneau redimensionnable et repliable « » comme ceux de Flore ; en dessous sur téléphone, à moitié de la hauteur, la poignée l'agrandit) : nom, plantes avec abondance, qualité, notes et journal de récolte, « + Ajouter une plante », notes du lieu, partage, export, suppression ; en tête, le nombre de plantes, la distance et « Itinéraire ». Tout est **enregistré automatiquement**. La carte au-dessus est celle du lieu : toucher une plante sur la carte ouvre son panneau, ouvrir une plante dans la fiche la met en évidence sur la carte, « Déplacer » passe la carte en modification (✎). Un lien vers un lieu (Mes plantes, « Noter ici › Détails », fiche plante) ouvre la Carte sur ce lieu. En mode cueillette, le panneau d'une plante rappelle aussi les **plantes à confondre**.
- **Pour chaque lieu** : nom, notes (accès, propriétaire…), et ses plantes. **Pour chaque plante du lieu** : abondance, qualité (★), notes et **journal de récolte** (date, quantité, remarque). Une plante est **« en saison »** à un lieu si elle y a été récoltée, une année quelconque, à ±15 jours de la date du jour ; un lieu est en saison si l'une de ses plantes l'est.
- **Carte** : deux icônes distinctes. Un **lieu** est un carré sur pied, coloré selon l'abondance la plus forte, avec le nombre de plantes ; il est toujours visible. Une **plante** est sa **photo en miniature** dans un rond cerclé de la couleur de son abondance (une feuille si elle n'a pas de photo), à sa propre position, visible **en zoomant** (niveau 16 et plus) ; la toucher ouvre la fiche du lieu sur cette plante. Filtres « En saison » et par plante. **Choisir un lieu zoome sur lui et toutes ses plantes.** Le bouton **✎** de la carte est toujours là : en mode modification, **tous les marqueurs se glissent librement** (lieux, et plantes en zoomant) : une plante est **enregistrée au lâcher**, sans question ; un lieu lâché (ou placé par un appui long, le lieu choisi) demande **« Déplacer le lieu ici ? »** et n'est enregistré qu'une fois confirmé (la question prend la place de « Terminé » ; Échap le remet où il était) ; « Terminé » (ou ✎) quitte le mode. Un marqueur tenu sous le doigt n'est jamais replacé par une mise à jour du GPS. Pendant la modification, la carte occupe **tout l'écran**, puis reprend sa place. Une plante sans position propre suit son lieu.
- **Une seule carte** : la même interface partout (Carte et ses lieux, nouveau lieu, lieux d'une plante sur sa fiche, lien partagé) — recherche d'adresse, ▦ fonds, couches et légende, ◎ ma position, repère et fiche d'un point à l'appui long (confirmé), et ✎ pour déplacer les marqueurs (sauf sur un lien partagé). **Liste** triée par distance.
- **Hors ligne** : le GPS et les lieux fonctionnent toujours ; les zones de carte déjà affichées restent disponibles (3 000 tuiles en cache ; à part, les noms par-dessus les photos, trois tuiles pour chacune : 9 000, qui ne poussent jamais les photos dehors).
- **Plusieurs onglets ou fenêtres** (l'application installée et un onglet, la Carte d'un côté et une fiche de l'autre) : chaque enregistrement relit le lieu tel qu'il est stocké et n'y applique que **ce qui a été modifié ici** (dans une même transaction IndexedDB) ; une plante ou une récolte ajoutée ailleurs entre-temps n'est jamais effacée, un lieu supprimé dans un autre onglet n'est pas recréé (l'éditeur le dit). Les autres onglets sont prévenus aussitôt (`BroadcastChannel`) et relisent collections, notes, modules, modes et mise en page.
- **Stockage plein** : si l'appareil refuse une écriture faute de place, un message le dit une fois, avec **Exporter mes plantes** et ce qu'il faut faire (libérer de l'espace, recharger) — jamais d'enregistrement perdu en silence. Au premier lancement, si la flore ne tient pas, le message donne la place disponible et la flore n'est pas retéléchargée tant qu'il n'y a pas plus de place.
- **Stockage local qui ne s'ouvre pas** (Chrome : « Internal error opening backing store for indexedDB.open. » — base abîmée par un plantage ou une mise à jour, disque presque plein, profil tenu par un autre processus) : l'ouverture est **retentée** deux fois (après 250 ms puis 1 s), jamais une version plus récente déjà ouverte (`VersionError`), ni le manque de place, ni un stockage bloqué (navigation privée, données des sites bloquées). Au démarrage, l'échec est gardé jusqu'au rechargement ; en cours de session (connexion fermée par le navigateur), il ne l'est pas : l'action suivante réessaie. Si elle échoue encore, un bandeau le dit **en français, selon la cause**, avec quoi essayer (fermer les autres onglets et l'application installée, redémarrer le navigateur, libérer de l'espace), **Réessayer**, **Télécharger la copie de secours** (un fichier, lu sans IndexedDB, que *Réglages → Mes plantes → Importer un fichier…* relit) et les mots du navigateur dans « Détails techniques ». Quand l'effacer peut la réparer, **Réparer le stockage** demande d'abord, en disant ce qui revient (la copie de secours de cet appareil : sa date, ses favoris, collections, lieux et notes de fiche — ou qu'il n'y en a pas, et qu'ils seraient perdus), ce qui est téléchargé de nouveau (la flore : il faut une connexion, vérifiée avant ; les réponses des services en ligne) et ce qui reste (réglages, modes, mises en page, parties en cours, images et cartes déjà vues) ; puis la base est rouverte une dernière fois (si elle s'ouvre, rien n'est effacé ; si elle échoue alors pour une autre cause, une version plus récente ou le manque de place, rien n'est effacé non plus et le dialogue le dit), effacée (**jamais le `localStorage`**) et la page rechargée sur « Mes plantes », où collections et notes **reviennent d'elles-mêmes** de la copie de secours dès que la flore est enregistrée — un ♥ ajouté entre-temps gardé —, et le bandeau dit ce qui est revenu avec les mots du dialogue. Jusque-là la copie de secours est tenue (`geoflora.restorePending`) : rien ne la remplace, pas même une base vide. Une restauration qui échoue le dit (les mots du navigateur dans « Détails techniques »), garde la copie et est retentée au lancement suivant. Une base **vidée par le navigateur lui-même** (refaite vide à l'ouverture alors qu'une copie de secours existe : Chromium refait ainsi une base abîmée) est traitée de même : la copie est tenue aussitôt, avant toute écriture, et remise. Un autre onglet ouvert retient l'effacement (le dialogue le dit, et il reprend dès qu'il se ferme) ; si le navigateur ne peut pas non plus l'effacer, rien n'est effacé et le dialogue dit la suite (télécharger la copie, redémarrer, en dernier recours effacer les données du site puis importer le fichier). L'app ne tourne pas sans stockage : la flore servie par le worker sans IndexedDB demanderait de servir aussi ses lectures complètes (sans elles, les confusions dangereuses autour d'un lieu ne seraient plus listées) et un message unique pour toutes les écritures refusées.
- **Sécurité des données** : une **copie de secours** de toutes les collections et des notes de fiche est réécrite dans le `localStorage` à chaque modification (jamais remplacée par une liste vide, sauf suppression volontaire). Si la base IndexedDB perd des collections, « Mes plantes » propose de les **restaurer**. La protection du stockage est demandée au navigateur dès la première collection, et *Réglages → Protéger mes données* la redemande ; « Mes plantes » rappelle d'**exporter** quand la dernière sauvegarde a plus de 14 jours. Seul un fichier exporté survit à l'effacement complet des données du site par le navigateur. Réglages affiche un diagnostic du stockage (version, nombre de collections, protection, espace, dates de copie et d'export).
- **Confidentialité** : les lieux restent **sur l'appareil** (IndexedDB, stockage persistant demandé). Ils sont stockés au format **GeoJSON** : *Réglages → Exporter* produit un fichier `.geojson` lisible par QGIS, uMap, geojson.io…, et *Importer* le fusionne : pour une collection déjà présente, les champs de la version la plus récente l'emportent, mais **les plantes des deux versions sont gardées** (une plante ajoutée sur cet appareil n'est jamais retirée par un fichier plus récent qui ne l'a pas ; les journaux de récolte sont réunis) — pour retirer une plante, retirez-la sur chaque appareil. L'ancien format à une plante par point est aussi accepté. Le fichier complet contient aussi les **notes de fiche** (`sheetNotes`), restaurées à l'import (la plus récente l'emporte). Pensez à exporter régulièrement.

Format d'échange (`formatVersion` 5) : un **GeoJSON allégé** qui ne contient que **vos saisies**. Ce que l'application connaît déjà (noms des plantes, familles…) n'y figure pas : les plantes sont désignées par leur identifiant TAXREF et leurs noms sont retrouvés à l'import. Les valeurs par défaut (abondance « moyen », note 0, notes vides…), les champs calculés et la position d'une plante quand c'est celle de l'endroit sont omis ; le fichier est écrit sur une ligne. Les anciens fichiers (formats 1 à 4) restent importables.

```json
{
  "type": "FeatureCollection", "generator": "GeoFlora", "formatVersion": 5, "exportedAt": "…",
  "features": [{
    "type": "Feature", "id": "c0f3…",
    "geometry": { "type": "Point", "coordinates": [4.8357, 45.7641] },
    "properties": {
      "name": "Lisière nord", "notes": "Parking au bout du chemin", "accuracy": 8,
      "createdAt": "…", "updatedAt": "…",
      "plants": [
        { "plantId": 81541, "abundance": "abondant", "rating": 4,
          "harvests": [{ "date": "2026-04-12", "quantity": "1 kg" }] },
        { "plantId": 128268, "coordinates": [4.83581, 45.76402], "accuracy": 6 }
      ]
    }
  }]
}
```

Une collection sans `geometry` est une liste ; l'identifiant `favorites` désigne les favoris.

**Transférer vers un autre appareil** (*Réglages*) : le même GeoJSON allégé, compressé (deflate + base64url), voyage dans un lien `#/shared?d=g…` — rien ne passe par un serveur. À l'ouverture, un aperçu liste les collections ; « Importer » les ajoute ou les met à jour (même identifiant → la plus récente l'emporte, sans doublon). Une case permet d'inclure ou non les notes et journaux de récolte ; une copie plus récente sans notes ne supprime pas celles déjà présentes sur l'appareil.

## Génération locale

Node.js 22+ :

```bash
mkdir -p .cache/taxref
curl -L "https://assets.patrinat.fr/files/referentiel/TAXREF_v18_2025.zip" -o .cache/taxref.zip
unzip .cache/taxref.zip -d .cache/taxref
node scripts/build-plants.mjs
npm ci --ignore-scripts --prefix scripts   # SheetJS, pour enrich-baseflor.mjs et build-safety.mjs
```

La GitHub Action `Build flora dataset` télécharge les sources, valide les modules d'enrichissement, génère puis versionne :

- `data/plants.json`
- `data/meta.json`
- `data/thumbnails.json` (cache d'enrichissement Wikimedia)
- `data/safety.json`

Elle tient en deux jobs. « build » télécharge et analyse les fichiers extérieurs (archive TAXREF, tableurs Baseflor et TPPT, PDF de l'ANSM, Wikimedia) avec un jeton en lecture seule, sans identifiant laissé dans la copie du dépôt ; il vérifie les données, puis les remet dans un artefact gardé sept jours. « commit », sur `main` seulement, reprend ces quatre fichiers, les revérifie et les pousse ; il n'exécute rien de ce qui lit l'extérieur. Un fichier source piégé ne peut donc pousser ni code ni workflow : seulement le contenu de ces quatre fichiers de données, dans les limites que vérifie `scripts/check-data.mjs`.

**Données dégradées : jamais versionnées.** Les étapes qui lisent une source extérieure (Baseflor, statuts INPN, ANSM et TPPT) n'ont plus de `continue-on-error` : une source injoignable garde sa part du jeu précédent (`build-safety.mjs` source par source dans `safety.json`, `enrich-statuses.mjs` et `enrich-baseflor.mjs` depuis `HEAD`), et une erreur restante fait échouer le build avant tout commit. Avant le commit, `scripts/check-data.mjs` (`npm run check:data`) bloque aussi : une source de `safety.json` absente ; un compteur sous son plancher (plantes de `safety.json`, listes A et B de l'ANSM, TPPT, plantes protégées et réglementées, floraisons) ; une baisse de plus de 5 % d'un compteur par rapport au jeu versionné (`HEAD` : plantes, protégées, réglementées, floraisons, vignettes, entrées de `safety.json` par source, paires de confusions). Une baisse voulue passe par un lancement manuel de l'action avec un `max_drop` plus grand. Une source reprise d'un build précédent depuis plus de 30 jours donne un avertissement. Le code est sous licence **MIT** ([`LICENSE`](LICENSE)) ; les données de `data/` sont sous licence **ODbL 1.0** (exigée par Baseflor), sources et attributions dans [`data/LICENSE`](data/LICENSE) ; signaler une faille : [`SECURITY.md`](SECURITY.md). Lancée à la main sur une autre branche, l'action construit sans rien versionner : le résultat est dans l'artefact du run. `Enrich search media` (vignettes de repli GBIF et iNaturalist) suit chaque build de `main` et tourne chaque dimanche, avec le même découpage ; `Deploy web app` republie ensuite.

## IndexedDB recommandée

```text
plants
 ├─ id
 ├─ family
 ├─ genus
 ├─ species
 ├─ scientificName
 ├─ vernacularNames[]
 ├─ synonyms[]
 └─ status.france

plantDetails
 ├─ id
 ├─ fetchedAt
 ├─ identifiers
 ├─ thumbnail
 └─ remoteData
```

Indexes principaux :

```text
by_family
by_genus
by_taxon [genus, species]
```
