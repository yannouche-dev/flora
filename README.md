# GeoFlora — flore française

Référentiel léger destiné à une application de recherche dans la flore vasculaire de France métropolitaine.

## Dataset local

Le build TAXREF v18 produit actuellement :

- **7 745 espèces**
- **180 familles**
- **1 245 genres**
- **15 487 noms vernaculaires français uniques**
- **33 121 synonymes scientifiques**
- **7 177 espèces** avec au moins un nom français
- **568 espèces** sans nom français disponible dans les données TAXREF utilisées
- **3 504 espèces** avec une vignette de recherche Wikimedia Commons (**45,24 %**)

Le principe est simple :

- **IndexedDB locale** = recherche, tri, filtres et données taxonomiques de base ;
- **sources ouvertes distantes** = vignette, photos, répartition, descriptions, traits et liens détaillés ;
- les images ne sont **pas téléchargées dans le dataset**.

## Structure d'une plante

`data/plants.json` contient notamment :

```json
{
  "id": 100225,
  "family": "Rosaceae",
  "genus": "Geum",
  "species": "urbanum",
  "scientificName": "Geum urbanum",
  "author": "L.",
  "vernacularNames": [
    "Benoîte des villes",
    "Benoîte commune",
    "Herbe de saint Benoît"
  ],
  "synonyms": [],
  "flowering": [4, 10],
  "status": {
    "france": "P"
  },
  "identifiers": {
    "taxref": 100225
  },
  "links": {
    "taxref": "https://taxref.mnhn.fr/taxref-web/taxa/100225",
    "inpn": null
  },
  "thumbnail": {
    "url": "https://upload.wikimedia.org/...",
    "source": "Wikimedia Commons",
    "sourceUrl": "https://commons.wikimedia.org/...",
    "author": "...",
    "license": "CC BY-SA 4.0"

```

Les identifiants externes (GBIF, iNaturalist, Wikidata, Trefle) sont volontairement résolus **à la demande** au lieu d'être recalculés pour les 7 745 espèces à chaque build.

## Source et sélection

Le générateur utilise l'archive officielle **TAXREF v18** diffusée par PatriNat/MNHN :

- `TAXREFv18.txt` pour taxonomie, auteurs, synonymes et statut en France métropolitaine ;
- `TAXVERNv18.txt` pour les noms vernaculaires.

Filtres actuels :

- règne `Plantae` ;
- rang espèce `ES` ;
- nom accepté uniquement (`CD_NOM = CD_REF`) ;
- groupe TAXREF `Trachéophytes` ;
- présence en France métropolitaine ;
- statuts `P N E S C I J`.

Les synonymes TAXREF de rang espèce sont rattachés au taxon accepté. Les noms français portés par ces synonymes sont également rattachés à l'espèce acceptée.

**Statuts de protection** : `scripts/enrich-statuses.mjs` ajoute `statuses` depuis la **Base de connaissance Statuts** de l'INPN (PatriNat — OFB, MNHN, CNRS ; données ouvertes, archive `BDC.zip`), rapprochée par identifiant TAXREF (`CD_REF`). Sont retenus : protections **nationale** (`PN`), **régionale** (`PR`) et **départementale** (`PD`), **réglementation de la cueillette** (`REGL`), et **listes rouges** nationale (`LRN`) et régionales (`LRR`) pour les seules catégories menacées (RE, CR, EN, VU, NT). Chaque statut garde son territoire (`area`, `level`, `iso`) et l'intitulé du texte (`label`) ; les territoires d'outre-mer sont écartés. Si le téléchargement échoue, les statuts du jeu de données déjà versionné (`git show HEAD:data/plants.json`, `scripts/previous-data.mjs`) sont repris plante par plante, avec un avertissement dans le journal de l'action et `kept: true` dans `meta.json` ; sans jeu précédent, le build échoue. Un jeu de données n'est donc jamais publié sans ses statuts de protection.

**Territoires** : `data/territories.json` (généré par `scripts/build-territories.mjs`) contient les contours simplifiés des départements métropolitains (d'après IGN ADMIN EXPRESS via france-geojson, Licence Ouverte), avec leur région actuelle et leur **ancienne région** : beaucoup d'arrêtés régionaux de protection nomment encore les régions d'avant 2016. Il porte aussi les contours propres des régions et de la France métropolitaine (simplifiés un peu plus : ils ne servent qu'à tracer un périmètre vu de loin) : des départements simplifiés un à un ne partagent plus exactement leurs frontières, leur assemblage en garderait des bouts à l'intérieur.

**Catalogue des couches de l'IGN** : `data/ign-catalog.json` liste, en compact (identifiant, titre, description de 240 caractères au plus, format, style, zooms), les couches WMTS de la Géoplateforme que les cartes savent afficher (grille Web Mercator, tuiles PNG ou JPEG), lues dans sa description `GetCapabilities` — plusieurs Mo de XML, trop lourds à télécharger et à analyser sur un téléphone — par `scripts/build-ign-catalog.mjs`, avec le même lecteur que l'app (`lib/ign-catalog.mjs`, sans dépendance). Le service nomme ses grilles `PM_6_16`, `PM_0_19`… (zooms mini et maxi) et non `PM` : c'est ce qu'ignorait l'ancien lecteur, qui ne trouvait aucune couche (« Catalogue de l'IGN indisponible »). **Le fichier publié est régénéré à chaque déploiement** (`deploy-pages.yml`, job « catalog », lancé aussi **le 2 de chaque mois** pour qu'il reste frais sans commit) et contrôlé (au moins 50 couches, chacune avec un identifiant sûr, un format PNG/JPEG, un titre et des zooms ; les couches de l'app présentes ; pas de chute de plus de 30 %) ; si le service ne répond pas, la copie versionnée est publiée, avec un avertissement, et le déploiement continue. Il est précaché par le service worker et compté dans sa `VERSION` : un nouveau catalogue fait une nouvelle version, un catalogue inchangé n'en fait pas. La copie versionnée n'est qu'un repli (et le fichier des tests) : la première est une **graine** (`"seed": true`), tirée de l'autoconfiguration publiée par l'IGN (dépôt IGNF/geoportal-configuration, elle-même générée depuis ce `GetCapabilities`), que l'app tient pour vieille ; la remplacer par une copie lue au service : `node scripts/build-ign-catalog.mjs` (`--check <fichier>` vérifie un fichier). Dans l'app (`app/core/ign-catalog.js`), la copie la plus récente — livrée, ou lue sur l'appareil — s'affiche tout de suite ; plus d'un mois (ou une graine), module allumé et en ligne, le service est redemandé en fond : téléchargement lu au fil de l'eau, abandonné seulement après 20 s sans aucun octet (3 min au plus en tout), analyse dans un worker (`app/workers/ign-catalog.worker.js`), liste remplacée puis gardée sur l'appareil. Un échec ne remplace jamais la liste, n'est pas redemandé avant 5 minutes, sauf par « Réessayer ». `api-health.yml` lit chaque jour ce `GetCapabilities` avec ce même lecteur (au moins 50 couches) et échoue si le catalogue publié est une graine ou date de plus de 45 jours ; `post-deploy.yml` le signale après chaque déploiement.

**Floraison** : `scripts/enrich-baseflor.mjs` ajoute `flowering: [premier mois, dernier mois]` (1–12 ; un dernier mois plus petit que le premier signifie une floraison à cheval sur l'année) depuis **Baseflor**, l'index botanique, écologique et chorologique de la flore de France de Philippe Julve (programme CATMINAT), diffusé par [Tela Botanica](https://www.tela-botanica.org/ressources/donnees/telechargements/) : données sous licence **CC BY-SA 2.0**, base sous **ODbL 1.0**. Le tableau (`baseflor.xlsx`, colonne `floraison` au format « 6-9 ») est récupéré dans le porte-documents Tela Botanica (Cumulus). Le rapprochement se fait par identifiant TAXREF (`CD_REF`), sinon par binôme latin (nom accepté, puis synonymes TAXREF) ; la ligne de l'espèce l'emporte sur celles de ses sous-espèces. Une autre adresse peut être imposée par la variable de dépôt `BASEFLOR_URL`. Environ la moitié des espèces ont une floraison renseignée dans Baseflor (case vide pour certaines plantes courantes, comme l'ail des ours ou l'ortie) ; pour les autres, le calendrier s'appuie sur les observations iNaturalist. Si le téléchargement échoue, les floraisons du jeu déjà versionné sont reprises de même (avertissement, `kept: true` dans `meta.json`).

## Enrichissement distant

`lib/plant-sources.mjs` fournit une couche ES6 sans dépendance pour enrichir une plante au moment où elle devient visible ou lorsque l'utilisateur ouvre sa fiche.

Sources actuellement prises en charge :

- **GBIF** : correspondance avec le Backbone GBIF (`species/match`, plantes seulement), descriptions, noms vernaculaires, répartition, profils d'espèce (habitat, port, envahissante), synonymes, catégorie UICN, publications ; occurrences en France (présences seulement, coordonnées sans problème connu) : nombre, par mois, par année, régions et départements (GADM), types de relevés, principales sources, carte de densité (tuiles GBIF), les plus proches de vous ; images d'occurrences sous licence libre (CC0, CC BY, CC BY-SA), photos d'observation et planches d'herbier à part. Chaque donnée n'est demandée que si son bloc ou sous-bloc est affiché ;
- **iNaturalist** : taxon, nombre d'observations et photo par défaut lorsque sa licence est libre ; **phénologie** : observations en France par mois, annotées « en fleurs » / « en fruits » (`phenology()`, histogramme `month_of_year`, `place_id=6753`) ;
- **Wikidata** : résolution sûre par propriété taxonomique `P225` ;
- **Wikimedia Commons** : photos libres avec URL, miniature, auteur et licence ;
- **Trefle** : taxon, image principale et fiche détaillée (token gratuit requis).

Exemple :

```js
import { PlantSources } from './lib/plant-sources.mjs';

const sources = new PlantSources({
  trefleToken: null
});

// Pour une ligne visible dans la liste :
const thumbnail = await sources.thumbnail(plant);

// Quand la fiche est ouverte :
const details = await sources.details(plant);
```

Avec un token Trefle :

```js
const sources = new PlantSources({
  trefleToken: 'YOUR_TREFLE_TOKEN'
});
```

Trefle impose actuellement un token et une limite standard de 60 requêtes par minute. Pour une application publique, il est préférable de placer le token derrière un petit proxy si le quota doit être protégé.

**Source indisponible — Réessayer.** Une source qui ne répond pas n'est plus prise pour une absence de donnée. Chaque bloc de la fiche (Descriptions, Noms, Occurrences, Interactions, Climat, Usages, Taxonomie, Identifiants…), le Calendrier et les infos d'un lieu (zones naturelles, plantes vues ici, pollens, climat) affichent « Source indisponible : GBIF (hors ligne | pas de réponse à temps | erreur 503 | réponse inattendue) — Réessayer » ; « Réessayer » redemande ce qui a échoué. Les messages « Aucune… » sont réservés aux réponses valides et vides, et un module coupé dans les Réglages reste « module désactivé » (rien n'est demandé). Un appel qui ne répond pas abandonne après 15 secondes : plus de « chargement… » sans fin sur un portail captif ou en zone blanche.

Côté code (audit STO-7, STO-8, STO-9, OPS-2, QUA-6, ARC-14, PERF-15, STO-17) :

- `app/core/net.js` : `fetchJson(url, { signal, headers, timeout, expect, allowEmpty })`, seul chemin des appels JSON distants : délai (15 s, corps compris, `AbortSignal.any` avec le signal de l'appelant), contrôle de forme minimal (`expect`, sinon `SchemaError`), erreurs typées (`SourceError.kind` : `offline`, `timeout`, `http`, `schema`, `network` ; `errorKind()` y ajoute `aborted` et `module-off`). `lib/plant-sources.mjs` le reçoit en option (`new PlantSources({ fetchJson })`) et nomme les services en échec (`unavailable`) au lieu de les lire comme « absent » ;
- `app/core/cache.js` : le seul cache des réponses (store `plantDetails`), utilisé par `sources.js`, `geoservices.js`, `open-data.js`, `nearby.js`, `uses.js`, `protected.js`, `ign.js` : requêtes en vol partagées, une panne jamais enregistrée (cache négatif de 5 min, en mémoire seulement, oublié par « Réessayer »), un résultat dégradé jamais gardé plus de quelques minutes ni à la place d'une copie complète, une copie expirée en repli hors ligne (pas après une annulation). Chaque entrée garde sa durée de vie (`ttl`) ; une purge, une fois par jour après le démarrage et au repos, retire les entrées expirées depuis plus de 30 jours, puis les moins récemment utilisées au-delà de 4 000 entrées ou d'environ 40 Mo. Clés versionnées à dessein pour oublier les réponses de panne déjà gardées : `details3`, `thumb2`, `wikibooks2` ;
- `app/core/source-state.js` : le message « Source indisponible — Réessayer » des blocs et des volets.

### Politique média

Par défaut, GeoFlora préfère uniquement les médias dont la licence est clairement compatible avec une réutilisation libre :

- CC0 / domaine public
- CC BY
- CC BY-SA

Les images iNaturalist sous CC BY-NC ou sans licence exploitable ne sont pas choisies automatiquement. Les résultats Wikimedia Commons sont filtrés de la même manière (jamais NC ni ND : « CC BY-NC 4.0 » ou « cc-by-nd » ne passent plus pour libres ; `tests/licenses.mjs`, lancé par `tools/check.sh`, vérifie la table des licences).

**Partout dans l'application**, une photo iNaturalist n'est montrée que sous CC0, CC BY ou CC BY-SA (son `license_code`) : cartes Rencontres et fenêtre du match, Toutes et Matchs, Carte › Autour, « Plantes vues ici », points photo des cartes ; sinon, la vignette de la flore (ou une feuille sur la carte). **Chaque photo porte son crédit** — « © auteur · licence · source », sans « © » pour CC0 et le domaine public — sur les cartes Rencontres, la fenêtre du match, les vignettes de Toutes et Matchs (au bas de la photo), la petite fiche d'un point de la carte, l'espèce choisie dans Carte › Autour ; les auteurs des « Plantes vues ici » sont cités sous la rangée, et la carte nomme ses sources de photos dans son attribution. Une vignette CC BY dont l'auteur manque renvoie à sa page Commons (« auteur sur sa page »). « On dit de moi » cite Wikipédia (CC BY-SA). Au build, l'auteur d'une vignette Commons vient d'`Artist`, sinon de son attribution ou de son crédit ; une vignette CC BY sans auteur est vérifiée de nouveau au build suivant, et une image sous GFDL, GPL ou FAL n'est plus choisie.

**Wikimedia** : les appels aux API de Wikidata, Wikipédia, Commons et Wikibooks portent l'en-tête `Api-User-Agent: GeoFlora (https://github.com/yannouche-dev/flora)`, comme le demande la politique User-Agent de Wikimedia (un navigateur ne peut pas changer son User-Agent). Le service de requêtes (`query.wikidata.org`) n'en reçoit pas.

Trefle reste disponible pour ses données structurées et ses images par organes, mais une image dont la licence précise n'est pas vérifiée n'est pas utilisée automatiquement comme miniature, sauf avec l'option :

```js
new PlantSources({
  trefleToken: '...',
  allowUnverifiedMedia: true
});
```

## Architecture GeoFlora

```text
Recherche / filtres
        │
        ▼
IndexedDB
7 745 espèces
        │
        ├── famille
        ├── genre
        ├── espèce
        ├── noms vernaculaires
        ├── synonymes
        └── statut TAXREF
        │
        ▼
Liste de résultats
        │
        ├── données locales immédiates
        └── thumbnail.url déjà présent dans plants.json
        │
        ▼
Fiche plante
        │
        ├── photos / organes
        ├── répartition
        ├── descriptions
        ├── traits
        ├── observations
        └── ressources externes
```

Les réponses distantes peuvent être mises en cache quelques heures ou quelques jours dans IndexedDB. Les images restent servies par leur source ; le service worker garde les 400 dernières vignettes et photos vues (pas les originaux), d'une version de l'app à l'autre, pour les afficher hors ligne. Il les demande en CORS : une réponse lisible est gardée à sa taille réelle ; un hôte sans CORS voit ses images affichées mais jamais gardées (une réponse opaque compte environ 7 Mo de quota chacune).

GeoFlora est une application HTML5 **sans serveur et sans étape de build** : des modules ES natifs, des composants [Lit](https://lit.dev) et un service worker écrit à la main. Elle est publiée telle quelle sur GitHub Pages et fonctionne hors ligne après la première visite.

### Disposition et panneaux

**Tous les volets (panneaux) sont redimensionnables horizontalement, toutes les dispositions sont responsives.** Un *panneau* est une région posée à côté d'une autre (une colonne) ; entre deux, un *séparateur* ; la *disposition* est leur arrangement selon la largeur : téléphone (moins de 700 px, `BP.phone` : les panneaux empilés, sans séparateur), tablette, grand écran (des colonnes qui ne tiennent plus se replient ou passent en onglets).

- **Un seul séparateur pour toute l'application** : `PaneSizer` (`app/core/panes.js`) — glisser (une ligne guide suit le pointeur, la largeur est prise au relâcher), ← → au clavier (Maj : par 64 px), Début / Fin, double-clic ou Entrée : largeur par défaut ; lu « Redimensionner le panneau … » (`role="separator"`, `aria-controls`, `aria-valuenow` / `min` / `max`) ; au doigt, 44 px à tenir et une languette.
- **Chaque panneau a son minimum et son maximum**, et la somme ne dépasse jamais l'écran : une largeur choisie sur un grand écran se resserre sur un plus petit, sans être oubliée (la fenêtre agrandie ou l'appareil tourné, elle revient). **Jamais de défilement de côté**, dès 320 px de large.
- **Les largeurs sont gardées par écran**, chacune sous sa clé de `config.storageKeys` listée dans `config.paneLayouts` (Flore, Mes plantes, Carte, éditeur d'un lieu, « À propos de l'image » à côté d'une photo…) : les premiers pas ne la prennent pas pour un « habitué ». Une mini-application garde les siennes dans son espace (`geoflora.app.<id>.*` : ses colonnes, le volet des photos, la fiche d'une plante à côté des cartes), listées dans son `owns` : « Recommencer » les oublie.
- **Ne sont pas des panneaux** : les barres d'outils et d'en-tête, une barre repliée (rail), le Sommaire et les menus (par-dessus la page), une carte flottante (le point de la Carte), les grilles de cartes (Découvrir, Mosaïque) et les colonnes d'un texte (étiquette / valeur des Réglages).
- `tests/e2e/panes-all.spec.mjs` le vérifie sur chaque écran, de 320 à 1920 px.

### Icônes

Toutes les icônes de l'application sont des [Bootstrap Icons](https://icons.getbootstrap.com) (licence MIT) : un seul fichier `assets/icons/bi.svg` ne contenant que celles utilisées (38), mis en cache hors ligne, et `icon('heart')` (`app/core/icons.js`) pour les afficher. Elles prennent la taille et la couleur du texte. Pour en ajouter une : son nom dans `scripts/build-icons.mjs`, puis `node scripts/build-icons.mjs <dossier du paquet bootstrap-icons>`. Sur téléphone, le bouton des filtres est une icône d'entonnoir (pleine quand un filtre est actif, avec leur nombre) ; « Compact » et « Partager » au-dessus des résultats sont aussi des icônes.

### Logo, icônes de l'app et écran de lancement

Le logo est `assets/icons/icon.svg` (l'épingle verte et sa feuille), celui de l'en-tête. Les icônes PNG de l'app en sont tirées par `node scripts/make-app-icons.mjs` (rendu par le Chromium de Playwright, sans autre dépendance), puis versionnées : `geoflora-192.png` et `geoflora-512.png` (« any » : le logo seul sur fond transparent, que Chrome pose au centre de l'écran de lancement Android, sur le `background_color` du manifeste), `geoflora-maskable-192.png` et `geoflora-maskable-512.png` (« maskable » : le logo blanc sur le vert de l'app, dans la zone sûre de 80 %, pour les icônes adaptatives d'Android : cercle, squircle, carré arrondi) et `apple-touch-icon-180.png` (écran d'accueil iOS, opaque). Le manifeste porte le nom court « GeoFlora » (celui de l'écran d'accueil et du lancement), un `id` fixe (`/flora/`, l'identité des installations existantes) ; le titre long reste dans `<title>` et `description`. **Changer de logo** : modifier `icon.svg`, relancer le script en donnant **de nouveaux noms** aux PNG (une app installée sur Android garde les icônes de son installation tant que leur adresse ou leur contenu ne change pas), puis les reporter dans `manifest.webmanifest`, `index.html` et la liste `SHELL` de `sw.js`.

**L'écran de lancement** de la page (`.gf-boot`, en fin d'`index.html`, ses styles en ligne dans le `<head>`) prend le relais de celui d'Android pendant le chargement des modules, et s'affiche pareil dans tous les navigateurs : le logo au centre de l'écran, « GeoFlora » (la police et le vert du nom de l'en-tête), « Flore de France », et une fine barre de progression qui n'apparaît qu'au-delà de 0,6 s ; fond `--gf-bg` (le `background_color` du manifeste), mode sombre, animations réduites respectées ; pour un lecteur d'écran, un `role="status"` « Chargement de GeoFlora… ». Il s'efface en fondu dès que `<gf-app>` est défini (CSS seul, `gf-app:defined + .gf-boot` : aucun script), sans clignoter sur un chargement rapide, et une fois caché ne prend plus aucun clic (`tests/e2e/launch.spec.mjs`).

### Mini-applications

Rencontres, le Parcours botanique, Cueillette prudente et Mosaïque sont des **mini-applications** : chacune s'ouvre **seule à l'écran**, à son adresse `#/app/<id>/<étape>` (`#/app/rencontres/cards`, `#/app/parcours/walk`, `#/app/cueillette/map`, `#/app/mosaique/cards`), sans en-tête ni barre d'onglets, sous une barre de 48 px : **« × Quitter … »** (la seule sortie : elle ramène là d'où on l'a ouverte — la liste de Découvrir, si on l'a ouverte de là), son titre, **ses étapes** (Départ › Carte › Rencontres, Cueillette ou Mosaïque ; Départ › En marche › Bilan) et **⋯** : masquer ou afficher les étapes, remettre la mise en page, **Rejouer**. Les étapes se touchent : une étape déjà faite y ramène, « Suite › » passe à la suivante ; chaque étape est une entrée de l'historique (Retour revient à la précédente). Les anciennes adresses (`#/discover?s=meet`, `?s=trail`, `?s=harvest`, `?s=mosaic`, `#/discover?p=<id>`) y mènent.
- **Chacune sa partie** : Rencontres, Cueillette prudente et Mosaïque gardent **chacune leur lieu, leur distance, leurs cartes passées et leurs matchs** (`geoflora.app.<id>.state`) : « Reprendre » (le lieu gardé, sur l'écran de départ) et « Continuer » (la liste) sont propres à chacune, et rejouer l'une ne touche pas les autres. Avant, les trois partageaient une même partie (`geoflora.discover`) : elle est **donnée une fois à la dernière jouée** si l'adresse ouverte le dit (`#/discover?s=harvest` ou `?s=mosaic`), sinon à Rencontres — rien n'est perdu, et une seule propose « Continuer » ; puis chacune va son chemin.
- **Rejouer** (⋯) et **Recommencer** (la liste de Découvrir) font la même chose : ils demandent d'abord, dans un dialogue qui dit **ce qui sera supprimé, avec les nombres** (« Recommencer : tout effacer ? Seront supprimés : 12 favoris ajoutés par Rencontres, la partie en cours. Cette action est définitive. » ; pour le Parcours « le parcours en cours « Chemin du lavoir » (4 plantes) », puis, s'il y en a, « Vos 3 parcours enregistrés dans Mes plantes sont conservés. »), le focus sur « Annuler » ; puis ils effacent **tout ce que la mini-application possède et tout ce qu'elle a fait**, et seulement cela, comme si elle n'avait jamais été ouverte, et rouvrent **son premier écran** (`#/app/<id>/start`, rien ne le saute, même après un rechargement), aussi dans les autres onglets ouverts : sa partie et sa mise en page (`geoflora.app.<id>.*`), en mémoire ses cartes, son paquet, ses retours en arrière, la vue choisie, le filtre « En fleur », l'animation qui montre qu'on peut glisser (elle revient) ; pour Rencontres aussi ses étapes guidées, l'embranchement, le premier match fêté et les largeurs de sa mise en page guidée (`geoflora.discoverLayout`) ; pour le Parcours le parcours en cours, la liste des parcours à reprendre, le bilan affiché et la largeur de sa colonne (`geoflora.trailLayout`). **Ce qu'elle a fait dans Mes plantes s'en va aussi** : chaque favori ajouté par un match et chaque parcours enregistré portent **l'application qui les a faits** (`origin: { app }`, gardé dans la sauvegarde et les exports GeoJSON, relu à l'import) ; Recommencer supprime ces favoris et le parcours en cours (ou un parcours resté vide), en une seule transaction. **Sauf ce que vous avez fait vôtre** : un parcours **terminé avec au moins une plante** (son bilan), ou renommé, modifié, complété depuis Mes plantes, partagé ou exporté seul ; un favori de match ensuite **rangé dans une liste** ou **annoté** (une note sur la fiche) — à ce moment-là il perd son origine (il garde seulement `from: { app }`, pour dire d'où il vient) et devient une donnée comme une autre : Recommencer le garde, et le dialogue le dit. Ce qui existait avant cette version est attribué une fois, au mieux, sans rien détruire : **les favoris d'avant sont à vous** (jamais attribués à une partie) ; le parcours en cours et les parcours vides sont au Parcours ; un parcours terminé avec ses plantes est déjà à vous. **Ce qui ne vient pas d'elle reste** : un favori mis depuis la Flore, ou qui l'était déjà avant le match, les autres lieux et leurs plantes, les premiers pas de l'application (les onglets venus, les plantes vues), les réglages et les réponses des services en ligne gardées en cache.
- **Afficher les étapes** (*Réglages › Premiers pas*) : « Pendant la découverte » (par défaut : jusqu'à la fin d'une première partie), « Toujours » ou « Jamais ».
- **Pour un développeur** : une mini-application est un **manifeste** (`app/miniapps/<id>.js`, inscrit dans `app/miniapps/index.js`) vérifié au chargement par `defineMiniApp` (`app/miniapp/define.js`) : son contexte et ce qui en dérive, ses colonnes (largeur de base, min, max, rang, colonne où se replier), ses étapes (la première est le départ ; chacune ajoute ou retire des composants du kit, `app/miniapp/kit.js`), ce qu'elle **possède** (`owns` : ses clés, `reset()` pour le reste — mémoire, ce qu'elle a fait dans Mes plantes —, vidés par Rejouer ; chaque manifeste en dresse la liste, avec la frontière de ce qu'elle **partage**, `shared`, jamais effacé). La grille (`ma-grid`) met toutes les cellules dans une seule grille CSS : changer d'étape ou de largeur ne recrée jamais une carte ; sous 700 px, une seule colonne ; quand la place manque, la colonne de plus petit rang devient un onglet de sa voisine, sans défilement horizontal. **Le kit des plantes autour** (`app/miniapp/kit/`) : la session de la partie (`session.js` : cartes, observations, Wikipédia, retours en arrière), la distance sur la carte (`ma-distance`), la liste (`ma-around-list` : le paquet `ma-deck`, les matchs, la grille ou la mosaïque, la fiche `ma-plant-sheet`, le premier match, et pour Rencontres les photos du premier match, `ma-meet-media`), la découverte guidée de Rencontres (`ma-guided`, sa carte `ma-around-map`), et ce qui est pur (`cards.js` : l'ordre de la Cueillette, la bio et ses lignes de sécurité, testés sous Node). Cueillette prudente et Mosaïque assemblent `distance` puis `aroundList` ; Rencontres, `meet` (la découverte guidée pendant les premiers pas, sinon les mêmes). **Le kit du Parcours** : sa partie (`trail-session.js` : le parcours en cours, ceux à reprendre, le bilan, la position suivie ; `trail-store.js` : ce qu'il garde sur l'appareil, et ce qui est pur — les plantes regroupées, les chiffres du bilan, testés sous Node), son écran de départ (`trail-start.js`, dessiné par la boîte), la marche (`ma-walk` : sa carte `ma-walk-card`, ses plantes `ma-walk-list`, sa recherche sous le pouce `ma-walk-search`, sa carte `ma-walk-map`) et le bilan (`ma-trail-recap`) ; ses étapes Départ › En marche › Bilan sont celles du manifeste (une adresse chacune, Retour étape par étape ; ouvert sans étape, le parcours en cours ou son bilan reviennent aussitôt : `resumeAt`). Aucune mini-application n'enveloppe plus un écran d'avant : `gf-discover` et `gf-trail` n'existent plus.

### Découvrir : la liste des mini-applications

**L'onglet Découvrir** (`#/discover`) ouvre **la liste** des façons de jouer, en page entière : les quatre mini-applications — Rencontres, Parcours botanique, Cueillette prudente, Mosaïque —, dans le même ordre que le lanceur. Scientifique n'y est pas : c'est un **mode** (Épuré, Standard, Scientifique ; voir « Modes d'affichage »), qui se choisit dans l'en-tête ou dans Réglages, pas une façon de jouer. Chacune a sa carte : son illustration (voir « Illustrations des scénarios »), son titre, ce qu'elle fait et **« Jouer »** — ou, pour une mini-application dont une partie est en cours sur l'appareil (un lieu choisi ; un parcours en marche), deux actions : **« Continuer »** (là où on l'avait laissée : son étape) et **« Recommencer »** (voir « Mini-applications » : tout effacer, après confirmation, et revenir au premier écran). Sur grand écran, des cartes, l'illustration en haut — les quatre sur une rangée, deux par deux sur un écran moyen ; sur téléphone, une liste, l'illustration en petit à côté des mots. Un titre de niveau 1 (« Découvrir »), un titre par carte, des boutons nommés d'après elle (« Jouer : Rencontres », « Continuer : Mosaïque », « Recommencer : Mosaïque »).
- **Jouer** ouvre la mini-application seule à l'écran, à son départ (`#/app/<id>/start`) ; **« × Quitter … »** ramène à la liste. Jouer la Cueillette prudente allume le mode cueillette.
- **Rien ne s'ouvre tout seul** : ni l'onglet ni le premier lancement n'ouvrent Rencontres directement.
- Les anciennes adresses mènent aux mini-applications : `#/discover?s=meet`, `?s=trail`, `?s=harvest` et `?s=mosaic` ; une plante ouverte sur leurs cartes (`#/discover?p=<id>`, `?s=mosaic&p=<id>`) aux cartes de la mini-application, cette plante ouverte (par-dessus son écran de départ s'il n'y a pas de lieu gardé) ; une adresse `#/discover?s=…` inconnue — dont `?s=science`, l'ancienne carte Scientifique —, à la liste (sans changer de mode).
- **Pour un développeur** : une seule liste, `gf-launcher` (`app/components/gf-launcher.js`), nourrie par `app/miniapps/index.js` (chaque mini-application dit si une partie est en cours : `underWay` ; l'étape où on l'a laissée est gardée dans sa partie) ; en page (`<gf-launcher page>`, l'onglet) ou compacte, dans le dialogue du lanceur (`gf-scenarios`).

### Scénarios (l'icône film)

L'icône film de l'en-tête (ordinateur et téléphone, et la barre d'une mini-application) est le **lanceur** : la même liste que l'onglet Découvrir, dans un dialogue — les quatre mini-applications, chacune avec les outils qu'il lui faut (le mode Scientifique, lui, se choisit dans l'en-tête ou dans Réglages) :
- **Rencontres** (mini-application) : les plantes observées autour de vous, à la Tinder (ci-dessous) ; ses étapes guidées sont les premiers pas de l'application.
- **Parcours botanique** (mini-application) : marchez et nommez les plantes que vous croisez (ci-dessous).
- **Cueillette prudente** (mini-application, `#/app/cueillette`) : autour de vous, seulement les plantes qui comptent pour la cueillette — les comestibles de la liste de l'Anses et des Centres antipoison et leurs sosies toxiques —, les confusions mortelles d'abord ; la bio de chaque carte commence par la confusion (« Ne me confondez pas avec Colchique (mortel). Partie : feuilles. ») ; un bandeau rappelle de ne jamais cueillir sans identification certaine, avec la conduite à tenir après ingestion (Centre antipoison : centres-antipoison.net, la liste officielle ; le 15 ou le 112 en cas de détresse vitale) ; le mode cueillette s'allume. Si la liste des confusions ne se lit pas, l'écran le dit (« Liste des confusions indisponible pour le moment : ne consommez aucune plante sans vérification », **Réessayer**) et garde toutes les plantes du coin, chaque bio rappelant que les données de sécurité sont indisponibles — jamais « Aucune plante de cueillette observée ».
- **Mosaïque** (mini-application, `#/app/mosaique`) : toutes les photos des plantes du coin en grande mosaïque (la vue « Toutes », dès que les cartes arrivent ; « Rencontres » et « Matchs » aussi), filtre « En fleur maintenant » ; une photo touchée ouvre la fiche à ses images. Sur grand écran (900 px et plus), la fiche d'une plante s'ouvre à côté des cartes (Mosaïque, Cueillette prudente, Rencontres) : sa largeur se règle par son séparateur (les cartes gardent 320 px), gardée dans l'espace de la mini-application (`geoflora.app.<id>.sheet`), oubliée par « Recommencer ».

### Écrans de départ des scénarios

Les **quatre mini-applications** — Parcours botanique, Rencontres, Cueillette prudente, Mosaïque — commencent par **le même écran**, sur le modèle du Parcours (`app/components/start-screen.js`, un gabarit partagé ; la recherche de commune est l'élément `gf-place-search`) :
- **En grand** : l'illustration, **le titre** (32 px sur téléphone, jusqu'à 40 px sur grand écran), **la description** (18 à 20 px), **la seule action** (un gros bouton de 56 à 60 px de haut, 19 à 21 px) — l'œil va droit à l'action, et elle est **sous le pouce**, dans la moitié basse de l'écran, sans défiler, jusqu'aux petits téléphones (360×640). Sous l'action : une erreur (en rouge, avec « Réessayer » si la position a mis trop de temps ou n'est pas disponible pour le moment) ou « Annuler » pendant la localisation, et toujours la ligne qui dit ce que devient la position. Le gros bouton occupé garde le focus du clavier ; « Annuler » le lui rend. **Téléphone couché** (écran bas et large) : l'illustration à gauche, les mots et l'action à droite, en vue sans défiler.
- **En petit** (14 px, 44 px de haut au doigt) : **les autres façons d'entrer** — « ou partir d'une commune » (la recherche dit « Recherche… », « Aucun lieu de ce nom », hors ligne, IGN coupé dans les Réglages ; ↑ ↓ et Entrée au clavier — Entrée choisit toujours un lieu trouvé pour tout ce qui est tapé, jamais pour moins de lettres ; la liste s'ouvre au-dessus du champ quand le clavier ne laisse pas de place dessous, sans jamais dépasser la place qui reste) ; ce qui se reprend (« Reprendre un parcours » : les 3 derniers, puis « Voir les N autres » — tous ceux qui sont gardés ; deux du même nom le même jour se distinguent par l'heure ; « Autour de Fontainebleau · 1 km » après « Changer de lieu ») ; un lien.
- **En plus petit encore** : **la seule sortie** (« Quitter … : autres scénarios » ; « Passer : montrer toute l'application » pendant les premiers pas de Rencontres — et sous la liste de Découvrir).
- **Les textes** : Parcours « Votre parcours botanique » ; Rencontres « Rencontrez les plantes d'ici » (un coup de cœur à droite, au suivant à gauche, les coups de cœur rejoignent les favoris) ; Cueillette « Cueillette prudente », avec sa mise en garde en grand, sur fond orangé (« Ne cueillez jamais une plante sans être sûr de vous. ») ; Mosaïque « La mosaïque du coin ». Pour les scénarios qui cherchent autour de vous : « Votre position est envoyée à iNaturalist et à l'IGN pour chercher autour de vous ; elle n'est gardée que sur cet appareil. » Pour le Parcours : « Votre position est envoyée à l'IGN pour nommer le lieu ; le parcours reste sur cet appareil, dans Mes plantes. » La mise en garde de la Cueillette porte un triangle d'avertissement (pas un bouclier coché).
- **La localisation** ne part qu'une fois (deux ou trois touchers rapides, ou une commune choisie pendant la création, ne font qu'un parcours), n'accepte pas une position de plus d'une minute, et s'arrête si l'on choisit une commune, reprend un parcours, change de scénario ou quitte l'écran ; chaque écran dit l'erreur à sa façon (refusée, trop longue, indisponible, navigateur sans GPS), et elle s'efface dès qu'on fait autre chose. « Réessayer » relance vraiment la recherche de position. Au premier chargement, la ligne « Chargement… » se pose par-dessus le haut de l'écran (sauf téléphone couché, où le titre est en haut) : l'action ne bouge pas sous le pouce.
- **Le bilan du Parcours** (« Parcours terminé ») suit le même gabarit : la carte du parcours et les plantes rencontrées en image, « Partager le parcours » en grand, puis en petit le voir dans Mes plantes, le reprendre, un nouveau parcours, et la sortie.

### Parcours botanique

Le plus simple des modes : un parcours, c'est un lieu de « Mes plantes » où chaque plante notée garde l'endroit où vous l'avez vue.
- **Une mini-application** (`#/app/parcours`, voir « Mini-applications ») : seule à l'écran, le reste de GeoFlora n'est pas là ; on en sort par « × Quitter le parcours » ; « Quitter le parcours : autres scénarios », sur son écran d'accueil et son bilan, ouvre le lanceur. Ses étapes ont chacune leur adresse (`#/app/parcours/start`, `/walk`, `/done`) : Retour depuis la marche revient au départ (le parcours en cours y est proposé en premier dans « Reprendre un parcours »), Suivant y retourne ; ouverte sans étape, elle retrouve le parcours en cours ou son bilan.
- **Démarrer** : l'écran de départ commun (voir « Écrans de départ des scénarios ») montre **un chemin parmi les fleurs**, fait des icônes de l'app (voir « Illustrations des scénarios ») ; « Commencer ici » en grand (votre position ; « Annuler » pendant la localisation), puis, plus petits, une commune et les parcours déjà commencés, qui se reprennent d'un toucher (leur nom sans « Mon parcours botanique », leur nombre de plantes et leur dernier jour : « En forêt de Fontainebleau · 12 plantes · 3 oct. »).
- **Son nom, tout seul** : « Commencer ici » nomme le parcours d'après **le lieu le plus précis que connaît l'IGN là où vous êtes** — « Mon parcours botanique en forêt de Chatel-Guyon », « au bois de Vincennes », « au jardin des Plantes », « au parc de la Tête d'Or », « au puy de Dôme (Orcines) », « au Roc Errant (Châtel-Guyon) », sinon « à Chazemais » (la commune). Dans l'ordre : un parc, un jardin, un square, un arboretum où vous êtes ; une forêt publique où vous êtes (« Forêt communale de … » devient « forêt de … ») ; un bois nommé assez proche pour sa taille (jusqu'à 1,2 km pour un grand bois) ; un sommet, un col, une vallée ; le lieu-dit ou le hameau le plus proche (250 m), avec sa commune entre parenthèses ; le quartier ; la commune. Les noms historiques, génériques ou égaux à la commune sont écartés ; la préposition suit le mot (« en forêt », « au bois », « aux gorges », « à l'arboretum », « au château »…). GPS imprécis (plus de 250 m) : la commune seule. Le temps que l'IGN réponde (8 s au plus, une requête refusée pour surcharge est reposée une fois), le parcours s'appelle « Mon parcours botanique » ; un nom changé entre-temps n'est jamais remplacé. Parti d'une commune : « Mon parcours botanique à Châtel-Guyon », « au Mont-Dore ». Source : IGN Géoplateforme (WFS BD TOPO® — `zone_d_activite_ou_d_interet`, `foret_publique`, `lieu_dit_non_habite`, `detail_orographique`, `zone_d_habitation` — et ADMIN EXPRESS pour la commune ; sept petites requêtes en parallèle, gardées un an sur l'appareil ; module « IGN – adresses et altitudes »).
- **Sur téléphone, tout tient sur un écran** (la barre d'onglets, grisée, ne sert pas) : en haut l'en-tête du parcours, puis **la carte**, puis la liste des plantes notées, et **la recherche collée en bas, sous le pouce**, au-dessus de la barre d'onglets — **même clavier ouvert** (la page se cale au-dessus des touches, sur Safari aussi — seulement pendant le parcours : ailleurs, le clavier se comporte comme d'habitude). **Le parcours ne défile pas** : glisser sur l'en-tête, la carte ou la recherche ne fait rien bouger. En paysage ou clavier ouvert, la carte se tient dans sa place, jamais par-dessus la liste. **Pendant une recherche**, dès que le champ est touché, **les propositions montent de la recherche** et couvrent l'en-tête, la carte et la liste, qui s'effacent en fondu : on ne voit plus que les propositions, la recherche et la barre d'onglets. **Les propositions tiennent à la recherche, sous le pouce** : la meilleure juste au-dessus du champ, les suivantes en montant, « Voir plus » tout en haut ; la liste défile depuis le bas. Chaque nouvelle lettre ramène la meilleure juste au-dessus du champ ; ouvrir ou fermer le clavier ne fait pas glisser les propositions. Au clavier (Tab) et pour les lecteurs d'écran, elles viennent dans l'ordre où on les voit, et l'en-tête, la liste et la carte cachés dessous sont hors d'atteinte. ✕ efface comme Échap : le champ et le clavier restent (touché clavier rangé, la recherche se ferme). **Clavier rangé sans rien taper** (le retour d'Android, la touche ⌄), même après avoir renommé le parcours ou tourné le téléphone : les propositions redescendent et le parcours revient. Le message « … ajoutée au parcours · Annuler » s'efface pendant la recherche (il ne couvre aucune proposition) et revient, « Annuler » compris, quand on la quitte. **Une plante ajoutée, elles redescendent** (le clavier se ferme) et l'en-tête et la carte réapparaissent tels quels, la plante dessus — rien n'est redessiné ni recalé, le mouvement reste fluide (simple fondu si les animations sont réduites). Sur grand écran, la même colonne à gauche (les propositions y prennent la place de l'en-tête et de la liste, le champ reste prêt pour la suivante), la carte à droite, toujours visible.
- **L'en-tête du parcours** (compact : nom, ✎ et les deux icônes sur une ligne, le compte et le GPS dessous) : **son nom en entier** (sur deux lignes au plus), toujours modifiable (✎) et **enregistré pendant la frappe** (Échap rend le nom d'avant) ; ce qui a été noté (« 12 observations · 9 plantes »), la précision du GPS ; deux icônes discrètes : **Partager** (un lien qui porte le parcours, sa carte et ses plantes : la feuille de partage du téléphone, ou copié) et **Terminer** (drapeau ; le parcours reste dans Mes plantes). Tout est enregistré au fil de l'eau, sans bouton « Enregistrer ».
- **Nommer une plante** : un grand champ, au clavier ou à la voix. **Le micro est un gros bouton rond à côté du champ, sous le pouce** : il réagit dès le toucher (vibration courte, il rougit), pulse quand la reconnaissance vocale du système (Android, iOS, via le navigateur) écoute, et le champ dit « Parlez : « ortie »… » ; les mots s'affichent pendant qu'on parle. Sans reconnaissance vocale dans le navigateur, le même bouton dit comment **dicter avec le micro du clavier** (voir ci-dessous) ; la dictée du clavier n'est jamais perturbée par l'app (le champ n'est pas réécrit pendant la saisie) ; la flore propose les plantes qui correspondent, avec photo, famille et un gros bouton rond **marqueur ＋** (l'ajouter ici) — toutes celles que trouve la recherche principale, 12 d'abord puis « Voir plus » ; Entrée ajoute la première, toujours pour le nom complet tapé. La plante est posée là où vous êtes ; « Annuler » la retire aussitôt.
- **Le micro n'ouvre jamais le clavier** : toucher le gros bouton rond laisse le champ (le clavier se ferme s'il était ouvert), les propositions montent avec « Parlez : « ortie »… » et la plante entendue s'y propose, sous le pouce. Sans dictée dans le navigateur, le bouton dit comment dicter avec le micro du clavier, sans l'ouvrir. Au départ d'un parcours, le champ n'est pas activé sur téléphone (pas de clavier qui surgit sur la carte).
- **Parcours terminé** (le drapeau) : une vue de fin montre **la carte du parcours avec toutes ses plantes**, son nom, ce qu'il contient (« 4 observations · 3 plantes, en 1 h 05, sur 1,2 km » — la durée depuis le départ jusqu'à la dernière plante, sans les pauses de plus de 2 h (un parcours repris un autre jour) ; la distance d'une plante à la suivante à vol d'oiseau, depuis le départ quand le parcours a commencé « ici », entre les plantes qui ont leur propre place (notées avec le GPS, ou replacées à la main) — ni la commune de départ, ni le point du parcours où va une plante notée sans GPS), les vignettes des plantes rencontrées ; **« Partager le parcours »** en grand, puis, plus petits : le voir dans Mes plantes, le reprendre, un nouveau parcours, quitter vers les autres scénarios. Elle reste affichée au retour de Mes plantes et après un rechargement, jusqu'à ce qu'on en sorte (reprendre, nouveau parcours, un autre scénario choisi ; la liste des scénarios refermée sans choix la laisse en place). Toutes ses commandes font au moins 44 px de haut ; « Lien copié » reste en vue en bas pendant le défilement, sans rien pousser ni bloquer de toucher.
- **L'altitude de chaque plante notée** : à chaque enregistrement d'un lieu ou d'un parcours, l'altitude du sol (RGE ALTI® de l'IGN, jamais celle du GPS du téléphone, imprécise et mesurée au-dessus de l'ellipsoïde) est demandée pour le point du lieu et pour chaque plante qui n'en a pas encore, **par lots** (une requête pour 100 points, au plus 4 par seconde), puis gardée avec la position : une plante déplacée retrouve la sienne, les autres ne sont pas redemandées. Hors ligne ou service indisponible, rien n'est perdu : elles attendent le prochain enregistrement en ligne (pas de nouvel essai avant 10 min). Module « IGN – adresses et altitudes ». L'export GeoJSON et la copie de secours les gardent (`altitude`, en mètres). Le récapitulatif du parcours ajoute **la montée** (« sur 1,0 km, 400 m de montée ») et **le profil d'altitude**, de plante en plante, avec le plus bas et le plus haut ; chaque point dit sa plante et son altitude au survol. Le départ « ici » compte désormais bien comme première étape (il n'était pas gardé).
- **Vue 3D** (bouton « Vue 3D » sur la carte du récapitulatif, et sur chaque lieu de Mes plantes qui a des plantes) : le parcours **sur le relief**, en lecture seule, plein écran par-dessus l'app — c'est **la carte de l'app** (`gf-map`) forcée en 3D (voir « Cartes en 3D ») : chaque plante avec sa photo dans l'anneau de son abondance comme sur toutes les cartes (une feuille sans photo, ou module « Photos en ligne » coupé), le trait de la marche de plante en plante (dans l'ordre où elles ont été notées, la même règle que la distance et le profil du récapitulatif : `app/core/walk.js`), le départ quand le parcours a commencé « ici » (avec son altitude) ; toucher une plante donne son nom et **son altitude** (celle de l'IGN, gardée avec elle). Inclinaison, exagération du relief, ciel… : ceux de Réglages › Cartes. C'est un dialogue : le focus y reste, Échap, ✕ ou Retour le ferment, le focus revient au bouton ; sa carte est détruite à la fermeture (libère la mémoire graphique). Il faut **WebGL2** (sinon le bouton dit « 3D indisponible sur cet appareil ») et le module « Vue 3D (relief) » ; hors ligne, ou relief injoignable, la vue s'ouvre à plat et le dit.
- **La même plante, plusieurs fois** : une ortie rencontrée plus loin s'ajoute encore (le même marqueur ＋, la proposition dit « Déjà une fois dans le parcours ») ; chaque **occurrence** a sa position.
- **La liste** des plantes du parcours, qui défile : **une ligne par plante**, sa vignette (photo), ses noms et, rencontrée plusieurs fois, « × 3 » ; la dernière rencontrée en haut. **Toucher une plante** (dans la liste ou sur la carte) l'allume : **ses occurrences en évidence sur la carte** (les autres plantes ne changent pas), cadrées avec votre position, et **dans l'en-tête** son nom, **le marqueur ＋** (« Ajouter ici ») — une occurrence de plus, là où vous êtes — et ✕, qui retire l'occurrence touchée sur la carte (sinon la dernière), avec « Annuler ». La toucher à nouveau l'éteint.
- **La carte** : **un marqueur par occurrence** (pas de repère qui les regroupe), avec votre position qui suit ; elle est **toujours cadrée sur tout le parcours** (son départ et chaque plante), et se recadre à chaque ajout.
- **Sur ordinateur, la colonne du parcours se redimensionne** : glisser le séparateur entre elle et la carte (une ligne guide suit le pointeur, la largeur est prise au relâcher), ← → au clavier (Maj : par grands pas), Début / Fin pour les extrêmes, double-clic ou Entrée pour la largeur par défaut ; la carte garde toujours 360 px et ne se recadre pas pendant le changement. La largeur est mémorisée.

### Rencontres : les plantes autour de vous (premiers pas)

- **À la première ouverture**, l'application montre **la liste de Découvrir** (l'adresse de départ devient `#/discover` : quitter une mini-application y ramène, même une fois la Flore venue) avec, en petit, « Passer : montrer toute l'application ». **Rencontres** (« Jouer ») commence par une seule action : « Autour de moi » (la position n'est demandée qu'à ce moment) ou une commune. Puis **jusqu'où chercher** : un curseur de 200 m à 50 km (« Juste devant la porte », « Le quartier », « Une balade à pied », « Un tour à vélo », « Toute la région »), **par-dessus une carte** : le cercle du rayon, bien visible, cadré quelle que soit la taille de l'écran, et les observations de plantes qu'il contient (iNaturalist : leur nombre total, et **les 100 plus récentes** sur la carte), **chacune la photo de sa plante** dans un rond qui apparaît l'un après l'autre (sa feuille d'abord, la photo une fois chargée) ; **au survol, une petite fiche** : sa photo, son nom, son nom scientifique, la date et le lieu de l'observation (un toucher ouvre l'observation) ; changer le rayon fait glisser la carte, sans flash. Les cartes des écrans Découvrir n'affichent pas d'alertes de zones protégées.
- **Rencontres, à la Tinder** : les plantes observées dans ce rayon (iNaturalist, observations confirmées, reliées à la flore embarquée), une carte à la fois, **les plus observées — donc les plus photographiées — d'abord**. Chaque carte dit **« On dit de moi : … »** (la première phrase de l'étymologie ou de l'histoire de son article Wikipédia, CC BY-SA ; demandé seulement pour les cartes en vue) et a sa « bio », tirée de ses vraies données : floraison, alertes (toxique, protégée ; sosies dangereux, avec la partie que l'Anses dit consommée — jamais « comestible », ni d'invitation « à table » pour une plante toxique, protégée ou réglementée), popularité dans le coin (en mots, sans chiffre : « Très populaire par ici », « Rare par ici »), famille. **Glisser à droite** : c'est un match (« C'est un match ! »), la plante rejoint les favoris ; **à gauche** : on passe ; **vers le haut** (ou toucher, ou ⋯) : sa fiche. Au clavier : ← →, ↑ **sur le paquet** (Tab y mène ; il dit sa carte et ses touches), ou quand rien n'a le focus — sur un onglet, un bouton, le curseur ou la carte, les flèches gardent leur rôle, jamais de match par mégarde ; les onglets Rencontres, Matchs, Toutes se parcourent aux flèches (un seul arrêt de Tab). Pour les lecteurs d'écran : seule la carte du dessus est lue (celle de dessous est hors d'atteinte), sans les tampons « MATCH » / « BOF » ; les boutons nomment la plante (« Passer : Ail des ours ») ; chaque choix est annoncé (« Match : Ail des ours, ajoutée aux favoris. Carte suivante : … »). La fenêtre du premier match est une vraie boîte de dialogue modale : le focus va sur son bouton et y reste, le reste de la page est hors d'atteinte, Retour la ferme comme le bouton, et le focus revient ensuite au paquet. Fin du paquet : « Chercher jusqu'à 5 km », « Revoir celles passées ». À l'arrivée des cartes, la première **penche un instant à droite puis à gauche** (ses tampons « MATCH » puis « BOF » apparaissent) pour montrer qu'elles se glissent — une fois par ouverture de l'application, pas si les animations sont réduites. Une carte est décidée à 30 % de sa largeur, ou d'un geste vif ; celle de dessous monte telle quelle (pas de clignotement). **↺** revient sur la dernière carte (un match annulé quitte aussi les favoris) ; dans Matchs, « Retirer ». Un match fait vibrer le téléphone.
- **Le premier match présente ses photos** (Rencontres, une fois la découverte guidée finie) : le premier coup de cœur d'une partie dont la plante a des photos ouvre **la visionneuse des « Médias » de la fiche** (la même : sa présentation, son zoom, ses crédits, ses types de médias dans son en-tête ; les photos d'abord), avec une ligne qui dit comment s'en servir (« Voici ses photos. Double-cliquez sur une photo pour zoomer ; ‹ › ou les flèches pour passer à la suivante. » ; au doigt : « Touchez deux fois… glissez… »), jusqu'à « Compris » ou la carte suivante. **Sur grand écran** (900 px et plus), un **volet à côté du paquet**, titré « Photos · <plante> », sa largeur réglable par son séparateur (← → au clavier, double-clic : largeur par défaut) ; il montre d'abord la plante aimée, puis **la carte du dessus** à chaque carte glissée (les photos de la plante en vue, pour décider) ; **×** ou Échap le ferment (le focus revient au paquet, et il reste fermé, même après un rechargement) ; **« Ses photos »** (le bouton aux images sous les cartes) le rouvre, son titre prend le focus. **Sur téléphone**, la visionneuse **plein écran par-dessus le paquet** (une boîte de dialogue modale, une étape de l'historique : Retour, × ou Échap la ferment et le focus revient où il était) ; ensuite « Ses photos » la rouvre sur la carte du dessus. **Une fois par partie** : les matchs suivants n'ont que leur cœur. **↺ sur ce match** ferme les photos et les rend au match suivant ; **Rejouer / Recommencer** les présentent de nouveau et oublient la largeur du volet (`geoflora.app.rencontres.state`, clé `media` : la plante qui les a ouvertes, le volet fermé ; `geoflora.app.rencontres.media` : sa largeur). Une plante **sans photo**, ou le module **« Photos en ligne » désactivé** : rien ne s'ouvre (jamais de volet vide), et c'est le prochain match qui a des photos qui les présente. Lecteurs d'écran : « Photos de <plante> ouvertes, à côté des cartes » est annoncé ; le volet est une région nommée par son titre. Animations réduites : il apparaît sans glisser. Pendant la découverte guidée, le premier match fait déjà venir ses photos à côté des cartes (l'étape « Photos ») : elles comptent pour la partie, la liste ne les présente pas une seconde fois.
- **Matchs** réunit les plantes gardées, **Toutes** les montre en grille (pastilles « En fleur », « Attention · 3 »).
- **La découverte pas à pas, du simple au complexe** (Rencontres) : **une seule mise en page, transformée à chaque étape** — chaque étape y ajoute un composant à découvrir. **Une barre d'étapes**, toujours en haut (dans la mise en page, jamais par-dessus) : Carte · Rencontres · Photos · Encyclopédie · Cueillette ou science · Voisines, celles faites cochées, celle en cours en vert, une ligne qui dit ce qu'elle montre et ce qui vient ; **‹ Précédent** et le bouton de la suivante, qui dit ce qu'elle ajoute (à la fourche, les deux chemins). Sur téléphone, les numéros seuls et le nom de l'étape en cours. **Les étapes se touchent** : une étape déjà atteinte y ramène (la mise en page de cette étape), la suivante avance comme le bouton (sauf la fourche, qui se choisit par ses deux boutons) ; les autres attendent, et chacune dit au survol ce qu'elle apporte. Pendant la découverte, pas de bulle « Nouveau : … » par-dessus : l'onglet arrive simplement dans la barre.
  1. **Carte** : la carte seule, le cercle et un **panneau d'accueil** posé dessus (en bas sur téléphone, à droite sur ordinateur — le cercle se cadre à côté) : « Jusqu'où part l'expédition ? », le lieu (changer de lieu), la distance et son curseur, ce qui a été vu (« 842 observations de plantes, 37 espèces différentes », quelques visages en vignettes) et le gros bouton **« Qui pousse par ici ? »** qui fait venir les cartes. À cette étape, toucher un point de la carte ne fait rien d'autre que montrer sa petite fiche.
  2. **Rencontres** : la même carte glisse à gauche (en haut sur téléphone), **les cartes arrivent à côté** — **rien d'autre : la carte, le bloc du lieu (distance, changer de lieu) et les cartes**, sans légende chiffrée, ni groupes chiffrés sur la carte (au plus 250 points pour la plante en vue), ni choix de zone (la carte reste sur le cercle autour de vous). La plante sur le dessus s'allume sur la carte : **sa photo, en grand, dans chacune de ses observations** (un rond rose et or qui rebondit en arrivant ; sa feuille tant que la photo charge) ; les autres pastilles ne changent pas. **Toucher une plante sur la carte la met sur le dessus du paquet** (une carte passée revient ; une plante déjà aimée s'affiche dans les volets) : les cartes, les médias et la carte la suivent ; une plante qui n'est pas parmi les rencontres est signalée.
  3. **Photos** : **dès le premier coup de cœur** (ou « Ses photos »), un troisième bloc, **Médias**, à côté des cartes, **zoomé** : la première photo s'agrandit doucement, une astuce dit comment zoomer et que le cadenas garde le zoom. **La carte du dessus est la plante du moment** : la carte l'allume, les médias la montrent ; après chaque glissement (coup de cœur ou « Bof »), tout passe à la nouvelle carte du dessus. **Toucher une plante sur la carte** (ou parmi les voisines) met sa carte sur le dessus du paquet, et la carte et les médias la suivent ; une plante déjà aimée revient sur le dessus avec son cœur (« Déjà aimée ») : la glisser, d'un côté ou de l'autre, la remet simplement de côté, toujours aimée. Les volets prennent toute la largeur qui leur revient, même un volet seul sur grand écran.
  **Le périmètre, en un seul bloc** (sur la carte ; sous elle sur téléphone) — la distance n'y est dite qu'une fois : dès le premier match, les **zones** où chercher la plante en vue : le cercle (« ⌖ 1 km »), **son département**, **sa région** (d'après l'adresse IGN du lieu ; hors ligne, d'après les contours embarqués), **la France**, **le Monde** — sur ordinateur toutes visibles, sur téléphone en une rangée qui défile, la zone choisie toujours en vue ; sous le cercle choisi, son curseur ; « changer de lieu » (le département et la région suivent le nouveau lieu) ; et la plante en vue (sa feuille, puis sa photo) avec son nombre d'observations dans la zone (« 2 345 observations (1 000 sur la carte) »). Avant le premier match, seulement la distance et son curseur ; pendant le rechargement des cartes, le bloc garde la plante affichée (rien ne saute). La carte n'a pas d'échelle : le bloc dit déjà la distance. Choisir une zone fait glisser la carte jusqu'à elle ; ses observations iNaturalist y sont placées et regroupées à l'arrivée (jusqu'aux 1 000 plus récentes) : **chaque groupe montre la photo de la plante, leur nombre en pastille**, ses points isolés aussi tant qu'ils sont au plus 40 (au-delà, des points rose et or).
  4. **Encyclopédie** : un volet Wikipédia sous les photos.
  5. **Cueillette ou science** : la cueillette ajoute un volet *Usages · À ne pas confondre · Calendrier* ; la science, *Carte · Occurrences · Climat · Classification*.
  6. **Voisines** : la liste des plantes autour, sous la carte ; puis **La flore complète** : la fiche dans Flore, sur cette plante, tous les onglets, en mode cueillette ou Scientifique selon le chemin choisi.
  **Seuls les volets des étapes franchies** s'affichent pendant la découverte (une carte ou un autre volet déjà dans la mise en page du mode n'y apparaît pas) ; ils rejoignent la mise en page du mode, que Flore montrera ensuite. « Précédent » revient d'une étape (avant la fourche, le chemin choisi est oublié ; depuis Rencontres, retour à la carte seule).
  Les volets suivent **la carte sur le dessus du paquet** : la garder (→, ♥, glisser à droite) ou la passer (←, ✕, glisser à gauche) montre la suivante ; une plante touchée parmi les voisines s'affiche dans les volets. La découverte a sa propre adresse (`#/app/rencontres/…`) : l'arrivée de Flore en cours de route ne la remplace pas.
- **La fiche**, hors découverte (une fois tout montré, ou une carte touchée avant le premier match), s'ouvre en Épuré, par-dessus la liste sur téléphone, à côté sur ordinateur, avec « ‹ Préc. · 3 / 15 · Suivante › » (et ← →, le balayage) ; l'adresse la garde (`#/app/<id>/cards?p=<id>` ; Retour la referme).
- **Les outils arrivent quand ils servent** : la barre d'onglets ne montre d'abord que Découvrir (et Réglages) ; **Mes plantes** vient avec le premier match ou favori, la **Carte** avec le premier lieu noté, **Flore** (toute la flore, recherche et filtres) après 5 plantes rencontrées — quelle que soit la mini-application jouée depuis la liste (un match de Rencontres, un parcours noté, des plantes ouvertes dans Cueillette ou Mosaïque) ; « Passer : montrer toute l'application », sous la liste, montre tout d'un coup. Chaque fois annoncé (« Nouveau : la Carte — … », l'onglet s'éclaire) ; de retour d'une mini-application, les onglets venus pendant la partie sont dans la barre. Pas de micro-astuces : les outils se présentent par les étapes.
- Quelqu'un qui utilisait déjà l'application garde tout, tout de suite. *Réglages › Premiers pas* : « Tout montrer maintenant » ou « Recommencer la découverte ».
- **Recommencer la découverte** (*Réglages › Premiers pas*) repart de zéro : étapes, embranchement et onglets venus sont oubliés, ainsi que les parties de Rencontres, Cueillette prudente et Mosaïque (lieu, distance, cartes passées, matchs ; les favoris restent), et ramène à la liste de Découvrir. **Rejouer** (⋯) ou **Recommencer** (la liste) une seule de ces mini-applications n'efface que sa partie et ce qu'elle a fait (voir « Mini-applications »).

- **Sur ordinateur, les colonnes se redimensionnent** : au premier pas, un séparateur entre la carte et les cartes ; ensuite, deux (carte ┃ cartes ┃ volets de la plante). Glisser le séparateur (une ligne guide suit le pointeur), ← → au clavier (sans faire passer la carte du dessus), Début / Fin, double-clic ou Entrée pour la largeur par défaut. Les volets de la plante gardent toujours 320 px, les cartes 300 : une largeur choisie sur un grand écran se resserre sur un plus petit. La carte ne se recadre pas pendant le changement. Les largeurs sont mémorisées ; sur téléphone, les colonnes restent empilées.

### Onglet Flore : filtres, résultats, plante

- **Ordinateur** : trois panneaux côte à côte, **Filtres ┃ Résultats ┃ Plante**. Chacun se replie (« / ») en une fine barre verticale et se redimensionne en tirant les séparateurs (une ligne guide suit le pointeur, la largeur est prise au relâcher), ← → au clavier (Maj : par grands pas, sans passer à la plante voisine), Début / Fin pour la plus petite et la plus grande largeur, double-clic ou Entrée pour la largeur par défaut ; les Résultats gardent toujours 280 px (une largeur choisie sur un grand écran se resserre sur un plus petit : jamais de défilement de côté). Largeurs et panneaux repliés sont mémorisés (les réglages des versions précédentes sont repris) ; sur téléphone, les panneaux restent empilés, sans séparateur. Les séparateurs sont lus « Redimensionner le panneau filtres / plante », avec leur largeur, leur minimum et leur maximum ; au doigt (tablette), une languette de 44 px les rend faciles à prendre. Toucher un résultat ouvre la fiche dans le panneau Plante (l'adresse `#/plant/<id>` reste partageable) ; ⤢ la passe en pleine largeur, × la ferme.
- **Recherche** en haut des résultats (« Ex. : ortie, Urtica dioica, ger rob, Lamiaceae »). Sous elle, **« Filtrer par »** propose les familles et genres qui commencent par le texte ; en choisir un le met en filtre (le texte s'efface) **et garde les autres propositions**, celle choisie allumée — retouchée, elle s'éteint ; tout éteint, le texte revient.
- **Filtres** : chaque en-tête de filtre reste **toujours visible** — collé en haut une fois dépassé, **empilé en bas tant qu'il est à venir**. Toucher un en-tête collé dont la liste est hors de vue y défile en douceur (sans la replier) ; liste en vue, il la replie. Le champ « Filtrer famille… » reste collé sous son en-tête, sur fond plein, pendant la saisie — même quand le texte tapé réduit la liste à une seule valeur.
- **Au clavier** : Tab atteint chaque ligne de résultat (dans la grille aussi), puis son ♥ et son 📍 ; Entrée ouvre la fiche. L'élément qui a le focus est entouré d'un anneau plein, de la couleur d'accent, partout dans l'application. **Sur téléphone**, la fiche qui s'ouvre par-dessus la liste prend le focus (le nom de la plante) ; la liste et l'en-tête cachés dessous sont hors d'atteinte du clavier et des lecteurs d'écran (la barre d'onglets reste) ; « ← » la ferme et rend le focus à la ligne de la plante.
- **Titres** : chaque vue a un seul titre de niveau 1, lu par les lecteurs d'écran (« Flore : recherche », « Carte des lieux », « Mes plantes », « Parcours botanique : … », « Découvrir » pour sa liste, « Découvrir : étape 2 sur 6, Rencontres ») ; une plante ouverte, c'est son nom, et les noms des panneaux (« Filtres », « Résultats », « Plante ») ne sont plus des titres.
- **Sans saut** : ouvrir une plante depuis les résultats ne recharge rien d'autre — la liste, les filtres et leur défilement restent tels quels, rien ne bouge sous l'en-tête.
- **Grille des résultats** : Photo, Nom français, puis Famille, Genre, Espèce (l'épithète, le genre ayant sa colonne), Statut, Protection, et les actions ♥ (favori) et 📍 (noter où je la trouve ; pleine si la plante est déjà dans un de mes lieux, elle ouvre alors la carte). Trois affichages, au choix par les icônes au-dessus de la grille (lignes · photo · tableau) : **Standard** (sans statut ni protection), **Épuré** (grandes photos, nom français sur le nom scientifique complet) et **Scientifique** (toutes les colonnes, auteur compris). Cliquer un en-tête trie par cette colonne, recliquer inverse l'ordre (`sort=-family` dans l'URL) ; un en-tête dont le filtre est actif affiche son nombre de valeurs, qui ouvre ce filtre. Quand le panneau est étroit, Genre (et Statut) se masquent, puis la liste repasse en fiches.
- **Tablette** : filtres en feuille, Résultats ┃ Plante. Les filtres cochés dans la feuille restent quand elle se ferme, par « Voir N espèces », Retour ou Échap. **Téléphone** : fiches, et la plante s'ouvre en plein écran par-dessus la liste (« ← Résultats » revient au même endroit).
- **Fiche plante : des blocs** : la fiche est faite des mêmes blocs dans les trois modes, en-tête compris : Nom, Photos, Protection et statuts, Plantes à confondre, Classification, Mes collections, Calendrier, Wikipédia, Descriptions, Noms, Occurrences et répartition, Carte, Médias GBIF, Habitat et écologie (GBIF), Trefle, Publications (GBIF), Identifiants, Ressources, et les blocs Note que l'on crée. Chacun est montré à la manière du mode (compact en Épuré, complet en Scientifique ; en Épuré, Noms n'est que la liste des noms français, style réglable en mode King ; Noms (TAXREF et GBIF, en français ; les autres langues seulement si « Autres langues » est coché) ne reprend pas le nom sous lequel la plante est affichée ni les doublons, et n'apparaît pas si la plante n'a pas d'autre nom ; de même, Wikipédia n'apparaît pas sans article) ; par défaut Nom, Photos et Wikipédia se lisent sans titre (le résumé Wikipédia porte sa source : « Source : article Wikipédia »), au choix en mode King ; un bloc sans donnée pour la plante le dit. Certains ont des **sous-blocs** (les lignes de Classification, Occurrences, Noms, Protection, chaque lien de Ressources et chaque Identifiant).
- **Même affichage d'une plante à l'autre** : en parcourant les résultats, la plante suivante s'ouvre comme la précédente — **à la même rubrique**, au même bloc s'il est là (lue sur « Carte », la suivante s'ouvre sur « Carte » ; sinon au début de la rubrique), dans Wikipédia au thème lu dès que l'article arrive — avec les mêmes choix dans les Médias (type, partie de la plante, zoom verrouillé au cadenas, détails ⓘ, diaporama), les mêmes volets ouverts, les thèmes Wikipédia ouverts, « Mes lieux » déplié. **Jamais cachée, jamais de saut** : la fiche apparaît tout de suite à cet endroit (l'en-tête d'une rubrique est là sans attendre les données) et y reste pendant que ses blocs se chargent. Pour la durée de la visite (en mémoire, rien d'enregistré).
- **Wikipédia, lu comme un article** : une seule requête apporte l'article entier (texte brut découpé par section), en cache 7 jours. Le bloc Wikipédia porte **dans son en-tête le sommaire de l'article** par thème — Description, Biologie et floraison, Habitat et écologie, Répartition, Toxicité et confusions, Alimentation, Usages, Noms et étymologie, Histoire et symbolique, Taxonomie —, collé en haut pendant la lecture, le thème lu allumé. Toucher un thème l'ouvre et y mène (une ancre par thème) ; **Description est ouverte d'emblée**, les autres repliées. Les références, liens, galeries et le statut de protection (l'INPN fait foi) sont laissés de côté. Sans article en français : « Lire l'article en anglais ».
- **Wikipédia dans les autres blocs** : chaque thème s'affiche aussi sous les données du bloc qui en parle — Description dans Descriptions, Biologie dans Calendrier, Habitat dans Habitat et écologie, Répartition dans Occurrences, Toxicité / Alimentation / Usages dans Usages et cuisine sauvage, Étymologie dans Noms —, en début de texte (« Lire la suite »), avec « D'après Wikipédia · CC BY-SA 4.0 · Lire dans l'article » qui ramène à son ancre ; dans l'article, « aussi dans « Usages… » → » mène au bloc. Un bloc sans donnée propre s'affiche dès que Wikipédia en parle.
- **Wikidata** : les autres noms français de l'élément (alias, CC0) rejoignent Noms, dédoublonnés.
- **Noms** : les autres noms, en italique et plus petits, sans doublons — même écrits autrement (majuscules, accents, traits d'union, article, pluriel : « Orties », « l'ortie », « Ortie-dioïque ») ou donnés en liste (« grande ortie, ortie dioïque ») ; la forme la mieux écrite (accentuée) est gardée.
- **Les rubriques, comme les filtres** : les blocs de la fiche sont **rangés par rubrique** — dans l'ordre du mode : une rubrique vient là où vient son premier bloc, et l'ordre du Mode King vaut à l'intérieur de chaque rubrique — chaque rubrique sous **son en-tête** (icône, nom, nombre d'alertes), **collé tant qu'on la lit**. Rubriques : **L'essentiel** (classification, noms, identifiants), **Images**, **Alertes**, **Usages** (usages et cuisine sauvage, Wikibooks), **Saisons**, **Encyclopédie** (Wikipédia, descriptions, publications, Trefle, ressources), **Écologie et climat**, **Répartition**, **Carte et territoire**, **Outils et notes**. Une rubrique est là dès que le mode a un bloc pour elle, quelles que soient les données de la plante (« Rien dans les sources consultées » sinon) : la pile garde ses places d'une plante à l'autre.
  - **Quand la place le permet** (au moins 62 % de la fiche restent à lire une fois le titre du bloc collé lui aussi : grand écran, fiche haute…), **toutes les rubriques sont empilées**, comme les en-têtes des filtres : celles déjà passées en haut, celles à venir en bas (au-dessus de la barre d'actions) — toujours toutes en vue, chacune à un toucher. **Sinon** (téléphone, volet bas) : la rubrique lue seule en haut, poussée par la suivante quand on y arrive. Sous l'en-tête, **le titre du bloc lu** reste collé, puis **le thème de l'article lu** dans Wikipédia. Où l'on en est, c'est ce qui est collé : rien n'est calculé pendant le défilement, rien ne clignote, l'en-tête de l'application ne bouge pas. La disposition ne bascule pas pour quelques pixels (la barre d'adresse d'un téléphone qui apparaît) : la pile complète reste jusqu'à 52 % ; quand elle change, la place atteinte (si la main n'a pas bougé depuis) est rejointe sous la nouvelle pile. Ce qui est collé en haut et en bas compte aussi pour le clavier : « Page suivante » et Espace montrent les lignes suivantes sans en sauter, et un élément atteint par Tab n'est jamais caché sous une pile ; un contrôle collé (en-tête, titre de bloc, barre d'actions) qui reçoit le focus ne fait pas défiler la fiche.
  - **Toucher un en-tête** mène au début de la rubrique, juste sous les en-têtes collés au-dessus (son en-tête s'éclaire), dans les deux dispositions. Le **Sommaire** (☰ au bout de chaque en-tête ; touché de nouveau, il se ferme) s'ouvre par-dessus tout, sous l'en-tête — ou au-dessus quand la place manque en dessous (pile du bas), toujours entier à l'écran : ce qu'est la fiche (« Espèce », « Sous-espèce », « Variété », « Hybride », « Genre »), chaque rubrique, ses blocs, les **thèmes de l'article Wikipédia** — un toucher y mène —, **la place lue marquée**, et **le cadenas**. Au clavier, le focus y entre (↑ ↓, Début, Fin), Échap le ferme et revient au ☰ — sans fermer la plante dans Découvrir ni en changer avec ← → ; une entrée choisie y mène et le focus la suit (Tab continue de là). Il se ferme quand la main fait défiler la fiche, pas quand le contenu arrive pendant qu'il est ouvert. Une rubrique dont les blocs sont dans un volet le dit (« dans un volet ») et, touchée, déplie le volet sur le bon onglet ; un thème de l'article choisi quand Wikipédia est dans un volet fait défiler ce volet, pas la fiche.
  - **Les places tombent pile et y restent** : une rubrique, un bloc ou un thème vient exactement sous ce qui est collé au-dessus de lui — d'un coup, en glissant seulement si c'est à moins d'un écran (pas avec « animations réduites ») — puis **reste en place pendant que le contenu au-dessus arrive** (photos, article, données) — tant que les données de la plante arrivent, même lentement, et jusqu'à ce que la fiche ne grandisse plus — ou jusqu'au premier geste de la main (molette, toucher, clavier) : la main a toujours le dernier mot, la fiche ne s'aimante jamais. **Lire à la main pendant le chargement** ne fait pas sauter non plus : quand la main s'arrête et se lève, la ligne lue (ou le début du bloc lu, encore vide) reste où elle est jusqu'à la fin du chargement — jamais sous un doigt encore posé ni sous le pouce de la barre de défilement, et tout défilement qui ne vient pas de la fiche la rend à la main. Une source qui ne répond pas ne compte plus au bout de 15 s. Changer de vue (Épuré, Standard, Scientifique) ou passer en Mode King et en revenir garde le bloc lu en vue. La fin de la fiche laisse la place pour que la dernière rubrique vienne en haut, elle aussi.
  - **La mémoire** (la place où s'ouvrira la plante suivante) s'écrit quand on choisit une place — Sommaire, en-tête, menu de l'article, « Lire dans l'article », une carte de la fiche mise en avant — et quand la main arrête la fiche (même si l'on passe aussitôt à la plante suivante) — jamais pendant un défilement de l'app. **Le cadenas** (dans le Sommaire) la verrouille : chaque plante s'ouvre à l'endroit lu au moment du verrouillage, même si l'on a défilé ailleurs entre-temps (choisir une place déplace le verrou).
  - **Mode King** : la liste simple des blocs, chacun avec sa poignée (ranger, masquer, renommer), sans rubriques collées.
  - Dans Flore, Mes plantes et Découvrir, l'en-tête du panneau Plante dit simplement « Plante » (Découvrir : le nom de la plante) ; les rubriques sont dans la fiche.
- **Barre d'actions** : Favori, Ajouter à… (choisir une collection ou un lieu), Partager, Noter ici, dans une barre fixée en bas de la fiche (au-dessus du menu sur téléphone), toujours à portée pendant le défilement. Chaque action s'affiche ou non, et s'ordonne, pour chaque mode : en mode King, une case ☑ sur chaque bouton de la barre ; dans *Réglages › Mode King › Barre d'actions*, la liste à cocher et à glisser.
- **Mode King** (en haut des *Réglages*) : le mode d'édition de la fiche. Une couronne dorée s'affiche en bas de l'écran tant qu'il est actif ; la toucher quitte le mode (elle disparaît). Tout est enregistré automatiquement, pour chaque mode d'affichage :
  - **ordre** : glisser un bloc par son titre (souris ou doigt ; pendant le glisser, les blocs se replient sur leur titre ; ↑ ↓ au clavier sur sa poignée ⠿) ; les sous-blocs s'ordonnent depuis l'icône « Sous-blocs » de leur bloc ;
  - **présence** : la corbeille masque un bloc (il reste, estompé, avec ↺ pour le réafficher ; hors mode King il n'apparaît pas et n'est pas chargé), une case masque un sous-bloc. Masquer un bloc de service (Photos, Wikipédia, Trefle) coupe ce module dans ce mode, comme dans *Réglages › Modules*, et inversement ; GBIF a plusieurs blocs, masqués un à un : le module n'est coupé qu'avec le dernier, et réafficher l'un d'eux le rallume ;
  - **masqué si vide** : l'icône « œil barré » d'un bloc qui peut n'avoir rien pour une plante (Protection, Plantes à confondre, Mes collections, Calendrier, Photos, Wikipédia, Descriptions, Noms, Occurrences, Médias GBIF, Habitat, Trefle, Publications, blocs Note) le retire de la fiche hors mode King quand il est vide, au lieu d'afficher « Aucune… » ; pour chaque mode (par défaut : Wikipédia, Noms, Habitat et Publications) ;
  - **titres** : ✎ renomme un bloc (vide : son nom d'origine) ;
  - **titre affiché ou caché** : l'icône « H2 » montre ou cache le titre d'un bloc hors mode King, pour chaque mode (par défaut Nom, Actions, Photos et Wikipédia sont sans titre) ;
  - **style** : certains blocs ont deux styles, au choix pour chaque mode (Noms : « Liste », les noms français seuls, par défaut en Épuré ; ou « Tableau », avec les autres langues et les sources) ;
  - **blocs Note** : « + Bloc Note » crée un bloc nommé, avec un texte libre par plante, gardé sur l'appareil (dans IndexedDB, avec les collections ; les notes des versions précédentes, dans le `localStorage`, y sont déplacées une fois au lancement, sans perte), dans l'export GeoJSON, le lien de transfert avec données personnelles et la copie de secours ; « Enregistré sur cet appareil » ne s'affiche qu'une fois le texte réellement enregistré, sinon « Non enregistré » ; ✕ le supprime avec ses textes. Importer une mise en page **ajoute** ses notes aux vôtres, sans jamais les remplacer ;
  - **blocs Carte** : la fiche a un bloc « Carte », et « + Bloc Carte » en ajoute d'autres, placés, renommés et masqués comme les autres blocs (✕ supprime une carte ajoutée). L'engrenage ⚙ d'une carte règle, pour tous les modes :
  - **le sujet de la carte** (en tête de sa portée) : **Cette plante** (sa répartition, mes lieux où elle est, ce qui est autour, ses sosies, une zone touchée), **Les résultats** (les plantes de la recherche et de ses filtres : mes lieux où elles sont, la carte suit quand les filtres changent) ou **une collection** (un lieu : lui et ses plantes ; une liste ou les favoris : les lieux où sont ses plantes). Hors « Cette plante », les couches propres à la plante (GBIF, autour de moi, sosies) s'effacent ; le cadrage suit les lieux montrés. Gardé pour cette carte (et dans ses réglages du mode King).
  - **la portée de la carte, sous elle** : tout ce qu'elle peut montrer, proposé selon ce qui est connu. **Cadrer** : Auto (selon ce qui est affiché), **Ma région** dès que votre région est connue (votre dernière position, ou le lieu choisi dans Découvrir ; la région vient de l'adresse IGN), **Autour de moi** (vous localise si besoin), **Les points** quand il y en a, France, Monde. **Rayon** (500 m à 10 km), dès qu'on cadre autour de soi ou qu'on montre ce qui est autour : gardé comme dans la Carte, les observations sont recherchées à nouveau. **Données** : la répartition GBIF (France ou Monde), Mes lieux, les observations **iNaturalist** et **GBIF autour de moi** (avec leur nombre), et **les sosies** de la plante (« Sosie : Colchique » pour l'ail des ours : leur répartition GBIF en violet, à côté). **Couches IGN** : parcelles, courbes de niveau, forêts publiques, parcs nationaux, réserves naturelles, protection de biotope. Chaque choix est gardé pour cette carte, comme dans ses réglages du mode King.
  - **une zone touchée dans la fiche** (une région, un département, dans Occurrences et répartition) : la carte **attend d'avoir la zone** — son contour et ses occurrences, demandés ensemble — puis **glisse en douceur** jusqu'à elle, sans repasser par la vue par défaut ; d'une région à une autre, elle va directement de l'une à l'autre. **Le contour** de la zone est tracé (pointillés ambrés, IGN ADMIN EXPRESS, pour les régions et départements français) et **ses occurrences** placées en points (jusqu'à 300), **regroupés** quand ils sont proches : un disque avec leur nombre, plus grand quand ils sont plus nombreux ; **le toucher déploie ses points** en éventail autour de lui, chacun relié à sa place (sa fiche au survol, son enregistrement au clic) — un très gros groupe (plus de 24) zoome d'abord sur sa zone ; un toucher ailleurs ou un zoom les regroupe. Les observations autour de moi sont regroupées de même, chaque source dans sa couleur (iNaturalist vert, GBIF bleu). La légende dit combien d'occurrences, combien placées, et les limites tracées. ✕ sur la pastille de la zone : retour en douceur.
    - ce qu'elle montre, à cumuler : répartition GBIF (France ou monde), mes lieux de cette plante (et chaque plant à sa position), observations proches (iNaturalist, GBIF ou les deux, dans le rayon d'« Autour » ; la position n'est demandée qu'au premier toucher de « Observations autour de moi ») ;
    - son fond (plan IGN ou photos aériennes) et ses couches IGN (cadastre, courbes, forêts publiques, espaces protégés), propres à cette carte : le bouton « couches » de la carte les change aussi, sans toucher au choix de l'onglet Carte ;
    - son cadrage (France entière, ajusté à ce qui est affiché, autour de moi) et sa hauteur ;
    - ses actions : « Ouvrir dans la Carte » (l'onglet Carte filtré sur la plante, avec sa répartition GBIF), créer un endroit ici (appui long : le nouvel endroit contient déjà la plante), déplacer mes plants (✎), « Noter ici », « Me localiser » (les boutons ronds de la carte — couches, me localiser, ✎ — sont petits et translucides, la carte d'abord ; ils s'affirment au survol). **Les petites fiches des plantes** (au survol d'un point, au toucher sur téléphone) **passent par-dessus tout** : boutons et panneaux de la carte, bandeaux de la page autour ; elles se posent au-dessus du point (en dessous s'il n'y a pas la place) et disparaissent dès que la carte bouge. Toucher un de mes lieux l'ouvre ; toucher une observation ouvre sa page ;
  - **Modeler la mise en page : un arbre de volets.** Le panneau Plante est, pour chaque mode, un arbre de volets comme dans un éditeur : la **fiche** (qui défile) et, à côté, au-dessus ou en dessous, des **volets** qui tiennent des blocs en **onglets**, découpés en lignes et en colonnes. En mode King, on **glisse** un bloc — par son titre, par son onglet, ou depuis la palette **« Ajouter »** (les blocs masqués, et « Nouvelle carte ») :
    - **près d'un bord** d'un volet ou de la fiche : un **nouveau volet** de ce côté (la moitié qu'il prendra s'ombre) ;
    - **au milieu d'un volet** : un de ses **onglets** ; sur sa barre d'onglets : entre deux onglets ;
    - **dans la fiche** : il y revient, à la place marquée d'un trait entre deux blocs (c'est aussi le geste pour réordonner la fiche) ;
    - **sur le bord extérieur** du panneau : une bande ou une colonne sur toute sa largeur ou sa hauteur.
    Échap annule ; un volet vidé disparaît. Exemple : à côté de la fiche, la répartition, puis le calendrier dessous, puis une carte en onglet. Au clavier ou au doigt, **« Déplacer vers… »** sur un bloc fait de même (dans la fiche, nouveau volet à droite / gauche / en haut / en bas, onglet d'un volet). Les **poignées** entre volets se tirent (aussi hors mode King ; ← → ou ↑ ↓ au clavier, Maj : par grands pas, Début / Fin jusqu'au bout, double-clic ou Entrée : parts égales ; lues « Redimensionner la fiche et « Classification » », avec leur part en % ; au doigt, une zone de 44 px et une languette ; le volet des Médias garde au moins 400 px de haut et 280 px de large — sa photo, sa barre de zoom et ses vignettes ne se chevauchent jamais, et sa bande sur une fiche étroite aussi ; en volet, le choix du type de média — photos, herbiers… —, les parties de la plante et le compteur « 1 / 4 » sont **dans l'en-tête du volet**, une ligne de gagnée pour l'image) ; la disposition est gardée **par mode**, partout où la fiche s'affiche (Flore, Mes plantes, Découvrir) et d'une plante à l'autre. Une vue qui garde sa propre disposition (une mini-application) donne à la fiche son arbre de volets (propriété `tree` de `gf-plant-detail`) : poignées, onglets, volets repliés ou déplacés lui reviennent (événement `pane-sizes`), sans toucher à celle du mode. Sur une fiche étroite (téléphone), les volets deviennent des bandes au-dessus et au-dessous de la fiche, dans l'ordre de l'arbre (l'arbre lui-même ne change pas). Le panneau Plante de Flore et de Mes plantes s'élargit quand des volets sont à côté de la fiche. Les mises en page des versions précédentes (blocs collés aux bords, « à côté ») sont converties en arbre. **Page web** : un bloc à placer dans un volet (puce de la palette du mode King, ou « Déplacer vers… »). Une fois dans la mise en page, **les liens de l'application vers d'autres sites s'y ouvrent** au lieu d'un nouvel onglet — un lien Wikipédia (ouvert dans sa version mobile, faite pour une colonne), une fiche INPN, une page GBIF, une ressource… — et l'onglet « Page web » passe devant s'il était derrière un autre. Le volet a sa barre : ← → parmi les pages ouvertes, l'adresse, « ouvrir dans un nouvel onglet », fermer la page ; la page reste d'une plante à l'autre. Certains sites refusent d'être affichés dans un autre (la page reste vide) : une ligne propose de l'ouvrir dans un onglet. Ctrl, ⌘ ou Maj + clic, ou le clic du milieu, gardent le comportement du navigateur ; sans volet Page web, rien ne change.
  - **options d'un volet** (sa barre) : ⚙ **Sans titre ni cadre** (le bloc remplit le volet, ses onglets et « agrandir » flottent dessus), **Replié** (la barre seule, le volet s'ouvre au toucher) ; **Agrandir** (⤢ : le volet couvre tout le panneau, Échap ou ⤡ le remet) ; replier / déplier.
  - **tableau ou liste** : les données en lignes (Occurrences : régions et départements, types de relevés, sources ; Habitat et écologie ; Publications ; Identifiants) se lisent en **tableau** par défaut (valeur, nombre, part avec une petite barre), ou en **liste** compacte, au choix pour chaque mode.
  - **Réglages › Mode King** : pour chaque mode, le **panneau Plante en miniature** (la fiche et ses blocs, les volets et leurs onglets) où l'on glisse les blocs comme sur la fiche — la fiche suit en direct —, puis les mêmes listes (glisser : toute la ligne à la souris, la poignée au doigt ; « Position » : dans la fiche ou un nouveau volet d'un côté), avec leurs sous-blocs, « Par défaut », « Nouveau bloc Note », **Exporter / Importer la mise en page** (un fichier JSON, version 2 : ordre, blocs et sous-blocs masqués, titres, arbre de volets, blocs Note et leurs textes ; un fichier de version 1 est converti) et « Tout réinitialiser » — ces trois boutons sont toujours visibles dans *Réglages › Mode King*, même sans entrer dans le mode.
- **Médias : la visionneuse** : le bloc **Médias** de la fiche (par défaut en Standard et Scientifique, à la place de Photos et Médias GBIF, qui restent disponibles en mode King ; en Épuré, la grande photo l'ouvre) réunit les images de la plante, de toutes les sources : photo du jeu de données, Wikimedia Commons, photos choisies du taxon sur iNaturalist, photos d'observation et planches d'herbier GBIF (licences libres seulement, auteur et licence sur chaque image).
  - **Dans la fiche** (compact) : l'image dans un cadre de forme fixe (4:3, 3:2 quand la fiche est large : rien ne saute d'une plante à l'autre ; pendant le chargement, la visionneuse a déjà sa taille), son crédit en une ligne, la pellicule des autres ; le type de média (Photos, Observations, Herbier) se choisit dans un menu quand il y en a plusieurs ; ⤢ l'ouvre **en volet**, sur l'image montrée. Dans le flux de la fiche, la molette fait défiler la fiche (Ctrl + molette zoome) ; collée à un bord de la fiche ou en volet, la molette zoome sur l'image.
  - **En volet** : l'image en grand. L'adresse `#/plant/<id>?pane=media&i=<n>` ouvre directement la n-ième image (les liens `?media=<n>` aussi).
  - **Zoom et carte de l'image** : une image plus haute que le cadre le remplit en largeur, et la **carte de l'image entière** se pose sur son bord droit, de toute la hauteur (fond sombre presque opaque, la zone vue cernée d'un trait fin) — quand elle tient (au plus 45 % de la largeur, 35 % sur téléphone ; sinon l'image entière). **Chaque image s'ouvre zoomée à 50 %** (un pixel de l'original pour deux : net, ses détails à portée), centrée — sauf une image trop petite pour cela, qui s'ouvre sur toute la largeur ; avec l'économiseur de données du navigateur, pas plus loin que ce que sa taille d'affichage permet (l'original n'est alors téléchargé qu'en zoomant). **Jamais au-delà de 100 %** (un pixel de l'original par pixel d'écran), ni à l'ouverture, ni au zoom : une petite image n'est pas agrandie, même entière (elle s'affiche à sa taille sur son fond flouté). Le bouton du milieu passe de « Largeur » (toute la largeur) à « 50 % » puis « 100 % », sur l'image montrée. Le **cadenas** de la barre de zoom garde le zoom affiché (son pourcentage) pour les images et les plantes suivantes ; déverrouillé (par défaut), chaque image repart à 50 %.
  - **Un fondu enchaîné partout** : quelle que soit la façon de changer d'image — ‹ ›, les flèches du clavier, un glissement, la pellicule, la mosaïque, le diaporama, le type ou la partie, l'adresse (Précédent, un lien), une photo touchée sur la fiche —, zoomée ou non, l'image qui part reste en dessous, telle qu'elle était (une copie peinte, sans nouveau téléchargement : jamais d'écran noir), pendant que la suivante apparaît en fondu par-dessus ; des changements rapprochés s'enchaînent sans saut. Les vignettes de la pellicule, de la mosaïque et de la carte de l'image apparaissent en fondu une fois chargées. Seulement de l'opacité (léger pour l'appareil) ; rien si le système demande moins d'animations. (Le passage à une autre plante change encore toute la fiche : son fondu viendra avec le modèle des mini-apps.)
  - **Toujours au moins toute la largeur** : au moindre zoom, l'image remplit la largeur du cadre (une image haute se fait défiler de haut en bas) ; le bouton du milieu dit alors « Largeur ». Seule exception : un original plus étroit que le cadre s'affiche à sa taille (100 %), sur son fond flouté.
  - **La carte de l'image, discrète** : le cadre de la partie vue est fin et à peine marqué ; il s'éclaire quand on pointe ou fait glisser la carte, puis redevient discret doucement.
  - **Glisser sur téléphone** : dans la fiche, glisser sur une image change d'image, plus de plante ; une image plus large que l'écran se fait d'abord défiler, puis un glissement vif contre son bord passe à la suivante.
  - **Le plus détaillé d'abord** : dans chaque type, les images les plus grandes (en pixels, quand la source le dit) passent devant, puis les plus récentes.
  - **Parties de la plante (Trefle)** : avec un jeton Trefle (*Réglages › Modules*), les photos Pl@ntNet par partie s'ajoutent — seulement celles dont le crédit porte une licence libre (« (cc-by-sa) »…), la plupart (Photoflora) n'en ayant pas. Un menu d'icônes — Toutes, Fleur, Feuille, Fruit, Écorce, Port — filtre la scène, la pellicule, la mosaïque et le diaporama.
  - **Hauteur réglable** : dans la fiche, une poignée sous l'image en règle la hauteur (glisser, ↑ ↓, double-clic : taille par défaut) ; gardée comme une proportion de la largeur (elle suit l'écran), pour toutes les plantes et d'une visite à l'autre.
  - **Détails ⓘ** : sur écran étroit sous l'image, sur écran large à côté — jamais par-dessus, entiers quel que soit le zoom. À côté (visionneuse de 760 px et plus), leur largeur se règle par leur séparateur (l'image garde 320 px ; ← → au clavier, double-clic ou Entrée : 30 % par défaut), retenue (`geoflora.mediaLayout`).
  - **Rien ne saute au chargement** : l'image montrée est choisie une fois, quand toutes les sources ont répondu ou 0,9 s après les premières (avant, le squelette de la visionneuse, à sa taille) ; la pellicule garde sa place ; quand la vraie forme de l'image arrive, l'image glisse en place ; la carte de l'image apparaît en fondu ; le bouton de vue a une largeur fixe.
  - **Fond flouté** : là où l'image ne couvre pas le cadre, la même image, agrandie et floutée, le remplit.
  - **La carte de l'image** : saisir le cadre de la zone vue le déplace depuis l'endroit saisi (sans sauter) ; toucher ailleurs sur la carte y fait glisser la vue en douceur.
  - **Un seul zoom, comme dans une appli Photos** : double-clic ou double-tap pour zoomer à l'endroit pointé (encore une fois : l'image entière), la molette pour un zoom progressif quand la visionneuse est collée à un bord ou en volet (Ctrl + molette dans le flux de la fiche), ou pincer, les boutons − / vue / + en bas à droite (« 100 % » : un pixel de l'original par pixel d'écran), et glisser pour se déplacer. Dès que l'image dépasse le cadre, la **carte** de l'image entière montre la zone vue ; la toucher ou y glisser déplace la vue. La carte couvrant le haut droit du cadre, l'image zoomée peut être poussée au-delà de ce côté — vers la gauche jusqu'à dégager son bord droit, vers le bas (carte moins haute que le cadre) jusqu'à passer sous la carte — : aucune partie n'en reste cachée ; ailleurs, pas de bande vide. Le cadre de la zone vue reste toujours entier dans la carte. Les flèches ‹ › sont **en bas du cadre, une dans chaque coin**, à la même place d'une image à l'autre, zoomé ou non (par-dessus la carte quand elle descend jusque-là) ; la barre de zoom se tient à côté de la flèche suivante. Clavier (quand la visionneuse a le focus) : ← → (image précédente / suivante, ou se déplacer quand on est zoomé), + − 0, Échap (l'image entière, puis fermer).
  - **La bonne image au bon moment, toute seule** : la vignette s'affiche aussitôt (floutée), l'image d'affichage (iNaturalist « large », Commons 1 280 px) apparaît en fondu, **sans effet de zoom** (l'image prend sa place d'un coup), et dès que le zoom dépasse ce qu'elle contient, **l'original** se charge (un point discret dans la ligne de crédit, qui pulse pendant le chargement). Rien n'est posé sur l'image hormis les boutons et la carte ; le crédit tient en une ligne discrète dessous. Une image qui ne se charge à aucune taille **disparaît** de la scène, du bandeau, de la mosaïque et des comptes, et la suivante s'affiche ; ailleurs dans l'application, une image en échec se cache sans icône cassée, et toutes les images hors écran se chargent à la demande. Les images voisines sont préchargées.
  - **Calme** : le crédit (type, source, auteur, licence) tient en une ligne sous l'image ; ⓘ ouvre le détail (taille de l'original, collection, année, lieu, « Voir à la source », « Ouvrir l'original »). Sur ordinateur, les commandes s'effacent quand la souris reste immobile. Au doigt : balayer change d'image quand on n'est pas zoomé ; zoomé, glisser déplace la vue.
  - Les tailles se déduisent des adresses des images (iNaturalist `…/photos/<id>/square|small|medium|large|original`, Commons `…/thumb/…/<N>px-<fichier>` et le fichier), dans `app/core/media-items.js` ; une taille qui n'existe pas (Commons n'agrandit pas) bascule sur l'image donnée par la source. Les originaux, lourds, ne sont pas gardés par le service worker.
  - **Présentations** (style du bloc, en mode King) : **Scène** (la photo, ses détails et la pellicule), **Mosaïque** (toutes les images en grille ; une image touchée s'ouvre dans la scène, « ← Mosaïque » y revient) ou **Diaporama** (une image à la fois, ▶ pour défiler toutes les 5 s). Le zoom marche partout.
- **Les blocs en volet** : tout bloc de la fiche (sauf Nom et la barre d'actions) peut s'ouvrir **en grand dans un volet à côté de la fiche** : ⤢ sur son titre (au survol sur ordinateur). Le volet prend la place des résultats (les filtres se replient ; les déplier ferme le volet), avec le nom du bloc et de la plante, « plein écran » (toute la largeur) et ✕ ; dans la fiche, le bloc laisse une ligne « affiché dans le volet ». Une carte y remplit toute la hauteur, les tableaux s'y lisent en entier, la visionneuse y a sa loupe à côté. L'adresse `#/plant/<id>?pane=<bloc>` est partageable ; Retour ferme le volet ; plante précédente / suivante garde le volet ouvert, sur la nouvelle plante. Téléphone : le volet couvre la fiche (« ← Fiche ») ; hors de Flore (Mes plantes, Carte) : par-dessus la page.
- **Plante précédente / suivante** : une barre en bas du volet de la fiche (juste au-dessus du menu sur téléphone) parcourt les résultats dans leur ordre — ou, dans *Mes plantes*, les plantes de la collection ou de l'endroit ouvert. Sur téléphone, simple : « ‹ Préc. · 3 / 17 · Résultats « ortie » · Suiv. › ». Sur ordinateur, complète : première, précédente, les positions autour (1 … 4 5 **6** 7 8 … 17), un champ pour aller directement à un numéro, d'où vient la liste, suivante, dernière ; un trait en haut de la barre montre où l'on en est. Les touches ← → font de même ; sur téléphone, la fiche se balaie comme une carte (à la Tinder, en CSS) : elle suit le doigt en s'inclinant, et la fiche de la plante vers laquelle on va attend déjà dessous, grandissant à mesure ; lâchée assez loin (ou d'un geste vif), elle poursuit sa course hors de l'écran et la fiche de dessous, déjà chargée, devient la fiche ouverte, sinon elle revient en place ; pas sur une carte ni une galerie. Sur ordinateur et tablette, pas de balayage : ‹ › et les touches ← → font disparaître la fiche en fondu, puis apparaître la suivante (déjà chargée). La ligne de la plante reste visible dans la liste, « Résultats » ramène à la liste et le retour à la plante précédente.

### Modules : les services en ligne, un par un

L'app fonctionne hors ligne avec la flore locale ; chaque service en ligne est un **module** qu'on active **mode par mode** dans **Réglages › Modules** : trois cases, Épuré · Standard · Scientifique (toutes cochées par défaut ; Trefle demande un jeton). La fiche plante suit son affichage, la grille des résultats le sien, la carte et le reste le mode de l'application. Dans un mode où il est décoché, un module n'est jamais appelé et ses données ne s'affichent pas, copies en cache comprises :

**Catégories.** Les services, comme les blocs de la fiche, sont rangés par ce que la donnée dit de la plante, quel qu'en soit le fournisseur (GBIF, par exemple, sert à plusieurs) :

| Catégorie | Question | Services |
|---|---|---|
| L'essentiel | Qui est-elle, en quelques mots ? | Wikidata (TAXREF en local ; aussi GBIF) |
| Images | À quoi ressemble-t-elle ? | Wikimedia Commons, Photos en ligne (aussi GBIF, iNaturalist) |
| Alertes | Quels risques lui connaît-on ? | statuts INPN et plantes à confondre en local (aussi GBIF, Wikidata, IGN espaces protégés) |
| Usages | À quoi sert-elle, se mange-t-elle ? | Wikibooks (recettes) |
| Saisons | Quand la voir ? | Baseflor en local (aussi iNaturalist, Open-Meteo pollens) |
| Encyclopédie | Que sait-on d'elle ? | Wikipédia, Trefle (aussi GBIF, Wikidata) |

Vous pouvez le réactiver dans Réglages › Modules »). Seul un geste de l'utilisateur (ramener un bloc à la main, cocher le module) le rallume.

### Mentions légales, confidentialité et position

**Réglages › Mentions légales et confidentialité** (`#/legal`) dit qui publie GeoFlora et où il est hébergé (GitHub Pages), comment le contacter (issues du dépôt, `SECURITY.md` pour une faille), qu'il n'y a ni compte, ni publicité, ni mesure d'audience, ce qui reste sur l'appareil (flore, lieux et collections, réglages, dernier lieu de Découvrir, réponses des services gardées de 7 jours à un an, images et cartes en cache) et, service par service, ce qui est envoyé, votre position surtout et quand. Deux boutons : **Oublier ma dernière position** (Découvrir) et **Effacer le cache des services en ligne**.

**La position, après un geste.** Le navigateur ne demande la position qu'après « Autour de moi », « Me localiser », « Commencer ici », « Noter ici » ou « Près d'ici » ; la Carte, Mes plantes, un lieu ou un parcours repris ne la suivent d'eux-mêmes que si l'autorisation est déjà accordée (`whenGranted`, `app/core/geo.js`). Avant un envoi, une ligne dit à quel service elle part (Découvrir, Parcours, « Près d'ici », climat ici, observations autour de moi sur la carte d'une fiche, Autour de la Carte, adresse d'un nouveau lieu).

### Modes d'affichage : Épuré, Standard, Scientifique

Un mode pour toute l'application, choisi par trois icônes dans l'en-tête (ou dans Réglages › Affichage sur téléphone) :

- **Épuré** — grandes photos et actions rapides. La fiche plante devient une « porte de collection » : photo, noms, famille, alertes de protection, calendrier de floraison, et un gros bouton **« ＋ Ajouter à <collection en cours> »** (« ✓ Dans … » une fois ajoutée, un nouvel appui la retire). La collection ou le lieu en cours se choisit dans la liste juste dessous et reste mémorisé ; c'est aussi la dernière collection utilisée dans « Ajouter à… ».
- **Standard** — grand public : calendrier, photos, description (résumé Wikipédia, sinon GBIF), noms ; « Dans mes collections » tient en une ligne qu'on déplie.
- **Scientifique** — tout ce que l'application connaît ou peut obtenir, sources citées : classification (Wikidata, jusqu'à l'ordre), auteur, synonymes, noms dans d'autres langues, tous les statuts INPN par territoire, statut UICN mondial, phénologie, observations iNaturalist, occurrences GBIF en France, répartition et descriptions GBIF, médias GBIF, données Trefle (avec votre jeton), identifiants (TAXREF, INPN, GBIF, iNaturalist, Wikidata, Tela Botanica, IPNI, POWO).

La grille des résultats et la fiche plante ont chacune leurs icônes pour s'écarter du mode (un point ↺ ramène au mode de l'application) ; changer le mode de l'application les réaligne.

**Vos modes** (*Réglages › Affichage › Modes d'affichage*) : « Dupliquer » un mode en crée un nouveau, copie de celui-ci — blocs et sous-blocs, ordre, titres, styles, épinglés et leur position, volets, barre d'actions, modules — qu'on renomme, à qui on donne une icône, puis qu'on arrange à sa guise en mode King et dans les modules, sans toucher à son modèle. Par exemple une **visionneuse** (à partir d'Épuré : Médias en volet, presque rien d'autre) ou un **poste scientifique** (à partir de Scientifique : carte épinglée, interactions, climat, occurrences en volet). Il s'affiche à la manière de son modèle (Épuré, Standard ou Scientifique : la grille des résultats et la façon de dessiner chaque bloc), apparaît dans tous les sélecteurs d'affichage et voyage avec la mise en page exportée. « Supprimer » l'efface avec sa mise en page ; s'il était utilisé, l'application revient au mode Standard. Les trois modes de l'application restent, modifiables et réinitialisables.

### Recherche, filtres et tri

- **Texte** : noms français, noms scientifiques, synonymes et familles, sans tenir compte des accents ni des majuscules, ligatures comprises (`benoite` → *Benoîte*, `oeillet des chartreux` → *Œillet des Chartreux*).
- **Filtres à longue liste** (Famille, Genre) : leur champ « Filtrer… » reste sous le titre du filtre pendant que sa liste défile ; il ne s'en va qu'avec la fin du filtre, ou quand on le replie.
- **Partout la même recherche** : « Ajouter une plante » (liste, lieu) et « Noter ici » trouvent les mêmes plantes, dans le même ordre, que l'onglet Flore, avec leur nombre et « Afficher plus » jusqu'à la dernière.
- **La liste ne bouge pas** sous les actions d'une ligne (♥ favori…) : elle ne revient en haut que pour une nouvelle recherche (texte, filtres, tri), et retrouve sa position au retour d'une fiche plante.
- **Abréviations** : chaque mot tapé correspond au début d'un mot du nom, dans l'ordre (`ger rob` → *Geranium robertianum*, `ben vil` → *Benoîte des villes*).
- **Fautes de frappe** : s'il y a moins de 5 résultats, une seconde passe tolère 1 faute (mots de 5 lettres et plus) ou 2 fautes (8 lettres et plus), avec la mention « résultats approchants » (`pisenlit` → *Taraxacum*).
- **Suggestions** : les familles et genres qui commencent par le texte saisi sont proposés comme filtres en un clic (`ros` → Rosaceae, *Rosa*).
- **Filtres à choix multiples** : statut, famille, genre, photo, nom français. Les valeurs d'un même filtre se combinent en OU, les filtres entre eux en ET. Chaque valeur affiche le nombre de résultats qu'on obtiendrait en l'ajoutant.
- **Tri** : pertinence, nom français, nom scientifique, famille, avec photo d'abord. Un affichage **compact** est disponible.
- **URL partageable** : `#/?q=ortie&family=Urticaceae,Lamiaceae&status=I,J&photo=avec&sort=sci`.

Sur ordinateur, les filtres sont dans un panneau latéral ; sur mobile, dans un panneau qui s'ouvre depuis le bas de l'écran.

Fonctionnement :

1. au démarrage, l'app part **aussitôt sur la copie locale** de la flore quand elle en a une ; `data/meta.json` est vérifié en arrière-plan (8 s au plus : un réseau lent ou muet ne bloque jamais la recherche). `data/plants.json` n'est téléchargé que si son contenu a changé (son empreinte sha256, publiée dans `meta.json` — une nouvelle construction de la même flore ne se retélécharge pas), vérifié (empreinte, nombre de plantes) puis stocké dans IndexedDB à la place de l'ancienne copie ; la recherche passe alors sur la nouvelle flore, sans recharger. Un téléchargement qui échoue ou ne correspond pas laisse la copie locale intacte (« Mise à jour de la flore reportée ») ; il est retenté au lancement suivant. Seule la première visite attend le téléchargement ;
2. un Web Worker construit l'index de recherche depuis IndexedDB ;
3. la fiche plante appelle `PlantSources.details()` à la demande, et la réponse reste en cache dans IndexedDB ;
4. sans réseau, la recherche, les fiches déjà consultées et les images déjà vues restent disponibles. Seule la page de l'app (la racine du site ou `index.html`) est servie et gardée comme telle par le service worker : un fichier du site ouvert dans un onglet (une icône, le manifeste) ne la remplace plus.

Lancer en local (n'importe quel serveur statique fait l'affaire) :

```bash
python3 -m http.server 8000
# puis http://localhost:8000
```

L'app démarre aussi en http depuis un autre appareil (un téléphone sur le réseau local : `http://<adresse de l'ordinateur>:8000`) : sa CSP n'exige pas https (ci-dessous). Hors https et localhost, le navigateur refuse toutefois le service worker (pas de hors-ligne), la position et le presse-papiers (copier un lien, des coordonnées) ; les lieux et les listes se créent quand même. Pour tout essayer depuis un téléphone, passer par un tunnel https.

Le workflow `Deploy web app` publie l'application sur GitHub Pages à chaque modification de l'app sur `main`, après chaque build du dataset et après chaque enrichissement des médias réussis (leurs commits, poussés avec le jeton du workflow, ne déclenchent aucun workflow sur push : `workflow_run`), puis vérifie le site en ligne (ci-dessous, « Surveillance »). Il faut l'activer une fois : **Settings → Pages → Source : GitHub Actions**.

Ajouter un fichier dans `app/`, `vendor/`, `lib/` ou `assets/` impose de l'ajouter aussi à la liste `SHELL` de `sw.js` ; `tools/check.sh` le vérifie. Une seule exception, la liste `ON_DEMAND` de `sw.js` : des fichiers de `vendor/` déployés mais **pas précachés** — aujourd'hui MapLibre (`vendor/maplibre/`, ≈ 1,6 Mo, pour la seule Vue 3D, qui a de toute façon besoin du réseau pour son relief) : le précacher alourdirait chaque installation et chaque mise à jour de l'app pour une vue facultative. Le service worker garde ces fichiers dans le cache de la version **à leur première demande** (la vue 3D marche ensuite hors ligne, à plat), et `tools/stamp-sw.mjs` les compte dans l'empreinte ; `tools/check.sh` vérifie qu'ils sont dans `vendor/`, déployés, et pas aussi dans `SHELL`.

**Version du service worker : rien à incrémenter.** Dans le dépôt, `sw.js` porte `const VERSION = 'dev';` et ne doit pas être modifié à la main (`tools/check.sh` échoue sinon). Au déploiement, `tools/assemble-site.sh` y écrit l'empreinte (sha256, 12 caractères) des fichiers de `SHELL` et de `sw.js` lui-même (`tools/stamp-sw.mjs`) : tout changement d'un fichier précaché donne une nouvelle version, un déploiement sans changement garde la sienne. Le shell est servi depuis le cache de sa version (cache-first, sans requête réseau au lancement) ; le navigateur vérifie `sw.js` à chaque lancement et au retour au premier plan, installe la nouvelle version en entier en arrière-plan (un fichier manquant : elle ne s'installe pas, l'ancienne reste intacte), puis l'app affiche « Nouvelle version de GeoFlora disponible. Recharger ». En local (`VERSION` à `'dev'`), le shell vient du réseau d'abord : une modification se voit au rechargement. Les caches des images (`geoflora-images`) et des tuiles (`geoflora-tiles`) ne dépendent pas de la version. Pour mettre Lit, Leaflet ou MapLibre à jour : `LIT_VERSION=3.x.y LEAFLET_VERSION=1.x.y MAPLIBRE_VERSION=6.x.y scripts/vendor.sh` (MapLibre : l'archive npm, vérifiée contre l'empreinte `dist.integrity` du registre, puis ses fichiers `dist/` copiés tels quels ; une version publiée depuis sept jours au moins), puis mettre les mêmes versions de `lit` et `@types/leaflet` dans `package.json` (les types que lit `tsc`, ci-dessous « Analyse statique ») et relancer `npm install --ignore-scripts`.

**Contrôles avant fusion.** `bash tools/check.sh` réunit ce qu'une modification doit passer, et liste tous les problèmes d'un coup : chaque module se lit comme module ES ; chaque import trouve son fichier et les noms qu'il demande, parmi les fichiers que publie le déploiement, carte d'imports d'`index.html` comprise (`tools/check-imports.mjs` : sans build, un import cassé ne se voit qu'au navigateur, en écran blanc) ; le service worker précache tous les fichiers de `app/`, `vendor/`, `lib/` et `assets/`, `index.html` et le manifeste, et rien qui ne soit déployé ; sa `VERSION` reste `'dev'` dans le dépôt, et l'empreinte écrite par `tools/stamp-sw.mjs` suit les fichiers (contre un site assemblé : elle correspond à ses fichiers) ; les données de sécurité tiennent (`scripts/check-data.mjs` : chaque taxon des confusions est un nom accepté de la flore ; chaque confusion « publiée » de la liste de référence `data/confusions-reference.json` est dans `lookalikes.json`, à sa gravité au moins, et aucune piste « à vérifier » n'y est (`scripts/check-confusions.mjs`) ; une paire dont la plante toxique est au niveau 4 du TPPT n'est jamais « toxique » seulement ; une confusion mortelle ou grave a ses critères et ses symptômes, ou dit qu'ils manquent ; `safety.json` a ses trois sources, ses effectifs au-dessus de seuils et ses libellés TPPT en français, `meta.json` porte l'empreinte sha256 et le nombre de plantes de `plants.json` — `scripts/fingerprint-dataset.mjs` les écrit, les workflows de données le lancent après la dernière étape qui modifie `plants.json`) ; la CSP d'`index.html` autorise son import map par empreinte (`tools/csp-hash.mjs`). Le workflow `CI` (`.github/workflows/ci.yml`) le lance (job « check ») sur chaque pull request, chaque push sur `main` et dans une file de fusion ; `Deploy web app` le relance sur le site assemblé avant de publier, et `Build flora dataset` vérifie les données avant de les versionner.

**Analyse statique.** Le job « lint » du workflow `CI` réunit trois contrôles, qui tournent chacun même si le précédent échoue :

- **types, à cliquet** (`npm run typecheck`, `tools/tsc-ratchet.mjs`) : `tsc` vérifie les annotations JSDoc de `app/` (les fichiers portent `// @ts-check`) selon `jsconfig.json` — `checkJs`, mode non strict, avec les types de lit (`types/lit.d.ts` : ce qu'exporte `vendor/lit.js`, `repeat` et `classMap` compris) et de Leaflet (`@types/leaflet`), dev-dépendances à la version de `vendor/`. Les erreurs actuelles sont gelées dans `tools/tsc-baseline.json`, comptées par fichier et par code d'erreur (sans numéro de ligne : modifier un fichier au-dessus d'une erreur ancienne ne fait rien échouer). **Le job échoue dès qu'un fichier compte plus d'erreurs d'un code que le plancher**, en affichant les lignes en cause ; une correction fait baisser un compte : le job le signale, et `node tools/tsc-ratchet.mjs --update` réécrit le plancher — jamais à la hausse. Un éditeur ouvert à la racine du dépôt lit le même `jsconfig.json` ;
- **ESLint** (`eslint.config.js`) : les règles recommandées, `no-unsanitized` (pas de `innerHTML` ni d'`insertAdjacentHTML` avec autre chose qu'un littéral), les règles de gabarits de `eslint-plugin-lit`, `import-x/named` (chaque nom importé d'un module du dépôt y existe ; `lit` et `leaflet` passent par la carte d'imports, que `tools/check-imports.mjs` vérifie) et des interdits `no-restricted-syntax` : pas de `location.hash =` ni de `location.replace()` hors de `app/core/history.js` (passer par `openView()` et `replaceView()`), pas de `localStorage` dans un composant (les réglages passent par un module de `app/core/`), pas de tooltip ni de popup Leaflet en chaîne (Leaflet la pose en HTML : lui donner un élément bâti en texte, `elem()`), pas de propriété réactive Lit nommée comme un membre d'`HTMLElement` (`focus`, `blur`, `click`, `title`, `hidden`…, qu'elle masquerait : `el.focus()` lèverait une erreur). Les exceptions restantes sont écrites sur place, avec leur raison (`// eslint-disable-next-line … -- pourquoi`) ; une exception devenue inutile fait échouer le job ;
- **knip** (`knip.json`) : fichiers, exports et dépendances inutilisés. Les alias historiques lieu/collection de `app/core/collections.js` (`savePlace`/`saveCollection`…) sont signalés sans faire échouer le job, en attendant que leurs appelants n'en utilisent plus qu'un.

```bash
npm ci --ignore-scripts   # une fois
npm run typecheck         # tsc contre le plancher (quelques secondes)
npm run lint              # ESLint puis knip
```

**Dépendances de développement.** L'app n'a ni dépendance ni build : `package.json` (non déployé) ne liste que Playwright (test de fumée, accessibilité) et `@playwright/test` (tests de bout en bout), à la même version, axe-core (accessibilité), et les outils d'analyse statique : TypeScript, ESLint et ses greffons, knip, ainsi que lit et `@types/leaflet` pour leurs seuls types ; SheetJS (`xlsx`, lecture des tableurs Baseflor et TPPT) est à part, dans `scripts/package.json`, pour les seuls scripts du jeu de données (le test de fumée n'en dépend pas). Chaque `package-lock.json` fixe les versions et les empreintes ; la CI installe par `npm ci --ignore-scripts` (aucun script d'installation ne s'exécute ; `--prefix scripts` pour SheetJS), puis `npm audit --audit-level=high`, lancé après le test de fumée, bloque une PR sur une vulnérabilité haute. SheetJS vient de son propre dépôt (`cdn.sheetjs.com`, version 0.20.3) : npm ne propose que la 0.18.5, vulnérable (pollution de prototype, ReDoS). Le changement de version ne modifie pas les données : mêmes mois de floraison (3 879 plantes), mêmes 635 correspondances TPPT. Dependabot (`.github/dependabot.yml`) propose chaque semaine la mise à jour des actions GitHub (épinglées par commit) et des dev-dépendances (ESLint et ses greffons en une seule PR), une fois la version publiée depuis sept jours ; il ne suit ni lit et `@types/leaflet`, mis à jour avec `vendor/` (`scripts/vendor.sh`), ni SheetJS, à mettre à jour à la main (`scripts/package.json`, puis `npm install --package-lock-only --ignore-scripts --prefix scripts`).

**Protéger `main`** (*Settings → Rules → Rulesets → New branch ruleset*, cible : la branche par défaut). Interdire la suppression et le force-push (*Restrict deletions*, *Block force pushes*) ne gêne rien. Exiger une pull request et les contrôles « check », « lint », « smoke », « tests » et « a11y » (*Require a pull request before merging*, *Require status checks to pass*) bloquerait en revanche les commits des workflows de données, poussés directement sur `main` avec le jeton du workflow (`GITHUB_TOKEN`), qu'aucune liste d'exceptions d'un ruleset n'accepte. Il faut d'abord les faire pousser avec le jeton d'une GitHub App placée dans cette liste. D'ici là, une pull request affiche « check », « lint », « smoke », « tests » et « a11y » : ne la fusionner qu'au vert.

**Surveillance : le site en ligne et les services tiers.** Deux workflows regardent ce que la CI ne voit pas :

- **après chaque déploiement** (`post-deploy.yml`, « Check live site », dernier job « verify » de `Deploy web app`) : le site est réassemblé depuis le commit déployé, puis `tools/check-live.mjs` vérifie sur `https://yannouche-dev.github.io/flora/` que `sw.js` porte la même `VERSION` (l'empreinte de `tools/stamp-sw.mjs`) et `data/meta.json` la même empreinte de flore, en redemandant toutes les 15 s pendant 10 minutes au plus (le temps que Pages publie et que son CDN oublie l'ancienne copie), puis que chaque fichier précaché et chaque fichier de données répond 200 ; enfin le test de fumée (`tests/smoke.mjs`) ouvre chaque écran sur le site en ligne. Comme en CI, ses requêtes vers l'extérieur reçoivent une réponse locale : il vérifie le site tel que Pages le sert (fichiers, modules, CSP), pas les services tiers. Si `main` a déjà avancé (un autre déploiement suit), la différence de version n'est qu'un avertissement : le déploiement suivant est vérifié par son propre job. C'est un job du workflow de déploiement plutôt qu'un `workflow_run` : GitHub n'enchaîne pas plus de trois `workflow_run`, et un déploiement après `Enrich search media` après `Build flora dataset` est déjà le troisième. Il se lance aussi à la main (*Actions → Check live site → Run workflow*) ; en local : `bash tools/assemble-site.sh _site && node tools/check-live.mjs _site https://yannouche-dev.github.io/flora/` ;
- **chaque jour** (`api-health.yml`, « Outside services health », 5 h 41 UTC, et à la main) : `tools/api-health.mjs` pose une petite question à chaque service tiers de l'app (GBIF, iNaturalist, Wikidata et son service SPARQL, Wikipédia, Commons, Wikibooks, GloBI, Open-Meteo archive et qualité de l'air, IGN Géoplateforme WMTS — chaque couche de `app/core/ign.js` doit figurer dans son catalogue, que `lib/ign-catalog.mjs` doit savoir lire —, le catalogue publié `data/ign-catalog.json` (45 jours au plus), altimétrie, géocodage et WFS, API Carto) et à l'archive TAXREF du build (son premier octet), avec l'en-tête `Origin` du site : statut, en-tête CORS (sans lui, le navigateur ne lit pas la réponse) et forme minimale de la réponse lue par l'app. Une requête par service, l'une après l'autre, avec un `User-Agent` qui nomme le dépôt (et `Api-User-Agent` pour Wikimedia, comme l'app) ; une erreur réseau, un 5xx ou un 429 est redemandé une fois 20 s plus tard. Le tableau des résultats est dans le résumé du run ; le run échoue si un service est en panne, et GitHub le notifie comme tout run planifié en échec. Aucune clé ni aucun jeton : Trefle (jeton personnel) n'est pas sondé, et le workflow n'ouvre pas d'issue. En local : `node tools/api-health.mjs [gbif ign-wmts …]` (derrière un proxy, Node 22 demande `NODE_USE_ENV_PROXY=1`).

Les sondes ponctuelles d'autrefois (workflows temporaires poussés sur une branche) n'ont plus lieu d'être : une vérification se fait par ces deux workflows, lancés à la main au besoin. GitHub garde dans sa liste les workflows temporaires dont le fichier a disparu (`tmp-check`, `Temporary API check`, `Check IGN services (temporary)`) : sans fichier sur aucune branche ils ne tournent plus, et `gh workflow disable <nom>` les retire de la liste active.

**Sécurité dans le navigateur.**
- *Content-Security-Policy* (balise `<meta>` en tête d'`index.html`) : scripts du site seulement, plus l'import map par son empreinte sha256 — après l'avoir modifiée, `node tools/csp-hash.mjs --fix` (sans `--fix`, il vérifie) ; aucun gestionnaire inline (`onerror="…"`) ni `<script>` injecté ne s'exécute ; connexions limitées aux API des modules (dont `s3.amazonaws.com`, le relief de la Vue 3D) ; workers du site seulement (`worker-src 'self'` : la recherche, et le worker module de MapLibre) ; images de tout hôte web, http compris (une photo GBIF peut l'être) ; cadres en https (volet « Page web »). Pas de `upgrade-insecure-requests` : il ferait demander en https les fichiers de l'app elle-même, servie en http lors d'un test sur le réseau local.
- *Données tierces* : les champs libres des enregistrements GBIF (institution, lieu, collecteur…) deviennent du texte brut et borné (balises et contrôles bidirectionnels retirés ; les liants des écritures persane ou indiennes et des emoji restent) ; un lien venu d'une source (licence, page, original ou source d'une photo — dans la fiche comme dans la visionneuse —, publication, recette, zone naturelle ou espace protégé, source d'une confusion) n'est gardé qu'en http(s) (`app/core/safe-url.js`), sinon son texte s'affiche seul ; les étiquettes de la carte sont posées en texte, jamais en HTML.

### Navigation et saisie rapide

- **Navigation et historique** : chaque vue est une étape de l'historique du navigateur — recherche, fiche plante (chaque plante parcourue avec ‹ › aussi), carte et lieu ouvert, collections, éditeur, réglages. Le bouton retour du navigateur ou du téléphone revient à la vue précédente et ferme une fenêtre ouverte (Ajouter à…, Noter ici, filtres, couches de carte). La recherche (texte, filtres, tri) est une seule vue mise à jour sur place. « ✕ / Résultats » revient à la liste, « Terminé » à la vue d'où l'on venait ; une collection supprimée ou un lieu fusionné ne restent pas dans l'historique.
- Sur téléphone, une barre en bas : **Flore** (feuille) · **Carte** · **Mes collections** · **Réglages** (engrenage ; sauvegarde) ; l'onglet actif a son icône pleine sur une pastille. « Noter ici » est dans Mes collections, sur la carte (+) et dans les Actions de la fiche plante. Sur ordinateur, les mêmes entrées sont dans l'en-tête.
- **Noter ici** : le GPS démarre, des suggestions s'affichent (plantes des lieux à moins de 200 m, favoris, plantes récentes) ; un toucher sur une plante l'enregistre **dans le lieu le plus proche (< 30 m)** ou dans un nouveau lieu. Un bandeau propose **Annuler** et **Détails**.
- **Recherche vocale** 🎙 (recherche Flore et « Noter ici ») : on dit le nom, la recherche se lance. Elle utilise la reconnaissance vocale du navigateur, en français (sur Chrome l'audio part chez Google, sur Safari chez Apple ou reste sur l'appareil) ; le bouton n'apparaît que si le navigateur la propose et si le module « Dictée vocale » est actif. **Le micro est demandé au navigateur** : au premier toucher, sa fenêtre d'autorisation s'ouvre (rien n'est écouté avant) ; une fois autorisé, plus de question. Refusé, ou bloqué auparavant (le navigateur ne redemande plus), le bouton dit où le réautoriser : les réglages du site (le cadenas ou ⓘ à gauche de l'adresse) ; sans micro, il le dit aussi.

### Mode cueillette (module optionnel)

*Réglages → Mode cueillette.* Activé automatiquement si l'appareil contient déjà des récoltes, désactivé sinon. Désactivé, un lieu est simplement « des plantes vues ici » (abondance, notes) ; rien n'est effacé. Activé :

- journal de récolte, qualité (★), « Récolté aujourd'hui », bouton « + Récolte » ;
- badges **En saison** (récolté à ±15 jours de la date, une année quelconque) et **Bientôt** (dans les 30 prochains jours) ;
- **plantes à confondre** : noter une plante avec « Noter ici » ou « + Récolte » rappelle les plantes toxiques avec lesquelles elle est confondue (ci-dessous) ;
- **jamais de récolte cochée d'office** : dans « Noter ici », « Noter aussi une récolte aujourd'hui » est décoché à l'ouverture, comme « Récolté aujourd'hui » pour une plante ajoutée à un lieu. Pour une plante que nos sources disent toxique (liste B ou parties toxiques de l'ANSM, TPPT « toxique » ou plus, plante toxique d'une confusion) — ou dont les données de toxicité ne se lisent pas —, cocher la récolte ouvre d'abord un **avertissement à lire** : « Plante toxique : récolte déconseillée », ce que disent les sources, la conduite à tenir (Centre antipoison, 15, 112). « Noter sans récolte » est le choix proposé ; « Noter la récolte quand même » ne s'active qu'une fois « J'ai lu cet avertissement » coché. Dans l'éditeur d'un lieu, « Récolté aujourd'hui » et « Ajouter une récolte » demandent la même confirmation.

### Données ouvertes croisées : interactions, climat, pollens, zones naturelles

GeoFlora croise la flore avec des API ouvertes appelées directement par le navigateur, sans clé (vérifié depuis le site déployé). Chacune est un **module** (*Réglages › Modules*) ; désactivé, il n'est jamais appelé. Les réponses sont gardées en cache (IndexedDB).

- **Pollinisateurs et interactions** (bloc de la fiche, module GloBI) : ce que [GloBI](https://www.globalbioticinteractions.org/) recense pour l'espèce, regroupé par rôle — pollinisateurs et visiteurs des fleurs, ce qui la mange ou la parasite (chenilles, pucerons, rouilles…), symbioses (mycorhizes), ce qu'elle-même parasite, autres — et par groupe (abeilles et bourdons, syrphes, papillons, coléoptères, champignons…). Trois styles au choix en mode King : **tableau** (par défaut : espèce, groupe, nombre de mentions), **liste** (groupes puis espèces) ou **réseau** (la plante au centre, chaque partenaire coloré par groupe et dimensionné par ses mentions). Chaque rôle est un sous-bloc. Source : nombre de mentions et d'études.
- **Climat et pollen** (bloc de la fiche, module Open-Meteo) :
  - *Niche climatique* : le climat (température moyenne annuelle, pluie annuelle ; ERA5 via Open-Meteo, deux ans) de 24 occurrences GBIF de l'espèce réparties en France, en nuage de points ; le cadre réunit 80 % d'entre elles. « Me situer » ajoute votre position (arrondie à 100 m) : dans sa niche ou non, et le diagramme climatique de chez vous (10 ans).
  - *Altitude* : sous la niche, l'altitude à laquelle l'espèce a été observée en France — « le plus souvent entre 340 m et 1 260 m » (10 % à 90 % des occurrences), les extrêmes, et combien des occurrences GBIF la donnent (le champ `elevation`, rempli ou non selon les observateurs ; rien sous 5 valeurs). Avec « Me situer », votre altitude (celle d'Open-Meteo pour votre position) : dans cette tranche, plus bas ou plus haut.
  - *Pollen aujourd'hui* : pour les plantes dont le modèle européen CAMS prévoit le pollen (aulne, bouleau, graminées, armoise, olivier, ambroisie), le niveau du jour autour de vous.
- **Autour d'un lieu ou d'un point** (panneau d'un endroit sur la Carte et dans Mes plantes ; « Ici : zones naturelles… » dans la fiche d'un point de la carte, appui long) :
  - *Zones naturelles* (module IGN – zones naturelles au point, API Carto) : ZNIEFF I et II, sites Natura 2000 (habitats, oiseaux), parcs nationaux et régionaux, réserves naturelles qui contiennent le point, avec leur fiche INPN ;
  - *Plantes vues ici* (iNaturalist, observations validées à moins de 500 m) : les plus observées, celles de la flore ouvrent leur fiche, celles du lieu sont signalées ;
  - *Pollens aujourd'hui* (CAMS via Open-Meteo) et *Climat du lieu* (diagramme : pluie par mois en barres, température en courbe, moyennes sur 10 ans, ERA5).
- **Usages et cuisine sauvage** (bloc de la fiche, rubrique Usages) — la prudence d'abord, chaque ligne avec sa source et la partie de la plante concernée ; l'app ne dit jamais qu'une plante est « comestible » (ni la fiche, ni les cartes de Découvrir, qui nomment la partie consommée selon l'Anses) :
  - *Prudence* : Pharmacopée française, **liste B** de l'ANSM (plantes dont les effets indésirables potentiels l'emportent sur le bénéfice attendu) et parties toxiques citées par la **liste A** ; toxicité de la base **TPPT** d'Agroscope (plantes toxiques d'Europe centrale : niveau, parties toxiques, principales toxines), en français — « cancérogène » (au niveau « toxique »), « œstrogénique », « seulement les plantes infestées », et « toxicité pour l'humain inconnue » quand la base ne la donne pas (aucun niveau) ; les parties traduites terme à terme (« sommités fleuries », « herbe ») ; le texte anglais de la base reste à côté (`levelEn`, `partsEn`, au survol) ; risque de confusion (Anses), à la gravité de la paire, des deux côtés (la plante toxique elle-même : « Plante mortelle, confondue avec Carotte sauvage », même sans donnée ANSM ni TPPT) ; espèce protégée ou cueillette réglementée (INPN) ; puis la conduite à tenir (Centre antipoison, 15, 112). Ces données sont dans `data/safety.json`, construit en CI (`scripts/build-safety.mjs`) et disponible hors ligne. Une source se rattache à une plante par son nom accepté, ou par un synonyme qu'une seule plante porte : un synonyme partagé (« Vicia parviflora », porté par trois plantes) ne rattache à aucune, avec un avertissement dans le journal, sauf correspondance relue à la main (`NAME_LINKS` : « Ranunculus ficaria » est la Ficaire printanière, *Ficaria verna*, qui retrouve son alerte TPPT) ; l'espèce passe avant l'hybride qui commence par son nom. La liste B « Senecio sp. » couvre aussi les jacobées (*Jacobaea*, séparées de *Senecio*, dont le séneçon jacobée), « listée sous Senecio sp. » (`GENUS_SPLITS`, relu à la main). Une source injoignable garde ses entrées précédentes, relues avec ces règles. Sans aucune donnée de toxicité, la Prudence le dit (« Aucune donnée de toxicité dans nos sources (ANSM, TPPT) : cela ne veut pas dire qu'elle est comestible ni sans danger ») ; les usages sont toujours titrés « non vérifiés ».
  - *Usages rapportés* : usages déclarés sur Wikidata (alimentation, médecine traditionnelle, autres) et, pour la liste A de l'ANSM, les parties utilisées ;
  - *Parties et produits* (tableau ou liste) : ce que l'on tire de la plante et de quelle partie (Wikidata) ;
  - *En cuisine* : plats qui l'utilisent (Wikidata) et recettes de Wikibooks (module « Wikibooks (recettes) ») ;
  - *Pour aller plus loin* : PFAF (identifiant Wikidata), monographies de l'Agence européenne du médicament, Pharmacopée française.
- La **floraison observée** (iNaturalist, observations annotées « en fleurs » / « en fruits » en France) était déjà dans le bloc Calendrier, à côté de la floraison Baseflor.

### Plantes à confondre (Anses, Centres antipoison)

Sur la fiche d'une plante comestible souvent confondue avec une plante toxique — ou de la plante toxique elle-même —, un encadré **« Peut être confondue avec… »** (rouge si l'intoxication peut être mortelle ; « Plante mortelle, confondue avec… » sur la fiche de la toxique) donne la partie concernée, les **critères pour les distinguer**, les **symptômes** — ceux d'une confusion mortelle dans toutes les vues, les autres en vue Scientifique — et les sources. En vue Épurée (et dans l'éditeur d'un lieu en mode cueillette), une ligne par confusion, le reste sur demande ; une confusion mortelle y garde, hors du pli, une ligne « Symptômes : … » (en entier une fois dépliée). Sous l'encadré, la conduite à tenir : **Centre antipoison** ([centres-antipoison.net](https://centres-antipoison.net/), la liste officielle des centres et de leurs numéros), le **15** ou le **112** en cas de détresse vitale (liens d'appel, utilisables hors ligne) ; la même consigne accompagne les avertissements de « Noter ici » (mode cueillette) et le bandeau de la Cueillette prudente. Exemples : ail des ours ↔ colchique et muguet, consoude ↔ digitale, gentiane jaune ↔ vérâtre, carotte sauvage ↔ œnanthe safranée, sureau noir ↔ sureau yèble, châtaignier ↔ marronnier d'Inde.

Les données (`data/lookalikes.json`, 16 confusions) ne reprennent **que** les confusions et critères publiés par l'Anses et les Centres antipoison : aide-mémoire *Plantes toxiques et plantes comestibles : attention aux confusions !* (2020), *Vigil'Anses* n°8 (2019), articles de l'Anses sur le colchique et l'ail des ours (2025), « gare aux confusions » (2020) et les plantes de l'été (2022). Un genre entier (« Digitalis sp. ») y est noté par son seul nom. Le fichier est inclus dans l'application : l'avertissement fonctionne hors ligne.

**Gravité.** Trois niveaux : **mortel** quand ces sources le disent ; **très toxique** (`grave`, `severityFrom: "tppt"`) quand la plante toxique est au niveau le plus haut de la base TPPT d'Agroscope (« very strong toxic », très fortement toxique) — grande et petite ciguë, muguet, arum, cytise, laurier rose, datura ; **toxique** sinon. Mortel et très toxique ont le ton rouge, passent en tête des listes et de la Cueillette prudente, et se disent dans les messages (« Grande ciguë (très toxique) ») ; la fiche cite la base TPPT comme source de cette gravité. Le laurier rose (TPPT 4) et le laurier cerise (TPPT 2) sont deux paires. Quand les sources citées ne donnent pas de critère pour distinguer les plantes, l'encadré le dit (« Nos sources ne donnent pas de critère pour les distinguer : en cas de doute, ne la cueillez pas »).

**Liste de référence.** `data/confusions-reference.json` liste les confusions que l'app doit signaler, chacune avec son statut : **publiée** (dans les sources citées : elle doit figurer dans `lookalikes.json`, à sa gravité au moins — `scripts/check-confusions.mjs` le vérifie en CI), ou **à vérifier** (une piste — ciguë vireuse ↔ carotte sauvage, panais, céleri ; grande ciguë ↔ carotte, cerfeuils ; petite ciguë ↔ cerfeuil ; œnanthe safranée ↔ céleri, panais, persil ; arum ↔ ail des ours ; digitale ↔ bourrache ; bryone ↔ tamier, asperge sauvage ; vérâtre ↔ ail victorial ; berce du Caucase ↔ berce commune — qu'aucune source lue n'a encore confirmée : elle n'est montrée à personne, et la CI refuse qu'elle le soit). `gaps` y note, pour une confusion mortelle ou très toxique, les critères ou symptômes que les sources citées ne donnent pas. Le champ `review` dit ce qui a été relu et quand : le 2026-10-13, les publications de l'Anses et des Centres antipoison (anses.fr, vigilanses.anses.fr, centres-antipoison.net) n'ont pas pu être lues depuis l'environnement de travail ; les pistes attendent cette lecture, puis l'avis d'un Centre antipoison.

**Retrouver la plante sous ses noms.** Les noms se comparent sans auteur, sans casse, « × » valant « x » : un mot seul, même suivi d'un auteur abrégé (« Colchicum L. »), est le genre entier (un auteur écrit en entier, « Colchicum Hill », serait lu comme une épithète : `scripts/check-data.mjs` refuse toute écriture qui n'est pas le nom accepté de la flore) ; le mot qui suit le genre est l'épithète, même écrit avec une majuscule (« molopospermum Peloponnesiacum »). Un nom qui n'est qu'un synonyme désigne la seule plante qui le porte, jamais une autre dont c'est le nom accepté : « Molopospermum peloponnesiacum », ancienne graphie, est bien le Couscouil (*M. peleponnesiacum* dans TAXREF), et l'avertissement « Aconit napel (mortel) » le suit, sur sa fiche et, en mode cueillette, dans « Noter ici » et dans un lieu. `scripts/check-data.mjs` exige malgré tout le nom accepté tel qu'écrit dans la flore. Dans Autour et Découvrir, une observation iNaturalist d'un hybride (« Heracleum mantegazzianum × Heracleum sphondylium ») n'est jamais prise pour l'espèce de son premier parent, qui garde ses alertes.

**Jamais « rien » faute de données.** Si `lookalikes.json` ou `safety.json` ne se lit pas (première visite sans réseau, fichier abîmé ou vide), aucun écran ne conclut « aucune confusion » : l'encadré, la Prudence, le compteur de la rubrique Alertes, les cartes de Découvrir, la Cueillette prudente et « Noter ici » (mode cueillette) disent « Liste des confusions indisponible… » ou « Données de toxicité indisponibles pour le moment : ne consommez aucune plante sans vérification » ; l'encadré, la Prudence et la Cueillette prudente ont **Réessayer** (un fichier en échec est redemandé), « Noter ici » renvoie à la fiche, et un nouveau chargement de la fiche ou de Découvrir redemande le fichier. Et quand la liste ne cite pas la plante, la fiche dit « Aucune confusion de notre liste (Anses, Centres antipoison) ne concerne cette plante : cela ne garantit pas l'absence de risque. »

### Contexte et passerelles Flore ⇄ lieux

L'application retient où vous en êtes dans chaque partie, aussi après un rechargement :

- **Flore** : la recherche (texte, filtres, tri) et la plante ouverte. L'onglet Flore rouvre la plante ; touché une seconde fois, il revient à la liste. Rouvert ailleurs (Carte, lien), la recherche est restaurée : les flèches ‹ › d'une fiche parcourent les mêmes résultats.
- **Mes plantes** : la collection ou l'endroit ouvert et la plante à côté. **Carte** : le lieu choisi et le filtre de plantes.
- **Plante courante** : la dernière ouverte, où que ce soit. **Collection courante** : la dernière collection ou le dernier lieu ouvert.

Passerelles :

- d'une **fiche** : « Carte » (l'onglet Carte filtré sur la plante, avec sa répartition GBIF) et « + *collection courante* », qui ajoute la plante d'un geste à la dernière collection ou au dernier lieu ouvert (le bouton disparaît une fois la plante ajoutée) ; deux actions de la barre, à afficher ou non par mode ;
- d'une **collection ou d'un lieu** : « Voir dans Flore » (Mes plantes, éditeur de collection, fiche d'un lieu sur la Carte) ouvre la recherche filtrée sur ses plantes ;
- des **résultats Flore** : l'icône carte ouvre la Carte limitée à mes lieux qui ont une plante de ces résultats (puce « Recherche Flore » pour l'enlever) ;

**Les données de la fiche parlent à ses cartes.** Quand la fiche a une carte (épinglée ou dans la fiche), ses valeurs se touchent (soulignées en pointillés) et la carte les montre :
- une **région** ou un **département**, un **mois**, une **année**, un **type de relevé** (spécimens d'herbier…), une **source** (jeu de données) : la carte n'affiche plus que ces occurrences GBIF (tuiles GBIF filtrées, présences aux coordonnées sans problème connu) ; une région ou un pays recadre la carte sur ses occurrences ;
- un **pays** de la répartition dans le monde, quand la liste GBIF donne son code : ses occurrences, carte dézoomable jusqu'au monde ;
- une occurrence **Près d'ici**, une **photo** ou une **planche d'herbier** géolocalisée (📍 sous l'image), un de **mes lieux** : un point rouge nommé, la carte y vole ;
- **Plantes à confondre** : « Comparer sur la carte » ajoute les occurrences GBIF de la plante à confondre, en violet, à côté de celles de la plante.
Une puce sur la carte dit ce qui est affiché (« Filtre : Occitanie », « Comparaison : Colchique d'automne ») ; ✕, ou toucher à nouveau la valeur, l'efface. Sans carte dans la fiche, les valeurs restent du texte.

Le **cadrage** d'un bloc Carte suit ses réglages : « Automatique » (par défaut) cadre le cercle autour de moi quand les observations proches sont affichées, sinon mes lieux et leurs plants, sinon le monde pour une répartition GBIF mondiale, sinon la France ; « Monde entier » permet de dézoomer jusqu'au planisphère. Chaque changement de réglage recadre la carte ; la déplacer à la main reste jusqu'au réglage suivant.

### Mes plantes : favoris, listes et lieux

Une **collection** est un ensemble de plantes, avec ou sans position :

- **Favoris** ♥ : un toucher sur ♡ dans la liste de recherche ou sur la fiche d'une plante.
- **Listes** (« Mellifères », « À chercher cet été »…) : sans position. « Ajouter à… » sur une fiche plante coche/décoche les collections et en crée une à la volée.
- **Lieux** : une liste avec une position GPS, visible sur la carte (voir ci-dessous). « 📍 Ajouter une position » transforme une liste en lieu ; « Retirer la position » fait l'inverse.
- **Noms** : dans chaque champ de nom de collection (« Ajouter à… → Nouvelle collection », éditeur d'une nouvelle collection), les collections existantes qui correspondent sont proposées ; en choisir une y ajoute la plante au lieu de créer un doublon.

**Espèces protégées** : la fiche plante, le panneau d'une plante dans un endroit et le message de « Noter ici » signalent une **protection** (bandeau rouge) ou une **cueillette réglementée** (bandeau orange) là où l'on est, ainsi que la liste rouge. Le territoire est celui du point GPS de l'endroit (département, région, ancienne région), sinon « Ma région » choisie dans *Réglages* ; les statuts d'ailleurs restent consultables. Un statut n'est **national** que s'il est une protection ou une liste rouge nationales, ou s'il n'a ni région ni département (aucun code « FR-… ») et vaut pour la France ou la France métropolitaine : la protection et la liste rouge d'Île-de-France ne s'affichent plus « ici » en Provence. Les **réglementations** (`REGL`) sont classées par code (`app/core/regulation.js`), la même règle pour le badge, la Prudence, le filtre de Flore, le bloc statut et les messages : seule la **cueillette en métropole** compte comme « Cueillette réglementée » — arrêté d'un département, liste nationale (article 3), ou espèce dont un préfet peut réglementer la cueillette (PV1, expliquée dans le bloc statut) ; le **commerce** (annexes CITES) a sa ligne dans le bloc statut ; les listes d'**outre-mer** (PV97, Nouvelle-Calédonie, SPAW) et d'**espèces envahissantes** ne disent rien de la cueillette ici. Chaque bloc renvoie aux textes officiels sur l'INPN. La recherche a un filtre « Protection et menace ».

**Calendrier** sur la fiche plante, chargé automatiquement : floraison Baseflor (hors ligne, dans le jeu de données) et observations iNaturalist en fleurs / en fruits en France, mois par mois, chaque ligne avec sa source. Ce sont des indications de floraison et de fructification, **pas des dates de cueillette**.

L'onglet **Mes plantes** les regroupe : collections, puis endroits triés par distance. Une collection à laquelle on ajoute des coordonnées GPS devient un endroit ; toucher un endroit ouvre la carte cadrée sur son point et toutes ses plantes. Toucher l'en-tête d'une collection (Favoris, collection, endroit) **déplie la liste de ses plantes** (ce qui est déplié est mémorisé) ; un endroit montre aussi **sa carte**, avec chacune de ses plantes. Toucher une plante ouvre **sa fiche à côté**, avec en bas la barre plante précédente / suivante de la collection : sur ordinateur, trois volets (liste · carte de l'endroit · fiche), comme dans Flore : chacun a son en-tête, se **redimensionne** en glissant son séparateur (← → au clavier, Début / Fin, double-clic ou Entrée : largeur par défaut) et se **replie** (« ») en une fine colonne titrée ; la liste garde sa largeur quand une plante ou un endroit s'ouvre à côté (rien ne bouge sous le doigt) et un volet « Aperçu » attend tant que rien n'est ouvert ; sur tablette, la carte et la fiche se partagent la colonne de droite ; sur téléphone, la carte s'affiche dans l'endroit déplié et la fiche glisse par-dessus la page. L'adresse garde ce qui est ouvert (`#/collections?c=…&plant=…`) : le retour du navigateur revient à la vue précédente. Sur chaque ligne, **Partager** envoie un lien qui contient la collection (la position exacte d'un endroit, après confirmation) et l'icône crayon (ou carte, pour un endroit) ouvre la collection pour la modifier. Le rappel « Sauvegardez vos collections » est en bas de la page. Les modifications sont **enregistrées automatiquement**. Dans la recherche, le filtre **Mes plantes** limite les résultats aux favoris, à une liste, à un lieu ou à « dans un de mes lieux ».

**Partager** sans serveur :

- une plante : lien `#/plant/<id>` ;
- une recherche (famille, statut…) : bouton *Partager* au-dessus des résultats, l'URL contient les filtres ;
- une liste ou un lieu : le lien contient la collection elle-même (`#/shared?d=…`, JSON compressé deflate + base64url, ~200 caractères pour 30 plantes). Notes et journaux de récolte ne sont **jamais** inclus ; pour un lieu, la position exacte l'est (confirmation demandée), ainsi que celle de chaque plante — **chaque occurrence** d'une plante notée plusieurs fois, jusqu'à ~100 km du point du lieu. Le destinataire voit un aperçu — **la carte cadrée sur tout le lieu ou le parcours**, chaque plante à sa place, la liste avec « × 2 » pour une plante notée deux fois — et peut l'enregistrer comme nouvelle collection, avec toutes ses occurrences.

Partout où des plantes sont listées (lieu ou collection, ajout d'une plante, « Noter ici », fiche du lieu sur la carte, lien partagé), chaque nom est précédé de la **miniature de sa photo**, comme dans les résultats de recherche ; les photos déjà vues restent disponibles hors ligne (cache du service worker, 400 images).

### Carte : recherche, réglages, infos d'un point

Sur **toutes les cartes** de l'app (Carte, Découvrir, fiche plante, lieux, parcours, lien partagé) :
- **Les périmètres** — le cercle d'« Autour », un département, une région, la France — sont tracés à chaque fois : **leur bordure seule, en vert clair**, avec une ombre portée discrète (pas de fond : la carte reste visible). Ceux de la France (et ceux d'un département ou d'une région quand l'IGN ne répond pas) viennent des contours embarqués dans l'app : départements, régions et France métropolitaine ont chacun le leur, sans aucun bout de frontière intérieure.
- **La plante choisie** (la plante en vue de Découvrir, l'espèce touchée dans « Autour », la valeur touchée dans une fiche) : **sa photo, en grand**, dans un rond rose et or qui rebondit en arrivant, une onde au moment où il se pose. Une plante sélectionnée dans un lieu grandit et rebondit de même, cerclée de vert (trois ondes, puis immobile).
- **Survoler une plante** (la toucher, sur un téléphone) l'agrandit et **allume aussi les autres points en vue de la même espèce** — observations, plante choisie, plantes des lieux, reconnues par leur nom scientifique — ; **les autres pastilles ne changent pas** (ni estompées ni déplacées). L'allumage tient quand la carte redessine ses points (une sélection, une photo qui arrive). Une plante sélectionnée allume ses autres emplacements (cerclés d'or, avec un halo).
- **Sur un téléphone**, un premier toucher sur un point montre sa petite fiche et allume ses semblables ; un second ouvre l'observation (la fiche le dit) — l'app n'est jamais quittée d'un seul toucher.
- **Chaque pastille de plante apparaît avec sa feuille**, et sa photo s'y pose (en fondu) une fois chargée ; une photo qui échoue laisse la feuille.
- **La petite fiche** d'un point (photo, noms, date, lieu) a une bordure fine et transparente ; tous les points d'une plante choisie l'ont, regroupés ou non.
- Les effets ne déplacent que ce que la carte graphique compose sans redessiner (échelle, rotation, opacité) : ombres immobiles, aucune animation en boucle sur de nombreux points, les points SVG changent d'un coup ; les groupes se refont une fois le zoom (ou le vol vers une zone) fini, sans rejouer leur entrée ; tout est figé si le système demande moins d'animations.

- **Barre de recherche** en haut de la Carte : adresse, commune ou lieu-dit avec suggestions (géocodage IGN) ; le résultat choisi est centré et sa fiche s'ouvre.
- **▦ Carte** (au bout de la barre, ou bouton rond sur les autres cartes) : un seul panneau pour tout ce qui règle l'affichage — **fond** (photos aériennes, plan IGN), **couches** de terrain (parcelles cadastrales, courbes de niveau) et de **règles de cueillette** (forêts publiques ONF, parcs nationaux, réserves naturelles nationales et régionales, arrêtés de protection de biotope — données INPN / PatriNat servies par l'IGN), **légende** et **sources**. Les choix sont mémorisés. **Toutes les couches de l'IGN** : « Ajouter une couche de l'IGN… » ouvre tout le catalogue de la Géoplateforme — relief ombré, géologie, hydrographie, cartes anciennes… —, avec une recherche : la copie livrée avec l'app (`data/ign-catalog.json`, voir *Catalogue des couches de l'IGN*) s'affiche aussitôt, hors ligne aussi ; vieille de plus d'un mois, elle est mise à jour en fond depuis le service, sans jamais disparaître si celui-ci échoue (« Hors ligne : catalogue gardé du … », ou « Le catalogue de l'IGN ne répond pas » avec **Réessayer**) ; module « IGN – fonds de carte » coupé, la liste reste consultable et une couche ajoutée n'affiche que les zones déjà vues ; une couche ajoutée rejoint la liste, se coche et se décoche comme les autres, sur toutes les cartes, et reste là d'une visite à l'autre (hors ligne aussi, ses tuiles déjà vues).
- **Espaces protégés** : dès le zoom 11, sur toutes les cartes (Carte, éditeur d'un lieu, fiche plante, lien partagé), un petit bandeau nomme le **parc national** (cœur), la **réserve naturelle** nationale ou régionale ou l'**arrêté de protection de biotope** que la vue touche, avec le lien vers sa fiche INPN : « la cueillette y est souvent interdite ou réglementée : vérifiez les règles du site ». × le masque pour ces espaces ; il ne s'affiche pas pendant le déplacement des positions. Données INPN / PatriNat interrogées sur le WFS de l'IGN (noms seulement), gardées un mois sur l'appareil ; module « IGN – espaces protégés ».
- **Appui long** n'importe où sur la carte : fiche du point avec l'**adresse la plus proche**, l'**altitude** (RGE ALTI®), les **coordonnées** (copiables), « Créer un endroit ici » et « Itinéraire ». La fiche d'un endroit affiche sa commune et son altitude, l'éditeur l'adresse, l'altitude et les coordonnées de son point.

Source : IGN – Géoplateforme (WMTS, WFS, géocodage, altimétrie ; gratuit, sans clé, Licence Ouverte). Adresses et altitudes déjà vues sont gardées sur l'appareil.

### Cartes en 3D

**Réglages › Cartes › Affichage des cartes : 2D ou 3D** (2D par défaut). Le choix vaut pour **toutes les cartes** de l'app — la Carte, la carte de la fiche plante, les lieux de Mes plantes, l'éditeur d'un lieu, Parcours (marche et récapitulatif), Rencontres et Découvrir, le lien partagé — et il n'y a **pas de bouton 2D ⇄ 3D sur les cartes** : on change dans Réglages, et les cartes ouvertes suivent aussitôt (les autres onglets aussi). Deux exceptions voulues : l'étape **« Jusqu'où part l'expédition ? »** des mini-applications reste **toujours en 2D, vue de dessus** ; sur une fiche plante, les **cartes ajoutées** en plus du bloc « Carte » principal (et la petite carte « Mes lieux ») restent en 2D — une seule carte WebGL par fiche.

En 3D, c'est **la même carte** (`gf-map`), avec les mêmes marqueurs, groupes, cercles, contours, fiches de point, panneau de couches et la même API pour les pages : seul le moteur de dessin change. MapLibre GL JS dessine ; la carte Leaflet reste dessous, cachée, comme « miroir » qui garde la vue et toute la logique (cadrages, groupes refaits au zoom, plantes visibles à partir du zoom 16, espaces protégés, vue mémorisée). Ses couches de tuiles deviennent des sources raster de MapLibre ; ses marqueurs (les éléments eux-mêmes) passent dans des marqueurs MapLibre posés sur le relief ; ses cercles, contours et fils deviennent une couche GeoJSON drapée sur le terrain. Détails : `app/components/gf-map-gl.js`, `app/core/gl-style.js`, inventaire des cartes et fonctions dans l'en-tête de `gf-map-gl.js`.

**Options** (Réglages › Cartes, visibles en 3D) :
- **Relief** (tuiles AWS Terrain Tiles, Terrarium : Mapzen, EU-DEM © Copernicus) et son **exagération** (× 1 à × 3) ; **ombrage** des pentes sous les couches ; les **courbes de niveau** de l'IGN se drapent sur le relief comme toutes les couches ;
- **inclinaison à l'ouverture** (0 à 85°) ; on tourne et on incline au clic droit, à deux doigts, ou au clavier (**Maj + flèches** ; flèches pour se déplacer, + et − pour zoomer) ; la **boussole** remet le nord ;
- **bâtiments en 3D** (tuiles vectorielles PLAN IGN de la Géoplateforme, surfaces bâties de la BD TOPO extrudées à leur hauteur, dès le zoom 15) ;
- **ciel et brume** (horizon, atmosphère au loin) ; **globe à petite échelle** (la Terre ronde en dézoomant) ;
- **plan IGN vectoriel** au lieu des images du « Plan IGN » (noms et traits plus nets ; le style, les polices et symboles de la Géoplateforme) ;
- **éclairage** : fixe, soleil de maintenant, ou soleil à l'heure choisie (heure de Paris) — la position du soleil oriente l'ombrage, la lumière des bâtiments, la couleur du ciel, et la nuit assombrit le fond.

Aussi en 3D : toutes les couches IGN du panneau « Carte » (et celles du catalogue ajoutées), la répartition GBIF, les vols animés vers un lieu ou une adresse (aucun si le système demande moins d'animations), plein écran, échelle, crédits en français, **altitude sous le pointeur** (celle du relief ; l'appui long donne toujours celle de l'IGN, RGE ALTI®). Le dialogue « Vue 3D » d'un parcours ou d'un lieu est la même carte, forcée en 3D, avec la marche et l'altitude de chaque plante.

**Replis** (toujours une carte, jamais d'erreur) : pendant la **modification des positions** (glisser des marqueurs), la carte repasse en 2D le temps de l'édition et le dit, puis revient en 3D ; **sans WebGL2**, les cartes restent en 2D (« 3D indisponible sur cet appareil ») ; si MapLibre ne peut pas se charger (hors ligne avant sa première ouverture), 2D ; module **« Vue 3D (relief) »** coupé : 3D à plat, aucune tuile de relief demandée ; module **« IGN – fonds de carte »** coupé : tuiles IGN lues dans le cache de l'appareil seulement, ni bâtiments ni plan vectoriel ; **hors ligne** : à plat, tuiles déjà vues, et la carte le dit ; relief injoignable : à plat, dit ; contexte graphique perdu : 2D, dit. Au-delà de trois cartes en 3D à la fois, les suivantes restent en 2D.

**Performance** : MapLibre (≈ 1,6 Mo) n'est chargé qu'à la première carte affichée en 3D (jamais en 2D), puis gardé par le service worker (`ON_DEMAND`) ; chaque carte en 3D a son contexte WebGL, rendu (`map.remove()`) dès qu'elle quitte la page ; les tuiles de la carte miroir ne se chargent pas pendant ce temps.

**Limites** : relief grossier (EU-DEM, ≈ 25 à 30 m) ; les hauteurs de bâtiments viennent des tuiles vectorielles PLAN IGN (attribut `hauteur` de la couche `bati_surf`, une hauteur par défaut sinon) — les adresses exactes du style et des tuiles vectorielles de la Géoplateforme (`data.geopf.fr/annexes/ressources/vectorTiles/styles/PLAN.IGN/standard.json`, `data.geopf.fr/tms/1.0.0/PLAN.IGN/{z}/{x}/{y}.pbf`) sont celles documentées par l'IGN, testées avec des tuiles simulées ; groupes et éventails sont calculés vue du dessus (à plat, ils restent justes ; inclinés, un peu écrasés).

**Confidentialité** : en 3D, `s3.amazonaws.com` (relief, module « Vue 3D (relief) ») et `data.geopf.fr` (tuiles, bâtiments, plan vectoriel, module « IGN – fonds de carte ») reçoivent la **zone de carte affichée**, jamais votre position ; aucune nouvelle origine dans la Content-Security-Policy (les deux y étaient déjà).

### Autour : les plantes observées dans un périmètre

Sur la **Carte**, le bouton **Autour** trace un cercle (5 km par défaut ; 500 m, 1, 2, 5 ou 10 km) autour de l'endroit sélectionné, sinon de votre position, sinon du centre de la carte, et liste **toutes les espèces de plantes observées dans ce cercle**, classées par nombre d'observations (toutes dates confondues). Toucher une espèce place ses observations sur la carte (les 200 plus récentes, **chacune avec sa photo** ; au survol, sa petite fiche ; un clic ouvre l'observation — sur téléphone, un premier toucher pour la fiche, un second pour l'observation) et mène à sa fiche quand elle fait partie de la flore de l'app (rapprochement par nom scientifique ou synonyme TAXREF). En tête de liste, un récapitulatif : nombre d'espèces, de familles et de genres (familles et genres TAXREF pour les espèces de la flore de l'app) et d'observations ; une recherche filtre la liste par nom français, nom scientifique, genre ou famille (sans tenir compte des accents), et deux filtres à choix multiples, **Famille** et **Genre** (repliés par défaut, valeurs de la plus à la moins représentée dans le cercle, ordre fixe), la restreignent ; le filtre Genre ne propose que les genres des familles choisies.

Source : API **iNaturalist** (`observations/species_counts` et `observations`), observations de **niveau recherche** uniquement (identification confirmée par la communauté) ; résultats gardés 24 h sur l'appareil.

### Lieux de récolte

L'onglet **Carte** enregistre les endroits où vous récoltez, sur les **photos aériennes IGN** (Géoplateforme, sans clé ; aussi Plan IGN et parcelles cadastrales). Un **lieu** (endroit) est une **collection de plantes qui a des coordonnées GPS** : une lisière peut réunir l'ail des ours, l'ortie et la benoîte. **Chaque plante du lieu a aussi sa propre position GPS.** **Une même plante peut y être notée plusieurs fois** (des orties tout le long d'un chemin) : chaque **occurrence** a sa position, son abondance, ses notes et son journal de récolte, numérotée dans la fiche du lieu (« n° 2 ») ; « Ajouter une plante » propose toutes les plantes, même déjà présentes, et « Retirer cette occurrence » n'enlève que celle-là. « Noter ici » d'une plante déjà notée dans le lieu, à moins de 15 m d'une de ses occurrences, enrichit celle-ci (récolte du jour) ; plus loin, c'est une nouvelle occurrence. **La carte d'un lieu est toujours cadrée sur lui et toutes ses plantes**, et se recadre quand une plante est ajoutée, retirée ou déplacée. Les anciennes données reçoivent un identifiant d'occurrence stable (aucune migration de base) ; l'export, le transfert et les liens de partage gardent chaque occurrence.

- **Sur place** : depuis une fiche plante, « 📍 Ajouter un lieu », ou **+** sur la carte. Le GPS s'affiche avec sa précision (± m) ; l'épingle peut être déplacée à la main, ou posée par un appui long sur la carte. À moins de 100 m d'un lieu existant, l'application propose d'**y ajouter la plante** plutôt que de créer un doublon.
- **Position de chaque plante** : « Noter ici » enregistre la plante à votre position GPS (et la rattache au lieu le plus proche à moins de 30 m). Ajoutée depuis l'éditeur, une plante prend votre position GPS si vous êtes à moins de 100 m du lieu, sinon le point du lieu. Sur la carte d'un endroit, les marqueurs sont **fixes** : son bouton **✎** permet de faire glisser le point de l'endroit (le carré) et chaque plante (les ronds), indépendamment (appui long : placer l'endroit) ; chaque position est **enregistrée dès qu'on lâche** le marqueur, « Terminé » quitte le mode. En mode modification, le panneau d'une plante propose aussi « Ici (GPS) » ; sinon « Déplacer » ouvre ce mode. Un nouvel endroit s'ouvre directement en mode modification. **Sur ordinateur** (dès 700 px de large), l'éditeur d'un nouvel endroit montre **la carte ┃ le lieu** côte à côte : le séparateur entre eux se tire (← → au clavier, Début / Fin, double-clic ou Entrée : 480 px), la carte garde au moins 260 px et ne se recadre pas pendant le changement ; la largeur est mémorisée. Plus étroit, la carte reste au-dessus du formulaire.
- **Carte et lieu, une seule page** : choisir un lieu sur la Carte ouvre **toute sa fiche** à côté de la carte (à droite sur ordinateur, dans un volet redimensionnable et repliable « » comme ceux de Flore ; en dessous sur téléphone, à moitié de la hauteur, la poignée l'agrandit) : nom, plantes avec abondance, qualité, notes et journal de récolte, « + Ajouter une plante », notes du lieu, partage, export, suppression ; en tête, le nombre de plantes, la distance et « Itinéraire ». Tout est **enregistré automatiquement**. La carte au-dessus est celle du lieu : toucher une plante sur la carte ouvre son panneau, ouvrir une plante dans la fiche la met en évidence sur la carte, « Déplacer » passe la carte en modification (✎). Un lien vers un lieu (Mes plantes, « Noter ici › Détails », fiche plante) ouvre la Carte sur ce lieu. En mode cueillette, le panneau d'une plante rappelle aussi les **plantes à confondre**.
- **Pour chaque lieu** : nom, notes (accès, propriétaire…), et ses plantes. **Pour chaque plante du lieu** : abondance, qualité (★), notes et **journal de récolte** (date, quantité, remarque). Une plante est **« en saison »** à un lieu si elle y a été récoltée, une année quelconque, à ±15 jours de la date du jour ; un lieu est en saison si l'une de ses plantes l'est.
- **Carte** : deux icônes distinctes. Un **lieu** est un carré sur pied, coloré selon l'abondance la plus forte, avec le nombre de plantes ; il est toujours visible. Une **plante** est sa **photo en miniature** dans un rond cerclé de la couleur de son abondance (une feuille si elle n'a pas de photo), à sa propre position, visible **en zoomant** (niveau 16 et plus) ; la toucher ouvre la fiche du lieu sur cette plante. Filtres « En saison » et par plante. **Choisir un lieu zoome sur lui et toutes ses plantes.** Le bouton **✎** de la carte est toujours là : en mode modification, **tous les marqueurs se glissent librement** (lieux, et plantes en zoomant) et chaque position est **enregistrée au lâcher**, sans étape de validation ; « Terminé » (ou ✎) quitte le mode. Un marqueur tenu sous le doigt n'est jamais replacé par une mise à jour du GPS. Pendant la modification, la carte occupe **tout l'écran**, puis reprend sa place. Une plante sans position propre suit son lieu.
- **Une seule carte** : la même interface partout (Carte et ses lieux, nouveau lieu, lieux d'une plante sur sa fiche, lien partagé) — recherche d'adresse, ▦ fonds, couches et légende, ◎ ma position, fiche d'un point à l'appui long, et ✎ pour déplacer les marqueurs (sauf sur un lien partagé). **Liste** triée par distance.
- **Hors ligne** : le GPS et les lieux fonctionnent toujours ; les zones de carte déjà affichées restent disponibles (3 000 tuiles en cache).
- **Plusieurs onglets ou fenêtres** (l'application installée et un onglet, la Carte d'un côté et une fiche de l'autre) : chaque enregistrement relit le lieu tel qu'il est stocké et n'y applique que **ce qui a été modifié ici** (dans une même transaction IndexedDB) ; une plante ou une récolte ajoutée ailleurs entre-temps n'est jamais effacée, un lieu supprimé dans un autre onglet n'est pas recréé (l'éditeur le dit). Les autres onglets sont prévenus aussitôt (`BroadcastChannel`) et relisent collections, notes, modules, modes et mise en page.
- **Stockage plein** : si l'appareil refuse une écriture faute de place, un message le dit une fois, avec **Exporter mes plantes** et ce qu'il faut faire (libérer de l'espace, recharger) — jamais d'enregistrement perdu en silence. Au premier lancement, si la flore ne tient pas, le message donne la place disponible et la flore n'est pas retéléchargée tant qu'il n'y a pas plus de place.
- **Sécurité des données** : une **copie de secours** de toutes les collections et des notes de fiche est réécrite dans le `localStorage` à chaque modification (jamais remplacée par une liste vide, sauf suppression volontaire). Si la base IndexedDB perd des collections, « Mes plantes » propose de les **restaurer**. La protection du stockage est demandée au navigateur dès la première collection, et *Réglages → Protéger mes données* la redemande ; « Mes plantes » rappelle d'**exporter** quand la dernière sauvegarde a plus de 14 jours. Seul un fichier exporté survit à l'effacement complet des données du site par le navigateur. Réglages affiche un diagnostic du stockage (version, nombre de collections, protection, espace, dates de copie et d'export).
- **Confidentialité** : les lieux restent **sur l'appareil** (IndexedDB, stockage persistant demandé). Ils sont stockés au format **GeoJSON** : *Réglages → Exporter* produit un fichier `.geojson` lisible par QGIS, uMap, geojson.io…, et *Importer* le fusionne : pour une collection déjà présente, les champs de la version la plus récente l'emportent, mais **les plantes des deux versions sont gardées** (une plante ajoutée sur cet appareil n'est jamais retirée par un fichier plus récent qui ne l'a pas ; les journaux de récolte sont réunis) — pour retirer une plante, retirez-la sur chaque appareil. L'ancien format à une plante par point est aussi accepté. Le fichier complet contient aussi les **notes de fiche** (`sheetNotes`), restaurées à l'import (la plus récente l'emporte). Pensez à exporter régulièrement.

Format d'échange (`formatVersion` 5) : un **GeoJSON allégé** qui ne contient que **vos saisies**. Ce que l'application connaît déjà (noms des plantes, familles…) n'y figure pas : les plantes sont désignées par leur identifiant TAXREF et leurs noms sont retrouvés à l'import. Les valeurs par défaut (abondance « moyen », note 0, notes vides…), les champs calculés et la position d'une plante quand c'est celle de l'endroit sont omis ; le fichier est écrit sur une ligne. Les anciens fichiers (formats 1 à 4) restent importables.

```json
{
  "type": "FeatureCollection", "generator": "GeoFlora", "formatVersion": 5, "exportedAt": "…",
  "features": [{
    "type": "Feature", "id": "c0f3…",
    "geometry": { "type": "Point", "coordinates": [4.8357, 45.7641] },
    "properties": {
      "name": "Lisière nord", "notes": "Parking au bout du chemin", "accuracy": 8,
      "createdAt": "…", "updatedAt": "…",
      "plants": [
        { "plantId": 81541, "abundance": "abondant", "rating": 4,
          "harvests": [{ "date": "2026-04-12", "quantity": "1 kg" }] },
        { "plantId": 128268, "coordinates": [4.83581, 45.76402], "accuracy": 6 }
      ]
    }
  }]
}
```

Une collection sans `geometry` est une liste ; l'identifiant `favorites` désigne les favoris.

**Transférer vers un autre appareil** (*Réglages*) : le même GeoJSON allégé, compressé (deflate + base64url), voyage dans un lien `#/shared?d=g…` — rien ne passe par un serveur. À l'ouverture, un aperçu liste les collections ; « Importer » les ajoute ou les met à jour (même identifiant → la plus récente l'emporte, sans doublon). Une case permet d'inclure ou non les notes et journaux de récolte ; une copie plus récente sans notes ne supprime pas celles déjà présentes sur l'appareil.

## Génération locale

Node.js 22+ :

```bash
mkdir -p .cache/taxref
curl -L "https://assets.patrinat.fr/files/referentiel/TAXREF_v18_2025.zip" -o .cache/taxref.zip
unzip .cache/taxref.zip -d .cache/taxref
node scripts/build-plants.mjs
npm ci --ignore-scripts --prefix scripts   # SheetJS, pour enrich-baseflor.mjs et build-safety.mjs
```

La GitHub Action `Build flora dataset` télécharge les sources, valide les modules d'enrichissement, génère puis versionne :

- `data/plants.json`
- `data/meta.json`
- `data/thumbnails.json` (cache d'enrichissement Wikimedia)
- `data/safety.json`

Elle tient en deux jobs. « build » télécharge et analyse les fichiers extérieurs (archive TAXREF, tableurs Baseflor et TPPT, PDF de l'ANSM, Wikimedia) avec un jeton en lecture seule, sans identifiant laissé dans la copie du dépôt ; il vérifie les données, puis les remet dans un artefact gardé sept jours. « commit », sur `main` seulement, reprend ces quatre fichiers, les revérifie et les pousse ; il n'exécute rien de ce qui lit l'extérieur. Un fichier source piégé ne peut donc pousser ni code ni workflow : seulement le contenu de ces quatre fichiers de données, dans les limites que vérifie `scripts/check-data.mjs`.

**Données dégradées : jamais versionnées.** Les étapes qui lisent une source extérieure (Baseflor, statuts INPN, ANSM et TPPT) n'ont plus de `continue-on-error` : une source injoignable garde sa part du jeu précédent (`build-safety.mjs` source par source dans `safety.json`, `enrich-statuses.mjs` et `enrich-baseflor.mjs` depuis `HEAD`), et une erreur restante fait échouer le build avant tout commit. Avant le commit, `scripts/check-data.mjs` (`npm run check:data`) bloque aussi : une source de `safety.json` absente ; un compteur sous son plancher (plantes de `safety.json`, listes A et B de l'ANSM, TPPT, plantes protégées et réglementées, floraisons) ; une baisse de plus de 5 % d'un compteur par rapport au jeu versionné (`HEAD` : plantes, protégées, réglementées, floraisons, vignettes, entrées de `safety.json` par source, paires de confusions). Une baisse voulue passe par un lancement manuel de l'action avec un `max_drop` plus grand. Une source reprise d'un build précédent depuis plus de 30 jours donne un avertissement. Le code est sous licence **MIT** ([`LICENSE`](LICENSE)) ; les données de `data/` sont sous licence **ODbL 1.0** (exigée par Baseflor), sources et attributions dans [`data/LICENSE`](data/LICENSE) ; signaler une faille : [`SECURITY.md`](SECURITY.md). Lancée à la main sur une autre branche, l'action construit sans rien versionner : le résultat est dans l'artefact du run. `Enrich search media` (vignettes de repli GBIF et iNaturalist) suit chaque build de `main` et tourne chaque dimanche, avec le même découpage ; `Deploy web app` republie ensuite.
